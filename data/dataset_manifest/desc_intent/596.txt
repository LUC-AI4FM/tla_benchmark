Write a TLA+ specification for a distributed transaction system supporting both optimistic and pessimistic clients operating over a shared set of keys. Each client is assigned a set of keys to read, a set of keys to write, and a designated primary key. Optimistic clients perform reads before locking, while pessimistic clients lock keys directly without prior reads. The system must guarantee the following correctness properties: type safety across all state components; that any transaction commits or aborts at most once (uniqueness of commit and abort); that committed transactions reflect a consistent snapshot for both reads and writes; that aborted transactions are handled consistently; that writes across transactions do not conflict in an inconsistent way; that locks and writes are not duplicated; that each key is written at most once per committed transaction; that optimistic clients observe snapshot isolation during reads; that pessimistic clients also observe snapshot isolation; and that message timestamps remain consistent throughout the protocol. The specification should be validated against a concrete scenario with two keys and two clients, one optimistic and one pessimistic, where both clients read and write both keys.
