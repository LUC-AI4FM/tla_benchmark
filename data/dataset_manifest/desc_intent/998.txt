Specify a resource allocator that manages a finite set of resources among a set of competing clients using a scheduling discipline. Clients may request a non-empty set of resources only when all prior requests have been fulfilled and they hold no resources. Requests may be partially satisfied incrementally, and clients may return resources before their full request is met, but are only obligated to return resources once their entire request has been granted. The allocator maintains an ordered schedule of clients with outstanding requests; resources may be allocated to any scheduled client out of order, provided no client appearing earlier in the schedule has requested those resources. The schedule is extended by appending permutations of currently unscheduled clients with pending requests.

The specification must guarantee the following safety properties: resources are allocated exclusively (no resource held by two clients simultaneously), all clients in the schedule have outstanding requests, and the allocator can always satisfy each scheduled client's request assuming earlier-scheduled clients eventually release their resources. For liveness, assuming the allocator eventually schedules pending clients, eventually allocates available resources, and clients eventually return all held resources once fully satisfied, every client must obtain each requested resource eventually, every satisfied client must eventually release all resources, and every client must be fully satisfied infinitely often.
