Specify a multi-instance consensus system over a fixed set of named slots, each of which must independently reach consensus on a value drawn from a fixed nonempty set of values. The system operates by first proposing values into a shared pool and then choosing one proposed value per slot. Once a slot has a chosen value it must never change (stability), and each slot may have at most one chosen value (consistency). No value may be chosen for any slot unless it was previously proposed (nontriviality). These three are the core safety properties. For liveness, under fair execution every slot must eventually have a chosen value. Assume both the set of values and the set of slots are nonempty. The specification should be checked with two values and two slots, verifying the type invariant as an invariant and all four properties — nontriviality, stability, consistency, and liveness — as temporal properties, with deadlock checking disabled.
