Specify a voucher redemption protocol modeled after the "Redeem" operation from RFC 3506, implemented as a Two-Phase Commit protocol. The system involves three kinds of participants: a set of Vouchers, a set of Voucher Holders, a set of Voucher Collectors, and a single Voucher Transaction Provider (VTP) that coordinates the redemption. Each voucher begins in a valid state and may transition to redeemed; each holder starts in a holding state and each collector in a waiting state. Holders and collectors independently decide to either prepare for redemption or spontaneously abort, sending prepared messages to the VTP without an explicit prepare phase from the coordinator. The VTP commits the redemption only once all holders and all collectors have signaled readiness; otherwise it may abort spontaneously. On receiving a redeem or abort broadcast, holders and collectors update their states accordingly. The key safety invariant is consistency: no holder must reach the redeemed outcome while any collector reaches aborted, and vice versa. The specification must also refine a higher-level voucher lifecycle model in which a voucher simply moves from a working state to done.
