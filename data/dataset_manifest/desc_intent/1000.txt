Specify a resource allocator managing a shared pool of resources among a fixed set of clients. A client may submit a request for a nonempty set of resources only when it has no outstanding unsatisfied requests and currently holds no resources. The allocator may fulfill a request partially — allocating any nonempty subset of the requested resources that are currently available — and a client may return any subset of its held resources at any time, even before its full request has been satisfied. A client is only obligated to return resources once its entire request has been fulfilled.

The specification must guarantee the following properties: mutual exclusion (no resource is ever held by more than one client simultaneously); eventual return (whenever a client has no outstanding requests, it will eventually release all held resources); eventual allocation (every resource in an outstanding request will eventually be allocated to that client); and infinite satisfiability (every client's outstanding request is eventually fully satisfied infinitely often). Fairness conditions should ensure that allocations are made with strong fairness and that clients return their full allocation with weak fairness once fully satisfied.
