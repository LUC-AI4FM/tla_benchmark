Specify a small TLA+ demonstration model for illustrating how a model-checking state constraint can interact with liveness checking. The system is a single deterministic process with two normal control locations, A and B. It starts in A with an empty record of prior progress. Each time it moves from A to B, it appends an entry to that record; each time it moves from B to A, the record is left unchanged. The process should be allowed to stutter, but the normal alternating transition must be weakly fair, so an execution cannot avoid taking progress steps forever when they remain possible.

Include a finite-state exploration constraint that permits only states where the record contains fewer than three entries. The intended liveness property to check is that the process eventually reaches a terminal Done location, even though the modeled transition structure never actually reaches such a location. The specification is meant as a warning/test case for liveness under constraints.
