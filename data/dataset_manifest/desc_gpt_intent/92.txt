Write a TLA+ specification for a small demonstration module that shows how configuration-supplied constants of several kinds are bound and checked. The model should have a simple state containing an integer parameter, a string parameter, one selected symbolic/model value, and a set of integers, all initialized directly from constants supplied by the configuration. After initialization, the system is quiescent: no transition changes any part of the state.

The specification should be intended as a configuration-parameter test rather than a real algorithm. Its main safety property is that the initialized and forever-unchanged state reflects the configured values: the integer is 42, the string is "hello", the set is exactly {1, 2, 3}, and the selected symbolic value is the first configured model value and is distinct from the second configured model value. There is no substantive liveness requirement beyond permitting infinite stuttering behavior while preserving the invariant.
