Specify a TLA+ specification for a utility that models the PlusCal translation phase from a parsed, renamed abstract syntax tree into a TLA+ token sequence. The spec should accept either a uniprocess or multiprocess algorithm AST, including declarations, definitions, procedures, processes, labels, loops, conditionals, nondeterministic choices, with-statements, assignments, calls, returns, gotos, assertions, prints, skips, and guards. It must validate that the tree conforms to the expected grammar, report malformed input, reject duplicate labels within the same control context, and reject gotos whose targets are not legal labels except for the reserved termination/error targets.

For valid input, it must generate a TLA+ specification faithfully representing the algorithm’s atomic labeled steps, initialization, variables, control state, procedure-call stack behavior, unchanged variables, process sets, procedure actions, overall next-state action, complete temporal specification, and a termination predicate. It must detect translation errors such as undeclared assignments, conflicting multiple assignments, nonexistent procedures, and wrong argument counts. The generated temporal spec must include exactly the requested fairness condition: none, weak fairness of process actions, weak fairness of the whole next action, or strong fairness of process actions.
