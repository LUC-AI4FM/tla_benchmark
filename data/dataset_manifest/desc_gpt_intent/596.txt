Specify a TLA+ specification for a small model-checking instance of a distributed transaction protocol over two data keys and two clients. One client should use a pessimistic transaction style, writing both keys and reading no keys; the other should use an optimistic style, reading and writing both keys. Both transactions should have the same primary key.

The model should cover transaction execution, reads, writes, locking or write ownership, commit, abort, and timestamped messages sufficient to reason about distributed consistency. It must guarantee safety properties: each transaction has at most one final outcome, committed and aborted states are internally consistent, writes correspond to valid transaction behavior, no conflicting lock/write ownership is possible, each key/version write is unique, optimistic and pessimistic reads observe valid snapshot-isolated states, and message timestamps remain consistent with the protocol’s ordering assumptions. This is a bounded test scenario for invariant checking; no additional fairness, termination, or eventual-commit liveness requirement is needed.
