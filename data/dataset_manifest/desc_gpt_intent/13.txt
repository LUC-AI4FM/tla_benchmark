Specify a TLA+ specification for a rolling deployment of a fixed three-server service behind a load balancer. Each server starts on the old version and can later be in an in-progress updating state or on the new version. The model should include a deployment controller that decides which servers are eligible to update and which servers are currently receiving traffic, while individual servers update asynchronously once permitted.

The deployment strategy should allow the service to migrate all servers from old to new without exposing mixed versions to clients. At every reachable state, all servers currently receiving traffic must report the same version/status. The model should also guarantee zero downtime: at least one traffic-serving server is always available and not in the in-progress updating state. Servers not receiving traffic may update concurrently.

Assume fair scheduling for the deployment controller and server update activities. Under these assumptions, the deployment should eventually complete, with every server updated and returned to service.
