Specify a TLA+ specification for a scheduling resource allocator with a finite set of resources and a set of clients. Clients may issue a nonempty request for a set of resources only when all prior requests are complete and they hold no resources. Requests may be fulfilled partially, and clients may return any resources they hold even before the whole request is satisfied, but once a client’s request is fully satisfied it must eventually return its resources.

The allocator should maintain an explicit ordering of pending clients, extending it by choosing some order for newly pending requests. It may allocate available requested resources to a scheduled client, including out of order, provided no earlier scheduled client is still requesting those resources. When a client’s remaining request is fully allocated, it leaves the schedule.

The specification must guarantee exclusive ownership of each resource, maintain that the schedule only contains clients with outstanding requests, and preserve that scheduled requests remain satisfiable assuming earlier clients eventually release resources. Under weak fairness, every requested resource is eventually obtained, satisfied clients eventually release resources, and every client is infinitely often without an outstanding request.
