Specify a TLA+ specification for a simple single-client key-value store over finite sets of keys and values. The store initially contains no keys, using a distinguished marker to represent absence. Model four operations: get, insert, update, and delete, with at most one operation in progress at a time through a request/response interface.

A get for a key must return the currently stored value if present, otherwise the distinguished missing result. An insert must add the key-value binding and return “ok” only when the key is absent; if the key already exists, it must leave the store unchanged and return “error”. An update must change the value and return “ok” only when the key is present; otherwise it leaves the store unchanged and returns “error”. A delete must always return “ok” and make the key absent, whether or not it existed.

The specification should maintain type correctness and include only a minimal progress assumption that deletion requests are eventually accepted whenever the store remains continuously ready to accept one.
