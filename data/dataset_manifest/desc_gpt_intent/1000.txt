Specify a TLA+ specification for a simple shared-resource allocator with a finite set of resources and a set of clients. Clients may issue a nonempty request for resources only when they have no outstanding unmet request and hold no resources. The allocator may satisfy requests incrementally, granting any nonempty subset of currently free resources that the client requested. Clients may return any nonempty subset of resources they currently hold, including before their whole request has been granted.

The model should require fair progress: if a client continues to hold resources, returning them must eventually occur, and if allocation to a client remains possible, allocation must eventually occur. The specification must maintain correct typing and guarantee mutual exclusion: no resource is ever allocated to two distinct clients at once. It should also prove liveness properties: each requested resource is eventually obtained, once a client’s request is fully satisfied the client eventually holds no resources, and every client is infinitely often in a state with no outstanding request.
