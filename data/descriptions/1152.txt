This specification models a simplified version of the Ghostferry data-copying algorithm that copies a source database table to a target database while concurrently streaming and applying binlog entries. The model represents the system as four processes: a table iterator that copies rows, a binlog streamer that replays source updates onto the target, an application that performs concurrent INSERT/UPDATE/DELETE-style changes on the source and appends corresponding binlog entries, and a ferry coordinator that performs cutover by making the application read-only and then stopping binlog streaming after a target position is reached. The spec checks a liveness-style termination property and a safety property asserting that once all processes are done, the source and target tables are equal; it also uses fairness assumptions for all four processes and an action constraint to bound binlog growth for model checking feasibility.
