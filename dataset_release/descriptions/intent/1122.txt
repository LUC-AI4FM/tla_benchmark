Specify a two-phase commit protocol with a backup transaction manager. The system involves a configurable set of resource managers and a primary transaction manager, where both the resource managers and the primary transaction manager may optionally be configured to fail. Each resource manager begins in a working state and may prepare, decide to commit or abort based on the transaction manager's decision, or fail. The primary transaction manager monitors the resource managers and, once all are prepared (or one has already committed), issues a commit decision; if any has aborted or failed and none has committed, it issues an abort decision. After broadcasting its decision, the primary transaction manager may fail by hiding its state. A backup transaction manager watches for this failure and, if the primary's decision is hidden, re-issues the appropriate commit or abort decision so that resource managers can proceed. All three participant types must be modeled with fair scheduling. The key safety property is consistency: no two resource managers must ever reach conflicting decisions, meaning one must never commit while another aborts. The type correctness of all state variables must also be maintained as an invariant. The specification should also exhibit termination, guaranteeing that all processes eventually finish.
