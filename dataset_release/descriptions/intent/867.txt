Specify the classic Paxos consensus protocol without explicit leaders or learners. The system consists of a fixed set of replicas acting as both proposers and acceptors, a set of possible values, a set of ballot numbers (including zero as a sentinel), and a collection of quorums — each quorum being a strict majority subset of replicas such that any two quorums intersect.

The protocol proceeds in two phases. In Phase 1, a proposer broadcasts a Prepare message for some ballot to all acceptors; each acceptor that has not yet seen a higher ballot responds with a Promise carrying its highest previously accepted ballot and value. In Phase 2, a proposer that has collected promises from a full quorum selects a value — constrained to the value paired with the highest accepted ballot among the promises if any acceptor previously accepted one, otherwise freely chosen — and broadcasts an Accept request; acceptors that have not promised a higher ballot record the value and broadcast an Accepted acknowledgment. A decision is recorded when a quorum of acceptors has sent Accepted messages for the same ballot.

The specification must enforce two safety properties: non-triviality, meaning only values that were actually proposed can be decided, and consistency, meaning once a value is decided it never changes. The system need not guarantee liveness, reflecting the FLP impossibility result, so the only liveness obligation is strong fairness on the decide action.
