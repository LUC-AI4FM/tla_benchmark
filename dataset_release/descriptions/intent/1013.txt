Specify a voucher issuance protocol modeled after the "Issue" operation from RFC 3506, implemented over Two-Phase Commit. The system involves three kinds of participants: a Voucher Transaction Provider (VTP) that coordinates the transaction, a set of Voucher Issuers, and a set of Voucher Holders, along with a set of vouchers that begin in a "phantom" state and transition to "valid" upon successful issuance. The VTP collects "Prepared" messages from all Holders and Issuers; once every participant has prepared, the VTP may issue the voucher, broadcasting an Issue message to all parties. At any point before issuing, the VTP may spontaneously abort instead, broadcasting an Abort message. Holders and Issuers may also spontaneously choose to abort locally without notifying the VTP. The key safety property is consistency: no Holder should end up in the "holding" state while any Issuer is "aborted," and no Issuer should end up "issued" while any Holder is "aborted." The specification must also implement a higher-level voucher lifecycle specification, demonstrating that the Two-Phase Commit protocol correctly refines that abstract voucher state machine.
