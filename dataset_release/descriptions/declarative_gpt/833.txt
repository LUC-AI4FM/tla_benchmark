This specification models MultiPaxos in the style of state machine replication (SMR) for a single key, supporting both write and read commands. The network is modeled as a monotonic set of sent messages, capturing asynchronous, non-Byzantine behavior: messages may be delayed, duplicated, or lost (with the assumption that lost messages are retried until received). The spec checks linearizability from the client's perspective by observing the sequence of request and acknowledgement events, and verifies liveness by ensuring no deadlocks occur until all requests are observed. The design is modular, with clear separation of client events, server states, and message types, and is implemented in PlusCal with a translation to TLA+ for model checking. Notable design decisions include the use of unique ballots for leader election, explicit modeling of majority quorums, and a focus on practical system behaviors such as idempotency and efficient state space reduction.
