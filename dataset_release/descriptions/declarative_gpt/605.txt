This specification models the Raft consensus algorithm, a distributed protocol for managing a replicated log across a cluster of servers. The model captures the core Raft roles (Follower, Candidate, Leader), the election process, log replication, and client request handling. It includes detailed state variables for each server, message passing via a bag abstraction, and history variables to support proof obligations. The fault model allows for message duplication, loss, and server restarts, but not Byzantine faults. The temporal property Spec asserts that the system starts in Init and all transitions follow Next, which covers all possible state changes, including network nondeterminism. The design is modular, with helper operators for message handling and log management, and is structured to facilitate both model checking and deductive proofs.
