This module specifies a Tendermint light client verification state machine together with an instantiated blockchain environment. The light client begins from a socially trusted block at TRUSTED_HEIGHT, fetches or reuses light blocks, verifies them via an external verification API, updates a light store and block-status map, and iterates until it either reaches TARGET_HEIGHT successfully or finishes with failure. The model includes clock drift between a local client clock and a reference blockchain clock, a primary that may be correct or faulty, and a faulty-validator ratio parameter; it defines many safety-style invariants about correctness, trust, and stored headers, as well as some expected-to-fail candidate properties and complexity/postcondition checks.
