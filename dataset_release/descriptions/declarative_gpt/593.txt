This specification models a distributed transaction protocol with both optimistic and pessimistic clients, inspired by TiKV/Percolator-style locking, prewrite, commit, rollback, and lock resolution behavior. The model represents requests as a monotonically growing set of sent messages and models responses as direct atomic client-handling actions, explicitly abstracting away in-transit response delivery while retaining enough history to verify safety properties. It focuses on safety rather than liveness, including type correctness, commit/abort consistency, lock/write consistency, uniqueness properties, message timestamp consistency, and snapshot isolation for both optimistic and pessimistic transactions; stale-lock cleanup is modeled via check_txn_status and resolve messages, with TTL abstracted as always expired when checked.
