This is a test module for the Apalache model checker, created to reproduce a specific bug (issue #1425) related to the original Bakery algorithm. It is not a full system specification but rather a minimal reproduction case.

The module defines two variables over a fixed process set `Procs = 1..4`: `unchecked`, a function mapping each process to a set of integers, and `nxt`, a function mapping each process to a single integer. Initially, every process has an empty `unchecked` set and `nxt` value of 1.

The `Next` relation allows one of two things to happen: either some process `self` nondeterministically picks an element `i` from its `unchecked` set and updates `nxt[self]` to that value, with the additional guard that the newly assigned `nxt'[self]` must still belong to `unchecked[self]`, leaving `unchecked` unchanged; or the system stutters with no state change. The notable feature being tested is the use of a primed variable (`nxt'`) in a guard condition within the same action that assigns it, which is the pattern that triggered the Apalache issue. No invariants, liveness properties, or temporal specification are defined.
