The PlusCal module specifies the translation phase of the PlusCal-to-TLA+ compiler. It is not a behavioral model of a concurrent system but rather a functional specification of a program transformation, intended to be executed by TLC as a model-checker-driven evaluator rather than as a state-space exploration.

The module imports an external module AST, which is expected to supply two constants: `ast`, the abstract syntax tree of a PlusCal algorithm, and `fairness`, a string selecting the fairness condition. The module is organized into three parts. Part I defines the predicate `IsAlgorithm`, which recursively characterizes well-formed ASTs for both uniprocess and multiprocess PlusCal algorithms, covering all statement types (assignment, if/either/with/while/goto/call/return/skip/when/print/assert), variable declarations, procedures, and processes. Part II defines `CheckLabels`, which traverses the AST to verify that no duplicate labels appear within the same scope and that every `goto` destination refers to an existing label. Part III defines `Translation`, the core artifact: given a legal AST, it produces a sequence of strings representing the complete TLA+ specification derived from the algorithm, including variable declarations, the `Init` predicate, labeled-action definitions for each labeled statement in each procedure and process, the `Next` next-state action, the `Spec` temporal formula with the appropriate fairness conjuncts, and the `Termination` liveness formula. Recursive operators are simulated via CONSTANT substitutions in the configuration file. The module's ASSUME clause invokes TLC to validate the AST, check labels, and print the translation.
