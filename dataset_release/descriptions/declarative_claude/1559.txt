The LockHS module augments a simple mutual-exclusion Lock specification with two auxiliary variables — a history variable and a stuttering variable — so that it can be shown equivalent (via refinement) to a Peterson's algorithm specification.

The module extends the base Lock module and introduces `h_turn`, a history variable that tracks which process was assigned the Peterson turn value, and `s`, a stuttering variable drawn from the Stuttering module. Together these auxiliary variables allow LockHS to simulate the three atomic steps Peterson uses to enter the critical section, even though the base Lock collapses them into one. The initial condition `InitHS` requires `Init` from Lock, `h_turn = 1`, and `s = top` (no active stutter). The key action `l1HS` wraps the base `l1` step with two inserted stuttering steps via `PostStutter`, updating `h_turn` only during the appropriate stutter transition. All other process actions (`l0`, `cs`, `l2`) proceed without stuttering and leave `h_turn` unchanged. The overall specification `SpecHS` is a safety property over the combined variable tuple.

The module checks three invariants: `TypeOKHS` asserts well-typedness of all variables; `InvHS` asserts consistency conditions linking the stuttering state and program counters to `h_turn`; and `LockInv` is the mutual-exclusion invariant inherited from Lock. Via the `pc_translation` and `c_translation` functions, the module instantiates the Peterson specification `P` and asserts that both `Spec` (the base Lock temporal property) and `PSpec` (Peterson's temporal property) hold, establishing bidirectional refinement.
