The module models a simplified network protocol involving two processes — a sender and a receiver — that together achieve in-order delivery of sequenced messages to a client.

Four variables track the system state: `sentSeqNo`, the sequence number of the next message the sender will produce; `sent`, the set of all messages (identified by sequence number) that have been sent; `received`, the subset of sent messages that the receiver has collected; and `deliveredSeqNo`, the sequence number of the last message delivered to the client (initialized to −1, meaning nothing delivered yet). The three actions are `Send`, which adds the current sequence number to `sent` and increments `sentSeqNo`; `Receive`, which non-deterministically adds any subset of undelivered sent messages to `received`, modeling out-of-order network arrival; and `Deliver`, which advances `deliveredSeqNo` by one whenever the next expected message is already in `received`, enforcing strict in-order delivery. The overall next-state relation is the disjunction of these three actions. The sole invariant, `Inv`, asserts that if any message has been delivered (i.e., `deliveredSeqNo ≥ 0`), then that sequence number must belong to the set of sent messages — ensuring the receiver never delivers a message the sender has not yet produced. No fairness conditions or liveness properties are specified.
