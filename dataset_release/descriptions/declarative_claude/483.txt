The module specifies a simplified version of the Paxos consensus algorithm without explicit leader or learner processes, operating over a fixed set of three acceptors, two values, and three ballot numbers. The four variables are `maxBal` (the highest ballot number each acceptor has promised to respect), `maxVBal` and `maxVal` (the ballot number and value of the highest-numbered vote each acceptor has cast), and `msgs` (the ever-growing set of all messages sent, serving as a reliable broadcast medium).

The four actions correspond to the standard Paxos phases. `Phase1a(b)` broadcasts a prepare message for ballot `b`. `Phase1b(a)` lets acceptor `a` respond to a prepare message for any ballot exceeding its current `maxBal`, updating that bound and reporting its highest prior vote. `Phase2a(b, v)` fires when no phase-2a message for ballot `b` exists yet and a quorum of phase-1b responses establishes that value `v` is safe at `b` — either because no quorum member has voted before, or because `v` matches the value voted in the highest prior ballot among quorum members. `Phase2b(a)` lets acceptor `a` cast a vote for the value in any phase-2a message whose ballot meets or exceeds `a`'s current `maxBal`. Notably, the `Next` relation includes only `Phase2a`, making `Spec` a heavily restricted behavior used for refinement checking rather than full execution. The module defines a `votes` function mapping acceptors to their phase-2b votes, copies the `ShowsSafeAt` predicate from the companion `Voting` module, and states an inductive invariant `Inv` capturing type correctness, vote-record consistency, and the safety of every phase-2a message sent.
