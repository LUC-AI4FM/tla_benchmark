The module specifies a fault-tolerant two-phase commit (2PC) protocol involving a set of resource managers (RM), a primary transaction manager (TManager), and a backup transaction manager (BTManager). The constants RM, RMMAYFAIL, and TMMAYFAIL control the participating RMs and whether failures are enabled; in the model configuration, RM has three members and both failure flags are TRUE.

Each resource manager progresses through states "working", "prepared", "committed", "aborted", or "failed", tracked in `rmState`. The transaction manager state `tmState` takes values "init", "commit", "abort", or "hidden". Resource managers may prepare, decide to commit or abort based on `tmState`, or fail (at most one RM may be in the failed state at a time). The primary TManager waits until either all RMs are prepared (or one has already committed) to issue a commit, or until some RM is aborted or failed (and none committed) to issue an abort; if TMMAYFAIL is TRUE, it then hides its decision by setting `tmState` to "hidden". The BTManager monitors for a hidden TManager decision and reissues the commit or abort, thereby recovering from TManager failure. All three process families run under weak fairness, ensuring that enabled actions are eventually taken. The temporal property Termination asserts that all processes eventually reach their done states.

The checked invariants are TypeOK (all state variables hold legal values) and Consistency (no two RMs ever reach conflicting commit and abort decisions simultaneously). The constant NotCommitted is defined but not listed as an invariant in the configuration.
