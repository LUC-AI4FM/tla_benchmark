The module models Microsoft Azure Cosmos DB's five consistency levels — strong, bounded staleness, session, consistent prefix, and eventual — from the perspective of clients interacting with a multi-region database, without modeling internal replication protocol details.

Constants parameterize the number of total regions (`NumRegions`), writable regions (`NumWriteRegions`), clients per region (`NumClientsPerRegion`), a maximum operation count (`MaxNumOp`), the chosen `Consistency` level, and the staleness bound `K`. Variables track a global operation `History`, per-region `Data` values and `Database` logs (sequences of written values), a shared incrementing `value`, and per-client `session_token` and `numOp` counters.

Client processes each perform up to `MaxNumOp` operations, nondeterministically choosing to write or read at their local region. Writes are gated by the staleness bound (the difference between any two regions' data values must stay below `Bound`) and append to the regional database log and global history. Reads are gated by session-token and strong-consistency preconditions before recording the observed value. A single CosmosDB server process continuously and nondeterministically replicates data from any write region to any region by merging and deduplicating logs. All processes have weak fairness.

The `Invariant` property selects consistency-level-specific safety checks: linearizability and read-after-write for strong; bounded staleness differences and monotonic reads for bounded staleness; per-client monotonic reads and read-your-writes for session; monotonic writes and valid regional reads for consistent prefix; and data-in-database membership for eventual. A `Liveness` property asserts that all regional databases eventually converge to identical state.
