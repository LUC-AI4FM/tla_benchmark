The module models a simplified leader-election and consensus protocol over a fixed set of three nodes ("1_OF_N", "2_OF_N", "3_OF_N") with two possible decision values. It is adapted from the consensus-epr benchmark and is noted as a test case for function operations in TLA+.

The state consists of six variables: `vote_request_msg` and `vote_msg` (sets of directed node pairs representing in-flight request and vote messages), `voted` (a per-node boolean tracking whether a node has cast a vote), `votes` (a per-node set recording received votes), `leader` (a per-node boolean), and `decided` (a per-node set of chosen values). Initially all variables are empty or false.

The five actions model the protocol steps: `SendRequestVote` adds a request-vote message between any two nodes; `SendVote` allows an unvoted node that received a request to cast a vote and mark itself as voted, optionally removing or retaining the triggering request message; `RecvVote` lets a node record an incoming vote; `BecomeLeader` promotes a node once a quorum of votes is collected; and `Decide` lets a leader choose a value, provided it has not already decided. No fairness conditions are imposed. The sole checked property, `Safety`, asserts that any two decided values across any two nodes must be identical, capturing the agreement requirement of consensus.
