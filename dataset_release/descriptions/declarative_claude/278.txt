The module specifies the Two-Phase Commit (2PC) protocol, adapted from Leslie Lamport's canonical TLA+ example and annotated with Apalache type annotations. It models a transaction manager (TM) coordinating a set of resource managers (RMs) to reach a consistent commit or abort decision.

The constant `RM` is the set of resource managers. The variables are `rmState`, a function mapping each RM to one of `"working"`, `"prepared"`, `"committed"`, or `"aborted"`; `tmState`, the TM's state (`"init"`, `"committed"`, or `"aborted"`); `tmPrepared`, the set of RMs from which the TM has received Prepared messages; and `msgs`, the set of messages in transit, drawn from typed variants `Commit`, `Abort`, and `Prepared(rm)`. Initially, all RMs are working, the TM is in `"init"`, and no messages have been sent.

The TM actions are: `TMRcvPrepared`, which records receipt of a Prepared message from an RM; `TMCommit`, which transitions the TM to committed and broadcasts a Commit message once all RMs have prepared; and `TMAbort`, which spontaneously moves the TM to aborted and broadcasts an Abort message. The RM actions are: `RMPrepare`, which moves an RM from working to prepared and sends a Prepared message; `RMChooseToAbort`, which moves an RM directly to aborted; `RMRcvCommitMsg`, which commits an RM upon seeing the Commit message; and `RMRcvAbortMsg`, which aborts an RM upon seeing the Abort message. The temporal specification `TPSpec` is a safety-only stuttering-closed formula with no fairness. The invariant `TCConsistent` asserts that no two RMs ever reach conflicting decisions.
