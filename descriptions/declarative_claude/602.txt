This TLA+ module specifies Google's Percolator distributed transaction protocol, which implements snapshot isolation over a multi-version key-value store.

The system models multiple clients executing transactions concurrently over a set of keys. Constants define the keys, clients, and each client's designated primary key. Variables track a global monotonic timestamp counter, per-client state (init, working, prewriting, committing, committed, or aborted), per-client timestamps and key assignments, and per-key storage structures including multi-version data, locks, and committed write records. Auxiliary variables track read timestamps and snapshot isolation violations.

Clients progress through transaction phases: Start assigns a start timestamp; Get allows reading keys, cleaning stale locks, or advancing to prewrite; Prewrite acquires locks on the primary key first then secondaries, storing tentative data; Commit writes the commit record for the primary key and releases its lock; Abort halts the client at any non-committed state. The protocol handles lock cleanup by checking if primary keys are committed, then either rolling back or committing secondary keys accordingly.

The specification checks several invariants: type correctness for all variables; write consistency ensuring non-overlapping ordered commits; lock consistency ensuring at most one lock per key and that secondary locks exist when primaries do during commit; committed and aborted consistency ensuring proper key states; and snapshot isolation preservation verified through auxiliary tracking that no write commits below a prior read timestamp.
