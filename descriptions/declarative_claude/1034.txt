The module `TLCSailfish1` is a model-checking configuration wrapper for the `Sailfish` consensus protocol, instantiated with a specific small-scale scenario designed to exercise Byzantine fault tolerance while keeping the state space manageable.

The system comprises three nodes (`n1`, `n2`, `n3`), where `n1` is the single Byzantine node (`F = {n1}`). Rounds are bounded to `1..5`. Quorums are defined explicitly as any set containing at least two nodes including `n3` or the full set, and blocking sets are those containing `n3`. The leader schedule cycles through the three nodes in order. The global stabilization time (`GST`) is set to round 3, after which the network is assumed synchronous.

The `Sailfish` module is instantiated with these parameters and the four variables `vs`, `es`, `round`, and `log`, which track vertices, edges, per-node round progress, and committed log entries respectively. The temporal specification `TerminatingSpec` allows the system to stutter once all correct nodes have reached the maximum round, enabling the model checker to terminate cleanly. A `StateConstraint` restricts correct nodes' rounds to the bounded range.

The configuration checks three invariants imported from `Sailfish`: `TypeOK` (type correctness), `Agreement` (safety: no two correct nodes commit conflicting logs), and `Liveness` (correct nodes make progress). Three `Falsy` properties are defined as negations of reachable states—such as all correct nodes reaching the final round, any correct node having a log longer than one entry, or round-2's leader vertex being committed—intended to be used as false invariants to extract interesting counterexample traces from the model checker.
