This TLA+ module defines a collection of invariants for verifying properties of an external transaction history in a distributed system, extending a base module called ExternalHistory. The specification models a system where clients submit read-write and read-only transaction requests and receive responses, with transactions identified by IDs containing view and sequence number pairs.

The module checks numerous safety invariants organized into several categories. Request-response ordering invariants ensure every transaction response is preceded by a corresponding request in the history. Uniqueness invariants verify that transaction IDs uniquely identify read-write transactions, that requests are unique, and that committed transactions have unique sequence numbers.

Commitment consistency invariants establish that committed and invalid transaction statuses are mutually exclusive, that commitment of a transaction implies commitment of all earlier transactions in the same term, and that commitment implies invalidity of transactions with smaller terms but equal or greater sequence numbers.

Observation invariants ensure responses only observe previously requested transactions, each transaction is observed at most once per response, and committed transactions observe all previously committed transactions respecting real-time ordering.

The specification defines serializability as requiring observation sequences to form prefix relationships. The key correctness property is ordered speculative linearizability for committed read-write transactions, combining serializable ordering by transaction ID with real-time ordering constraints. This captures CCF's consistency guarantee where clients receive speculative responses before learning commit status.

Several debug invariants test reachability of states with committed or invalid transactions.
