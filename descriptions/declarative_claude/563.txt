This module serves as a model-checking configuration wrapper for a Two-Phase Commit protocol specification defined in an imported `TwoPhase` module.

The specification models a distributed transaction commit protocol involving resource managers (RMs) and a transaction manager (TM). The system tracks four variables: the state of each resource manager (which can be working, prepared, committed, or aborted), the transaction manager's state (either init or done), the set of resource managers the transaction manager knows are prepared, and a set of messages exchanged between participants.

The module defines a type-correctness invariant `TPTypeOK` that constrains all variables to their expected domains, ensuring resource manager states, transaction manager state, prepared set membership, and message contents remain well-typed throughout execution.

The specification imports a `TCommit` module and instantiates it to check that the Two-Phase Commit protocol correctly implements transaction commit semantics. The theorem asserts that the two-phase protocol specification implies the transaction commit specification property.

The model-checking configuration instantiates the system with three resource managers (r1, r2, r3), verifies the type invariant holds in all reachable states, checks that the transaction commit specification property holds, and disables deadlock checking since the protocol may legitimately reach terminal states.
