This module provides a model-checking configuration for a PlusCal-based Paxos consensus specification. It extends a PaxosPlusCal module that defines the core algorithm behavior.

The specification models the Paxos distributed consensus protocol with three acceptors forming three overlapping quorums (any two acceptors constitute a quorum), two possible values that can be proposed, and ballots numbered zero through two. Symmetry reductions over acceptors and values optimize state exploration.

The module defines helper predicates for reasoning about the protocol: whether an acceptor voted for a value in a ballot, whether an acceptor cannot vote in a ballot, and whether a value has been chosen by a quorum.

Four invariants are checked. TypeOK ensures all variables have appropriate types—messages belong to a structured set, and acceptor state variables map to expected domains. MessageInv verifies message validity: 1b messages correctly report voting history, 2a messages propose only safe values with unique values per ballot, and 2b messages correspond to existing 2a messages. AcceptorInv ensures acceptor state consistency, including that maxPrepared always meets or exceeds maxAccepted. ConsistencyInv states the core safety property: at most one value can ever be chosen.

The specification also checks refinement of a single-value consensus specification through the ConsensusSpec property, demonstrating that Paxos implements abstract consensus. Deadlock checking is disabled since termination is not required.
