This TLA+ module provides a formal framework for specifying and checking client-centric isolation levels for database transactions, based on the theoretical work by Crooks et al.

The module defines fundamental data types for modeling transactional systems: States map keys to values, Operations are reads or writes on key-value pairs, and Transactions are sequences of operations. An Execution represents a totally ordered sequence of transactions paired with their parent states—the database state from which each transaction reads.

The specification introduces the concept of ReadStates, which determines from which states an operation can legally obtain its value, considering both direct reads from committed states and reads-your-own-writes within a transaction. The Complete predicate checks whether a state satisfies all read requirements for a transaction, while NoConf ensures no write conflicts exist between a transaction's write set and changes since its read state.

The module defines commit tests for multiple isolation levels: Read Uncommitted (trivially satisfied), Read Committed (all operations have valid read states), Snapshot Isolation (exists a complete state without conflicts), Serializability (parent state is complete), and Strict Serializability (serializability plus timestamp ordering constraints).

The satisfyIsolationLevel operator checks whether there exists any valid execution of a transaction set that satisfies a given isolation level's commit test. Helper functions generate all possible execution orderings and compute state transitions from transaction effects.
