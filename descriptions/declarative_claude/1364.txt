This TLA+ module is a test case designed to verify correct behavior of the TLC model checker when handling nested EXCEPT operations on function values, specifically addressing a potential bug related to GitHub issue 1302.

The specification defines a domain S consisting of functions from the singleton set {1} to {1, 2}, and an initial function I that maps all elements of S to zero. Two record values r1 and r2 are defined as functions mapping 1 to 1 and 1 to 2 respectively. A function fcn maps r1 to the value 10.

The system uses two variables, x and y. In the initial state, x is constructed by modifying I at position r1 to hold fcn, and y is then constructed by further modifying x at position r2 to hold 99. The next-state relation leaves both variables unchanged, making this a single-state specification.

The module defines a reference value called correct that computes the expected result by evaluating the same nested EXCEPT expressions from scratch, avoiding any potential shared mutable state.

The invariant Inv checks that the TLC fingerprint of y equals the fingerprint of correct. This verifies that the incremental construction of y through successive EXCEPT operations produces the same result as computing the expression directly, detecting any corruption from improperly shared internal data structures.
