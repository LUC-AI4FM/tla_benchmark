The Client module models the client-side behavior of a session-based client–server protocol, extending a Messages utility and a Server module. It introduces two variables: `client`, a per-client record tracking each client's current session identifier (initialized to `Nil`), and `clientCommand`, a monotonically increasing counter used to label successive commands (initialized to 1).

The module defines four actions. `OpenSession` allows a client with no active session to send an `OpenSessionRequest` message to a designated server. `CloseSession` allows a client that holds an active session to send a `CloseSessionRequest` carrying its session ID. `ClientRequest` allows a client with an active session to send a `CommandRequest` carrying its session ID and the current command counter, then increments `clientCommand`. The `ClientReceive` action dispatches incoming messages by type: an `OpenSessionResponse` stores the assigned session ID in `client`; a `CloseSessionResponse` resets the session ID back to `Nil`; a `CommandResponse` is simply discarded with no state change. All actions use `Send` and `Discard` from the Messages module to manage the message bag. The module specifies no temporal properties or invariants of its own; it serves as a behavioral component to be composed within a larger specification.
