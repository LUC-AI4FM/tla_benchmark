This TLA+ module tests the TLCExt extension's model value functionality, specifically the `TLCModelValue` operator that creates typed model values at runtime.

The specification defines a single variable `mvs` representing a set of model values. The initial state creates a set containing three model values named "T_MV1", "T_MV2", and "T_MV3", constructed by concatenating a prefix with string representations of integers 1 through 3.

The temporal specification allows only stuttering steps after initialization—the variable `mvs` never changes from its initial value.

The invariant verifies that the set `mvs` always contains exactly three elements and that each of the three expected model values is present in the set. This confirms that dynamically created model values can be stored in sets and that membership testing works correctly.

The module also includes several assumptions that are checked at specification load time. These verify that: the `ToString` operator correctly converts model values back to their string names; model values with identical names are equal; model values with different names (but the same type prefix "T_") are unequal; and comparing model values of different types (prefixes "T_" versus "S_") produces an expected error message.

This specification serves as a test suite for the TLCModelValue operator's behavior regarding equality, string conversion, and type safety.
