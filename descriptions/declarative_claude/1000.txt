The module specifies a resource allocator managing a finite set of shared resources among a set of clients. Each client tracks two pieces of state: `unsat`, the set of resources it has outstanding requests for, and `alloc`, the set of resources currently allocated to it. Initially both mappings are empty for every client.

Three actions drive the system. `Request(c,S)` allows client `c` to submit a new request for a nonempty set `S`, but only when it holds no resources and has no pending unsatisfied request. `Allocate(c,S)` lets the allocator grant any nonempty subset of the available (unallocated) resources that overlap the client's outstanding request, partially fulfilling the request if needed. `Return(c,S)` allows a client to return any nonempty subset of its currently held resources, even before its full request has been satisfied.

The principal specification `SimpleAllocator` combines the initial condition and stuttering-closed next-state relation with weak fairness on full returns and strong fairness on allocations. A weaker variant, `SimpleAllocator2`, relaxes the return fairness condition to require returns only after the entire request has been satisfied. The model checks two invariants—`TypeInvariant` and `ResourceMutex` (no two clients hold the same resource simultaneously)—and three liveness properties: `ClientsWillReturn` (clients eventually release resources once satisfied), `ClientsWillObtain` (every requested resource is eventually allocated), and `InfOftenSatisfied` (every client is satisfied infinitely often). The theorems note that the weaker `SimpleAllocator2` preserves `ClientsWillReturn` but not the stronger liveness properties. The model is configured with three clients and two resources.
