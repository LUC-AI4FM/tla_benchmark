This TLA+ module serves as a test specification for exploring assignment constraint ordering in SMT-based model checking tools, particularly examining how different constraint orderings affect solvability.

The specification defines two integer variables, v1 and v2, both initialized to 1. A constant set S contains only the value 1.

The module defines two alternative next-state actions that demonstrate different constraint ordering scenarios:

The MayFail action assigns v1 to 1, existentially quantifies over S to assign v2 while requiring v1' be positive, and requires v1' equal v2'. The comments explain that depending on how an SMT solver orders the assignment constraints, this action may or may not be processable.

The MustFail action uses two existential quantifiers: the first assigns v1 from S while checking v2' is positive, and the second assigns v2 from S while checking v1' is positive. This creates circular use-before-assignment dependencies between the quantified blocks, making it impossible to find a valid constraint ordering under assignment-before-use semantics.

No temporal specification, fairness conditions, or properties are defined. The module exists purely to test and document edge cases in how assignment solvers handle constraint reordering when primed variables appear in both assignment and non-assignment contexts.
