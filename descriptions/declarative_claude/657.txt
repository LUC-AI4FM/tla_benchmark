This TLA+ module configures a model-checking instance for a light client protocol, specifically modeling a scenario with a faulty primary node.

The system models a blockchain light client that verifies block headers by communicating with full nodes. The configuration specifies a network of seven nodes (n1 through n7) where the light client attempts to verify blocks from a trusted height of 1 up to a target height of 5.

The temporal parameters define a trusting period of 1400 time units, with clock drift assumptions: the model assumes up to 10 units of drift while actual drift is 3 units. Crucially, the primary node is configured as incorrect (faulty), with the fault tolerance threshold set at less than one-third faulty validators.

The specification tracks numerous state variables: the client's current state, the next height to fetch, fetched light blocks and their verification status, the latest verified block, probe counts, and both local and reference clocks. It also maintains the blockchain state and set of faulty nodes. Additional variables track previous values of verified blocks, current block, local clock, and verdict for monitoring purposes.

This module instantiates the Lightclient_003_draft specification, which contains the actual protocol logic, state transitions, and properties being verified under these specific faulty-primary conditions.
