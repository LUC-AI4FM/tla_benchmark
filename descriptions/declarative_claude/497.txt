The module specifies Atomix's implementation of the SWIM (Scalable Weakly-consistent Infection-style Membership) failure-detection protocol. Each member of a fixed set `Member` maintains a logical clock (`incarnation`), a view of all other members' states (`members`), a queue of pending gossip updates (`updates`), and a state-transition history (`history`). Messages are modeled as a bag (`messages`) supporting duplication and loss.

Members may be in one of three numeric states — `Alive`, `Suspect`, or `Dead` — with the constraint `Alive > Suspect > Dead`, enforcing that state values decrease monotonically along the transition path. Members join via `AddMember` (setting incarnation to 1) and leave via `RemoveMember` (resetting incarnation to `Nil`). The protocol operates through five core actions: `Probe` sends a heartbeat probe to a peer; `HandleProbe` responds with an ack, optionally incrementing the destination's incarnation to refute suspicion; `HandleAck` marks a peer `Alive` if the acknowledged incarnation is newer; `HandleFail` marks a non-responding peer `Suspect`; and `Expire` transitions a `Suspect` peer to `Dead`. Gossip actions propagate state changes between members, accepting updates only when the received incarnation is strictly greater or, at equal incarnation, when the new state is strictly lower (i.e., more severe). The network may also duplicate or drop any in-flight message.

The invariant `Inv` asserts, for every member's recorded history of observed states about every peer, that state values are strictly decreasing across transitions (never revisiting a state within the same incarnation) and that no more than three state transitions occur per incarnation, enforcing the `Alive→Suspect→Dead` progression.
