This TLA+ module is a test configuration for a distributed transaction system, instantiating the `DistributedTransaction` module with specific constants for model checking.

The specification models a distributed transaction protocol with both optimistic and pessimistic concurrency control. It defines two keys (k1, k2) and three clients (c1, c2, c3). Clients c1 and c2 operate pessimistically, while c3 uses optimistic concurrency. The configuration specifies each client's read and write sets: c1 writes to both keys without reading, c2 writes only to k1, and c3 both reads and writes both keys. Each client designates a primary key for coordination purposes.

The model checker uses the Init and Next relations from the parent DistributedTransaction module to explore system behaviors. The configuration verifies ten invariants: TypeOK ensures type correctness; UniqueCommitOrAbort guarantees transactions reach at most one terminal state; CommitConsistency and AbortConsistency verify proper commit and abort semantics; WriteConsistency and UniqueWrite ensure write integrity; UniqueLockOrWrite prevents conflicting locks and writes; OptimisticReadSnapshotIsolation and PessimisticReadSnapshotIsolation verify snapshot isolation properties for each client type; and MsgTsConsistency checks timestamp consistency in messages.

This test configuration enables exhaustive verification of the distributed transaction protocol's correctness properties across a small but representative set of concurrent clients and shared keys.
