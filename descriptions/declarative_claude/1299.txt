This TLA+ module serves as a test case documenting a bug in the TLC model checker (specifically CodePlex Bug 21) related to function override operations.

The module defines two functions that should be semantically equivalent: `func1` is explicitly constructed as a function mapping the domain 1 to 3 to their identity values, while `func2` is defined as a tuple (sequence) containing elements 1, 2, and 3. The module confirms via ASSUME statements that these two representations are equal.

The specification tests the function override operator (`@@`) combined with the single-pair function constructor (`:>`). When overriding position 3 with value 11 using `func1`, TLC correctly evaluates the result as equal to the tuple `<<1,2,11>>`. However, the bug manifests when performing the identical override operation on `func2`: despite the two source functions being equal, TLC erroneously evaluates this comparison to FALSE.

Additionally, the module demonstrates that attempting to extend `func2` by adding a new key-value pair at position 4 causes TLC to throw an error rather than producing the expected four-element tuple.

This module contains no variables, temporal operators, or next-state relations. It exists purely to demonstrate inconsistent behavior in TLC's handling of function overrides when applied to tuples versus explicitly constructed functions.
