# ExternalHistory Module Description

This TLA+ module defines the structure and properties of an externally observable client history for a distributed transaction system. The model captures a unique scenario where clients receive transaction responses before those transactions are committed.

## System Overview

The specification models a transaction processing system supporting two transaction types: read-write transactions and read-only transactions (both as forward-always transactions). A dummy application model has transactions append integers to a list and read it back, with transactions represented simply as natural numbers.

## Constants

The module defines event type constants (`RwTxRequest`, `RwTxResponse`, `RoTxRequest`, `RoTxResponse`, `TxStatusReceived`) and transaction status constants (`CommittedStatus`, `InvalidStatus`). Transaction identifiers combine views and sequence numbers, both starting at 1. The `FirstBranch` constant allows configuring the initial branch for trace validation against implementations.

## Variables

A single `history` variable represents the globally ordered sequence of events as observed by clients according to a global clock.

## Type Invariants and Properties

`HistoryTypeOK` specifies the valid structure for each event type: requests contain a transaction, responses include the transaction plus observed data and transaction ID, and status events contain transaction ID and status.

`HistoryMonoProp` is a temporal property asserting the history is append-only—each state's history must be a prefix of the subsequent state's history.

## Helper Definitions

The module provides extensive helper definitions for querying the history, including extracting committed and invalid transaction IDs, finding response event indexes, and identifying which transactions ultimately committed.
