This TLA+ module specifies a concurrent implementation of Google's Percolator distributed transaction protocol, modeling multiple clients executing transactions with snapshot isolation over a shared key-value store.

The system models transactions using a multi-version concurrency control approach with three key columns per data key: data versions, locks, and write records. Constants define the set of keys, clients, and each client's designated primary key. Variables track a global monotonic timestamp counter, per-client state (init, working, prewriting, committing, committed, or aborted), per-client timestamps and key assignments, and per-key storage for data versions, locks, and write history. Two auxiliary variables track last-read timestamps and snapshot isolation violations.

Clients progress through transaction phases: Start assigns a start timestamp, Get allows reading keys or cleaning up stale locks, Prewrite acquires locks on all keys (primary and secondary concurrently), and Commit writes the commit record for the primary key. Clients may Abort at any point before committing. Lock cleanup handles both primary locks (which rollback) and secondary locks (which either rollback or commit based on primary key status).

The specification includes comprehensive type invariants and safety properties: WriteConsistency ensures commit timestamps are ordered and non-overlapping, LockConsistency limits each key to one lock and ensures secondary locks exist when primary does during commit, CommittedConsistency verifies proper state after commit, AbortedConsistency confirms no committed primary for aborted transactions, RollbackConsistency prevents mixed commit/rollback states, UniqueWrite ensures unique timestamps, and SnapshotIsolation verifies no reads observe out-of-order commits.
