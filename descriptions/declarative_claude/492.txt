The module specifies a client-side sequencer that imposes a total, causally consistent ordering on two kinds of messages — `Response` and `Event` — received from a server over an unreliable network.

The server side maintains a `serverSequence` (monotonically incrementing per response), a `serverIndex` (incrementing per response), and a `previousIndex` (tracking the last index acknowledged by an event). `SendResponse` emits a response tagged with its sequence number, current index, and the prior event boundary; `SendEvent` emits an event tagged with the current server index and the previous index, but only when unacknowledged events exist. Messages are stored in a bag (`messages`) allowing duplicates; the network may also duplicate or drop any in-flight message.

The client side accumulates fully ordered output in `responses` and tracks `responseSequence`, `responseIndex`, and `eventIndex` to know what it has accepted so far. When a response arrives in sequence order and its embedded `eventIndex` matches the client's current `eventIndex`, it is accepted immediately; otherwise it is queued in `pendingResponses`. Similarly, an event is accepted immediately when its `previousIndex` matches the client's `eventIndex` and its `eventIndex` matches `responseIndex`; otherwise it is queued in `pendingEvents`. Pending messages can be retried in any later step.

The `TypeInvariant` asserts that every consecutive pair of entries in `responses` satisfies strict monotonicity constraints between their index and eventIndex fields, depending on whether adjacent entries are responses or events, enforcing causal ordering throughout the accepted sequence.
