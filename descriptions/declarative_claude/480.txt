The module specifies the classic Paxos consensus algorithm as a message-passing system, without explicit leader or learner processes. It is parameterized with concrete constants: four acceptors ("a1"–"a4"), two values ({0, 1}), ballots ranging over 1..10, and four three-element quorums drawn from the acceptors, satisfying the quorum intersection assumption.

The state consists of four variables: `maxBal` (the highest ballot number each acceptor has promised to respect), `maxVBal` and `maxVal` (the ballot number and value of each acceptor's most recent vote), and `msgs` (the ever-growing set of all messages ever sent, modeling a reliable message history). The four message types cover the two phases of Paxos: 1a (ballot-open), 1b (promise with prior vote), 2a (propose), and 2b (vote). The four actions are `Phase1a` (broadcast a phase-1a message for ballot b), `Phase1b` (an acceptor responds with its current state if the ballot exceeds its promise), `Phase2a` (propose a value for ballot b once a quorum of 1b messages establishes safety), and `Phase2b` (an acceptor votes for the proposed value and updates its local state). The next-state relation `Next` is the disjunction of all these actions, and the temporal specification is `Init ∧ [][Next]_vars` without fairness.

The module also defines a partial inductive invariant `Inv` asserting that each acceptor's recorded vote is consistent with the actual votes cast, and includes auxiliary definitions (`VotedFor`, `ShowsSafeAt`) copied from a companion `Voting` module to support a refinement mapping, though the refinement theorem itself is commented out.
