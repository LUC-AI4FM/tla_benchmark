The VoucherIssue module specifies the voucher issuance operation from RFC 3506, modeled as a Two-Phase Commit protocol. Three constants parameterize the system: V (a set of vouchers), H (a set of voucher holders), and I (a set of voucher issuers). The seven variables track each voucher's state (phantom or valid), each voucher's lifecycle machine state (init or working), each holder's state (waiting, prepared, holding, or aborted), each issuer's state (waiting, prepared, issued, or aborted), the Voucher Transaction Provider's state (init or done), the set of participants from which the VTP has received Prepared messages, and the global message set.

Initially all vouchers are phantom, all lifecycle states are init, all holders and issuers are waiting, and the VTP is idle with no messages sent. Holders and issuers independently send Prepared messages or spontaneously abort; the VTP collects Prepared messages from both sets and, once all holders and issuers have prepared, broadcasts an Issue message that transitions the relevant voucher to valid and its lifecycle to working, or at any earlier point spontaneously broadcasts an Abort. Holders and issuers react to Issue or Abort broadcasts by moving to holding/issued or aborted states respectively. The safety invariant VTPConsistent asserts that no holder ever reaches "holding" while any issuer is "aborted," and vice versa. The temporal specification is VTPInit ∧ [][VTPNext]_VTPVars with no fairness conditions. The module also asserts via INSTANCE VoucherLifeCycle that VTPSpec implements the higher-level VSpec voucher lifecycle specification. The model-checking configuration instantiates three vouchers, three holders, and three issuers, checks both type-correctness and consistency as invariants, and verifies VSpec as a temporal property.
