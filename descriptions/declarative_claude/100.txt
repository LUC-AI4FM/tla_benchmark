This TLA+ module demonstrates a subtle deadlock detection issue in the Apalache model checker. The specification models a simple system with a single integer variable x that starts at zero.

The system defines two possible transitions. Action A can execute when x is even, incrementing x by one (making it odd). Action B can also execute when x is even, but increments x by two (keeping it even). The next-state relation allows either action to occur.

From the initial state where x equals zero, both actions are enabled. If action B executes repeatedly, x remains even (0, 2, 4, ...), and the system can continue indefinitely. However, if action A ever executes, x becomes odd, and neither action's guard is satisfied since both require x to be even. This creates a deadlock state.

The specification contains no explicit invariants, liveness properties, or fairness conditions. Its purpose is to illustrate that a model checker performing bounded exploration might only discover infinite B-only executions and miss the deadlock reachable via action A. The module serves as a test case showing that deadlock detection requires exploring all reachable states, not just finding some infinite execution path.
