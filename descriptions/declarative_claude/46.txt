This TLA+ module serves as a regression test for issue #592, specifically testing the behavior of module instantiation and type annotations across nested module hierarchies.

The specification defines a small hierarchy of nested modules to verify correct handling of annotations when modules are instantiated in various ways. The innermost module, Utils, declares a type-annotated operator Foo that takes a function from integers to integers and returns the value at index 1.

Module UserA extends Utils and defines Bar as a wrapper around Foo. Module UserB uses INSTANCE to import Utils and defines Baz as another wrapper around Foo. Module UserC instantiates UserA, creating a chain of module dependencies.

The top-level module demonstrates multiple instantiation patterns: it directly instances UserA (making Bar available), creates a named instance B of UserB (making B!Baz available), and instances UserC (which transitively provides access to UserA's operators).

This specification contains no variables, state transitions, temporal formulas, or properties to check. Its sole purpose is to test that the TLA+ tooling correctly propagates type annotations through different module instantiation mechanisms—both named and unnamed INSTANCE declarations and EXTENDS—without errors or annotation loss.
