This TLA+ specification tests the scoping and namespacing behavior of TLA+ when identifiers are overloaded between a main module and an instantiated submodule.

The specification declares one constant, `overloadedConst`, which is assigned the value 4711 in the configuration. It declares one variable, `overloadedName`, which shares its name with a definition in the instantiated module Github362B.

The module instantiates Github362B as `Abstract`, substituting the parameter `x` with the string "x" and the constant `C` with 42. This creates a namespace where the submodule's definitions coexist with the main module's identifiers of the same names.

The initial state predicate sets `overloadedName` to "fizzbuzz" and verifies that `overloadedConst` equals 4711. It uses Print statements to demonstrate that the main module's variable `overloadedName` holds "fizzbuzz" while accessing `Abstract!overloadedName` yields "x" from the instantiated module. Similarly, it shows that the local constant and the instantiated module's constant resolve to their respective distinct values.

The next-state relation simply leaves `overloadedName` unchanged, making this a stuttering system.

The property being checked, `Correct`, delegates to `Abstract!Spec`, verifying whatever specification property is defined in the Github362B module. This tests that temporal properties from instantiated modules work correctly despite name overloading.
