This module extends a typed specification of the Two-Phase Commit protocol and defines an inductive invariant suitable for proving correctness properties.

The specification captures the Two-Phase Commit protocol, which coordinates distributed transactions across a set of resource managers (RMs) with a transaction manager (TM). The protocol ensures all participants either commit or abort a transaction atomically.

The inductive invariant `IndInv` combines several conditions that together form a strengthened invariant sufficient for inductive proof. It includes the type correctness predicate and transaction consistency. The invariant captures key protocol relationships: if any RM has committed, the TM must be in committed state; if the TM is committed, all RMs must have prepared, no RM can be working or aborted, and a commit message must exist. If the TM is aborted, an abort message must be present.

For each resource manager, the invariant maintains consistency between preparation status and message presence: prepared RMs cannot be working and must have sent prepare messages; working RMs have not sent prepare messages; aborted RMs either received an abort message or never prepared.

The invariant also constrains message origins: abort messages require either the TM to be aborted or some unprepared RM to be aborted; commit messages require all RMs prepared and either the TM or some RM to be committed.

`InitInv` conjoins type correctness with the inductive invariant for initialization checking.
