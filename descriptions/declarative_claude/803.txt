This TLA+ module specifies the level-checking semantics for the TLA+ language, as described in Section 17.2 of "Specifying Systems." Level checking ensures expressions respect the TLA+ hierarchy: level 0 (constants), level 1 (state functions), level 2 (actions), and level 3 (temporal formulas).

The specification models TLA+ modules as semantic forests composed of nodes. The CONSTANT `NodeId` represents node identifiers, and `Node` maps these to semantic node structures. Node kinds include ModuleNode, OpDefNode, ConstantDeclNode, VariableDeclNode, OpApplNode, LetInNode, ValueNode, IdentifierNode, and others representing modules, operator definitions, declarations, and expressions.

The core of the specification defines level constraint data structures: `LevelConstraint` bounds parameter instantiation levels, `ArgLevelConstraint` specifies minimum argument levels for operator parameters, and `ArgLevelParam` tracks parameter appearances in operator arguments. The `LevelConstraintFields` record captures level computation data including `level`, `levelParams`, `levelConstraints`, `argLevelConstraints`, and `argLevelParams`.

The module enforces that primed expressions, ENABLED, UNCHANGED, and action composition operators receive arguments of appropriate levels. It also restricts non-Boolean operator arguments to level at most 2, preventing malformed expressions like arithmetic on temporal formulas.

The specification acknowledges limitations in handling second-order operators and certain INSTANCE substitutions, noting that the algorithm makes conservative approximations that may reject some technically valid expressions.
