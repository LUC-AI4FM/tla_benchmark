# InternalMemory Module Description

This TLA+ module specifies an internal memory system that handles read and write requests from multiple processors. It extends a MemoryInterface module and models how processors interact with a shared memory through a request-response protocol.

## State Variables

The specification uses four variables: `mem` represents the memory as a function mapping addresses to values; `ctl` tracks each processor's control state; `buf` serves as a buffer for each processor holding pending requests or response values; and `memInt` (from the extended module) represents the memory interface.

## System Behavior

Each processor cycles through three states: "rdy" (ready), "busy" (processing), and "done" (completed). The **Req** action allows a ready processor to send a memory request, storing it in the buffer and transitioning to busy. The **Do** action performs the actual memory operation—for writes, it updates memory and clears the buffer; for reads, it loads the requested value into the buffer. The **Rsp** action sends the response back through the interface and returns the processor to ready state.

## Specification and Properties

The temporal specification ISpec requires the system to start in a valid initial state and take only valid next steps (or stutter). The module includes a type invariant theorem asserting that all variables maintain proper types throughout execution, ensuring memory remains a valid address-to-value mapping and control states stay within their defined domain.
