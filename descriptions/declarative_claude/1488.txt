This TLA+ module specifies and proves correctness of a voting algorithm underlying consensus protocols like Paxos. The specification models acceptors that can increase their ballot numbers or cast votes for values at specific ballot numbers.

The module declares three constants: Value (choosable values), Acceptor (the set of acceptors), and Quorum (sets of acceptors where any two quorums intersect). Ballots are natural numbers.

Two variables track state: votes maps each acceptor to its set of ballot-value pairs it has voted for, and maxBal tracks each acceptor's maximum ballot number seen.

Each acceptor process repeatedly either increases its maxBal to a higher ballot or votes for a value at some ballot. Voting requires that maxBal permits it, the acceptor hasn't voted in that ballot, any other acceptor's vote in that ballot agrees on the value, and the value is safe at that ballot. Safety at a ballot is defined recursively, ensuring that any previously chosen value would be preserved.

The specification establishes several invariants: TypeOK for type correctness, VInv1-VInv4 constraining voting behavior. The key theorems prove that the invariant VInv is preserved by all transitions, and that at most one value can be chosen (VT1). The module proves refinement to a Consensus specification (VT3), showing the voting protocol implements consensus correctly.

A liveness assumption provides fairness conditions for showing progress under certain scheduling constraints.
