This TLA+ module configures a model-checking instance for a light client verification protocol, specifically modeling a scenario with clock drift exceeding trusted assumptions.

The system models a blockchain light client that verifies block headers by fetching and validating light blocks from a potentially faulty primary node. The configuration specifies four nodes ("n1" through "n4") participating in the network.

The constants define the verification parameters: the client starts from a trusted height of 1 and attempts to verify up to target height 4. The trusting period is set to 1400 time units. Critically, this configuration models a drifted clock scenario where the assumed clock drift (10 units) is significantly less than the actual drift (30 units), representing a situation where safety assumptions may be violated. The primary node is configured as faulty, and the system tolerates fewer than one-third faulty validators.

The variables track the light client's state machine including current state, next height to fetch, fetched light blocks with their verification status, the latest verified block, probe count, and both local and reference clocks. Additional variables monitor the blockchain state, faulty nodes, and previous values of key state components for verification purposes.

This module instantiates the Lightclient_003_draft specification to check light client behavior when real-world clock drift exceeds the protocol's drift assumptions, with a Byzantine primary node.
