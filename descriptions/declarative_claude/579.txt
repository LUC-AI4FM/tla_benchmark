This TLA+ module specifies a bounded model-checking version of a multi-node distributed ledger system, extending both a base MultiNode specification and a bounded single-node specification.

The system models a distributed ledger that can process read-write and read-only transactions, handle transaction status queries, and undergo view changes that may truncate the ledger. The specification captures scenarios where ledger branches can form due to view changes, and clients may receive status responses indicating transactions are either committed or invalid.

The module introduces a ViewLimit constant that bounds the number of view changes (ledger truncations) allowed during model checking. The key actions include single-node transaction processing operations inherited from the bounded single-node spec, a truncate ledger action representing view changes that create new ledger branches (bounded by ViewLimit), and a status invalid response action representing clients receiving notification that transactions are invalid (bounded by HistoryLimit).

The temporal specification states the system starts in an initial state and repeatedly takes bounded multi-node actions. No fairness conditions are specified, and deadlock checking is disabled.

The configuration checks numerous invariants covering transaction uniqueness, serializability of read-write transactions, linearizability, consistency between observations across different views, and proper handling of committed versus invalid transaction statuses. These properties ensure that despite view changes and ledger truncation, the system maintains strong consistency guarantees about transaction ordering and visibility.
