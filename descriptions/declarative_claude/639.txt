This TLA+ module specifies a light client verification algorithm for Tendermint blockchain consensus. The light client attempts to verify a target block header starting from a trusted block header, following a bisection-based approach.

The specification uses constants defining the trusted and target heights, a trusting period during which validators remain trusted, a flag indicating whether the primary node is correct, and a set of all possible validator nodes. Variables track the client's control state (working, finished successfully, or failed), the next height to verify, a light store mapping heights to fetched light blocks with their verification status, the latest verified block, and a probe counter.

The system combines a blockchain model (instantiated from a separate module) that maintains the reference chain and global time, with the light client logic. The light client begins with a trusted block and iteratively fetches and verifies blocks toward the target height. Verification checks whether blocks satisfy validity conditions including trusting period membership, proper commit signatures from validators, and sufficient overlap with trusted validator sets.

Key properties include type correctness, correctness invariants ensuring verified headers match the actual blockchain, a proof-of-chain-of-trust invariant for verified headers, precision guaranteeing that failure implies either trusting period expiration or primary misbehavior, and success guarantees when the primary is correct and trust conditions hold. The specification also bounds algorithmic complexity by the number of probes performed.
