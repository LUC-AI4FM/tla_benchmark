This TLA+ module specifies the Slush protocol, a simple probabilistic consensus algorithm from the Avalanche family. The specification models nodes attempting to reach agreement on a color value (Red or Blue) through repeated sampling of peers.

The system consists of nodes, each hosting two processes: a SlushLoop process that drives consensus and a SlushQuery process that responds to queries. Constants define the node set, process identifiers, a host mapping relating processes to nodes, the number of iterations each loop executes, the sample set size for queries, and a threshold for flipping color preferences.

Variables track each node's current color pick (initially unassigned), the set of messages in transit, process-local sample sets, and loop iteration counters. A separate ClientRequest process non-deterministically assigns initial colors to nodes that have none.

The SlushLoop process waits for an initial color assignment, then repeatedly selects a random sample of other nodes, sends query messages with its current color, awaits replies, and potentially flips its color if replies for one color meet the threshold. The SlushQuery process waits for incoming queries and responds with its node's current color, adopting the queried color if currently unassigned.

The specification defines a TypeInvariant ensuring picks and messages have correct types. A Termination property asserts that all processes eventually reach completion. No fairness conditions are specified, and the module notes that TLA+ cannot express the probabilistic convergence questions central to analyzing Slush.
