The module models a simple algorithm that transforms a finite set into a sequence by iteratively picking elements from the set and appending them to an output sequence.

The constant `InSet` represents the input set, initialized to `1..4` via `ConstInit`. The two variables are `Left`, which holds the elements not yet transferred, and `OutSeq`, the sequence being constructed. Initially, `OutSeq` is empty and `Left` equals `InSet`. On each step, if `Left` is non-empty, some element `x` is nondeterministically chosen from it, appended to `OutSeq`, and removed from `Left`; if `Left` is empty, both variables remain unchanged. The algorithm terminates when all elements have been moved from `Left` into `OutSeq`.

The invariant `Inv` asserts that at every reachable state, `InSet` equals the union of the remaining elements in `Left` and the set of elements already placed in `OutSeq`, ensuring no elements are created or lost during the transformation. The module's name alludes to the motivation for type invariants in model checking: without an explicit type invariant, the model checker may explore states with unexpected variable values, illustrating why such constraints are useful.
