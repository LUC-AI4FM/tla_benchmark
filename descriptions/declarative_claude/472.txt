The module specifies the classic Paxos consensus algorithm as a message-passing system, without explicit leader or learner processes. It is instantiated with concrete constants: values `{1, 2}`, acceptors `{1, 2, 3}`, quorums `{{1,2},{2,3},{1,3}}`, and ballots `1..3`.

The state consists of four variables: `maxBal` (the highest ballot number each acceptor has promised to respect), `maxVBal` and `maxVal` (the ballot and value of each acceptor's highest-numbered vote), and `msgs` (the monotonically growing set of all messages ever sent). Four message types are modeled: phase-1a (ballot proposals), phase-1b (acceptor promises with their current vote state), phase-2a (leader value proposals), and phase-2b (acceptor votes).

The next-state relation comprises four actions. `Phase1a(b)` broadcasts a phase-1a message opening ballot `b`. `Phase1b(a)` allows acceptor `a` to respond to a phase-1a message whose ballot exceeds `maxBal[a]`, updating `maxBal[a]` and sending its prior vote information. `Phase2a(b,v)` allows a leader to propose value `v` in ballot `b` provided no phase-2a message for `b` exists yet and a quorum of phase-1b responses demonstrates that `v` is safe (either no prior votes exist in the quorum or the highest prior vote was for `v`). `Phase2b(a)` lets acceptor `a` vote for a proposed value if the proposal's ballot is at least `maxBal[a]`. The temporal specification is `Init ∧ [][Next]_vars` with no fairness conditions, targeting safety verification. The module defines an inductive invariant `Inv` asserting type correctness, consistency of per-acceptor vote records, and that every phase-2a message proposes a value shown safe by some quorum, supporting a refinement mapping to an abstract voting specification.
