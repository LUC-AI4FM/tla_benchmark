This TLA+ module specifies a transaction commit protocol for distributed resource managers, modeling how multiple participants reach consensus on committing or aborting a transaction.

The constant RM represents the set of resource managers participating in the transaction. The variable rmState is a function mapping each resource manager to its current state, which can be "working," "prepared," "committed," or "aborted."

Initially, all resource managers begin in the "working" state. Three actions define the possible state transitions: Prepare allows a working resource manager to move to the "prepared" state, signaling its readiness to commit. DecideCommit permits a prepared resource manager to commit, but only when all resource managers are either prepared or already committed—ensuring unanimous agreement before any commit occurs. DecideAbort allows a resource manager that is either working or prepared to abort, but only if no resource manager has yet committed—preventing inconsistent outcomes where some commit and others abort.

The next-state relation allows any resource manager to nondeterministically execute one of these three actions. The temporal specification combines the initial condition with a stuttering-allowed next-state relation, permitting the system to remain idle.

No explicit fairness conditions or liveness properties are specified. No invariants are declared for model checking, though the protocol structure inherently prevents the unsafe state where some managers commit while others abort.
