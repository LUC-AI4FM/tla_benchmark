This TLA+ module is a model-checking configuration for a light client verification protocol, specifically instantiating a draft light client specification with concrete parameters for a seven-node blockchain system.

The specification models a light client attempting to verify blockchain blocks from a trusted height of 1 to a target height of 7 across a network of seven nodes. The configuration sets a trusting period of 1400 time units, assumes clock drift bounds of 10 units with actual drift of 3 units, and specifies that less than one-third of validators may be faulty. Notably, the primary node is configured as incorrect, indicating this models a scenario with a Byzantine primary.

The variables track the light client's verification state, including the current state, next height to fetch, fetched light blocks and their statuses, the latest verified block, probe count, and local clock. Additional variables track reference clock, blockchain state, and which nodes are faulty. Monitoring variables preserve previous values of verified blocks, current block, local clock, and verdict for temporal property checking.

By instantiating the Lightclient_003_draft module, this configuration enables model checking of the light client protocol's behavior under specific faulty conditions, testing whether safety and liveness properties hold when the primary is malicious but Byzantine nodes remain below the one-third threshold.
