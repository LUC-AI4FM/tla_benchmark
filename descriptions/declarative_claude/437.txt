This TLA+ module tests the treatment of prefix and postfix operators when passed as arguments to higher-order operators. It verifies that TLC correctly handles operators like negation, SUBSET, UNION, DOMAIN, prime, ENABLED, UNCHANGED, and user-defined postfix operators when used as parameters.

The module declares two variables, x and y, both initialized to the singleton set containing "a". The next-state relation keeps x unchanged by unioning it with "a" and changes y by unioning it with "b". The temporal specification combines the initial state with a stuttering-allowed next relation.

The ASSUME block executes static tests at model-checking startup. It defines custom prefix and postfix operators that perform set difference, then passes both built-in and user-defined operators to test operators like SetOpTest and DomainTest, verifying the results match direct application of those operators.

The Invariant uses EnabledTest to check that ENABLED can be passed as an operator argument and applied to an action. The ImpliedAction tests UNCHANGED and the prime operator similarly. The Property asserts that ImpliedAction holds as an action property across all transitions.

The configuration specifies the temporal formula Spec and checks the Property. The Invariant is commented out due to a known TLC bug with ENABLED handling in this context. This module primarily serves as a test suite for TLC's operator-argument functionality rather than modeling a real system.
