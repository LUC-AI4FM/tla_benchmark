This TLA+ module specifies a model-checking configuration for testing the Percolator distributed transaction protocol, extending a base Percolator module.

The specification models a system with two keys (1 and 2) and two concurrent clients (c1 and c2). Each client has a designated primary key: client c1 uses key 1 as its primary, and client c2 uses key 2. This setup enables exploration of concurrent transaction scenarios where two clients may conflict on shared keys.

The module relies on the Percolator parent module for its variables, actions, and the main specification called PercolatorSpec, which defines the system's temporal behavior including initial states and the next-state relation governing transaction operations.

The model checker verifies six invariants. TypeInvariant ensures all variables remain within their declared types. WriteConsistency, LockConsistency, CommittedConsistency, and AbortedConsistency verify various consistency properties related to the transaction protocol's write operations, lock management, and transaction outcomes. SnapshotIsolation confirms that the system maintains snapshot isolation semantics, ensuring transactions observe consistent snapshots of data.

This test configuration is designed for exhaustive state-space exploration with TLC, using a minimal but sufficient setup of two clients and two keys to detect protocol violations in the Percolator two-phase commit implementation.
