This module serves as a wrapper that adds Apalache type annotations to the CoffeeCan specification, allowing the original spec to remain free of tool-specific syntax while enabling type-checked model checking.

The specification models the Coffee Can problem, a classic puzzle involving a can containing black and white beans. The system uses one constant, MaxBeanCount, set to 5 in the configuration, which bounds the initial number of beans.

The single variable "can" is a record with two integer fields: "black" and "white," representing the count of each bean color currently in the can.

Through the INSTANCE statement, this module inherits all definitions from the CoffeeCan module, including the state transitions and properties. The underlying algorithm repeatedly removes two beans from the can and applies a replacement rule based on their colors, eventually reducing the can to a single bean whose color depends on the initial parity of beans.

The configuration specifies that the system should satisfy the Spec temporal formula, which defines valid initial states and allowed transitions. The TypeInvariant is checked as a safety property, ensuring the can variable maintains its expected structure with non-negative bean counts throughout all reachable states.
