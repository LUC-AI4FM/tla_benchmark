This TLA+ module demonstrates a type-checking scenario involving model values of different sorts. The specification models a minimal single-step system with two uninterpreted constant types.

**Constants**: The module declares two constants, `C` and `G`, which are annotated with different uninterpreted types (`UT` and `XY` respectively). The `CInit` predicate constrains these to specific model value literals of their respective types.

**Variables**: Three variables are defined: `x` (a set of `UT` values), `z` (a set of `XY` values), and `s` (a string tracking state).

**Initial State**: The system starts with `x` as an empty set, `z` containing the constant `G`, and `s` set to "init".

**Next-State Relation**: A single transition assigns `C` to `x`, empties `z`, and changes `s` to "next".

**Invariant**: The module checks an invariant `Inv` that asserts equality between `C` and `G`. This invariant is explicitly noted as expected to fail because it attempts to compare model values belonging to different uninterpreted types—an operation that type-checking systems should reject or flag as invalid.

The specification serves as a test case for type-checking tools to verify they correctly identify cross-type comparisons of model values as errors.
