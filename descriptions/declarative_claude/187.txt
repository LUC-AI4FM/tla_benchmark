This TLA+ module serves as a regression test for issue #1084, which concerns the correct instantiation of polymorphic definitions during model checking.

The specification defines a trivial system where both the initial state predicate and the next-state relation are simply TRUE, meaning any state is valid and the system can remain in any state indefinitely. There are no declared variables, making this effectively a stateless specification used purely for testing type system behavior.

The core element being tested is the polymorphic operator X, which extracts the domain from a function. The type annotation indicates X accepts a function from any type to integers and returns a set of that same type. Two concrete functions are defined: f1 maps the integer 1 to 1, while fa maps the string "a" to 1.

Three invariants test that the polymorphic operator X correctly handles both function types. Inv1 and Inv2 check that X returns the expected domains in different orderings, while Inv3 tests the same property using nested LET expressions. All three invariants verify that X(fa) yields the singleton set containing "a" and X(f1) yields the singleton set containing 1, ensuring the polymorphic definition instantiates correctly regardless of invocation order or expression context.
