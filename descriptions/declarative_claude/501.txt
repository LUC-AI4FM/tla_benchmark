This module provides a model-checking configuration for a Multi-Paxos consensus protocol specification.

The system models a distributed consensus algorithm where multiple replicas coordinate to agree on values across multiple slots, using ballot numbers to order proposals. The configuration instantiates the model with three replicas, two possible values, two slots, and ballots ranging from 0 to 1.

The module defines comprehensive type constraints through the TypeOK invariant. Variables include: msgs (the set of protocol messages), lBallot and lStatus (leader ballot numbers and per-slot status tracking), rBallot and rVoted (replica ballot numbers and voting records), proposed (values proposed per slot), and learned (values decided per slot). Messages encompass Prepare, PrepareReply, Accept, and AcceptReply types with appropriate fields.

The specification verifies refinement to a ConsensusMulti module, establishing that Multi-Paxos correctly implements multi-slot consensus. This refinement maps the union of all proposed values and the learned mapping to the abstract specification's state.

Two safety invariants are checked directly: NontrivialityInv ensures learned values were previously proposed for their respective slots, and ConsistencyInv guarantees at most one value is learned per slot. The module notes that full temporal refinement checking should only run on very small inputs due to state explosion.

Symmetry reductions are applied across replicas, values, and slots to reduce the state space. Deadlock checking is disabled.
