This TLA+ module specifies a draft supervisor component intended to eventually model verification and attack detection functionality, likely for a distributed system such as a blockchain light client.

The specification defines a state machine with two variables: `state`, which tracks the current phase of execution, and `output`, which records produced results. A constant `INITDATA` is declared but unused in the current draft.

The system begins in an "Init" state with no output. From initialization, it may either enter the main processing loop or fail to initialize. The main loop involves two interleaved processes: verification toward a target and attack detection. During verification, the system can replace a primary peer, proceed to detection, or exhaust available primary peers. During attack detection, the system may find no evidence of misbehavior, discover evidence, or exhaust secondary peers.

When no evidence is found, the system outputs data and returns to the main loop. The system terminates and stutters upon reaching any terminal state: failed initialization, exhausted peers (primary or secondary), or evidence found.

The specification includes one invariant, `InvEnoughPeers`, which asserts that the system never reaches states indicating peer exhaustion. No fairness conditions or liveness properties are specified. This represents an early draft focused on modeling control flow states.
