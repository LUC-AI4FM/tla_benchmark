The module specifies a B-tree data structure supporting get, insert, and update operations, with node splitting modeled as a multi-step process. Deletions are explicitly noted as unimplemented.

The tree is built over a fixed pool of `Nodes` (1..`MaxNode`) and `Keys` (1..`MaxKey`). Each node is characterized by whether it is a leaf (`isLeaf`), its set of keys (`keysOf`), child pointers for inner nodes (`childOf`, `lastOf`), and key-value pairs for leaves (`valOf`). A single `root` node is tracked. An operation in progress is described by `op`, `args`, `ret`, `focus` (the node currently being examined or modified), and `toSplit` (a sequence of nodes that need splitting). The `state` variable drives a state machine through phases: `READY`, `GET_VALUE`, `FIND_LEAF_TO_ADD`, `WHICH_TO_SPLIT`, `ADD_TO_LEAF`, `SPLIT_LEAF`, `SPLIT_INNER`, `SPLIT_ROOT_LEAF`, `SPLIT_ROOT_INNER`, and `UPDATE_LEAF`.

Inserts locate the target leaf via recursive traversal and, if the leaf is at `MaxOccupancy`, propagate splits upward through `toSplit` before adding the key-value pair. Root splits allocate two new nodes and promote a pivot key. The specification includes a refinement mapping to an abstract key-value store (`kvstore`) via a `Mapping` instance, asserting that the B-tree implements a key-value abstraction. The model checks several structural invariants: inner nodes must have a `lastOf` pointer, leaves must not, key order must be preserved across inner nodes and their children, leaf keys must be globally unique, and at least one free node must always remain.
