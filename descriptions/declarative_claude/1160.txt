This TLA+ module specifies the Transaction Commit protocol, modeling how a set of resource managers coordinate to reach a consistent commit or abort decision in a distributed transaction.

The specification has one constant, RM, representing the set of participating resource managers, and one variable, rmState, a function mapping each resource manager to one of four states: "working", "prepared", "committed", or "aborted".

Initially, all resource managers are in the "working" state. The next-state relation allows two types of actions by any resource manager: Prepare and Decide. A resource manager can prepare by transitioning from "working" to "prepared". The Decide action has two disjunctive cases: a prepared resource manager may commit if all resource managers are either prepared or committed, or a working or prepared resource manager may abort if no resource manager has yet committed.

The temporal specification combines the initial condition with a next-state relation under stuttering, meaning steps either follow TCNext or leave rmState unchanged.

Two safety properties are specified. TCTypeOK is a type-correctness invariant ensuring rmState maps each resource manager to valid states. TCConsistent asserts that no two resource managers reach conflicting decisions—one aborted and one committed. The specification includes a theorem claiming both properties are invariants of the protocol.
