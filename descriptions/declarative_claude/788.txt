This TLA+ module specifies a simple key-value store implementing snapshot isolation, modeled using PlusCal. The system allows multiple concurrent transactions to read and write keys while ensuring snapshot isolation guarantees.

The specification uses three constants: Key (the set of possible keys), TxId (transaction identifiers), and NoVal (the initial value for all keys). Global variables include store (the persistent key-value mapping), tx (the set of currently active transactions), and missed (tracking writes each transaction has not seen).

Each transaction process follows four phases. In START, a transaction joins the active set, captures a local snapshot of the store, and nondeterministically selects non-empty sets of keys to read and write. In READ, it reads from its snapshot and logs the operations. In UPDATE, it applies writes to its local snapshot using its own transaction ID as the value. In COMMIT, it checks for write-write conflicts by verifying its write keys do not intersect with writes it missed from concurrent transactions. If no conflict exists, it commits atomically: removing itself from active transactions, updating the missed sets for remaining active transactions, and persisting writes to the store.

The specification includes weak fairness for all transaction processes, ensuring eventual progress. It checks a TypeOK invariant and verifies SnapshotIsolation by instantiating a ClientCentric module that validates isolation properties against logged operations. A Serialization property is also defined but noted as unsatisfied due to write skew anomalies inherent to snapshot isolation.
