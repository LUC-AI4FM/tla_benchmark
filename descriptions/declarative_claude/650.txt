This TLA+ module is a model-checking configuration for a light client verification protocol, specifically instantiating a draft specification called "Lightclient_003_draft" with concrete parameters for a faulty primary scenario.

The configuration models a distributed system with four nodes where the primary node is explicitly set as incorrect (not trustworthy). The system operates between a trusted height of 1 and a target height of 6, with a trusting period of 1400 time units. Clock drift is modeled with assumed drift of 10 units and actual drift of 3 units. The fault tolerance threshold follows the standard Byzantine assumption of less than one-third faulty validators.

The specification tracks numerous state variables: the light client's current state, the next height to fetch, collected light blocks and their verification status, the latest verified block, probe counts, and both local and reference clocks. It also maintains the blockchain state and tracks which nodes are faulty. Additionally, previous-state variables monitor the verification process by recording prior verified blocks, current blocks, local clock values, and verdicts.

This module serves as a specific test scenario for the light client protocol under adversarial conditions, where the primary source of blockchain data is Byzantine, allowing model checking to verify protocol correctness despite a malicious primary.
