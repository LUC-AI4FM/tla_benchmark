This TLA+ module is a test suite for **positional subexpression naming**, a syntactic feature that allows referencing specific parts of complex expressions using numeric or symbolic selectors like `!1`, `!2`, `!<<`, and `!>>`.

The module defines several operators to exercise this feature. The constant `xx` is a nested sequence. Operator `F` is a conjunction of four clauses, and the ASSUME statements verify that subexpression selectors correctly extract components: `F(2)!3` selects the third conjunct, `F(2)!3!1` extracts the `Len(...)` subexpression, and deeper selectors navigate into nested structures.

Additional operators test subexpression naming across different TLA+ constructs: `G` tests EXCEPT expressions, `H` tests record field access, `I` and `J` test record constructors, `K` tests IF-THEN-ELSE with selectors for condition, then-branch, and else-branch, `L` tests CASE expressions, `M` tests LET-IN with local definitions, and `N` through `Q` test stuttering and fairness operators (`[...]_v`, `<<...>>_v`, `WF_v`, `SF_v`).

The operators `R` and `S` test existential quantification and function constructors with multiple bound variables. `T`, `U`, and `V` test lambda extraction using the `!@` selector to obtain the body of a quantified expression as a lambda.

All behavioral assertions are static ASSUME statements verified at parse or evaluation time. The module contains no variables, temporal properties, or state transitions—it purely validates the subexpression naming mechanism.
