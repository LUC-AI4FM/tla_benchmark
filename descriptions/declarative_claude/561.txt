This TLA+ module extends a base `TCommit` module to provide model-checking configuration for a transaction commit protocol involving multiple resource managers.

The specification models a distributed transaction commit scenario where a set of resource managers (RM) must coordinate to either all commit or all abort a transaction. The constant RM represents the set of participating resource managers, instantiated in the model as three participants: r1, r2, and r3.

The single variable `rmState` (inherited from TCommit) maps each resource manager to one of four possible states: "working" (initial state, not yet voted), "prepared" (voted to commit), "committed" (transaction committed), or "aborted" (transaction aborted).

The specification checks two safety invariants. First, `TCTypeOK` is a type invariant ensuring that every resource manager's state remains within the four valid states throughout execution. Second, `TCConsistent` enforces the critical safety property of transaction commit protocols: no two resource managers can end up in conflicting final states where one has committed and another has aborted.

The temporal specification `TCSpec` from the base module defines the initial state and next-state relation governing how resource managers transition between states. Deadlock checking is disabled, acknowledging that the protocol may legitimately reach terminal states where no further transitions are possible.
