This module specifies the Ghostferry algorithm for live database migration, modeling how data is copied from a source database to a target database while the source remains writable.

The system models four concurrent processes. The TableIterator copies rows sequentially from the source table to the target table up to a specified maximum primary key. The BinlogStreamer reads database change events from a binlog and applies them to the target, using conditional writes that only succeed if the target row matches the expected old value. The Application continuously performs writes to the source database, recording each change as a binlog entry containing the primary key, old value, and new value. The Ferry process coordinates termination: it waits for the TableIterator to complete, sets the application to read-only mode, waits for the application to stop, then records the target binlog position and signals the BinlogStreamer to stop after catching up.

The constants include the initial table state, maximum primary key, the set of possible records, process identifiers, and a maximum binlog size for bounded model checking. Variables track the source and target tables as sequences, the binlog as a sequence of change entries, the current maximum primary key, and various process-local state.

The specification includes weak fairness for all four processes, ensuring each eventually progresses. The safety property SourceTargetEquality asserts that upon termination of all processes, the source and target tables are identical. The Termination property asserts that all processes eventually complete. An action constraint bounds binlog growth to keep model checking feasible.
