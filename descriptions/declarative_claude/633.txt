This TLA+ module is a model-checking configuration for a Light Client Detector specification, instantiating the `LCDetector_003_draft` module with specific parameters for a faulty primary scenario.

The specification models a blockchain light client detection system with five nodes. The configuration sets up verification between a trusted height of 1 and a target height of 5, with a trusting period of 1400 time units. Clock drift parameters distinguish between assumed drift (10 units) and actual drift (3 units). Critically, this configuration marks the primary peer as faulty while the secondary remains correct, with a faulty validator ratio below one-third.

The module declares eleven state variables tracking: the reference blockchain state, local and reference clocks, the set of faulty validators, the detector's current state, three separate collections of fetched light blocks (for primary, secondary, and an auxiliary set), a common trusted height used during evidence creation, the next height to attempt verification, and collected evidences.

This configuration specifically tests the light client detector's behavior when interacting with a Byzantine primary peer while having access to a correct secondary peer. The faulty ratio constraint ensures the system operates within Byzantine fault tolerance bounds where less than one-third of validators are faulty, allowing the detection mechanism to identify and produce evidence of misbehavior.
