This TLA+ module configures a model-checking instance for a light client verification protocol, specifically instantiating a draft light client specification with concrete parameters for a four-node blockchain system.

The specification models a light client attempting to verify blockchain headers between a trusted height and a target height. The system includes four nodes and operates with time-sensitive parameters: a trusting period of 1400 time units, an assumed clock drift of 10 units, and an actual clock drift of 30 units—modeling a scenario where the real drift exceeds assumptions. The primary node is configured as correct, and the faulty validator ratio is set below one-third.

The variables track the light client's verification state, including its current state, the next height to fetch, fetched light blocks and their verification status, the latest verified block, probe counts, and local clock time. Additional variables model the reference clock, the actual blockchain state, and the set of faulty nodes. Monitoring variables preserve previous values of the verified block, current block, local clock, and verdict for temporal reasoning.

By instantiating the Lightclient_003_draft module, this configuration enables checking the light client protocol's behavior under clock drift conditions where actual drift exceeds the assumed drift, testing resilience against timing discrepancies in a correctly-behaving primary scenario.
