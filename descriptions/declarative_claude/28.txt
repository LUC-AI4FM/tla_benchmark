The module specifies the Two-Phase Commit (2PC) distributed protocol, in which a single transaction manager (TM) coordinates a set of resource managers (RM) to reach a consistent commit-or-abort decision. The constant RM is the set of participating resource managers. The variables are rmState (a function mapping each RM to one of "working", "prepared", "committed", or "aborted"), tmState (the TM's state: "init", "committed", or "aborted"), tmPrepared (the set of RMs from which the TM has received Prepared messages), and msgs (the ever-growing set of all messages sent, modeled as a set rather than a channel to capture only safety behavior).

The actions cover both TM and RM roles. The TM can receive a Prepared message from an RM (TMRcvPrepared), commit once all RMs have prepared (TMCommit, which broadcasts a Commit message), or spontaneously abort (TMAbort, broadcasting an Abort message). Each RM can move from working to prepared by sending a Prepared message (RMPrepare), spontaneously abort without sending a message (RMChooseToAbort), or transition to committed or aborted upon receiving the corresponding broadcast from the TM (RMRcvCommitMsg, RMRcvAbortMsg). The specification TPSpec is the initial condition TPInit conjoined with a stuttering-tolerant always-TPNext temporal formula, with no liveness conditions. Two theorems are stated: that TPTypeOK is an invariant, and that TPSpec implements the abstract Transaction Commit specification TCSpec from the TCommit module.
