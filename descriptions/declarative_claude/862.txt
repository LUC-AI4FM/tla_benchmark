This module configures model checking for a specification called SPA_Attack_New, which models a Single Packet Authorization (SPA) security protocol under attack scenarios.

The specification examines an SPA system involving a legitimate client, an attacker, an SDP (Software-Defined Perimeter) server, and a protected backend server. Constants define network configurations: the SDP server listens on IP 12 at port 8000, the protected server runs on IP 22 at port 80, and both the client and attacker share source IP 11 (suggesting the attacker may attempt IP spoofing). The client possesses authentication credentials (LoginID 1, Key 44), while special sentinel values mark unknown authentication and wildcard matching. A NAT flag indicates network address translation is active, with separate base ports for user and attacker traffic.

The model checker uses a fair specification (FairSpec) as the temporal formula, incorporating fairness conditions on system actions.

Two safety invariants are checked: SPASafeLaw and DataAccessSafeLaw, which likely ensure authentication requirements and proper access control.

Six liveness and safety properties are verified: SPA availability, anti-denial-of-service protection, user access availability, server hiding (the SDP goal of concealing protected resources), firewall rule consistency, and firewall correctness.

Deadlock checking is disabled, permitting terminal states in the protocol execution.
