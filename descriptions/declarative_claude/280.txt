This TLA+ module serves as a regression test for a specific tool issue related to how the UNCHANGED operator handles grouped variables through operator references.

The specification defines four variables: myVar1 (a boolean), myVar2 (a string), myVar3 (an integer), and myVar4 (a string). These variables are organized into two tuples via operator definitions: myList1 contains myVar1 and myVar2, while myList2 contains myVar3 and myVar4. A third operator, vars, combines both tuples into a nested structure.

The initial state sets myVar1 to TRUE, both string variables to empty strings, and myVar3 to zero.

The next-state relation simply specifies that all variables remain unchanged. This is expressed using UNCHANGED with the nested operator reference vars, which is the construct being tested. The desugarer must properly expand these operator references to reach the actual variables.

The temporal specification combines the initial condition with a stuttering-allowed transition relation, meaning the system either takes a Next step or stutters while preserving all variables.

This module contains no explicit safety or liveness properties beyond the basic specification structure. Its purpose is purely to verify correct handling of nested tuple references in UNCHANGED expressions during model checking.
