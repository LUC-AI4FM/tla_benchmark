This TLA+ module demonstrates various patterns related to weak fairness conditions and serves as a test case for detecting redundant or equivalent fairness specifications.

The module models an extremely simple system with a single boolean variable that transitions from FALSE to TRUE exactly once. The initial state sets the variable to FALSE, and the only possible action sets it to TRUE.

The module defines multiple specification variants (SpecA through SpecH) that combine the same basic state machine with different fairness condition formulations. These variants explore how fairness conditions can be expressed in equivalent or redundant ways:

- SpecA uses a simple weak fairness condition on the Next action
- SpecB uses a conjunction of two identical fairness conditions defined through intermediate operators
- SpecC uses universal quantification over a finite set, which yields an equivalent fairness condition
- SpecD wraps the fairness condition in a universal quantifier at the specification level
- SpecE and SpecF demonstrate cases with multiple separately defined but identical fairness conditions
- SpecG shows explicit duplication of the same fairness condition

The module also includes a refinement relationship where SpecH (without fairness) is checked against an abstract specification imported from a separate module Github1198abs. Comments indicate which patterns should trigger warnings about redundant fairness conditions in tooling.
