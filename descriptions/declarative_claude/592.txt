This TLA+ module defines a test configuration for model-checking the ConcurrentPercolator specification, which models Google's Percolator distributed transaction protocol used for concurrent multi-row transactions.

The module instantiates a minimal checking scenario with two keys (1 and 2) and two concurrent clients (c1 and c2). Each client is assigned a distinct primary key for its transactions: client c1 uses key 1 as its primary, and client c2 uses key 2.

The model-checking configuration specifies that the system should follow the PercolatorSpec temporal specification from the extended ConcurrentPercolator module. The configuration checks eight invariants: TypeInvariant ensures variables remain within expected types; WriteConsistency, LockConsistency, CommittedConsistency, AbortedConsistency, and RollbackConsistency verify correctness properties of the transaction protocol's write, lock, commit, abort, and rollback mechanisms respectively; UniqueWrite ensures no duplicate writes occur; and SnapshotIsolation verifies that the implementation provides snapshot isolation semantics, meaning transactions see a consistent snapshot of data and concurrent writes are properly isolated.

This test module serves as a concrete instantiation for exhaustively checking that the Percolator protocol maintains transactional correctness under concurrent execution with a tractably small state space.
