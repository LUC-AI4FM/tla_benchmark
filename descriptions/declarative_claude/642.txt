This TLA+ module is a configuration wrapper for model-checking a light client verification protocol, specifically instantiating the `Lightclient_003_draft` module with concrete parameters.

The specification models a blockchain light client operating in a network of four nodes. The light client attempts to verify blocks between a trusted height of 1 and a target height of 3. The model incorporates timing assumptions: a trusting period of 1400 time units, an assumed clock drift bound of 10 units, and an actual clock drift of 3 units. The primary node is configured as correct, and the faulty validator ratio is set below one-third, representing a system where Byzantine fault tolerance assumptions hold.

The variables track the light client's protocol state, including the current verification state, the next height to fetch, fetched light blocks and their verification status, the latest verified block, and a probe counter. Clock-related variables model both local and reference clocks. The blockchain state and set of faulty nodes are also tracked. Additional variables preserve previous values of verified blocks, current block, local clock, and verdict for monitoring state transitions.

By setting `IS_PRIMARY_CORRECT` to true and keeping faulty validators below one-third, this configuration represents the correct-operation scenario where the light client should successfully verify blocks without encountering Byzantine behavior.
