This TLA+ module specifies a variant of the Percolator distributed transaction protocol with a "collapse rollbacks" optimization. Percolator is a two-phase commit protocol used for multi-version concurrency control in distributed databases.

The specification models multiple clients executing transactions over a set of keys. Constants define the keys, clients, and each client's designated primary key. Variables track a global monotonic timestamp counter, client states (init, working, prewriting, committing, committed, or aborted), client timestamps and key assignments, and per-key storage including multi-version data, locks, write records (commits and rollbacks), and auxiliary variables for verifying snapshot isolation.

Clients progress through transaction phases: starting (acquiring a start timestamp), working (reading keys or cleaning stale locks), prewriting (acquiring locks on primary and secondary keys), and committing (writing the commit record for the primary key). Clients may abort at any time before committing. The protocol handles lock cleanup by rolling back uncommitted transactions or committing secondary keys when their primary is already committed. The collapse rollback optimization logically deletes older rollback records when writing new ones to reduce metadata overhead.

The specification checks type invariants plus several safety properties: write consistency (ordered, non-overlapping commits), lock consistency (at most one lock per key), committed and aborted consistency (correct state after transaction completion), rollback consistency (no transaction both commits and rolls back), unique write records per key, and snapshot isolation preservation.
