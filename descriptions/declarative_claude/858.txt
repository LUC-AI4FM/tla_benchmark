This module provides Apalache-compatible type annotations for a readers-writers specification defined in a separate ReadersWriters module, which it imports via INSTANCE.

The system models the classic readers-writers concurrency problem with a fixed number of actors. The constant NumActors specifies how many actors participate. Three variables track the system state: readers holds the set of actor identifiers currently reading, writers holds the set of actor identifiers currently writing, and waiting is a sequence of pending requests represented as tuples pairing an operation type (read or write) with an actor identifier.

The module redefines three helper operators with explicit type annotations required by Apalache: ToSet converts a sequence to a set, while read and write are predicates checking whether a request tuple represents a read or write operation respectively.

The actual state transitions and behavioral logic come from the instantiated ReadersWriters module, which defines Init and Next. The model-checking configuration sets NumActors to 3 and checks only the Safety invariant, bypassing the temporal specification's fairness conditions since Apalache cannot handle weak fairness. The Safety property presumably ensures mutual exclusion between writers and prevents simultaneous reading and writing, which are the core safety requirements of the readers-writers problem.
