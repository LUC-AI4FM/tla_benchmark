This TLA+ module is a minimal test case designed to expose a bug in Apalache's Snowcat type checker, specifically issue #860. The module demonstrates a scenario where the type checker would incorrectly raise a MatchError when processing type annotations for operators with multiple arguments.

The module defines a single operator called `Op` that takes two parameters, `n` and `m`, and always returns the boolean value `TRUE`. The operator is annotated with a type signature indicating it accepts two integers and returns a boolean.

The key aspect of this specification is the type annotation syntax. The annotation uses `->` (arrow notation) rather than `=>` for the function type, which represents a specific syntactic choice that was causing the type checker to fail with an internal error rather than providing a proper error message or handling the annotation correctly.

This module contains no variables, no temporal logic, no state transitions, and no properties to verify. It serves purely as a regression test to ensure the Apalache tool correctly handles or reports errors for this particular type annotation pattern involving multi-argument operators.
