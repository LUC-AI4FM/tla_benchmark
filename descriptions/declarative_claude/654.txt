This TLA+ module configures a model-checking instance for a blockchain light client verification protocol, specifically testing a scenario with a faulty primary peer and a significant proportion of faulty validators.

The specification models a light client attempting to verify blockchain headers from a trusted height of 1 to a target height of 5, operating within a trusting period of 1400 time units. The system includes five nodes and accounts for clock drift, with an assumed drift of 10 units and actual drift of 3 units. Critically, this configuration sets the primary peer as incorrect and allows up to two-thirds of validators to be faulty, representing an adversarial scenario at the Byzantine fault tolerance threshold.

The module declares thirteen variables tracking the light client's verification state, including the current state, next height to fetch, collected light blocks with their verification status, the latest verified block, probe count, and local clock. Additional variables track the reference clock, actual blockchain state, and the set of faulty nodes. Four monitoring variables preserve previous values of the verified block, current block, local clock, and verdict for temporal analysis.

The actual protocol logic, safety properties, and liveness conditions are defined in the imported Lightclient_003_draft module, which this configuration instantiates for model checking under specific adversarial conditions.
