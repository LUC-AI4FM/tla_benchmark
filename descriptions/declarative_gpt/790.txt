This specification models a simple key-value store with snapshot-isolated transactions. Each open transaction has its own snapshot of the store, a set of keys it has written, and a set of writes it has missed from other transactions; commits succeed only when there is no write-write conflict between the transaction's written keys and its missed keys. The spec defines transaction opening, add, update, remove, rollback, and close/commit steps, and proves that under the behavior specification the type invariant and transaction lifecycle cleanup properties always hold.
