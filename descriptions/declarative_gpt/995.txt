This specification models a resource allocator that manages a finite set of resources for a set of clients, with explicit communication between clients and the allocator through a network of in-transit messages. Clients can issue requests only when they have no pending requests and hold no resources, allocations may satisfy requests only partially, and clients may return held resources even before their full request has been satisfied. The spec combines allocator state imported through an instance of a scheduling allocator with client-local state and message passing, and it verifies type correctness, a lower-level invariant relating allocator and client views, mutual exclusion of held resources, liveness of returns and eventual acquisition, and a recurring satisfaction property under weak fairness assumptions.
