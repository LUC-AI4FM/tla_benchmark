# Specification Request: Balance Scale Weighing Puzzle

## System Overview

I need a formal specification to solve a classic weighing puzzle: Given a stone of a certain total weight, determine how to break it into a fixed number of pieces such that any integer weight from 1 up to the total can be measured using a balance scale.

## Problem Description

The scenario involves:
- A stone of total weight N pounds
- The stone must be broken into exactly P pieces (each piece having a positive integer weight)
- A two-pan balance scale is available for weighing

The key insight is that with a balance scale, weights can be placed on *either* side of the scale. This means when measuring an unknown quantity (like corn), some stone pieces can go on the same side as the item being weighed, while other pieces go on the opposite side.

## Requirements

The specification should:

1. **Enumerate all valid ways to break the stone** - Find all possible combinations of P positive integer weights that sum to exactly N. To avoid counting equivalent solutions multiple times (where pieces are just numbered differently), only consider combinations where weights are in non-decreasing order.

2. **Define what it means to measure a weight** - A target weight w can be measured if there exist two disjoint subsets of pieces where: the target weight plus the total weight of one subset equals the total weight of the other subset.

3. **Identify complete solutions** - A way of breaking the stone is a valid solution if and only if every integer weight from 1 through N can be measured using that configuration of pieces.

4. **Compute all solutions** - The specification should enable finding all valid solutions for given values of N and P.

## Expected Output

The specification should support:
- Computing the set of all solutions (ways to break the stone that allow measuring all weights 1 through N)
- Optionally, for each solution, showing how each individual weight from 1 to N can be measured (which pieces go on which side of the balance)

## Typical Use Case

The classic instance of this puzzle uses N=40 (a 40-pound stone) and P=4 (breaking into 4 pieces), but the specification should be parameterized to work for arbitrary positive integer values of N and P.
