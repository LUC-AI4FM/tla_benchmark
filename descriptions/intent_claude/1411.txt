# Specification Request: Model Checker Counterexample Introspection

## System to Model

A minimal incrementing counter system that serves as a test harness for verifying the model checker's counterexample reporting functionality.

## Goal

Create a simple specification that is *designed to fail* an invariant check, then verify that the model checker produces a correctly structured counterexample trace. The purpose is to test and validate that the model checking tool's counterexample output has the expected format and content.

## System Behavior

The system should model the simplest possible state machine:
- Start with an initial counter value of 1
- At each step, increment the counter by 1

## Correctness Properties

1. **Invariant (expected to fail):** The counter must remain below 2. This invariant is intentionally violated after the first step to trigger counterexample generation.

2. **Post-condition (the actual test):** After model checking completes (with the expected invariant violation), verify that:
   - The counterexample trace consists of exactly two states: the initial state and the state where the violation occurs
   - The counterexample data structure contains the correct action information, including the name of the transition and its source location in the specification
   - The state sequence in the counterexample matches the expected progression of values

## Purpose

This specification is a meta-test of the model checker itself, ensuring that when invariant violations are detected, the tool correctly captures and reports the execution trace leading to the violation, including accurate source location information for debugging purposes.
