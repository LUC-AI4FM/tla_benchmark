# Specification Request: Simultaneous Variable Swap with Arrays

## System Overview

I need a formal specification to verify the correctness of simultaneous (parallel) assignment semantics when working with array elements and scalar variables. The goal is to confirm that when multiple assignments are executed atomically in a single step, they use the original values from before the step—not intermediate values that might result from sequential execution.

## What Should Be Modeled

Model a simple concurrent system with multiple independent processes (e.g., three processes). Each process has:
- A local array initialized with sequential values (e.g., positions 1 through 5 contain values 1 through 5)
- A local scalar variable initialized to zero

Each process performs a single atomic operation that simultaneously:
1. Swaps two elements of the array (e.g., the first and third positions)
2. Assigns a new value to the scalar variable

## Key Correctness Requirements

The specification must verify that **simultaneous assignment has true swap semantics**:

1. **Atomicity of parallel assignment**: When multiple assignments occur in a single atomic step, all right-hand-side expressions must be evaluated using the state *before* any of the assignments take effect.

2. **Correct swap behavior**: After the simultaneous assignment, the array elements should have exchanged their original values. For example, if position 1 originally held value 1 and position 3 held value 3, then after the swap, position 1 should hold 3 and position 3 should hold 1.

3. **Value persistence**: The swapped values should remain stable in subsequent steps (until explicitly modified).

4. **Process independence**: Each process operates on its own local state, so the behavior should be consistent across all processes.

5. **Termination**: All processes should eventually complete their execution.

## Purpose

This specification serves as a validation test for simultaneous assignment semantics in a modeling language, ensuring that parallel assignments within a single statement behave as a true atomic swap rather than as sequential assignments that would overwrite values incorrectly.
