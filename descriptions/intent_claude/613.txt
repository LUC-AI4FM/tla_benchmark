# Specification Request: Byzantine Fault-Tolerant Consensus Protocol

## System Overview

I need a formal specification of a Byzantine fault-tolerant consensus protocol, specifically modeling the Tendermint consensus algorithm. The system should capture how a set of distributed processes reach agreement on a value despite some processes potentially behaving maliciously.

## System Requirements

### Participants and Fault Model
- The system consists of a fixed set of processes, some of which are correct (follow the protocol) and some of which may be faulty (Byzantine, can behave arbitrarily)
- The protocol must tolerate up to a threshold of faulty processes while guaranteeing safety properties
- For this configuration, model 4 total processes with 1 Byzantine fault tolerance

### Protocol Structure
- The consensus operates in rounds, with each round having a designated proposer
- Within each round, processes go through distinct phases (propose, prevote, precommit)
- Processes exchange messages to reach agreement on a proposed value
- The protocol should handle multiple rounds if consensus isn't reached in earlier rounds

### Values and Validity
- There should be a distinction between valid values that can legitimately be proposed and invalid values that Byzantine processes might introduce
- Model a small set of valid proposal values and at least one invalid value for testing Byzantine behavior

### Process State
- Each process tracks its current round and phase
- Processes maintain locking mechanisms to ensure safety across rounds (tracking locked values/rounds and valid values/rounds)
- Processes record their final decision once consensus is reached

### Message Passing
- Model the collection of proposal, prevote, and precommit messages sent in each round
- Track evidence of misbehavior that can be gathered during execution

## Correctness Properties

The specification should enable verification of:

1. **Agreement**: No two correct processes decide on different values
2. **Validity**: If all correct processes propose the same value, that value is decided
3. **Integrity**: A correct process decides at most once

## Configuration Parameters

- Bound the number of rounds to keep the state space finite for model checking
- The proposer selection function should be treated as arbitrary/unconstrained for safety verification purposes
