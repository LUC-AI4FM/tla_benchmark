# Specification Request: Nested Procedure Call and Return Mechanism

## System to Model

I need a formal specification of a simple call-return mechanism for nested procedure invocations, demonstrating that local variables and parameters are correctly preserved across calls and returns.

## Description

The system should model a sequential program with three procedures that call each other in a chain. The main program initiates a call to the first procedure, which calls the second procedure twice (with different arguments), and the second procedure calls the third procedure each time. This creates a call stack that grows and shrinks as procedures are invoked and return.

Each procedure should:
- Accept parameters passed by the caller
- Have its own local variables initialized to specific values
- Potentially call other procedures before returning

## Key Requirements

1. **Parameter Passing**: When a procedure is called, the argument value provided by the caller must be correctly received by the callee.

2. **Local Variable Isolation**: Each procedure has local variables that must retain their values across nested calls. When a procedure calls another procedure and that call returns, the caller's local variables must still hold the values they had before the call.

3. **Correct Call Chain**: The first procedure should call the second procedure with a computed argument (based on its local variable), and the second procedure should call the third procedure with an argument computed from its own parameter and local variable.

4. **Multiple Calls**: The first procedure calls the second procedure twice with different arguments, and both calls must work correctly with proper state preservation between them.

## Correctness Properties

The specification must verify:

1. **Parameter Integrity**: Parameters received by each procedure have the expected values (the first procedure receives 4; the second receives either 4 or 5; the third receives either 46 or 47).

2. **Local Variable Preservation**: After returning from a nested call, local variables in the calling procedure still have their pre-call values.

3. **Termination**: The entire call sequence eventually completes and the program terminates.
