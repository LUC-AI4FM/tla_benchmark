# Specification Request: Pedestrian Crossing Traffic Light

## System Overview

I need a formal specification for a simple traffic light system with a pedestrian crossing button. This models a single traffic light that can be either red or green, where pedestrians can request the light to turn green by pressing a button.

## System Description

The system consists of:
- A traffic light that can be in one of two states: red or green
- A request button that pedestrians can press to request the light turn green

## Behavioral Requirements

1. **Initial State**: The light starts red, with no pending request.

2. **Requesting a Green Light**: A pedestrian can press the button to request the light turn green, but only when:
   - The light is currently red
   - There isn't already a pending request (no duplicate requests while waiting)

3. **Turning Green**: The light can switch from red to green only when there is a pending request. When it turns green, the pending request is cleared (considered fulfilled).

4. **Turning Red**: The light can switch from green to red at any time (this models the light's natural cycle or timeout behavior).

## Key Correctness Property

The main liveness property the system must guarantee:

- **Request Fulfillment**: Whenever a pedestrian requests the light to turn green, it will eventually turn green. No request should be ignored indefinitely.

This property ensures the system is responsive to pedestrian requests and doesn't leave anyone waiting forever at a red light.
