# Specification Request: Alternating Bit Protocol Abstract Specification

## System Overview

I need a formal specification that captures the high-level behavior that the Alternating Bit protocol is supposed to achieve. This should be an abstract specification describing *what* the protocol accomplishes, not *how* it accomplishes it through message passing over unreliable channels.

## System Description

The system consists of two communicating entities: a sender and a receiver. The sender transmits data items (drawn from some configurable set of possible data values) to the receiver. Each transmission is tagged with a single bit that alternates between 0 and 1 with each new data item sent.

## Behavioral Requirements

1. **Initial State**: Both the sender and receiver should start in a synchronized state, agreeing on the same data value and bit.

2. **Sender Behavior**: The sender may only transmit a new data item when it is synchronized with the receiver (i.e., they agree on the current bit value). When sending new data, the sender:
   - Chooses an arbitrary data value from the allowed set
   - Flips its bit to indicate a new transmission

3. **Receiver Behavior**: The receiver may only accept new data when it detects the sender has transmitted something new (indicated by differing bit values). Upon reception, the receiver updates to match the sender's current data and bit.

4. **Message Format**: Data transmissions should be represented as structured records containing both the data payload and the alternating bit.

## Key Properties

The specification should capture the fundamental synchronization pattern of the Alternating Bit protocol:
- The sender and receiver take turns in a coordinated fashion
- New data is only sent after the previous data has been received
- The alternating bit serves as a simple mechanism to distinguish consecutive transmissions

## Purpose

This abstract specification will serve as a reference for verifying that concrete implementations of the Alternating Bit protocol (which must handle unreliable channels, message loss, and retransmission) correctly implement this intended behavior.
