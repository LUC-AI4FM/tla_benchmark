# Specification Request: ERC-20 Token Contract

## System Overview

I need a formal specification of an ERC-20 fungible token contract, modeling the core functionality of the widely-used Ethereum token standard. The system should capture how token balances are managed and how tokens can be transferred between accounts, including delegated transfers.

## Functional Requirements

The system must model the following operations:

1. **Direct Transfer**: An account holder should be able to send tokens directly from their own balance to another account.

2. **Approval**: An account holder should be able to authorize another account (a "spender") to transfer tokens on their behalf, up to a specified limit.

3. **Delegated Transfer**: A spender who has been granted an allowance should be able to transfer tokens from the approving account to a destination account, within the bounds of their approved allowance.

## State Requirements

The specification should track:
- The token balance of every account
- The spending allowances granted between pairs of accounts (owner → spender)
- Pending transactions waiting to be processed
- A mechanism to identify and order transactions

## Key Correctness Properties

The specification should be designed to verify:

1. **Conservation of Tokens**: The total supply of tokens should remain constant; tokens cannot be created or destroyed through transfers.

2. **Non-negative Balances**: No account should ever have a negative token balance.

3. **Allowance Enforcement**: Delegated transfers must not exceed the approved allowance.

4. **Proper Failure Handling**: Transactions that would violate constraints (insufficient balance, insufficient allowance) should fail gracefully and not modify state.

## Additional Considerations

- Account addresses should be treated as an abstract type
- The model should support concurrent pending transactions
- Each transaction should have a unique identifier for tracking
- Transactions should record whether they succeeded or failed
