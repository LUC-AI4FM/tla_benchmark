# Specification Request: Positional Subexpression Naming in TLA+

## System to be Specified

I need a formal specification of the **positional subexpression naming mechanism** for a TLA+ tooling system (such as a parser, type checker, or proof assistant). This mechanism allows users to reference specific parts of a complex expression using positional notation.

## Goal

The system should provide a way to extract and reference arbitrary subexpressions within TLA+ definitions using a hierarchical positional syntax. This enables users to refer to specific components of compound expressions without rewriting them, which is particularly useful in proofs and modular reasoning.

## Requirements

### Core Functionality

1. **Hierarchical navigation**: Given any TLA+ expression, the system must support navigating into nested subexpressions using numeric position indicators and directional markers.

2. **Support for all expression types**: The mechanism must work with:
   - Conjunctions and disjunctions (navigating to specific conjuncts/disjuncts)
   - Conditional expressions (IF-THEN-ELSE, with access to condition, then-branch, and else-branch)
   - CASE expressions (accessing individual case conditions and results, including OTHER)
   - LET-IN expressions (accessing local definitions)
   - Quantified expressions (accessing bound variable domains and bodies)
   - Function constructions and record definitions
   - Temporal operators (WF, SF) and action expressions (stuttering/non-stuttering)
   - EXCEPT expressions for record/function updates
   - Field access expressions

3. **Parameterized access**: When expressions involve bound variables (quantifiers, function definitions), the system must allow instantiating those variables with specific values to extract the resulting subexpression.

4. **Lambda extraction**: The system should support extracting the body of a quantified expression as a lambda, allowing it to be passed as an operator argument.

### Correctness Properties

1. **Referential integrity**: Extracting a subexpression at a given position must yield exactly the syntactic subexpression that appears at that position in the original definition.

2. **Consistency**: The same positional path must always resolve to the same subexpression for a given definition.

3. **Composability**: Positional navigation must be composable—navigating to position X then to position Y from there must be equivalent to navigating directly to the combined path.

4. **Evaluation preservation**: When a subexpression is extracted and evaluated in the appropriate context, it must produce the same value as evaluating it within the original expression.
