# Specification Request: Higher-Order Operator Argument Testing

## System Overview

I need a formal specification that serves as a test harness for verifying that a TLA+ model checker correctly handles **higher-order operators** — that is, operators that accept other operators as arguments.

## Goal

The purpose of this specification is to validate the language implementation's support for passing operators (including both user-defined operators and built-in infix operators) as arguments to other operators. This is essentially a conformance test for the TLA+ tooling.

## Requirements

### Core Functionality to Test

1. **User-defined operators as arguments**: It should be possible to define an operator and pass it as an argument to another operator that expects an operator parameter.

2. **Built-in infix operators as arguments**: Standard arithmetic operators (like addition and multiplication) should be passable as arguments to higher-order operators.

3. **Custom infix operators as arguments**: User-defined infix operators should also be passable as arguments.

4. **Partial application behavior**: When a higher-order operator receives an operator argument, it should be able to apply that operator to specific values and return the correct result.

### Correctness Properties

The specification must verify the following properties hold:

- Passing a user-defined binary operator and applying it to arguments `(7, 0)` yields `7` (for addition-like behavior)
- Passing the built-in `+` operator and applying it to `(7, 0)` yields `7`
- Passing the built-in `*` operator and applying it to `(7, 0)` yields `0`
- Different operators passed to the same higher-order operator produce appropriately different results based on each operator's semantics

### Test Reporting

Each test case should produce clear output indicating success, and the system should halt with an assertion failure if any test fails.
