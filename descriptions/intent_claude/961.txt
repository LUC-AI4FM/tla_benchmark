# Specification Request: TLA+ Language Grammar

## System to Model

I need a formal grammar specification for the TLA+ specification language. This should define the complete syntactic structure of TLA+ modules, capturing all valid constructs that can appear in a TLA+ specification file.

## What the Grammar Must Define

The grammar should cover the full syntax of TLA+ including:

1. **Module structure**: How a TLA+ module is delimited (with dashed lines), its name, optional extension of other modules, and the body containing various declarations and definitions.

2. **Declarations**: Variable declarations (single or multiple) and constant declarations, including higher-order constant parameters that can accept operators.

3. **Definitions**: 
   - Standard operator definitions with optional parameters
   - Function definitions with bounded quantification over domains
   - Module definitions for instantiation
   - Support for prefix, infix, and postfix operator syntax

4. **Module instantiation**: The INSTANCE mechanism with optional parameter substitution, supporting the ability to reference instantiated definitions through a qualified prefix notation.

5. **Assertions**: Assumptions (axioms) and theorems that state properties about the specification.

6. **Expressions**: The full expression language including:
   - Identifiers, numbers, and strings
   - Operator application (prefix, infix, postfix)
   - Quantified expressions (universal, existential, temporal)
   - CHOOSE expressions for definite description
   - Set constructions (enumeration, filtering, mapping)
   - Function constructions (explicit functions, function spaces, records)
   - Record and function update (EXCEPT notation)
   - Tuples and Cartesian products
   - Temporal operators (box actions, fairness conditions)
   - Conditionals (IF-THEN-ELSE and CASE)
   - Local definitions (LET-IN)
   - Bulleted conjunction and disjunction lists

7. **Lexical elements**: The reserved words, valid identifiers (excluding reserved words), numeric literals (decimal, binary, octal, hexadecimal), and string literals.

## Key Correctness Requirements

- The grammar must be unambiguous in distinguishing reserved words from user-defined identifiers
- Names starting with `WF_` and `SF_` must be handled specially as fairness operators, not identifiers
- The grammar should properly handle nested module definitions
- Local scoping (the LOCAL keyword) must be applicable to operator definitions, function definitions, instances, and module definitions
- The grammar should represent the least fixed point of the recursive grammar definition, ensuring all constructs are properly grounded
