# Specification Request: TLA+ Module Instantiation with Infix and Postfix Operators

## System to be Modeled

A test harness for verifying that TLA+'s module instantiation mechanism correctly handles user-defined infix, postfix, and prefix operators when they are accessed through an instantiated module reference.

## Goal

Demonstrate and verify that when a module defines custom operators using TLA+'s full range of symbolic operator syntax (infix operators like `+`, `-`, `*`, postfix operators like `^+`, `^*`, and prefix operators like `-.`), those operators can be correctly invoked from another module that instantiates the defining module, using the qualified name syntax.

## Requirements

1. **Operator Definition Coverage**: The source module must define operators using all standard symbolic operator forms that TLA+ allows users to redefine, including:
   - Basic arithmetic-style infix operators (addition, subtraction, multiplication, division, exponentiation)
   - Comparison operators (less than, greater than, range operators)
   - Logical connective symbols (single and double bars, ampersands)
   - Special symbols (dollar signs, question marks, percent signs, hashes)
   - Mathematical relation symbols (various forms of precedence, similarity, subset relations, and equivalences using backslash-escaped LaTeX-style names)
   - Postfix closure operators (plus, star, hash superscripts)
   - Prefix negation-style operators

2. **Qualified Access Verification**: When the module is instantiated with a name, each operator must be callable using the `InstanceName!operator(arguments)` syntax, where the operator symbol appears between the exclamation point and the argument list.

3. **Correctness Property**: Each operator, when invoked through the instantiated module reference with specific test arguments, must produce the expected result that demonstrates the arguments were passed correctly and the operator was resolved properly.

4. **Synonym Handling**: Operators that have multiple equivalent notations (such as `\leq` and `<=` and `=<`) must all resolve correctly through the instantiation syntax.
