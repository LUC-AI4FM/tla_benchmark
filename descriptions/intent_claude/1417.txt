# Specification Request: State Machine Refinement with Parameterized Property Checking

## System Overview

I need a formal specification of a simple three-phase state machine that models a process transitioning through initialization, processing, and completion stages. The system should demonstrate refinement relationships between concrete and abstract specifications.

## System Description

The concrete system represents a process that:
1. Starts in an initial state
2. Transitions to an active/in-progress state
3. Eventually completes and reaches a done state

The abstract system is simpler, with only two meaningful states: an in-progress state and a done state. The concrete system should refine this abstraction by mapping both its initial and in-progress states to the abstract "in-progress" state.

## Key Requirements

### Behavioral Requirements
- The system must progress through its states in a fixed order (no going backward)
- The system must eventually reach completion (liveness)
- Fairness should be enforced to guarantee progress

### Refinement Requirements
- The concrete three-state system must correctly implement (refine) a two-state abstract specification
- The abstraction mapping should collapse the first two concrete states into a single abstract state
- The refinement relationship should hold for both safety and liveness properties

### Property Checking Requirements
The specification should support various forms of parameterized property checking:
- Properties passed as constant-level parameters
- Properties involving state-level predicates (like type invariants)
- Properties involving temporal-level formulas
- Combinations of safety and liveness properties passed as parameters
- Both direct instantiation and parameterized instantiation of abstract modules

## Correctness Properties

1. **Type Safety**: The system state must always be one of the valid phase identifiers
2. **Refinement Correctness**: The concrete specification must refine the abstract specification
3. **Liveness**: The system must eventually reach completion
4. **Property Composition**: Combined safety and liveness properties specified through parameterization must hold

## Additional Context

This specification is intended to test a model checker's ability to handle module instantiation with computed substitutions, parameterized operators at different expression levels (constant, state, temporal), and nested module references.
