# Specification Request: Test Suite for Standard Integer Arithmetic Operations

## Goal

Create a validation test suite that verifies the correctness of standard integer and natural number arithmetic operations as provided by TLA+'s built-in modules. The purpose is to confirm that basic mathematical operators behave as expected when used in TLA+ specifications.

## System Description

This is not a distributed system or algorithm, but rather a verification harness that exercises arithmetic primitives. The specification should run a series of checks against fundamental integer operations to ensure the TLA+ tooling correctly implements standard mathematical semantics.

## Requirements

The test suite must validate the following arithmetic capabilities:

1. **Basic arithmetic operations**: Verify that multiplication produces correct results for multi-digit operands.

2. **Comparison operators**: Confirm that less-than, greater-than, less-than-or-equal, and greater-than-or-equal comparisons work correctly, including edge cases where operands are equal.

3. **Type boundaries**: Verify that subtracting a larger natural from a smaller one produces a result outside the natural numbers (i.e., negative integers are not naturals).

4. **Integer division and modulo**: Confirm that:
   - The fundamental division identity holds: for any dividend and divisor, the dividend equals the quotient times the divisor plus the remainder
   - Division by 1 returns the original number
   - Modulo 1 always returns 0
   - Modulo of 0 by any positive number returns 0
   - Specific modulo calculations produce expected remainders

5. **Integer range sets**: Verify that:
   - An empty range (where the lower bound exceeds the upper bound) produces the empty set
   - A valid range produces exactly the expected set of consecutive integers

## Correctness Properties

Each test case must either pass (confirming expected behavior) or fail with a clear assertion error identifying which test failed. All tests must pass for the specification to be considered valid. The test results should be reported during model checking to provide visibility into which validations succeeded.
