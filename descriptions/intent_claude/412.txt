# Specification Request: Test Suite for TLA+ Standard Bags Module

## Overview

I need a formal specification that serves as a test harness for validating the correctness of a standard Bags (multiset) library implementation. The goal is to verify that all fundamental bag operations behave according to their expected mathematical semantics.

## System Description

The specification should exercise a bags/multiset library by constructing sample bags and verifying that the operations produce correct results. A bag (or multiset) is a collection where elements can appear multiple times, unlike a set where each element appears at most once.

## Required Test Coverage

The test suite must verify the following bag operations and properties:

1. **Bag Construction**: Converting a set to a bag should produce a valid bag structure.

2. **Bag-to-Set Conversion**: Converting a bag back to a set should yield exactly the distinct elements, discarding multiplicity information.

3. **Membership Testing**: Checking whether an element belongs to a bag should correctly identify present and absent elements.

4. **Empty Bag**: The empty bag should convert to an empty set, and adding it to any bag should leave that bag unchanged (identity property).

5. **Bag Addition**: Combining two bags should sum the multiplicities of each element.

6. **Bag Subtraction**: Removing elements should correctly decrease multiplicities, and subtracting a singleton should reduce that element's count by one.

7. **Bag Union**: Taking the union of a collection of bags should be equivalent to pairwise addition.

8. **Subbag Relation**: A bag should be recognized as a subbag of another when every element's multiplicity in the first is less than or equal to its multiplicity in the second.

9. **Element Transformation**: Applying a function to transform all elements of a bag should preserve multiplicities appropriately.

10. **Cardinality**: The total count of elements (including repetitions) should be computed correctly.

11. **Multiplicity Counting**: Querying how many copies of a specific element exist should return the correct count, including zero for absent elements.

## Correctness Properties

- Each operation must match its expected mathematical behavior
- The test harness should report success or failure for each individual test case
- Any failed test should halt execution with a clear assertion failure

## Notes

The specification may acknowledge any known limitations in the underlying model checker's support for certain operations (such as enumerating all subbags), documenting these as expected gaps rather than failures.
