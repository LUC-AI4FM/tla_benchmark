# Specification Request: Transaction Commit Protocol

## System Overview

I need a formal specification for a distributed transaction commit protocol involving multiple resource managers (RMs). The system should model how a set of independent resource managers coordinate to reach a consistent decision about whether to commit or abort a transaction.

## System Behavior

Each resource manager participates in a transaction and must go through a lifecycle of states. Resource managers start in an initial working state, can signal their readiness to commit (preparing), and ultimately reach a final decision state of either committed or aborted. The protocol should capture the essential coordination problem where all participants must agree on the transaction's outcome.

## Key Correctness Properties

### Type Safety
The specification must ensure that each resource manager is always in one of the valid states: working, prepared, committed, or aborted.

### Consistency (Critical Safety Property)
The most important property is **transaction consistency**: it must be impossible for any two resource managers to reach conflicting final decisions. Specifically, the system must guarantee that no resource manager commits the transaction while another resource manager aborts it. This ensures atomic commitment—either all participants commit or all participants abort.

## Purpose

This specification should serve as a foundation for understanding and verifying transaction commit protocols, capturing the fundamental safety requirements that any correct implementation (such as two-phase commit) must satisfy.
