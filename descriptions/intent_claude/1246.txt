# Specification Request: Bag (Multiset) Data Structure Library

## Overview

I need a formal specification for a **bag** (also known as a multiset) data structure library. A bag is like a set, but it can contain multiple copies of the same element. For example, a bag might contain three copies of the element "apple" and two copies of "orange."

## Core Concept

A bag should be able to hold infinitely many distinct elements, but each individual element can only appear a finite (positive) number of times. The specification should define what constitutes a valid bag and provide the fundamental operations needed to work with bags.

## Required Operations

The specification must define the following capabilities:

1. **Validity check**: Determine whether a given structure is a valid bag.

2. **Conversion operations**: Convert between bags and ordinary sets (a set becomes a bag where each element appears exactly once; a bag becomes a set by ignoring multiplicities).

3. **Membership test**: Check whether an element exists in a bag (with at least one copy).

4. **Empty bag**: Represent a bag containing no elements.

5. **Bag union**: Combine two bags by adding the counts of each element together.

6. **Bag difference**: Remove elements of one bag from another, subtracting counts (an element disappears entirely if its count reaches zero or below).

7. **Generalized union**: Combine an arbitrary set of bags into one.

8. **Sub-bag relation**: Determine whether one bag is "contained in" another (meaning for every element, the first bag has no more copies than the second).

9. **Sub-bag enumeration**: Generate all possible sub-bags of a given bag.

10. **Mapping over bags**: Apply a function to each element of a bag, preserving multiplicities in the result.

11. **Cardinality**: Count the total number of element copies in a finite bag.

12. **Copy count**: Return how many copies of a specific element exist in a bag.

## Correctness Requirements

- The bag union operation must be commutative and associative.
- Bag difference must correctly handle cases where the second bag has equal or greater counts than the first.
- The sub-bag relation must define a partial order on bags.
- Cardinality must equal the sum of all individual element counts.
- Converting a set to a bag and back must return the original set.
