# Specification Request: Process Selection from Candidate Sets

## System Overview

I need a formal specification for a concurrent system where multiple processes each maintain a set of candidate processes and can select one candidate to focus on next.

## System Description

The system consists of a fixed number of processes (specifically 4). Each process has:
1. A collection of other processes it still needs to examine or interact with
2. A designated "next" process it is currently focused on

## Behavioral Requirements

The system should model the following behavior:

1. **Initial State**: All processes start with empty candidate sets, and each process's "next" designation starts at some default value.

2. **Selection Action**: A process may select any process from its candidate set to become its new focus. After selection, the newly chosen process must indeed be a member of the selecting process's candidate set.

3. **Idle Behavior**: The system may also remain unchanged (stuttering step).

## Key Constraints

- When a process updates its focus to a new target, that target must be present in the process's candidate set
- The candidate sets themselves remain unchanged during selection operations

## Context

This specification appears to capture a pattern found in mutual exclusion algorithms (similar to Lamport's Bakery algorithm), where processes need to check against a set of other processes and select which one to examine next. The specification focuses specifically on the mechanics of maintaining and selecting from these candidate sets.

## Correctness Properties

The specification should be suitable for model checking to verify that the selection mechanism maintains its basic invariant: a process's current focus is always either the default or a valid member of its candidate set.
