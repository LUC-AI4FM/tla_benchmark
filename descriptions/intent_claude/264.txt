# Specification Request: Record Type Safety Validation

## System Overview

I need a formal specification that tests the type safety properties of record (struct-like) data structures, specifically focusing on how records with different field structures should be handled.

## Goal

The specification should verify that record operations enforce consistent typing rules, particularly around record domain (field set) compatibility.

## Requirements

1. **Record Construction**: The system should support creating records with named fields and associated values of various types (e.g., integers, strings).

2. **Domain Consistency Checking**: The specification must demonstrate and validate behavior when attempting to combine or compare records that have different sets of fields (different "domains"). Specifically:
   - A record with fields {a, b} should be distinguishable from a record with only field {a}
   - The system should properly handle sets containing records of incompatible structures

3. **Type Safety Property**: The key correctness property to verify is that records with mismatched field sets cannot be silently treated as equivalent or compatible—the type system should recognize that shrinking or expanding a record's domain creates a fundamentally different type.

## Expected Behavior

When records with different field structures are placed together (e.g., in a set), the specification should expose whether this represents a type error or ill-formed construction, validating that the type checker properly rejects operations that would mix records of incompatible shapes.
