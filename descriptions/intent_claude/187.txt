# Specification Request: Polymorphic Definition Instantiation Verification

## System Overview

I need a formal specification to verify that a type system correctly handles polymorphic (generic) definitions when they are instantiated with different concrete types within the same specification.

## Goal

The system should demonstrate that a single polymorphic operator—one that can work with values of any type—correctly resolves to the appropriate concrete type each time it is used, even when called multiple times with arguments of different types in the same context.

## Requirements

1. **Polymorphic Operator**: Define a generic operator that extracts type-dependent information from its input (specifically, obtaining the domain of a function, which varies based on the function's input type).

2. **Multiple Instantiations**: The specification must exercise this polymorphic operator with at least two different concrete types:
   - One instantiation using integer-typed inputs
   - One instantiation using string-typed inputs

3. **Correctness Properties**: The system must verify that:
   - When the polymorphic operator is applied to a function with string keys, the result is a set of strings
   - When the polymorphic operator is applied to a function with integer keys, the result is a set of integers
   - These properties hold regardless of the order in which the instantiations appear in the specification
   - These properties hold whether the instantiations appear in direct conjunction, reversed order, or within nested local definitions

## Purpose

This specification serves as a regression test to ensure that the type inference and instantiation mechanism handles polymorphism correctly, avoiding bugs where type information from one instantiation incorrectly leaks into or conflicts with another instantiation of the same polymorphic definition.
