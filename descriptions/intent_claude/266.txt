# Specification Request: Record Field Access Type Checking

## System to Model

I need a formal specification that models the behavior of record (struct-like) data structures, specifically focusing on how field access and field update operations should be handled when attempting to access or modify fields that don't exist in a record.

## Requirements

The system should model:

1. **Record creation**: The ability to create records with named fields and associated values of potentially different types (e.g., integers, strings, booleans).

2. **Record update operations**: An "EXCEPT" style mechanism for creating a new record based on an existing one with modified field values.

3. **Field existence semantics**: Clear rules about what happens when an update operation references a field name that doesn't exist in the original record.

## Key Correctness Properties

The specification must verify the following properties:

1. **Domain preservation under invalid updates**: When attempting to update a non-existent field in a record, the resulting record's domain (set of field names) should remain unchanged from the original—the non-existent field should NOT be added.

2. **Type safety for field access**: The system should demonstrate or detect when field access patterns are ill-typed, specifically when code attempts to operate on fields that don't exist in a record's schema.

## Goal

The purpose of this specification is to formally capture and verify the expected behavior of record field operations, particularly edge cases involving references to undefined fields. This would support reasoning about type systems for languages with record types, ensuring that implementations correctly handle (or reject) operations on non-existent fields rather than silently adding them or causing undefined behavior.
