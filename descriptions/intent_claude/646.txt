# Specification Request: Blockchain Light Client Verification Protocol

## System Overview

I need a formal specification for a blockchain light client verification protocol. The system models how a light client can securely synchronize with a blockchain by fetching and verifying block headers, without downloading the full blockchain.

## System Description

The protocol involves a light client that:

1. Starts with a trusted block at a known height and attempts to verify blocks up to a target height
2. Fetches light blocks (block headers with validator signatures) from a primary node
3. Verifies fetched blocks against already-verified blocks using validator set information
4. Manages a local clock that may drift from real time

## Key Components to Model

- **Network participants**: A set of nodes, where one serves as the primary source of light blocks
- **Block fetching**: The light client requests blocks at various heights from the primary
- **Verification state**: Track which blocks have been fetched, their verification status, and the latest verified block
- **Clock modeling**: Both the light client's local clock (potentially drifting) and a reference clock representing real time

## Correctness Requirements

The specification must capture:

1. **Trust period constraints**: Verification must account for a trusting period during which validator sets are considered reliable
2. **Clock drift tolerance**: The protocol should handle some amount of clock drift between the light client and the blockchain
3. **Byzantine fault tolerance**: The system should behave correctly when fewer than 1/3 of validators are faulty

## Failure Scenarios to Explore

The specification should allow analysis of:

- Scenarios where the primary node is potentially malicious (providing incorrect blocks)
- Cases where actual clock drift exceeds the assumed drift bounds
- The interaction between clock drift, trusting periods, and verification security

## Configuration Parameters

The model should be parameterizable for:
- The set of participating nodes
- Starting (trusted) and target block heights
- The trusting period duration
- Assumed vs. actual clock drift amounts
- Whether the primary node behaves correctly
- The ratio of faulty validators in the network
