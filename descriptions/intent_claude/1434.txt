# Specification Request: TLC State Generation Behavior Testing

## System to Model

I need a test harness specification to verify the behavior of the TLA+ model checker (TLC) when it generates successor states from different syntactic forms of next-state actions. This is specifically about understanding how TLC handles duplicate state generation when evaluating disjunctions combined with state variable assignments.

## Goal

The specification should demonstrate and validate TLC's state enumeration behavior when the same logical conditions can be expressed in different syntactic arrangements. The key question is: does TLC generate duplicate intermediate states depending on where variable assignments appear relative to disjunctions in a formula?

## Requirements

1. **Initial state**: The system starts in a single known state.

2. **Transition variations**: Define several next-state actions that achieve similar logical outcomes but structure their conjunctions and disjunctions differently:
   - Cases where the variable assignment appears before a disjunction of always-true conditions
   - Cases where the variable assignment appears after such a disjunction
   - Cases using double-negation to force eager evaluation of conditions
   - Cases with disjunctions containing always-false conditions (unsatisfiable branches)
   - Simple disjunctions between different variable assignments

3. **Reachability correctness**: The specification must verify that exactly the expected set of states is reachable—no more, no less—regardless of internal duplicate generation.

4. **State counting properties**: The specification should support verification of how many times TLC considers certain transitions as "possible," to expose whether duplicate state generation occurred internally even if the final state space is correct.

## Key Correctness Properties

- **State space integrity**: Only the intended successor states should be reachable from the initial state.
- **Transition counting**: Specific transitions should be considered a precise number of times by TLC, revealing whether syntactic structure affects exploration efficiency.
- **No spurious states**: States that correspond to unsatisfiable conditions should never appear in the reachable state space.
