Write a specification that demonstrates and tests the semantic equivalence between different function representations in TLA+.

**System to Model:**
A test harness that verifies how TLA+ and its model checker handle functions defined in different syntactic forms—specifically, functions defined via explicit domain-value mappings versus tuple notation.

**Requirements:**

1. Create two logically equivalent functions over the same domain (integers 1 through 3), where:
   - One is defined using explicit function construction (mapping each domain element to its corresponding value)
   - One is defined using sequence/tuple literal notation

2. Verify that these two representations are treated as equal by the system.

3. Test function override/extension operations on both representations, specifically:
   - Overriding an existing key (e.g., replacing the value at position 3)
   - Extending with a new key beyond the original domain (e.g., adding position 4)

**Key Correctness Properties:**

- Two functions with identical domain-value mappings should be considered equal regardless of how they were syntactically constructed.
- Function override operations should produce consistent results when applied to semantically equivalent functions, regardless of their original syntactic form.
- The override operator should work uniformly whether modifying an existing key or adding a new key to the domain.

**Goal:**
Expose any inconsistencies in how the tooling handles function equality and override operations across different but equivalent function representations. This serves as a regression test for correct function semantics in the specification language implementation.
