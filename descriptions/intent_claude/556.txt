# Specification Request: Semaphore-Based Mutual Exclusion

## System to Model

I need a formal specification of a classic **binary semaphore** used to implement **mutual exclusion** among multiple concurrent processes.

## System Description

The system consists of N processes (where N is at least 1) that repeatedly cycle through phases of work:

1. **Non-critical section**: Each process performs some local work that doesn't require exclusive access to shared resources. Processes may remain in this phase indefinitely.

2. **Attempting to enter**: When a process wants to access the shared resource, it must acquire the semaphore before proceeding.

3. **Critical section**: The process performs work that requires exclusive access to a shared resource.

4. **Exiting**: The process releases the semaphore, allowing other processes to enter.

The semaphore is a shared variable that acts as a lock—only one process can hold it at a time. A process acquires the semaphore by atomically checking that it's available and claiming it. When done with the critical section, the process releases the semaphore.

## Key Correctness Properties

The specification must guarantee:

1. **Mutual Exclusion (Safety)**: At most one process may be in the critical section at any given time. Two or more processes must never simultaneously be in their critical sections.

2. **Starvation Freedom (Liveness)**: Any process that wishes to enter the critical section must eventually be able to do so. No process should be perpetually blocked while others repeatedly access the critical section.

## Fairness Assumptions

- Processes should not be required to leave the non-critical section if they don't want to (weak fairness outside the non-critical section).
- Processes actively trying to enter the critical section should eventually succeed (strong fairness on the entry attempt).
