# Specification Request: TLA+ Parser Keyword Handling Test

## Goal

Create a test specification to verify that a TLA+ parser (specifically SANY2, the Syntactic Analyzer) correctly handles reserved keywords when they appear as record field names.

## System Description

This is not a specification of a distributed system or algorithm, but rather a **parser conformance test**. The purpose is to ensure that the TLA+ language parser can distinguish between keywords used in their reserved syntactic roles versus the same identifiers used as field names in record expressions.

## Requirements

1. **Record Field Access**: The parser must accept all TLA+ reserved keywords as valid field names when used in record field access expressions (e.g., accessing a field from a record).

2. **Record Update Expressions**: The parser must accept all TLA+ reserved keywords as valid field names within record update (EXCEPT) expressions.

3. **Comprehensive Keyword Coverage**: The test must exercise field naming with the complete set of TLA+ reserved words, including but not limited to:
   - Proof-related keywords (LEMMA, THEOREM, PROPOSITION, PROOF, QED, etc.)
   - Declaration keywords (CONSTANT, VARIABLE, MODULE, INSTANCE, etc.)
   - Expression keywords (IF, THEN, ELSE, CASE, LET, IN, CHOOSE, etc.)
   - Temporal operators (ENABLED, UNCHANGED, etc.)
   - Set operators used as keywords (UNION, SUBSET, DOMAIN, etc.)
   - Fairness specifiers (SF_, WF_)
   - Proof step keywords (ASSUME, PROVE, SUFFICES, HAVE, TAKE, PICK, WITNESS, etc.)
   - Other reserved words (LOCAL, EXCEPT, WITH, LAMBDA, RECURSIVE, etc.)

## Correctness Properties

1. **Parsing Success**: The module must parse without syntax errors—this is the primary correctness criterion.

2. **No Ambiguity**: The parser must unambiguously distinguish contextual usage of keywords as field names from their reserved syntactic roles.

3. **Consistency**: Both field access and field update syntax must work uniformly for all keywords.

## Context

This test supports TLA+ tooling development by ensuring language implementations correctly handle the grammar's context-sensitivity around reserved words in record contexts.
