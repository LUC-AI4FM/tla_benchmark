# Specification Request: TLA+ Prime Operator and Variable Scoping Semantics

## System to Be Modeled

A test harness that verifies the correct behavior of TLA+'s prime operator (`'`) when applied in various syntactic contexts, particularly focusing on how priming interacts with operator arguments, local definitions, and variable references.

## Goal

Create a specification that systematically tests the semantics of the prime operator to ensure that a TLA+ tool (such as TLC) correctly evaluates primed expressions in the following scenarios:

1. **Priming within operator bodies**: When an operator's body contains a primed variable, verify that the prime applies to the correct variable (the one in scope at the call site, not the parameter name).

2. **Priming operator applications**: When the prime is applied to an entire operator call expression, verify that all free variables within the result are correctly primed.

3. **Priming with LET expressions**: When primed expressions involve local definitions, verify that the scoping rules are respected and primes are distributed correctly.

4. **Interaction between parameters and state variables**: When operator parameters shadow state variable names, verify that priming behaves correctly and doesn't confuse parameter references with state variable references.

## Requirements

The specification should:

- Define a simple state with a small number of integer variables
- Include operators that take parameters with names that may coincide with state variable names
- Execute transitions that change state while checking various primed expressions
- Validate expected outcomes using assertions or conditional checks that report success or failure

## Key Correctness Properties

- Priming a variable reference inside an operator body should refer to the next-state value of the actual state variable, not be confused with the formal parameter
- Priming an entire expression should be equivalent to priming all state variables within it
- Local definitions in LET expressions should correctly capture or not capture primed values based on where the prime operator is applied
- The semantics should be consistent regardless of whether variables are referenced directly or through operator applications
