# Specification Request: TLA+ Parser Test Suite for Infix Operator Handling

## Goal

Create a comprehensive test suite to verify that a TLA+ parser and toolchain correctly handles all infix operator symbols in the language. The system should validate that infix operators can be properly parsed, defined by users, and passed as arguments to higher-order operators.

## System Description

The test suite should exercise the TLA+ language's support for infix operators in several contexts:

1. **User-definable infix operators**: TLA+ allows users to define their own meanings for a large set of infix operator symbols that are not built-in. The parser must correctly recognize all of these symbols and allow them to be given custom definitions.

2. **Operators as arguments**: TLA+ supports passing operators (including infix operators) as arguments to other operators. The parser must correctly handle infix operator symbols being passed in this higher-order fashion.

3. **Built-in operators**: Certain infix operators have fixed meanings in TLA+ (logical connectives, set operations, etc.). These should also be passable as operator arguments while retaining their standard semantics.

4. **Temporal/action operators**: Special temporal logic operators should be recognized by the parser even when used in unusual syntactic positions.

## Requirements

The test suite must verify:

1. **Complete coverage of user-definable infix symbols**: All infix operator symbols that TLA+ reserves but does not give built-in meanings to (arithmetic-style, relational-style, algebraic-style, etc.) should be testable with custom definitions.

2. **Higher-order operator compatibility**: Each infix operator symbol should be passable as an argument to a higher-order operator, and when invoked through that higher-order operator, it should behave according to its definition.

3. **Synonym handling**: Operators that have multiple syntactic forms (such as alternative ASCII representations of the same logical symbol) must all be recognized and treated equivalently.

4. **Built-in operator passability**: Standard built-in operators for logic (conjunction, disjunction, implication, equivalence) and sets (membership, subset, intersection, union, difference) should be passable as operator arguments.

5. **Module instantiation compatibility**: The parsing of infix operators should work correctly in the context of module instantiation.

## Correctness Properties

- Every test case that passes an operator to a higher-order definition must produce results consistent with that operator's defined or built-in semantics.
- The parser must not reject any valid infix operator symbol.
- Synonymous operator notations must produce identical results.
- All tests must pass for the implementation to be considered correct.
