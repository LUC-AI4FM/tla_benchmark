# Specification Request: Set-to-Sequence Fold Operation Verification

## System to Model

A verification test for a fold operation that converts a finite set of integers into a sequence by iteratively appending each element.

## Goal

Verify that a fold operation over a set, which accumulates elements into a sequence by appending, produces a result that is some permutation of the original set's elements. Since sets have no inherent ordering, folding a set into a sequence should be able to produce any possible ordering of those elements.

## Requirements

1. **Fold Operation**: The system should model a fold operation that takes:
   - An append function that adds an element to the end of a sequence
   - An empty sequence as the initial accumulator
   - A finite set of integers as input

2. **Expected Behavior**: When folding the set {1, 2, 3} into a sequence using append, the result must be one of the six possible permutations of those three elements.

## Correctness Properties

The key property to verify is that the fold operation is **properly constrained** — specifically, that the result of folding a set into a sequence is guaranteed to be *some* permutation of the set's elements, not an arbitrary or malformed sequence.

## Verification Approach

The specification should assert the *negation* of the expected invariant (i.e., claim the result is *not* a valid permutation) so that a model checker or SMT solver will find this assertion unsatisfiable, thereby confirming the fold operation works correctly. If the tool reports the negated invariant cannot hold, it proves the original property is valid.
