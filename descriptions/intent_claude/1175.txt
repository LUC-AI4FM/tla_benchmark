# Specification Request: TLA+ Toolbox Error Handling Test Cases

## Overview

I need a minimal TLA+ specification that can be used to test how the TLA+ toolbox handles various parsing and semantic errors in model configuration files.

## Purpose

The goal is to create a simple base specification that serves as a foundation for testing error detection and reporting when users make common mistakes in their model configuration (MC) files.

## Test Scenarios Required

The specification should support testing at least two error conditions:

1. **Malformed Expression Error**: Test that the toolbox properly detects and reports when a model configuration contains a syntactically invalid expression.

2. **Duplicate Symbol Definition Error**: Test that the toolbox properly detects and reports when a symbol is defined multiple times (once in the specification and again in the model configuration).

## Requirements

- The specification should be as minimal as possible while still being valid TLA+
- It should declare at least one constant that can be assigned values in model configurations
- It should declare at least one variable to make it a stateful specification
- It should define at least one simple operator that could potentially conflict with model-level definitions

## Expected Behavior

When the associated model configurations contain errors, the TLA+ toolbox should:
- Detect the parsing or semantic error
- Report a clear error message to the user
- Prevent model checking from proceeding until errors are resolved
