# Specification Request: TLA+ Operator Override and Replacement Testing

## System to Model

A test harness for verifying that a TLA+ model checker correctly supports operator overriding and replacement mechanisms. This includes the ability to substitute custom implementations for declared constants (both prefix and infix operators), override built-in operators from standard modules, and define local infix operators using symbolic names.

## Requirements

The system should validate the following capabilities:

1. **Constant operator replacement**: When a multi-argument operator is declared as a constant, the model checker should allow substituting a concrete implementation at runtime. This applies to both standard prefix notation and infix notation operators.

2. **Built-in operator overriding**: The model checker should support replacing standard library operators (such as sequence length or sequence operations) with user-defined implementations during model checking.

3. **Infix operator constants**: Operators declared using infix syntax as constants should be replaceable with concrete implementations that get invoked using infix notation.

4. **Local infix operator definitions**: Users should be able to define local operators using symbolic infix notation (like precedence symbols) within LET expressions.

## Correctness Properties

The specification must verify that:

- Replacement operators for declared constants receive arguments correctly and return expected values
- Infix operator constants work properly when invoked with infix syntax
- Overridden built-in operators (like sequence length) behave according to their replacement definitions
- Standard module operators can be replaced with entirely different semantics (e.g., concatenation replaced with addition)
- Locally-defined symbolic infix operators evaluate correctly within their scope

## Goal

Confirm that the operator substitution and overriding mechanisms in the TLA+ tooling work correctly across various scenarios: constant replacement, infix operators, built-in operator overrides, and local operator definitions. Each capability should be independently verifiable through explicit test conditions.
