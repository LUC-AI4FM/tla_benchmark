# Specification Request

I need a formal specification that serves as a documentation and style guide reference for TLA+ specifications.

## System Overview

The specification should demonstrate and catalog the various commenting and documentation conventions available in TLA+ modules. This is essentially a reference document showing how specifications can be annotated and organized for readability and maintainability.

## Requirements

The specification must illustrate:

1. **Structured documentation blocks** - How to write formal, boxed documentation comments suitable for describing operators, including examples of usage with input/output demonstrations

2. **Nested explanatory comments** - How to write indented documentation for secondary or subordinate explanations within a specification

3. **Free-form descriptive text** - How to write less structured multi-line comments suitable for algorithm descriptions, citations, or prose explanations

4. **Technical inline annotations** - How to write line-by-line comments that explain implementation details, known issues, workarounds, or references to external resources like issue trackers

5. **Section organization** - How to visually separate major sections of a specification using horizontal dividers

6. **Code-adjacent documentation** - How to annotate individual declarations (such as variables) with brief inline explanations of their purpose

## Purpose

This specification serves as a living style guide that TLA+ authors can reference when deciding how to document their own specifications. It should make clear when each commenting style is appropriate and how they visually appear in the module structure.

## Correctness Properties

Since this is a documentation reference rather than a behavioral specification, the key property is simply that the module is syntactically valid—all demonstrated comment styles must be legal TLA+ syntax that the tooling will accept.
