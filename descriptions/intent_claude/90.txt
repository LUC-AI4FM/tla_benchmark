# Specification Request: Cigarette Smokers Problem

## System Overview

Please formally specify the classic **Cigarette Smokers Problem**, a concurrency puzzle originally described by Suhas Patil in 1971. This problem models resource allocation and synchronization between multiple processes that need complementary resources to complete a task.

## Problem Description

The system involves:

1. **A dealer (agent)**: An entity that provides resources to smokers
2. **Multiple smokers**: Each smoker has an infinite personal supply of exactly one ingredient needed to make a cigarette, but needs the other ingredients to smoke

To smoke a cigarette, a smoker needs a complete set of all ingredients. The dealer repeatedly places a subset of ingredients on a table—specifically, all ingredients *except* one. The smoker who possesses the missing ingredient can then take the offered ingredients, combine them with their own supply, and smoke.

## Behavioral Requirements

1. The dealer should offer combinations of ingredients, where each offer contains all ingredients except one
2. When the dealer makes an offer, exactly one smoker (the one holding the missing ingredient) should be able to smoke
3. A smoker can only start smoking when the appropriate ingredients are available from the dealer
4. After a smoker finishes smoking, the dealer should make a new offer
5. The system should alternate between the dealer providing ingredients and a smoker consuming them

## Correctness Properties

The specification must guarantee:

1. **Mutual Exclusion**: At most one smoker can be smoking at any given time. Since only one combination is offered and only one smoker has the complementary ingredient, concurrent smoking should be impossible.

2. **Type Safety**: The system state should always conform to expected types—smokers should be properly associated with their ingredients and states, and the dealer's offer should always be a valid combination (or empty when ingredients have been taken).

## Fairness Considerations

The specification should support reasoning about liveness under weak fairness assumptions, ensuring the system continues to make progress rather than stuttering indefinitely.
