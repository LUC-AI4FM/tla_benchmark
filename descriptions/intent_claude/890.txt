# Specification Request: Asynchronous Communication Interface

## System Overview

I need a formal specification for a simple asynchronous communication interface between two components—a sender and a receiver. This models the fundamental handshaking mechanism used when two independent processes need to exchange data without a shared clock.

## System Description

The interface should model a basic handshake protocol where:

1. A sender can transmit data values to a receiver
2. The sender signals when new data is available
3. The receiver acknowledges when it has consumed the data
4. The protocol alternates between sending and receiving phases

The communication is asynchronous, meaning the sender and receiver operate independently and coordinate only through the signaling mechanism.

## Behavioral Requirements

- The sender should be able to place a data value into the channel and indicate readiness
- The receiver should be able to observe when data is ready, consume it, and signal acknowledgment
- The protocol should ensure proper alternation: the sender waits for acknowledgment before sending again, and the receiver waits for new data before receiving again

## Correctness Properties

The specification must guarantee **type correctness**: all components of the interface remain within their expected domains throughout any execution. Specifically:

- Data values must always be valid elements from the defined data domain
- Signaling flags must always be proper boolean values

This type invariant should hold in all reachable states of the system, starting from proper initialization and preserved by every possible action.

## Verification Goal

I need a formal proof that the type invariant is maintained by the specification—that is, if the system starts in a valid initial state and follows the defined transitions, it will always remain in a type-correct state.
