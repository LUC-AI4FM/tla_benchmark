# Specification Request: Readers-Writers Synchronization

## System to Model

I need a formal specification of the classic **readers-writers synchronization problem**. This models a shared resource (like a database or file) that can be accessed by multiple concurrent actors, where some actors want to read the resource and others want to write to it.

## System Requirements

### Basic Behavior

- There is a fixed number of actors that can request access to a shared resource
- Each actor can request either read access or write access
- Actors that cannot immediately access the resource should wait in a queue
- The system should process waiting actors and eventually grant them access
- Actors should release their access when done

### Mutual Exclusion Constraints

The core synchronization requirements are:

1. **Multiple readers allowed**: Any number of actors may read the resource simultaneously
2. **Writers are exclusive**: When a writer has access, no other actor (reader or writer) may access the resource
3. **No reader-writer overlap**: Readers and writers must never access the resource at the same time

## Key Correctness Properties

### Safety Properties

- **Mutual exclusion**: At no point should there be both active readers and active writers simultaneously
- **Writer exclusivity**: At most one writer may have access at any time

### Liveness Properties

- **No starvation**: Every actor that requests access should eventually be granted access (the waiting queue should be fair)
- **Progress**: The system should continue to make progress and not deadlock

## Additional Considerations

- The specification should track which actors are currently reading, which are currently writing, and which are waiting for access
- The waiting mechanism should preserve some notion of ordering to ensure fairness
- The model should be parameterized by the number of actors in the system
