# Specification Request: One-Element Tuple Handling Verification

## System Overview

I need a test harness to verify that a TLA+ model checker correctly handles **one-element tuples** (also called singleton tuples or 1-tuples) in various language constructs.

## Goal

Create a specification that validates the model checker's implementation of singleton tuples like `<<1>>` or `<<x>>`. These are tuples containing exactly one element, and they should behave consistently with the general tuple semantics but may have edge cases worth verifying.

## Test Requirements

The specification should verify the following capabilities involving one-element tuples:

1. **Set membership**: Confirm that a singleton tuple can be correctly identified as a member of a set of singleton tuples (e.g., checking if `<<1>>` belongs to a set constructed from wrapping integers in tuples).

2. **Element access**: Verify that accessing the first (and only) element of a singleton tuple using indexing works correctly, particularly when iterating over a set of such tuples.

## Correctness Properties

- Each test case should either pass (printing confirmation) or immediately fail with an assertion error identifying which test failed.
- The tests should run as invariant checks, ensuring the tuple operations evaluate correctly in the initial state.

## Context

This is a **language feature test**, not a model of a distributed system or algorithm. The specification exists purely to exercise the model checker's handling of a specific syntactic and semantic feature. The system state itself is trivial and static—the real purpose is evaluating expressions involving one-element tuples during invariant checking.
