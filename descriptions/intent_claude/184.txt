# Specification Request

## System to Model

Design a formal specification for a system with two independent, concurrently growing collections that must remain distinct from each other, combined with a simple state machine that transitions through a small set of control states.

## Requirements

### Collection Dynamics
- The system maintains two separate collections that grow over time by accumulating elements
- Each collection follows its own cyclic pattern of element additions (e.g., cycling through sequences like 1→2→3→1 or 4→5→6→1)
- The additions to each collection are triggered by the presence of specific elements already in that collection
- A third derived collection tracks the combined contents of both primary collections
- The two collections operate independently of each other

### State Machine Behavior
- A control state variable cycles through a small finite set of states (0 through 4)
- The state transitions follow specific allowed paths, creating a directed graph of permissible transitions
- The state may also remain unchanged (stutter)
- State transitions happen concurrently with collection updates

### Key Correctness Property

**Invariant**: The two primary collections must never become identical to each other. Despite both collections growing and potentially accumulating overlapping elements, their complete contents must always differ.

## Goal

The specification should demonstrate a system where concurrent, loosely-coupled processes each build up their own accumulating state, while a safety property ensures they maintain their distinctiveness throughout all possible executions.
