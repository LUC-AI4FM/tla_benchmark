# Specification Request: Replicated Log Abstract Model

## System Overview

I need a formal specification for an abstract model of a replicated log system, similar to what you'd find in consensus protocols like Raft. The system consists of a cluster of servers that each maintain a log of entries, where entries are tagged with term numbers (logical timestamps representing leadership epochs).

## Core Functionality

The system should model:

1. **A cluster of servers**: Multiple nodes that each maintain their own copy of a log
2. **Term-based entries**: Log entries are associated with terms (monotonically increasing epoch numbers)
3. **Log extension**: Servers can append new entries to their logs
4. **Log convergence**: Some mechanism for logs to become consistent across servers (abstracting away the details of how replication actually occurs)

## Key Requirements

- Each server maintains a log that is a sequence of term numbers
- The system starts with servers having some initial log state
- Servers operate within a range of valid terms
- Logs can grow by appending entries tagged with appropriate terms

## Correctness Properties

The specification should maintain:

1. **Type Safety**: All logs must be valid sequences of terms from the allowed term range
2. **Bounded Growth**: For model checking purposes, logs should not grow beyond a reasonable maximum length

## Model Checking Considerations

The specification should be structured to support efficient model checking with:
- A small, configurable set of servers (e.g., three nodes)
- Symmetry reduction to treat servers as interchangeable
- Bounded log lengths to ensure termination
- A limited range of terms to constrain the state space

This is intended to be an *abstract* model that captures the essential properties of replicated logs without modeling the full complexity of leader election, message passing, or specific replication protocols.
