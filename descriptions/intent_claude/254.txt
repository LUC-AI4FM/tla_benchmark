# Specification Request: Functional Test Suite for Function Operations Library

## System Overview

I need a formal specification that serves as a comprehensive test suite for a library of operations on mathematical functions (mappings). The purpose is to verify that a set of utility operators for manipulating and analyzing functions behave correctly according to their mathematical definitions.

## What Should Be Modeled

The specification should model a static verification framework—essentially a collection of test cases that can be checked as invariants. There is no dynamic behavior or state transitions to model; the system simply needs to verify that various function operations produce expected results.

## Operations to Be Tested

The test suite must verify the correctness of the following categories of operations:

### 1. Function Manipulation
- **Domain restriction**: Given a function, produce a new function restricted to a subset of its domain
- **Range computation**: Extract the set of all output values of a function
- **Function inversion**: For an injective function, produce its inverse mapping

### 2. Injectivity Testing
- Determine whether a function is injective (one-to-one), meaning no two distinct inputs map to the same output
- This should work correctly for empty functions, single-element domains, and larger domains
- It should correctly identify non-injective functions where multiple inputs share an output

### 3. Folding/Aggregation
- Aggregate all values in a function's range using a combining operation
- Support folding over the entire function or only over a specified subset of the domain

### 4. Function Classification
- **Injection**: Verify membership in the set of all injective functions between two sets
- **Surjection**: Verify membership in the set of all surjective functions (where every element in the codomain is covered)
- **Bijection**: Verify membership in the set of all bijective functions (both injective and surjective)

### 5. Existence Predicates
- Determine whether there exists any injection, surjection, or bijection between two given sets

## Correctness Properties

The specification must guarantee:

1. **Consistency with mathematical definitions**: Each operation must match its standard mathematical semantics
2. **Equivalence verification**: Where alternative implementations exist (e.g., a pure logical definition vs. an optimized version), both must produce identical results for all inputs in the tested domains
3. **Edge case handling**: Empty functions, single-element domains, and boundary conditions must be handled correctly
4. **Completeness of test coverage**: All operations should be tested with both positive cases (where the property holds) and negative cases (where it should not hold)

## Goal

The goal is to have high confidence that the function operations library is implemented correctly by expressing expected behaviors as formal properties that can be mechanically verified. All test cases should pass (evaluate to true) when the library is correct.
