# Specification Request: TLA+ UNCHANGED Operator Semantics Test Suite

## Goal

Create a test harness specification to verify the correct behavior of the TLA+ `UNCHANGED` operator across a variety of expression forms. The purpose is to ensure that a TLA+ model checker correctly evaluates `UNCHANGED` when applied to different kinds of expressions, including array elements, records, quantified expressions, set comprehensions, and compound structures.

## System Description

The system under test is essentially the TLA+ tooling itself (specifically, the model checker's handling of `UNCHANGED`). The specification should set up a simple state with an array-like structure and a scalar value, then exercise multiple test cases that verify `UNCHANGED` behaves correctly when applied to:

1. Individual array elements using primed equality
2. Individual array elements using the `UNCHANGED` operator directly
3. Records constructed from array values
4. Existentially quantified boolean expressions over array elements
5. Universally quantified boolean expressions over array elements
6. `CHOOSE` expressions that select an element from the array
7. Set comprehensions that map over array indices
8. Set comprehensions with filtering predicates
9. The domain of an array
10. Sets containing the entire array structure
11. Sets containing a mix of constants and changing values

## Requirements

- The specification must include test cases where the state genuinely remains unchanged and verify that `UNCHANGED` evaluates to true for various derived expressions.
- The specification must include test cases where part of the state changes but `UNCHANGED` is applied to expressions that still evaluate to the same value (testing that `UNCHANGED` compares expression values, not syntactic variable references).
- Each test case should produce clear output indicating success.
- Failed tests should halt execution with an assertion error.
- The test suite should cover edge cases around how `UNCHANGED` interacts with set-builder notation, quantifiers, and selection operators.

## Correctness Properties

- All test cases must pass (no assertion failures).
- The specification should remain in valid states throughout execution (trivially satisfied since the invariant is always true—the real verification is that the model checker executes without errors).
