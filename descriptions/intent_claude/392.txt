# Specification Request: TLA+ Module Instantiation and Label Reference Test Suite

## System to be Specified

A comprehensive test suite for validating the TLA+ tooling's support for **module instantiation** combined with **label referencing** within theorems and operator definitions. This is a language-level feature verification system, not a distributed system or algorithm.

## Goal

Verify that the TLA+ tools (parser, semantic analyzer, and model checker) correctly handle the following advanced language features when used in combination:

1. **Parameterized and non-parameterized module instantiation** — including instances created with and without arguments, and with constant substitutions
2. **Local vs. non-local instantiation** — ensuring proper scoping rules apply
3. **Hierarchical label access** — referencing labeled sub-expressions within theorems and complex operator definitions from instantiated modules
4. **Nested label paths** — accessing deeply nested labels using the `!` notation, including special label forms
5. **Higher-order operator patterns** — passing operator references (including labeled sub-parts of operators) as arguments to other operators
6. **Multiple equivalent access paths** — confirming that different syntactic paths to the same sub-expression yield identical results

## Requirements

The test suite must validate that:

1. **Label accessibility**: Labels defined inside theorems in an instantiated module can be accessed through the instance name using proper path notation
2. **Instantiation variants behave consistently**: Whether the module is instantiated with parameters, without parameters, locally, or directly merged, the same labeled expressions should be reachable and evaluate identically
3. **Arithmetic and structural correctness**: All accessed sub-expressions evaluate to their expected values (specific numeric or structural results)
4. **Composite expressions**: Complex nested structures (tuples, sets, sequences) with multiple labeled components can be correctly decomposed via label paths
5. **Operator substitution**: Sub-expressions identified by labels can be extracted and passed to higher-order operators, behaving as expected

## Key Correctness Properties

- All assertions in the test suite must hold (no assumption violations)
- Equivalent access paths must yield identical values
- The constant substitution mechanism must properly propagate to all nested references
- Local instantiation must not leak definitions to outer scopes while still allowing internal label access
- The evaluation of labeled sub-expressions must be independent of the access path used to reach them
