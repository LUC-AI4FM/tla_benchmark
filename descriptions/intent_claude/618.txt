# Specification Request: Byzantine Fault-Tolerant Consensus Protocol

## System to Model

I need a formal specification of a Byzantine fault-tolerant consensus protocol, specifically modeling the Tendermint consensus algorithm. The system should capture how a set of distributed processes reach agreement on a value despite some processes potentially behaving maliciously.

## System Requirements

The protocol operates with the following characteristics:

- **Participants**: A fixed set of processes, divided into correct (honest) processes and faulty (Byzantine) processes that may behave arbitrarily
- **Rounds**: The protocol proceeds through multiple rounds, each with a designated proposer who suggests a value
- **Phases**: Each round consists of distinct phases (propose, prevote, precommit) where processes exchange messages
- **Values**: There is a set of valid values that can be legitimately proposed, as well as invalid values that only faulty processes would propose
- **Locking mechanism**: Processes maintain locked values and validity information across rounds to ensure consistency

## Configuration for This Instance

This particular model instance should be configured for:
- 5 total processes (3 correct, 2 faulty)
- Fault tolerance threshold allowing the system to tolerate up to 1 Byzantine failure for safety properties
- 2 valid values that can be proposed
- A maximum of 2 rounds of execution
- Arbitrary proposer assignment (any process can be the proposer in any round)

## Correctness Properties

The specification must guarantee the standard consensus safety properties:

1. **Agreement**: No two correct processes decide on different values
2. **Validity**: If a correct process decides a value, it must be a valid value (not an invalid/garbage value)
3. **Evidence collection**: The system should track evidence of misbehavior that can be used to detect Byzantine faults

The model should support verification using a model checker with configurable initial constraints for exploring the state space efficiently.
