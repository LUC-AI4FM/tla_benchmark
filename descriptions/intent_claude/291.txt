# Specification Request: Clock Drift Tracking System

## System Overview

I need a formal specification for a distributed system that tracks clock values across multiple processes and monitors the drift (difference) between pairs of process clocks.

## System Description

The system consists of a fixed set of processes (in this case, three processes). Each process maintains its own local clock. The system needs to track:

1. **Individual clock values**: Each process has an associated clock that holds an integer value representing its current time.

2. **Pairwise clock drift**: For every pair of processes, the system tracks the drift (difference) between their respective clock values.

## Requirements

### State Components
- A mapping from each process to its current clock value (integer)
- A mapping from each pair of processes to the drift between their clocks (integer)

### Functional Requirements
- The system should be able to update clock values for individual processes
- When clocks change, the drift values between affected process pairs should be updated accordingly
- The drift calculation should correctly reflect the difference between any two process clocks

### Correctness Properties

The specification should ensure:

1. **Drift Consistency**: The recorded drift between any two processes should accurately reflect the actual difference between their clock values at all times.

2. **Completeness**: Drift should be tracked for all relevant pairs of processes in the system.

3. **Update Propagation**: Any operation that modifies a process's clock should properly update all drift values involving that process.

## Context

This appears to involve using a fold operation with selective updates (updating a function/mapping except at certain keys), which is a common pattern when maintaining derived state that depends on multiple source values.
