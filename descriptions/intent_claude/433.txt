# Specification Request: TLA+ Standard Module Operator Alias Verification

## Goal

Create a test specification that verifies the TLA+ tooling (specifically TLC model checker) correctly supports alternative syntax aliases for operators defined in the standard library modules.

## System Description

This is not a behavioral system but rather a **conformance test suite** for the TLA+ language implementation. The specification should verify that commonly-used operator aliases are properly recognized and behave identically to their canonical forms.

## Requirements

The test must verify equivalence between the following operator pairs:

### Numeric Comparison Operators (from Naturals module)
- The ASCII-friendly `<=` notation must behave identically to the symbolic `\leq` operator
- The ASCII-friendly `>=` notation must behave identically to the symbolic `\geq` operator

### Sequence Operators (from Sequences module)
- The symbolic `\circ` concatenation operator must behave identically to the standard `\o` operator

### Bag/Multiset Operators (from Bags module)
- The ASCII-friendly `(+)` bag addition operator must behave identically to the symbolic `\oplus` operator
- The ASCII-friendly `(-)` bag subtraction operator must behave identically to the symbolic `\ominus` operator

## Correctness Properties

1. **Alias Equivalence**: For each pair of alias operators, applying both to identical operands must produce identical results

2. **Basic Functionality**: The operators must work correctly on representative test cases:
   - Bag operations on simple string multisets
   - Sequence concatenation on simple sequences
   - Numeric comparisons on natural numbers

3. **Test Reporting**: The specification should clearly indicate which tests pass or fail during model checking

## Purpose

This specification serves as a regression test to ensure that TLA+ tooling maintains backward compatibility and correctly implements all documented operator synonyms across the standard library modules.
