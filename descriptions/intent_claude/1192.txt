# Specification Request: One-Tuple Handling Verification

## Overview

I need a formal specification that serves as a test suite to verify correct handling of single-element tuples (one-tuples) in TLA+. The goal is to confirm that the model checker properly processes various operations involving tuples that contain exactly one element.

## System Description

This is not a distributed system or algorithm specification, but rather a verification harness. The specification should define a trivial system with no meaningful state transitions, used solely as a vehicle to check tuple-related language features during model checking.

## Requirements

The specification must verify the following properties about one-tuple handling:

1. **Set membership**: A one-tuple constructed from an element should be correctly identified as a member of a set of one-tuples built from that element's domain.

2. **Existential quantification with tuple destructuring**: The system should correctly support existential quantification that destructures one-tuples, allowing direct binding of the inner element.

3. **Tuple indexing**: Accessing the first (and only) element of a one-tuple via indexing should work correctly.

4. **Set comprehension with tuple destructuring**: Filtering a set of one-tuples using a predicate that destructures the tuple should produce the expected subset.

5. **Sequence concatenation**: Concatenating two one-tuples should produce a two-element sequence containing both values in order.

6. **Function definition over tuple domain**: Defining a function whose domain consists of one-tuples, using destructuring syntax in the mapping, should allow correct function application.

## Correctness Properties

Each test case must pass. If any tuple operation produces an unexpected result, the specification should fail with an assertion error identifying which test failed. If all operations behave correctly, the specification should report success for each test.

## Purpose

This specification is intended for regression testing or validation of a TLA+ toolchain's tuple implementation, ensuring that one-tuples are not treated as special cases that break standard tuple and sequence operations.
