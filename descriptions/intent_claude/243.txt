# Specification Request: Function Extension Behavior

## System Overview

I need a formal specification that models the behavior of extending or merging functions (mappings from integers to integers) in a system where new key-value pairs can be added or override existing ones.

## What Should Be Modeled

The system should track a function that maps integers to integer values. The system starts with an initial mapping and then applies an extension operation that combines the original function with new mappings.

## Behavioral Requirements

1. **Initial State**: The system begins with a function defined over a small initial domain (e.g., keys 1, 2, and 3), where each key maps to itself (identity mapping).

2. **Update Operation**: The system should support an extension operation that merges a new function into the existing one. When domains overlap, I need to understand and verify which values take precedence—specifically whether the original values are preserved or the new values override them.

## Key Correctness Properties

The specification should help verify:

1. **Value Preservation**: After the extension operation, do specific entries from the original function retain their original values, or are they overwritten?

2. **Precedence Rules**: When the original function and the extension have overlapping keys, which mapping "wins"? The property should check whether entries at particular positions (like positions 2 and 3) maintain their original identity-mapped values after the merge.

## Goal

The purpose of this specification is to formally verify the semantics of function extension/merge operations—specifically to confirm whether the left-hand side (original function) or right-hand side (new mappings) takes precedence when their domains intersect.
