# Specification Request: Higher-Order Operator Passing for Prefix and Postfix Operators

## System Overview

I need a formal specification that serves as a **test suite for a TLA+ tool's ability to handle prefix and postfix operators when passed as arguments to higher-order operators**. This is essentially a language feature verification specification rather than a system model.

## Goal

Verify that a TLA+ implementation correctly supports passing both built-in and user-defined prefix/postfix operators as first-class arguments to other operators, and that these passed operators behave identically to their direct invocation.

## Requirements

### Operator Categories to Test

The specification must verify correct handling of:

1. **Built-in prefix operators**: negation, temporal operators (always, eventually), set operations (powerset, distributed union), function domain extraction, and action enablement/unchanged predicates

2. **Built-in postfix operators**: the prime operator for referring to next-state values

3. **User-defined prefix and postfix operators**: custom operators using the various postfix syntactic forms available in TLA+

### Correctness Properties

1. **Static equivalence**: When a prefix or postfix operator is passed to a higher-order operator and applied to an argument, the result must equal direct application of that same operator to the same argument. This should be verifiable at specification initialization time.

2. **Temporal correctness**: When operators related to state transitions (enablement checking, unchanged predicates, primed expressions) are passed as arguments, they must correctly evaluate in the context of the system's behaviors.

3. **Invariant preservation**: Any state predicate constructed using passed action operators must hold in every reachable state.

4. **Action property preservation**: Properties about transitions constructed using passed operators must hold across all steps of the specification.

### Test Structure

The specification should include:
- A minimal state machine with simple set-valued variables to provide context for temporal operator testing
- Compile-time assertions that verify operator passing works for non-temporal operators
- Runtime invariants and temporal properties that verify action-related operators work correctly when passed as arguments
