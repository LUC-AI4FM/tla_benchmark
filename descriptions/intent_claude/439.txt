# Specification Request: TLA+ Operator Alias Definition Testing

## System Overview

I need a specification that serves as a test harness for verifying that TLA+ tooling (particularly the TLC model checker) correctly handles user-defined operators that use symbolic aliases—that is, operators defined with one notation but invoked using an equivalent alternative syntax.

## Goal

The purpose is to confirm that when a user defines custom binary operators using certain symbolic names, the tools correctly recognize and evaluate those operators when they are referenced via their standard alternative notations (aliases). This is essentially a language feature compatibility test.

## Requirements

1. **Define custom binary operators** using various symbolic operator names that have known alternative representations in TLA+ syntax (such as circle-based operators, comparison operators, and other standard mathematical symbols).

2. **Each custom operator should have trivial semantics** (e.g., simply return one of its arguments unchanged) so that the focus remains on whether the operator resolution works correctly, not on complex logic.

3. **Exercise each operator through its alias notation** to verify that the parser and model checker correctly resolve the alias to the user-defined operator.

4. **Cover a range of operator symbols** including:
   - Circle-based arithmetic symbols (circled plus, minus, dot, slash, times)
   - Sequence concatenation
   - Modulo operation
   - Comparison operators (less-than-or-equal, greater-than-or-equal)

## Correctness Properties

- The specification should expose any bugs where the tooling fails to recognize an alias and either reports an error or incorrectly uses a built-in interpretation instead of the user-defined operator.
- When an operator is defined to return its left operand, invoking it via any valid alias should produce that same left operand—not a boolean or other unexpected value.
- The parser should accept all valid alias syntaxes without errors.
