# Specification Request: Lamport's Mutual Exclusion Algorithm

## System Overview

I need a formal specification of Lamport's distributed mutual exclusion algorithm for a system of concurrent processes that communicate via message passing. This is the classic algorithm where processes coordinate to access a shared critical section without any centralized coordinator.

## System Description

The system consists of multiple distributed processes (for model checking purposes, we can fix this at 3 processes). Each process maintains a logical clock and can request access to a critical section. Processes communicate by sending messages to each other through network channels. Messages may include requests to enter the critical section, acknowledgments of those requests, and release notifications.

Each process must be able to:
- Request entry to the critical section
- Receive and process requests from other processes
- Send acknowledgments when appropriate
- Enter the critical section when conditions are met
- Release the critical section and notify other processes

## Key Requirements

1. **Logical Clocks**: Each process maintains a Lamport logical clock that advances according to Lamport's clock rules (incrementing on local events and updating based on received message timestamps).

2. **Message-Based Communication**: Processes communicate through point-to-point message channels. The network should model asynchronous communication where messages may be delayed but are eventually delivered in FIFO order between any pair of processes.

3. **Request Queue Logic**: Each process must track outstanding requests from all processes, using timestamps to establish a total ordering of requests.

4. **Acknowledgment Tracking**: Processes must track which other processes have acknowledged their requests.

## Correctness Properties

The specification must guarantee:

1. **Mutual Exclusion (Safety)**: At most one process may be in the critical section at any time.

2. **Liveness**: If a process requests the critical section, it will eventually enter (assuming fair scheduling and bounded clock values for model checking).

3. **Proper Ordering**: Entry to the critical section respects the logical timestamp ordering of requests.

## Model Checking Constraints

For finite-state model checking, assume an upper bound on clock values (e.g., 10) to keep the state space manageable while still exploring meaningful behaviors.
