# Specification Request: Reliable Communication Channel

## System Overview

I need a formal specification for a simple communication channel that allows messages to be sent from a sender to a receiver. The channel should model the basic mechanics of asynchronous message passing between two parties.

## Functional Requirements

The system should model:

1. **Message Sending**: A sender should be able to place a message into the channel when the channel is ready to accept it.

2. **Message Receiving**: A receiver should be able to retrieve a message from the channel when one is available.

3. **Channel State**: The channel should track whether it currently holds a message waiting to be received or is empty and ready for a new message.

## Correctness Properties

The specification must guarantee the following:

1. **Type Safety**: The channel state must always be well-formed—it should only ever be in valid, expected configurations (e.g., the channel status should only indicate "ready" or "message pending" states, and any stored message should be from the allowed set of values).

2. **Basic Protocol Integrity**: The operations should respect the channel's state—sending should only occur when appropriate, and receiving should only occur when a message is actually present.

## Goals

- Create a clean, minimal model of point-to-point communication
- The specification should be amenable to formal proof, particularly proving that type correctness is maintained as an invariant throughout all system behaviors
- The model should serve as a foundation that could be extended for more complex communication protocols
