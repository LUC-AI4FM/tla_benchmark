# Specification Request: Type System Validation for Polymorphic Functions

## System Overview

I need a formal specification that models a scenario in type checking where a function's declared type signature is overly general compared to what the function actually computes.

## Problem Description

Consider a type-checked programming environment where library authors declare type annotations for their functions. The system should detect cases where a programmer has specified a type that is more general than what the implementation actually supports.

Specifically, I want to model the case of an identity function—a function that simply returns its input unchanged. The key issue is when someone declares this function with a type signature claiming it can take any input type and return *any other* output type (two independent type variables), when in reality the output type must be the same as the input type.

## Requirements

The specification should capture:

1. **The mismatch scenario**: A function implementation that preserves its input (identity behavior) paired with a type declaration that incorrectly claims input and output types are independent.

2. **Type checker behavior**: The type checking system should recognize and flag this as an error, since the declared type promises more flexibility than the implementation delivers.

## Correctness Properties

The key property to verify is that the type checker correctly rejects overly general type annotations. When a function's declared type is strictly more general than what its implementation can satisfy, this should be detected as a type error rather than silently accepted.
