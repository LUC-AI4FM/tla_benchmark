# Specification Request: Graph Reachability Algorithm

## System to Model

I need a formal specification of an algorithm that computes all nodes reachable from a given starting node in a directed graph. The algorithm is a variant of breadth-first search, attributed to Jayadev Misra, that differs from the standard approach in how it manages the frontier of nodes to explore.

## Problem Description

Given a directed graph (defined by a set of nodes and a successor function that maps each node to its outgoing neighbors) and a designated root node, the algorithm must compute the complete set of nodes that can be reached by following directed edges starting from the root.

## Algorithm Behavior

The algorithm maintains two collections: one for nodes that have been fully processed, and one for nodes pending exploration. Initially, only the root is pending, and no nodes have been processed.

The key distinction from the standard algorithm is that these two collections are **not required to be disjoint**. The algorithm repeatedly selects a node from the pending set and:
- If the node hasn't been processed yet, it marks it as processed and adds all its successors to the pending set (even if some are already pending or processed)
- If the node has already been processed, it simply removes it from the pending set

This continues until no nodes remain pending.

## Correctness Properties

The specification must establish:

1. **Partial Correctness**: When the algorithm terminates, the set of processed nodes exactly equals the set of all nodes reachable from the root.

2. **Termination**: If the set of reachable nodes is finite, the algorithm must eventually terminate.

3. **Type Safety**: The collections must always contain valid graph nodes, and the algorithm state must remain well-formed throughout execution.

## Fairness Requirements

The algorithm requires weak fairness to guarantee termination—the system must eventually take a step if one is continuously enabled.

## Additional Context

This algorithm variant is notable because it is more amenable to parallel implementation than the standard approach, since it relaxes the invariant that the two node collections must be disjoint. A companion specification demonstrating the parallel implementation would be valuable.
