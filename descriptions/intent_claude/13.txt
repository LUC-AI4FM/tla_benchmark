Specify a rolling deployment system for a cluster of three servers behind a load balancer. The deployment coordinator upgrades servers in two phases to avoid downtime: first it removes one server from the load balancer and updates it, then once the remaining servers are updated it switches the load balancer to the newly updated servers and completes the update on the original server. Each server, when signaled, transitions through an intermediate "updating" state before finishing with the new version. The system must guarantee two correctness properties throughout the deployment: zero downtime, meaning the load balancer always contains at least one server that is not currently mid-update, and same version, meaning all servers currently behind the load balancer are always running the same version of the software as each other. The specification should also guarantee termination, meaning the deployment process always eventually completes with all servers updated.
