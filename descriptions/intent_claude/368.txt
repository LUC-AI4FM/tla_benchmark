# Specification Request: TLA+ Operator Syntax Verification

## Goal

Create a test specification that verifies the TLA+ language parser correctly handles user-defined operators when they are invoked using prefix notation (functional application syntax) rather than their standard infix or postfix notation.

## System Description

This is a language feature test for TLA+, not a system or algorithm specification. The purpose is to confirm that when a user redefines any of TLA+'s overloadable operators, those operators can be called using prefix syntax with parenthesized arguments (e.g., writing `+(a, b)` instead of `a + b`).

## Requirements

1. **Binary operator prefix invocation**: All user-definable binary (infix) operators should be callable in prefix form with two arguments. This includes:
   - Arithmetic-style operators (plus, times, division, exponentiation, etc.)
   - Comparison operators (less than, greater than, etc.)
   - Range operators (dot-dot, dot-dot-dot)
   - Logical connective symbols (ampersand, pipe, double versions)
   - Special symbols (dollar, percent, hash variants)
   - Assignment-like symbols
   - Set and lattice operators (union-plus, square cap/cup, etc.)
   - Order relations (precedes, succeeds, and their variants)
   - Similarity and equivalence relations (sim, simeq, congruence, etc.)
   - Subset/superset relations and their square variants

2. **Unary operator prefix invocation**: Postfix operators (like closure and transitive closure superscripts) and prefix operators (like unary minus) should also be callable in prefix notation with one argument.

3. **Operator synonyms**: Where multiple syntactic forms exist for the same operator (e.g., `\leq`, `<=`, and `=<` for less-than-or-equal), all forms should resolve to the same user-defined operator when invoked in prefix notation.

4. **Built-in operators**: Certain built-in operators that cannot be overloaded (like set membership and set union) should still be callable using prefix notation with their standard semantics.

## Known Limitations

- The binary minus operator (`-`) does not support prefix invocation syntax due to ambiguity with unary negation.

## Correctness Properties

- Each operator invoked in prefix form must produce exactly the same result as invoking it in its standard infix or postfix form.
- Synonym operators must be interchangeable when used in prefix notation.
- The parser must accept this syntax without errors for all supported operators.
