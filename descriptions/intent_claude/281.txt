# Specification Request

## System Description

I need a formal specification for a trivial static system that serves as a test case for tooling behavior, specifically around how unchanged state is expressed and processed.

## Requirements

The system should model a simple state space with two integer variables that remain completely static after initialization:

1. **Initial State**: The system starts with two integer variables set to specific constant values (e.g., 1 and 2).

2. **Behavior**: The system never changes state. Both variables must remain at their initial values forever—there are no meaningful transitions.

## Key Properties

The specification must express the "no change" constraint in a particular way:

- The unchanged state should be expressed using tuple notation for the variables, both individually and grouped together
- This is specifically to verify that type checking tools correctly interpret tuple syntax in this context as describing tuples (rather than potentially misinterpreting the notation)

## Purpose

This is a regression test specification to ensure that formal verification tooling (particularly type checkers) handles a specific syntactic pattern correctly. The actual system behavior is trivial by design—the important aspect is how the "unchanged" constraints are syntactically expressed and subsequently processed by analysis tools.
