Please write a formal specification for a **distributed checkpoint coordination system** in a replicated log-based architecture.

## System Overview

The system coordinates checkpointing operations across multiple nodes that maintain a replicated log. There is a leader node responsible for coordination, and the system uses a lease-based mechanism to manage checkpoint ownership or permissions.

## Key Requirements

1. **Replicated Log Management**: The system should track log indices and manage which indices are "open" (available for checkpointing or processing).

2. **Lease-Based Coordination**: Implement a lease mechanism where nodes can hold leases for checkpoint operations. The specification should define when a lease should be replaced or renewed.

3. **Leader-Based Architecture**: The system has a designated leader node that plays a special role in coordination decisions.

## Correctness Properties

1. **Progress**: There should always be at least some open indices available in the log (the system should not reach a state where all indices are closed/exhausted).

2. **Safe Lease Replacement**: Define correct conditions under which an existing lease should be replaced. Specifically, verify that optimizations to the lease replacement logic are safe—for example, simply allowing lease replacement when the current lease holder is the leader may be an *incorrect* optimization that violates safety properties.

## Model Checking Requirements

- The specification should be parameterized to allow bounded model checking with finite sets for natural numbers and log indices.
- Support symmetry reduction for nodes to improve model checking efficiency.
- Include state constraints to focus verification on meaningful system states.

The goal is to verify that the checkpoint coordination protocol maintains consistency and that any proposed optimizations to lease handling are actually correct.
