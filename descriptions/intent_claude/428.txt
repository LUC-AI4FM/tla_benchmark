# Specification Request: Custom Operator Definition Test

## System Overview

I need a formal specification that serves as a test harness to verify that a specification language correctly supports the definition of custom infix operators using symbolic aliases (special mathematical notation symbols).

## Goal

The primary goal is to confirm that users can define their own meanings for various built-in operator symbols—overriding or redefining standard mathematical and logical operators with custom semantics—and that these custom definitions are properly recognized and executed by the specification checker.

## Requirements

### Operator Definability

The specification must demonstrate that the following categories of symbolic operators can be user-defined:

1. **Arithmetic-style operators**: Addition-like, subtraction-like, multiplication-like, and division-like symbols
2. **Set/product operators**: Cartesian product notation
3. **Sequence operators**: Concatenation notation
4. **Modular arithmetic operators**: Remainder/modulo notation
5. **Comparison operators**: Less-than-or-equal and greater-than-or-equal relations

### Behavior

- Each custom operator should be defined with trivial semantics (such as always returning the left operand) to isolate the test to syntactic acceptance rather than mathematical correctness
- The system should exercise each operator definition to ensure it is actually invoked during execution

### Correctness Properties

The specification should be considered correct if:

1. The specification parses without syntax errors when custom operators are defined
2. Each custom operator can be invoked in expressions
3. The specification checker (like TLC) can evaluate all defined operators during state exploration

This is essentially a **language feature test** rather than a model of a real-world system—it validates tooling support for operator aliasing and custom operator definitions.
