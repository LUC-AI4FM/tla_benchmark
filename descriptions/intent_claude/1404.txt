# Specification Request: Module Instantiation with Primed Expressions

## System Overview

I need a formal specification that demonstrates how module instantiation interacts with temporal operators, specifically the prime (next-state) operator and the ENABLED operator.

## Requirements

The specification should model a minimal system with:

1. **A simple state variable** that remains constant (a stuttering system)
2. **A separate inner module** that defines an expression referencing its own local variable
3. **Module instantiation** where the inner module's variable is substituted with the outer module's variable

## Key Behavior

- The system should initialize to a known starting state
- The system should allow stuttering (no state changes)

## Correctness Properties

The specification must verify that:

- When accessing an expression from an instantiated module and applying the prime operator to it, the ENABLED operator correctly evaluates whether there exists a valid next state
- Specifically, the combination of module instantiation (with variable substitution), the prime operator applied to the instantiated expression, and the ENABLED operator should all compose correctly together

## Purpose

This specification is designed to test a specific corner case in TLA+ tooling: ensuring that when the prime operator is applied to an expression accessed through an INSTANCE declaration (where variable substitution has occurred), the system correctly handles the variable resolution in the context of checking enabledness conditions.
