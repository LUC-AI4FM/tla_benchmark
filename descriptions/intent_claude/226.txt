# Specification Request: Simple State Transition System for Symbolic Analysis Testing

## System Overview

I need a formal specification of a minimal state machine that can be used to test symbolic transition slicing capabilities in a model checker or verification tool.

## System Description

The system should model a simple state machine with the following behavior:

- The system starts in an initial state
- From any state, the system can transition to one of two possible target states (call them state A and state B)
- One of the transitions (to state B) should involve non-deterministic choice over a set of values and include local definitions, even if these don't affect the outcome—this is intentional to test how the tool handles such constructs during symbolic analysis

## Requirements

1. **Initial Condition**: The system must begin in a designated initial state
2. **Transitions**: The system must support at least two distinct transition paths leading to different states
3. **Complexity for Testing**: At least one transition should include:
   - Existential quantification over a finite set
   - Local constant definitions (LET expressions)
   - These constructs should be present even if they don't influence the final state assignment

## Correctness Property

The specification should include an invariant that is **intentionally violable**—specifically, an invariant asserting the system never reaches state B. Since state B is reachable via one of the defined transitions, this invariant should fail, making it useful for testing whether verification tools correctly detect the violation when processing symbolically sliced transitions.

## Purpose

This specification serves as a test case for verifying that symbolic transition slicing correctly handles:
- Disjunctive transitions
- Existential quantification within transitions
- Local definitions that may or may not be relevant to the state change
