# Specification Request: Enabled Action Set Membership with Module Instantiation

## System Overview

I need a formal specification that explores the behavior of TLA+'s `ENABLED` operator when combined with module instantiation and set membership tests on primed variables.

## Goal

The specification should model a trivial static system (a single variable that never changes) but use it as a vehicle to verify specific semantic properties about how temporal operators interact with expressions involving:

1. Module instantiation with variable substitution
2. Primed variable expressions imported from an inner module
3. Set membership tests applied to such expressions within an `ENABLED` context

## Requirements

### System Behavior
- The system should have a single state variable initialized to a fixed value
- The system should be completely quiescent (no state changes occur)

### Verification Goal
- The specification must check whether it is *enabled* for an imported primed-variable expression to take on values within a specific finite set (such as {0, 1, 2})
- This tests the semantic question: when we ask "is it possible for the next-state value to be in this set?", how does TLA+ evaluate this across module boundaries?

### Key Correctness Property
- The invariant should assert that the `ENABLED` predicate (checking set membership of the primed expression) holds in all reachable states
- This effectively tests whether the model checker correctly handles the combination of `ENABLED`, set membership, primed variables, and module instantiation

## Purpose

This specification serves as a test case or verification of TLA+ tooling behavior for a specific combination of language features, particularly around the semantics of enabledness conditions involving instantiated modules and primed expressions.
