# Specification Request: TLA+ Configuration File Grammar

## System to Model

I need a formal grammar specification for the configuration file format used by the TLA+ model checker (TLC). This configuration file tells the model checker which specification, initial state predicate, next-state relation, invariants, properties, and constant assignments to use when checking a TLA+ specification.

## What the Grammar Must Define

The grammar should define the complete syntax for configuration files that consist of a sequence of statements. Each statement begins with a keyword and is followed by appropriate content:

1. **Singular directives**: Keywords like SPECIFICATION, INIT, NEXT, VIEW, and SYMMETRY that take exactly one identifier as their argument.

2. **Plural directives**: Keywords like INVARIANT(S), PROPERTY(PROPERTIES), CONSTRAINT(S), and ACTION-CONSTRAINT(S) that can take zero or more identifiers.

3. **Constant definitions**: The CONSTANT or CONSTANTS keyword followed by zero or more constant bindings, where each binding is either:
   - A **replacement**: mapping one identifier to another (for substituting a model value or operator)
   - An **assignment**: setting an identifier equal to a value

4. **Values**: The grammar must support values that can be:
   - Identifiers (names)
   - Integers (optionally negative)
   - Quoted strings (supporting a broad range of characters)
   - Set literals using curly braces with comma-separated values (including nested sets and empty sets)

## Lexical Requirements

- Identifiers must contain at least one letter and consist only of letters, digits, and underscores
- Reserved keywords cannot be used as identifiers where a non-keyword identifier is expected
- Letters include both uppercase and lowercase plus underscore
- Strings can contain alphanumeric characters plus common punctuation and special characters

## Key Properties the Grammar Must Guarantee

- Every valid configuration file parses as one or more statements
- The grammar is unambiguous in distinguishing between replacements (using `<-`) and assignments (using `=`)
- Keywords are properly reserved and distinguished from user identifiers
- The grammar correctly handles the recursive structure of set values containing other values
