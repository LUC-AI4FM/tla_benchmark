# Specification Request: Distributed Consensus with Process Failure

## System Overview

I need a formal specification for a distributed consensus protocol involving a fixed number of processes. The system should model how multiple processes can agree on a single value from a set of proposed inputs, even in the presence of process failures and restarts.

## System Description

The system consists of N processes, where each process:
- Proposes an input value from a predefined set of possible inputs
- Eventually produces an output representing the agreed-upon decision
- May fail and restart with a potentially different input value

## Required Behaviors

1. **Input Proposal**: Each process begins with some input value it wishes to propose to the group.

2. **Decision Making**: Processes should be able to decide on an output value. A process that has not yet decided may do so at any time.

3. **Failure and Recovery**: Processes may fail at any point. When a process fails, it loses its current decision (if any) and may restart with a new input value to propose.

## Correctness Properties

The specification must guarantee the following consensus properties:

1. **Agreement**: All processes that have decided must have decided on the same value. There cannot be two processes with different non-null output values.

2. **Validity**: Any decided value must have been proposed by some process at some point (either initially or after a restart).

3. **Non-Triviality**: The protocol should allow decisions to actually be made (not simply prevent all progress).

## Additional Constraints

- The number of processes N is fixed and positive
- The set of possible input values is given
- A process's output should be distinguishable between "undecided" and "decided with value v"
- Once a value has been chosen by the system as a whole, all future decisions must agree with that choice, regardless of subsequent failures or new proposals
