Please formally specify a **debugging and visualization layer for a Raft consensus protocol model checker**.

## System Overview

I need a specification that provides enhanced observability and debugging capabilities when model-checking a Raft-based consensus protocol implementation. This layer should augment an existing Raft specification with rich diagnostic output without changing the underlying protocol behavior.

## Requirements

### Visualization Features

1. **Log visualization**: Provide a compact, human-readable representation of each server's log, where different entry types (reconfigurations, signatures, regular entries) are distinguished with abbreviated symbols, and entries from different terms are visually distinguishable using color coding.

2. **Server state display**: Show each server's current state (leader, follower, candidate, etc.) using distinct visual symbols, with color coding to identify individual servers.

3. **Active cluster view**: Display which servers are currently participating in the cluster as leaders or followers.

### Diagnostic Aggregations

The system should track and accumulate the following metrics across the entire model-checking run:

1. **Leader election count**: Total number of times any server has become leader.

2. **Vote tracking**: For each server, maintain the cumulative set of all nodes that have ever granted votes to it, and the set of all nodes it has ever voted for.

3. **Message delivery statistics**: Track the total count of messages delivered to each server.

4. **State transition history**: Record the sequence of leadership state transitions for each server, including the trace depth at which each transition occurred.

5. **Activity timeline**: Build a visual timeline showing which server was active at each step of execution.

6. **Blocked servers**: Identify which servers are currently unable to take actions.

### Display Modes

Support multiple display configurations:

1. **Full state view**: Show all protocol variables plus aggregated diagnostics.

2. **Acting server view**: Show only the state of the server that is taking action in the current step, providing a focused view for debugging specific server behavior.

3. **Animated view**: Support an animation mode that overwrites previous output to show log and state evolution in real-time during simulation.

### Technical Requirements

- Color coding must use terminal escape sequences for compatibility with command-line model checker output.
- Each server should have a unique foreground and background color assignment.
- Each leadership state should have a unique symbol.
- The visualization should handle an arbitrary number of servers through injective mappings.

## Correctness Properties

This is a diagnostic layer, so correctness means:
- The underlying Raft protocol variables must be faithfully exposed without modification.
- Aggregate counters must accurately reflect cumulative protocol events.
- Visualizations must be consistent with the actual protocol state.
