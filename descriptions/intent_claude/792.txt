Please write a formal specification for a **key-value store with snapshot isolation**.

## System Description

The system should model a transactional key-value store where multiple transactions can execute concurrently. The store supports read and write operations on keys, and transactions should operate under **snapshot isolation** semantics.

## Key Requirements

1. **Transactional Operations**: Multiple transactions should be able to run concurrently, each performing reads and writes to keys in the store.

2. **Snapshot Isolation**: Each transaction should see a consistent snapshot of the database as it existed at some point in time. Transactions should not see partial effects of other concurrent transactions.

3. **Key-Value Storage**: The store maps keys to values, where keys can either hold a value or be empty/unset.

## Correctness Properties

The specification should support verification of properties related to:

- Consistency of the stored data across different keys
- Proper isolation between concurrent transactions
- Correct visibility of committed changes

## Model Checking Considerations

The specification should be amenable to model checking with:
- A finite set of transaction identifiers that can be treated as interchangeable (symmetric) for state space reduction
- Support for exploring scenarios where different keys hold different values
