# Specification Request: Multiset (Bag) Operations Test Suite

## System Overview

I need a formal specification that serves as a comprehensive test suite for a multiset (bag) data structure library. The specification should verify the correctness of standard bag operations by checking their behavior against expected results for various test cases.

## What Should Be Modeled

The specification should test a library providing multiset functionality, where a multiset (or "bag") is a collection that allows duplicate elements, with each element having an associated count representing how many times it appears.

## Required Operations to Test

The test suite must verify the following bag operations:

1. **Validity checking** - Determining whether a given structure is a valid bag (counts must be positive)
2. **Conversion operations** - Converting between bags and regular sets in both directions
3. **Membership testing** - Checking if an element exists in a bag
4. **Empty bag** - Representing and working with bags containing no elements
5. **Bag addition** - Combining two bags by summing element counts (should be commutative)
6. **Bag subtraction** - Removing elements of one bag from another (counts cannot go negative)
7. **Bag union over a set of bags** - Combining multiple bags into one
8. **Subbag relationship** - Determining if one bag is contained within another (all counts less than or equal)
9. **Mapping over bags** - Applying a function to transform bag elements, properly handling cases where the function is injective versus non-injective
10. **Cardinality** - Computing the total count of all elements in a bag
11. **Copy counting** - Determining how many copies of a specific element exist in a bag

## Key Correctness Properties

The specification must verify:

- Addition of bags is commutative
- Subtracting a larger bag from a smaller one yields an empty result (no negative counts)
- Converting a set to a bag gives each element a count of exactly one
- Cardinality is additive under bag addition
- An empty bag contains no elements (copy count is zero for any element)
- Mapping with an injective function preserves individual counts; mapping with a non-injective function sums the counts of colliding elements
- A structure with negative counts is not a valid bag

## Test Data Requirements

The tests should exercise the operations with:
- Integer elements
- String elements
- Single-element bags with various counts
- Multi-element bags
- Empty bags
- Edge cases like subtracting disjoint bags
