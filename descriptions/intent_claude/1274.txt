# Specification Request: Expensive Initialization Caching Behavior

## System to Model

I need a formal specification that demonstrates how a model checker handles computationally expensive constant expressions during state initialization, specifically to verify that such expressions are evaluated only once rather than repeatedly.

## Goal

The specification should model a system where:

1. An initial state is chosen from a large range of possible values (on the order of 10,000 possibilities)
2. Each potential initial state involves computing an expensive operation (such as selecting an arbitrary element from a large power set)
3. After initialization, the system remains unchanged (a trivial "stuttering" system)

## Key Requirements

- The expensive computation should be defined as a constant expression that the model checker can recognize and cache
- The initialization should existentially quantify over a large numeric range
- The system behavior after initialization should be trivial (no state changes)

## Correctness Properties / Verification Goals

The primary purpose is **not** to verify a property of the modeled system, but rather to demonstrate and test that:

1. The model checker correctly caches and reuses the result of expensive constant expressions
2. The specification completes verification in reasonable time (seconds, not hours)
3. If the expensive operation were incorrectly treated as state-dependent (e.g., by adding an unused parameter), verification would time out due to repeated re-evaluation

## Context

This specification serves as a performance test case for model checker optimization. The contrast should be clear between a properly cached constant expression versus one that would be unnecessarily recomputed thousands of times during state space exploration.
