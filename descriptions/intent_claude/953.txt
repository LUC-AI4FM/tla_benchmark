# Specification Request: Multiset (Bag) Data Structure Library

## System to Model

I need a formal specification for a **multiset** (also known as a "bag") data structure and its associated operations. Unlike ordinary sets where each element either belongs or doesn't belong, a multiset allows elements to appear multiple times, tracking the count of each element.

## Core Requirements

### Data Structure Definition
- Define what constitutes a valid multiset: a collection where each element has an associated positive integer count representing how many copies of that element exist
- Provide a way to represent an empty multiset

### Fundamental Operations

The specification must support the following operations:

1. **Membership and counting**: Determine whether an element exists in a multiset, and retrieve the number of copies of any element

2. **Conversion operations**: Convert between ordinary sets and multisets (a set becomes a multiset where each element appears exactly once; a multiset's underlying set contains each element regardless of multiplicity)

3. **Multiset union**: Combine two multisets by adding the counts of each element from both

4. **Multiset difference**: Subtract one multiset from another, reducing counts appropriately and removing elements whose count would become zero or negative

5. **Generalized union**: Combine an arbitrary collection of multisets into one

6. **Sub-multiset relationship**: Determine when one multiset is "contained in" another (every element in the first appears in the second with equal or lesser count)

7. **Sub-multiset enumeration**: Generate all possible multisets that are contained within a given multiset

8. **Mapping operation**: Apply a function to transform all elements of a multiset, properly accumulating counts when multiple elements map to the same result

9. **Cardinality**: Compute the total number of elements in a multiset, counting multiplicities

## Key Correctness Properties

- Multisets must only contain elements with strictly positive counts (zero or negative counts mean the element is absent)
- Union should be commutative and associative
- The difference operation should never produce negative counts
- The sub-multiset relation should be reflexive and transitive
- Cardinality should equal the sum of all element counts
