Specification Request: TLC Model Checker Utility Library

**System Overview:**
I need a utility library that provides helper operators for use with the TLC model checker for TLA+ specifications. This library should offer debugging, instrumentation, and convenience functions that assist specification authors during model checking.

**Required Capabilities:**

1. **Debugging and Output:**
   - A mechanism to print values during TLC evaluation for debugging purposes, without affecting the logical result of expressions
   - An assertion facility that validates conditions and halts with an error message when conditions are false

2. **Runtime Instrumentation:**
   - A way to access the current system time during evaluation
   - A key-value storage mechanism that persists across expression evaluations, allowing specifications to track counters, store intermediate values, or monitor progress during long computations
   - Access to TLC's internal statistics such as: number of distinct states found, states remaining in the queue, elapsed time, maximum behavior length, and current behavior depth

3. **Function Construction Utilities:**
   - A convenient way to construct a single-element function (mapping one domain value to one range value)
   - A function merge operator that combines two functions, with the first function taking precedence on overlapping domains
   - Generation of all permutations of a set (bijections from a set to itself)

4. **Sequence Operations:**
   - A sorting operator for sequences that accepts a custom comparison relation

5. **Randomization Support:**
   - A way to randomly select an element from a set, useful for statistical sampling in simulation mode

6. **Type Flexibility:**
   - A special universal type marker where membership tests always succeed, supporting flexible recursive function definitions

7. **String Conversion:**
   - Conversion of arbitrary values to their string representation

8. **Evaluation Control:**
   - A mechanism to force eager evaluation of expressions, overriding TLC's default lazy evaluation strategy when needed for performance optimization

**Key Properties:**
- Debugging operators must not alter the semantic meaning of specifications (they should be side-effect-free from a logical perspective)
- The instrumentation storage must handle multi-threaded TLC execution appropriately, with initialization happening before worker threads start
- Random selection must be reproducible during breadth-first search to enable error trace generation
