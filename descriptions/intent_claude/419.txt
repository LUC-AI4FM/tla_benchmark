# Specification Request: Integer Arithmetic Operations Test Suite

## Goal

Create a test harness to verify that the TLA+ tooling correctly implements standard integer arithmetic operations, including operations on negative numbers. This is essentially a conformance test for the Integers module in TLA+.

## System Description

The system should be a minimal specification whose sole purpose is to validate the correctness of integer arithmetic operators when the specification is checked. It does not model any dynamic behavior—it simply asserts mathematical properties that must hold.

## Requirements

The test suite must verify the following categories of integer operations:

### Exponentiation
- Powers of 2 combine correctly (e.g., adding equal powers yields the next power)
- Zero raised to any positive power equals zero

### Membership in Integers
- The result of subtracting a larger natural from a smaller one is a member of the integer set (negative numbers are integers)

### Multiplication with Negative Numbers
- Multiplying two negative numbers produces the correct positive result

### Comparison Operators on Negative Numbers
- Greater-than comparisons between negative numbers
- Less-than comparisons between negative numbers
- Less-than-or-equal comparisons (including equality case)
- Greater-than-or-equal comparisons (including equality case)
- Mixed comparisons between negative and positive numbers

### Integer Division and Modulo
- The fundamental division identity holds: `n = d * (n ÷ d) + (n % d)` for various negative dividends
- Division by 1 returns the original number
- Modulo by 1 returns 0
- Modulo of negative numbers by positive divisors follows the expected mathematical convention (result is non-negative)

### Integer Range Operator
- Empty ranges when the lower bound exceeds the upper bound
- Correct set generation for ranges with negative endpoints

### Operator Precedence
- Multiplication binds tighter than addition
- Exponentiation binds tighter than multiplication
- Division binds tighter than addition
- Modulo has appropriate precedence relative to multiplication
- Unary minus interacts correctly with addition

## Correctness Properties

Each arithmetic identity or expected result must hold. If any test fails, the model checker should halt with an assertion failure indicating which test failed. If all tests pass, the checker should report success for each test case.
