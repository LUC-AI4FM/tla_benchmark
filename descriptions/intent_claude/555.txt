# Specification Request: Semaphore-Based Mutual Exclusion

## System to Model

I need a formal specification of a **semaphore-based concurrency control system** that coordinates access to a critical section among multiple concurrent processes.

## System Description

The system consists of a fixed set of processes (for verification purposes, 3 processes numbered 0, 1, and 2) that compete to enter a critical section. A semaphore mechanism should be used to control access, ensuring that processes properly synchronize when entering and exiting the critical section.

Each process should follow a lifecycle where it can:
- Attempt to enter the critical section
- Execute within the critical section
- Exit the critical section and return to its normal state

## Key Correctness Properties

The specification must guarantee the following properties:

1. **Mutual Exclusion**: At most one process may be in the critical section at any given time. No two distinct processes should ever be in the critical section simultaneously.

2. **Deadlock and Livelock Freedom**: If any process is attempting to enter the critical section, then eventually some process (not necessarily the same one) will succeed in entering the critical section. The system must make progress and not get stuck.

3. **Starvation Freedom**: Every process that attempts to enter the critical section must eventually succeed. No process should be indefinitely delayed while others repeatedly access the critical section.

## Goal

The goal is to verify that a semaphore implementation correctly provides safe and fair coordination for concurrent processes accessing a shared resource, ensuring both safety (mutual exclusion) and liveness (progress and fairness) properties hold under all possible interleavings of process execution.
