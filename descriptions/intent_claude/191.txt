# Specification Request: Exponential Type Inference Complexity Demonstration

## System to Model

I need a formal specification that demonstrates the exponential blowup phenomenon in type inference for let-polymorphism, specifically recreating the classic construction used to prove that ML type inference has exponential time complexity.

## Goal

The specification should construct an expression that, while syntactically simple and compact, causes a type inference algorithm to require exponential time and space to determine its type. This is a theoretical demonstration of computational complexity in type systems, not a runtime system.

## Requirements

1. **Nested let-binding structure**: The specification should use a series of nested local definitions, where each level references the previous definition in a way that doubles the type complexity.

2. **Self-application pattern**: Each nested definition should apply the previous definition to itself (or to results of applying it to itself), causing the inferred type to grow exponentially with each nesting level.

3. **Polymorphic base case**: Start with a simple polymorphic operation (like creating a pair from an element paired with itself) that serves as the seed for type doubling.

4. **Configurable depth**: The construction should be easily adjustable in depth, since deeper nesting exponentially increases resource requirements for type inference.

## Key Properties

- **Syntactic simplicity**: The expression should be small and have a fixed syntactic size regardless of how complex the inferred type becomes.
- **Type explosion**: The size of the principal type should double with each additional nesting level, resulting in a type of size 2^n for n levels of nesting.
- **Semantic triviality**: The actual runtime behavior can be trivial (operating on empty domains is acceptable)—the focus is purely on the type inference challenge.

## Context

This specification serves as a stress test or benchmark for type inference implementations, demonstrating that even simple-looking expressions can require exponential resources to type-check under let-polymorphism.
