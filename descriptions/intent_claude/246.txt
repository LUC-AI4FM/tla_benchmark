# Specification Request: Type Alias Backward Compatibility Test

## System Overview

I need a minimal specification that serves as a test case for verifying backward compatibility of deprecated syntax in a type system or specification language processor.

## Goal

Create a simple module that exercises legacy/deprecated type alias syntax to ensure that:

1. The old syntax is still recognized and processed correctly
2. The system generates appropriate deprecation warnings when encountering the old syntax
3. The module remains valid and can be checked without errors

## Requirements

- The specification should define a type alias using an older, deprecated syntax format
- The alias should reference an uninterpreted (opaque) type to test that type handling works correctly with the legacy syntax
- The module should be syntactically valid and pass all checks, even though it uses deprecated features
- The system processing this specification should emit a warning indicating that the old syntax is deprecated and suggesting migration to the newer syntax

## Correctness Properties

- **Backward Compatibility**: Old syntax must still be accepted and function correctly
- **Deprecation Signaling**: Processing the old syntax should trigger a warning (not an error)
- **Semantic Equivalence**: The behavior when using old syntax should be identical to using the new syntax for the same construct

This is essentially a regression test specification to ensure that syntax evolution in the tooling doesn't break existing specifications that haven't yet migrated to newer conventions.
