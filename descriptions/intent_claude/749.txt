# Specification Request: Cigarette Smokers Problem

## System Overview

I need a formal specification of the classic **Cigarette Smokers Problem**, a well-known concurrency puzzle used to illustrate synchronization challenges.

## Problem Description

The system involves a dealer and multiple smokers sitting around a table. To smoke a cigarette, a smoker needs three ingredients (typically: matches, paper, and tobacco). Each smoker has an infinite supply of exactly one ingredient but lacks the other two. The dealer repeatedly places two randomly chosen ingredients on the table. The smoker who has the complementary third ingredient should pick up the two offered ingredients, make a cigarette, and smoke it.

## Functional Requirements

1. **Dealer behavior**: The dealer should offer exactly two of the three ingredients at a time, choosing from all valid two-ingredient combinations.

2. **Smoker behavior**: Each smoker is associated with one specific ingredient they possess. When the dealer offers the two ingredients a smoker lacks, that smoker should be able to take them and smoke.

3. **Mutual exclusion**: Only one smoker should be able to pick up the ingredients and smoke at any given time.

4. **Turn-taking**: After a smoker finishes smoking, the dealer should offer a new combination of ingredients.

## Key Correctness Properties

1. **Safety**: At most one smoker should be smoking at any time.

2. **Type correctness**: The system state should always remain well-formed—smokers should only be in valid states, and the dealer should only offer valid ingredient combinations.

3. **Progress** (optional/liveness): The system should continue operating, with smokers eventually getting chances to smoke when appropriate ingredients are offered.

## Modeling Considerations

The specification should be parameterized by:
- The set of possible ingredients
- The set of valid ingredient combinations the dealer can offer (each combination being all ingredients minus one)
