# Specification Request: Simple Party-to-Party Messaging System

## System Overview

I need a formal specification for a basic distributed messaging system where multiple parties can send messages to each other over a network.

## System Description

The system consists of a fixed set of parties (specifically two parties, A and B) that can communicate by sending messages through directed communication channels. Each party should be able to send a greeting message to any other party in the system.

## Functional Requirements

1. **Network Structure**: The system should model point-to-point communication channels between distinct parties. Each ordered pair of different parties has its own dedicated channel (so the channel from A to B is separate from the channel from B to A).

2. **Message Sending**: Each party should perform exactly one action: choose another party and send a "hello" message to that party through the appropriate channel.

3. **Message Format**: Messages should be typed, with at least a "hello" message type supported.

4. **One-Shot Behavior**: Each party acts exactly once, sending a single message, and then is finished.

## Correctness Properties

1. **Termination**: The system must guarantee that all parties eventually complete their message-sending action. This should be ensured through fairness assumptions—if a party is able to send its message, it will eventually do so.

## Scope and Constraints

- The specification should work with a small, concrete set of parties for model checking purposes.
- Self-messaging is not allowed; parties can only send messages to other parties.
- Channels should be modeled as queues (sequences) to allow for potential extension to multiple messages, even though in this basic version each party sends only one message.
