# Specification Request: Concurrent Counter Increment with Semaphore Protection

## System Overview

I need a formal specification of a concurrent system where multiple processes each increment a shared counter exactly once. The increment operation is non-atomic—it consists of reading the current value and then writing back an incremented value as separate steps. A binary semaphore must be used to protect the critical section and ensure mutual exclusion.

## System Requirements

### Components
- A shared counter, initially zero
- A binary semaphore for synchronization
- N concurrent processes (where N is a positive integer), each attempting to increment the counter once

### Process Behavior
Each process should:
1. Wait to acquire the semaphore (blocking until available)
2. Once acquired, read the current counter value into a local variable
3. Write back the incremented value to the shared counter
4. Release the semaphore
5. Terminate after completing its increment

### Synchronization Mechanism
The binary semaphore should enforce mutual exclusion:
- Only one process may hold the semaphore at a time
- A process must wait if the semaphore is unavailable
- The semaphore is released after the critical section completes

## Correctness Properties

### Required Properties
1. **Termination**: All N processes should eventually complete their execution
2. **Mutual Exclusion**: At most one process should be in the critical section (between acquiring and releasing the semaphore) at any time

### Expected Outcome
When all processes have terminated, the shared counter should equal N, since each of the N processes increments it exactly once and the semaphore prevents race conditions.

## Purpose

This specification should demonstrate that a binary semaphore correctly protects a non-atomic read-modify-write operation from concurrent interference, ensuring the final result is deterministic despite the interleaved execution of multiple processes.
