# Specification Request: Bounded Counter with Bidirectional Movement

## System Description

I need a formal specification for a simple counter system that can both increment and decrement, with the goal of eventually reaching a specified upper bound.

## Behavioral Requirements

The system should model a counter that:

1. **Starts at zero** when initialized
2. **Can increment** its value by one at any time
3. **Can decrement** its value by one, but only when the counter is above zero (no negative values allowed)
4. **Tracks state changes** with a toggle that flips each time the counter is modified (this could represent alternating phases, parity tracking, or simply that an action occurred)

The system should be parameterized by a configurable upper limit that represents the target value.

## Correctness Properties

### Safety Property
The counter should never reach the limit value. (Note: This appears to be intentionally in tension with the liveness property, likely for testing or demonstration purposes of property violations.)

### Liveness Property
The counter must eventually reach the limit value. The specification should ensure progress by requiring that increments cannot be ignored forever when they are enabled—the system must be fair with respect to incrementing.

## Purpose

This specification appears designed to explore the interaction between safety and liveness properties, particularly cases where they may conflict. It could serve as a test case for model checking tools or as an educational example demonstrating how weak fairness ensures progress toward a goal despite the availability of competing actions (like decrement) that could potentially prevent progress indefinitely.
