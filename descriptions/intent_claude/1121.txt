# Specification Request: Tower of Hanoi Puzzle

## System Overview

I need a formal specification of the classic **Tower of Hanoi puzzle** that can model the puzzle with a configurable number of disks and towers (not just the traditional three towers).

## Problem Description

The Tower of Hanoi is a puzzle where:
- There are multiple pegs/towers arranged in a row
- A set of disks of different sizes starts stacked on one tower, ordered by size with the largest at the bottom
- The goal is to move all disks from the starting tower to the final tower

## Rules and Constraints

The specification must enforce these movement rules:
1. Only one disk may be moved at a time
2. Only the topmost (smallest) disk on a tower can be moved
3. A disk may only be placed on an empty tower or on top of a larger disk (never on a smaller disk)

## Initial Configuration

- All disks begin stacked on the first tower in proper order (largest on bottom, smallest on top)
- All other towers start empty

## Parameters

The specification should be parameterized by:
- The number of disks in the puzzle
- The number of towers available

## Correctness Properties

The specification must guarantee:
1. **Conservation of disks**: The total set of disks in the system remains constant throughout execution (disks are neither created nor destroyed)
2. **Type correctness**: Tower states remain valid throughout execution

## Verification Goal

The primary purpose of this specification is to use model checking to **find solutions** to the puzzle. By checking whether "the puzzle is not solved" holds as an invariant, the model checker should produce a counterexample trace that demonstrates a valid sequence of moves to solve the puzzle.

The solution trace should move all disks from the first tower to the last tower. For the classic 3-disk, 3-tower configuration, the optimal solution requires 7 moves (and in general, 2ⁿ-1 moves for n disks with 3 towers).
