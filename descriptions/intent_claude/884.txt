Please write a formal specification for a **sequential register system with per-process operation queues**.

## System Overview

Model a system where multiple processes can perform operations on a set of registers. Each process maintains its own queue of pending operations and has a local view of register states. The system processes operations sequentially (one at a time per process).

## Key Components

- **Processes**: A fixed set of concurrent processes that can issue operations
- **Registers**: A collection of registers that processes can read from or write to
- **Operation Queues**: Each process has a queue of pending operations waiting to be executed
- **Register File**: Each process maintains state information about registers, including tracking whether an operation is currently in progress on each register

## Behavioral Requirements

1. Processes can enqueue operations (such as reads or writes) to their operation queues
2. Operations are processed from the queues and executed against registers
3. Each register, from a process's perspective, tracks whether it is free or has an operation pending
4. The system should handle the lifecycle of operations: from being queued, to being in progress, to completion

## Correctness Properties

The specification must guarantee the following **liveness property**:

- **Every request eventually receives a response**: If any process has an operation in progress on any register (i.e., the register is not in a "free" state), that operation must eventually complete and return the register to the free state.

## Model Checking Constraints

For verification purposes, the specification should support bounding the length of each process's operation queue to enable finite-state model checking.
