# Specification Request: TLC Assumption Error Detection

## System Overview
I need a test harness specification that deliberately triggers different types of assumption violations in the TLA+ model checker (TLC). This is for validating that TLC correctly detects and reports errors in `ASSUME` statements.

## Goal
Create a minimal specification that can be configured to produce different categories of assumption failures, allowing verification that the model checker properly catches and distinguishes between these error types.

## Requirements

### Configurable Test Modes
The specification should support multiple test scenarios, selectable via a configuration parameter:

1. **False Assumption Test**: The specification should include an assumption that evaluates to `FALSE`, which TLC should reject before model checking begins.

2. **Evaluation Error Test**: The specification should include an assumption that causes a type error or evaluation failure (such as comparing incompatible types), which TLC should detect and report as an evaluation problem rather than a simple false result.

## Correctness Properties
This is a meta-testing specification, so the "correctness" being verified is external to the spec itself:
- TLC must halt and report an error when encountering a false assumption
- TLC must halt and report a distinct evaluation error when an assumption cannot be properly evaluated due to type mismatches or similar issues
- The error messages should clearly distinguish between these two failure modes

## Purpose
This specification serves as a test case for TLC's assumption-checking functionality, ensuring the model checker provides appropriate feedback for different categories of specification errors.
