Specify a key-value store that supports four operations: get, insert, update, and delete, over a fixed set of keys and values. Each operation follows a two-phase request/response protocol: a client submits a request, the store processes it, and then returns a result. The store should initially contain no entries. A get on a missing key returns a sentinel "missing" value; get on a present key returns the stored value. Insert succeeds with "ok" only if the key is not already present, and returns "error" otherwise without modifying the store. Update succeeds with "ok" and overwrites the value only if the key already exists, returning "error" otherwise. Delete always returns "ok" and removes the key regardless of whether it was present. The system must satisfy a type-correctness invariant ensuring that the store mapping, current operation, arguments, return value, and processing state all remain within their expected domains at all times. The specification should also ensure fair progress for delete requests.
