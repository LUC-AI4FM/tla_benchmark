# Specification Request: TLC Diagnostic Features Demonstration

## System Overview

I need a formal specification that demonstrates and verifies the behavior of TLC model checker's built-in diagnostic and state-tracking features, specifically the ability to store and retrieve arbitrary values during model checking, as well as access internal model checker statistics.

## System Description

The system should model a simple counting process that increments through a bounded range of integer values. This straightforward behavior serves as a vehicle for exercising TLC's diagnostic capabilities.

## Functional Requirements

1. **Value Storage and Retrieval**: The system should demonstrate storing a custom value at initialization that can be retrieved and displayed during subsequent state transitions.

2. **Progress Tracking**: As the system advances through its states, it should output the stored diagnostic value to confirm the storage mechanism works correctly across the model checking run.

3. **Bounded Execution**: The counting process should be finite, terminating after reaching a defined upper limit.

## Correctness Properties

The specification must verify that TLC's internal statistics tracking accurately counts:

1. **Predicate Satisfaction**: The number of times a specific state predicate (reaching a particular count value) is satisfied during exploration.

2. **Action Occurrences**: The total number of times transition actions are taken during the complete state space exploration.

These counts should match expected values based on the system's deterministic behavior—specifically, a predicate true at exactly one state should show a count of one, and the total number of increment steps should equal the range of values traversed.

## Purpose

This specification serves as a test harness to confirm that TLC's `TLCSet`, `TLCGet`, and statistics gathering features function as documented, ensuring these diagnostic tools can be reliably used in more complex specifications.
