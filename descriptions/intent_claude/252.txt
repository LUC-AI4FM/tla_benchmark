# Specification Request: Higher-Order Operator Testing Framework

## System Overview

I need a formal specification that serves as a regression test suite for verifying that a TLA+ model checker correctly handles **passing built-in operators as arguments to user-defined operators**.

## Goal

The specification should confirm that a TLA+ tool (specifically a model checker) properly supports higher-order operator usage, where standard built-in operators like arithmetic addition, set union, and set membership can be passed as functional arguments to other operators.

## Requirements

### Core Capability to Test

1. **Higher-order operator definition**: The system must support defining operators that accept other operators as parameters, where those parameter operators can then be applied within the body of the definition.

2. **Built-in operator passability**: The following built-in operators must be passable as arguments:
   - Integer addition
   - Set union
   - Set membership testing

### Test Cases Required

The specification must verify:

1. **Arithmetic test**: Passing the integer addition operator and applying it to two integers produces the correct sum.

2. **Set operation test**: Passing the set union operator and applying it to two singleton sets produces their proper union.

3. **Boolean/membership test**: A membership-checking operator correctly identifies that a boolean value belongs to the set of all booleans.

### Correctness Properties

The specification must guarantee that **all test cases pass simultaneously** as an invariant. This serves as a regression test—if any test fails, it indicates the model checker has a bug in handling built-in operators as arguments.

## Context

This is specifically a regression test related to a known issue in operator argument handling. The specification should be minimal and focused purely on exercising this particular language feature rather than modeling any real-world system behavior.
