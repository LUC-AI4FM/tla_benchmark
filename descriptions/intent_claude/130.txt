# Specification Request

## System Overview

I need a formal specification to test how a TLA+ model checker handles **subformula reference syntax** — a feature that allows referring to individual conjuncts or disjuncts within a named formula by their position (e.g., referencing the first or second clause of a multi-part predicate).

## Goal

The specification should serve as a **parser/tooling test case** to verify that a particular TLA+ analysis tool correctly rejects or handles subformula references. The system being modeled is trivial — the real purpose is to exercise the tool's handling of this specific syntactic feature.

## Requirements

1. **Simple State Machine**: Define a minimal state machine with a single integer variable that starts at some initial value and remains unchanged (a stuttering system).

2. **Multi-Clause Predicates**: Define predicates that consist of multiple conjuncts (e.g., a predicate that checks two separate inequality conditions).

3. **Parameterized Predicates**: Include both parameter-free predicates and predicates that take arguments, both containing multiple conjuncts.

4. **Subformula References**: Create invariants that attempt to reference individual conjuncts within these predicates using positional syntax (selecting the first conjunct, the second conjunct, etc.).

## Expected Behavior

The specification should trigger a **parse error** in tools that do not support subformula reference syntax. This serves as a test to confirm that such tools properly detect and report this unsupported feature rather than silently mishandling it.

## Correctness Properties

The invariants themselves, if the syntax were supported, would each represent a single inequality check extracted from a larger predicate. The focus is not on proving these properties hold, but on verifying the tooling behavior when encountering this syntax.
