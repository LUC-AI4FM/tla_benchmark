# Specification Request: TLA+ Counterexample Export Utility

## System Overview

I need a utility that automatically exports TLC model checker counterexamples to standalone TLA+ module files for easier sharing, analysis, and reuse.

## Goal

When TLC finds a counterexample (a trace demonstrating a property violation), I want the system to automatically serialize that counterexample into a properly formatted TLA+ module file that can be loaded and inspected independently.

## Requirements

### Core Functionality

1. **Counterexample Detection**: The system should detect when TLC has produced a counterexample during model checking.

2. **Module Generation**: When a counterexample exists, generate a valid TLA+ module containing:
   - A proper module header derived from the output filename
   - The counterexample data structure as a named definition
   - Proper module closing syntax

3. **File Output**: Write the generated module to a specified file path with appropriate encoding (UTF-8) and file handling (create new or overwrite existing).

4. **User Feedback**: Notify the user when a counterexample file has been successfully written.

### Conditional Behavior

- **Skip when empty**: If no counterexample exists (empty state), do nothing.
- **Console flag**: Respect a configuration flag that can suppress file output even when a counterexample exists.

### Output Format

The generated file should be a syntactically valid TLA+ module that:
- Can be parsed by TLA+ tools
- Contains the counterexample in a reusable form as a defined operator
- Derives its module name from the output filename (without the `.tla` extension)

## Use Case

This supports workflows where engineers need to:
- Archive specific failure traces for documentation
- Share counterexamples with team members who may not have the full model
- Programmatically process or compare counterexamples across different model versions
