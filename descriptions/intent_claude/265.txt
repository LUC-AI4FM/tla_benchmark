# Specification Request: Record Field Access Validation

## System to Model

I need a formal specification that models type-safe record field access in a system with structured records (similar to structs or objects in programming languages).

## Goal

The specification should demonstrate and verify the behavior when accessing fields on record values, specifically focusing on what happens when code attempts to access a field that does not exist on a given record.

## Requirements

1. **Record Definition**: The system should support records with named fields, where each field has an associated value of a specific type.

2. **Field Access Operation**: There should be an operation to access a field by name from a record.

3. **Key Correctness Property**: The specification must capture the expectation that accessing a non-existent field on a record should be detected as an error (ill-typed behavior). If a record is defined with fields "a" and "b", attempting to access field "c" should be flagged as invalid.

## Purpose

This specification serves as a test case or validation check for a type system or type checker. It should demonstrate that the formal modeling framework correctly identifies ill-typed operations—specifically, that accessing undefined fields on records is caught as a type error rather than silently succeeding or producing undefined behavior.
