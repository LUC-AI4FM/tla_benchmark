# Specification Request: TLA+ Positional Subexpression Naming

## System to be Specified

I need a formal specification that tests and validates the **positional subexpression naming mechanism** in TLA+. This is a language feature that allows users to reference specific parts of a complex expression using positional notation (like `!1`, `!2`, `!3` or `!<<` and `!>>`).

## Goal

The specification should verify that the TLA+ tooling correctly implements positional subexpression extraction across all major expression forms in the language. This is essentially a test suite for a TLA+ parser/evaluator feature.

## Requirements

The specification must demonstrate correct positional decomposition for the following expression types:

1. **Conjunction lists** - Extracting individual conjuncts from a series of `/\` expressions by position

2. **Nested data structures** - Accessing elements within sequences and nested sequences

3. **Record constructions** - Both record value literals and record set constructors, extracting field values by position

4. **Conditional expressions** - Extracting the condition, then-branch, and else-branch from IF-THEN-ELSE expressions

5. **Case expressions** - Accessing individual case conditions and their corresponding results, including the OTHER clause

6. **LET expressions** - Extracting locally defined values

7. **Temporal operators** - Decomposing stuttering/non-stuttering action expressions and weak/strong fairness conditions into their component parts

8. **Quantified expressions** - Extracting bound variable domains and the quantified body from existential/universal quantifiers

9. **Function constructors** - Accessing domain sets and function bodies from function definitions

10. **Lambda extraction** - Extracting implicit lambda expressions from quantified formulas for use as higher-order operator arguments

## Correctness Properties

The specification must guarantee that:

- Each positional reference resolves to exactly the expected subexpression
- Nested positional references (chained `!` operators) correctly traverse the expression tree
- Both numeric indexing (`!1`, `!2`) and bracket notation (`!<<`, `!>>`) work consistently
- Parameterized operators correctly substitute arguments before subexpression extraction
- The extraction mechanism works uniformly across all supported syntactic forms
