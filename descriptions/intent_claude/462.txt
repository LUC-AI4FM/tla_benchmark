# Specification Request: Test Suite for Set Operations

## Goal

Create a test harness that validates the correctness of fundamental set operations in TLA+. The purpose is to verify that the model checker correctly evaluates set union, intersection, difference, and subset operations according to standard mathematical set theory semantics.

## System Description

The system should be a minimal static specification whose sole purpose is to execute a battery of tests against set operation expressions. Since the tests are purely mathematical assertions with no dynamic behavior, the system state should remain constant throughout execution—the focus is entirely on validating set-theoretic computations during invariant checking.

## Required Test Coverage

The test suite must verify the following set operations:

1. **Set Union**: Combining two sets produces a set containing all elements from both, with duplicates removed appropriately.

2. **Set Intersection**: Finding common elements between two sets yields only the elements present in both.

3. **Set Difference**: Subtracting one set from another produces elements that exist in the first set but not the second.

4. **Empty Set Behavior**: All operations should handle the empty set correctly as an operand (both as left and right arguments).

## Correctness Properties

Each test case must:
- Produce the mathematically expected result for the given set operation
- Report success with a clear identifying message when the operation behaves correctly
- Halt execution with an assertion failure and descriptive error message if any operation produces an incorrect result

## Requirements

- The specification should use concrete, finite sets of integers for test cases
- Tests should cover edge cases including operations involving the empty set
- The test framework should make it immediately clear which specific test failed if a problem is detected
- All tests should be evaluated as part of checking that the system maintains its invariants
