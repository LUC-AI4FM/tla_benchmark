# Specification Request: Redundant Parenthesis Removal Algorithm

## System Overview

I need a formal specification for an algorithm that removes redundant parentheses from a tokenized expression. The algorithm should process expressions efficiently in a single pass.

## Problem Description

An expression is represented as a sequence of tokens, where each token is either a left parenthesis, a right parenthesis, or some other token (like an operator or operand). Each parenthesis token has an identifier to distinguish it from others.

A pair of matching parentheses is considered **redundant** if it appears immediately inside another pair of matching parentheses. For example, in the pattern `(outer( (inner( ... )inner) )outer)`, the inner parentheses are redundant because they are directly nested within the outer pair with no intervening tokens between the outer left and inner left, or between the inner right and outer right.

## Requirements

### Input
- A well-formed expression (a sequence of tokens where all parentheses are properly balanced)
- The parenthesis depth must never go negative when scanning left to right
- The final parenthesis depth must be zero

### Output
- The same expression with all redundant parenthesis pairs removed
- The algorithm should repeatedly identify and remove such pairs until none remain

### Processing Behavior
- The algorithm should scan the input expression sequentially
- It must track unmatched left parentheses seen so far
- It must detect when consecutive closing parentheses match consecutive opening parentheses (indicating redundancy)
- When redundancy is detected, the redundant pair should be removed from the output

## Correctness Properties

1. **Functional Correctness**: The output must equal the canonical result obtained by exhaustively removing all redundant parenthesis pairs from the input (in any order, since the final result should be the same).

2. **Termination**: The algorithm must terminate for all valid input expressions.

3. **Well-formedness Preservation**: If the input is well-formed, the output must also be well-formed.

## Verification Scope

The specification should be verifiable by exhaustive testing against all well-formed expressions up to a reasonable length (e.g., 9 tokens), comparing the algorithm's output against a reference implementation that uses a naive recursive removal strategy.
