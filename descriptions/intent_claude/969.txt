# Specification Request: Directed State Graph Test Suite for Model Checker Verification

## System Overview

I need a collection of directed state graph definitions that can serve as test cases for verifying model-checker implementations, particularly for reachability analysis and counterexample generation.

## What the System Should Provide

The system should define a library of directed state graphs with varying structural characteristics, along with associated test data for each graph. Each graph definition must include:

1. **Graph Structure**: A finite set of states, a designated subset of initial states, and a transition relation specifying which states are reachable from each state in one step.

2. **Violation States**: A set of "bad" or "violation" states that represent error conditions or states that should be flagged by a model checker.

3. **Expected Counterexamples**: For graphs where violation states are reachable from initial states, provide the expected counterexample paths (sequences of states from an initial state to a violation state).

## Test Case Variety Requirements

The test suite should cover diverse graph structures including:

- **Simple cases**: Small graphs with straightforward paths to violations
- **Unreachable violations**: Graphs where violation states exist but cannot be reached from any initial state
- **Multiple initial states**: Graphs with more than one starting point
- **Disconnected components**: Graphs that form forests with separate unreachable subgraphs
- **Cycles and strongly connected components**: Graphs containing loops
- **Multiple paths to violations**: Graphs where different counterexamples exist
- **Edge cases**: Empty graphs, single-node graphs, graphs with no initial states, graphs with no violations
- **Larger realistic examples**: Medium-sized graphs (e.g., 50+ states) representing actual puzzle or algorithm state spaces

## Correctness Properties

For each test case:

1. If the violation set is non-empty and reachable, the expected counterexamples must be valid paths through the graph from an initial state to a violation state.

2. If the violation set is empty or unreachable from all initial states, the counterexample set should be empty or indicate this appropriately.

3. Counterexample paths should be minimal or representative paths (not necessarily all possible paths).

## Configuration

The system should support runtime selection of which test case to use, allowing external configuration (e.g., via environment variables) to choose among the defined graphs for testing different scenarios.
