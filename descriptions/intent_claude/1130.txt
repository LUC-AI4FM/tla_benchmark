# Specification Request: Bounded Message Queue

## System Overview

I need a formal specification for a simple bounded message queue system that can be used to stress-test a model checker. The system should model a basic producer-consumer queue with configurable capacity and message types.

## Functional Requirements

The system should model a first-in-first-out (FIFO) queue with the following behaviors:

1. **Message sending**: Messages from a defined set can be added to the back of the queue, but only when the queue has not reached its maximum capacity.

2. **Message receiving**: Messages can be removed from the front of the queue, but only when the queue is non-empty.

3. **Bounded capacity**: The queue must have a fixed maximum size that cannot be exceeded.

4. **Message domain**: Only messages from a predefined, finite set of values may be placed in the queue.

## Configuration Parameters

The specification should allow configuring:
- The maximum queue capacity (should support values that generate a large state space, e.g., around 10 million states)
- The set of valid message values

## Correctness Properties

The specification must guarantee:

1. **Message integrity**: At all times, every message in the queue must be a valid message from the allowed message set. No invalid or corrupted messages should ever appear in the queue.

## Purpose

This specification is intended to serve as a benchmark for testing model checking tools under resource-intensive conditions. The combination of queue size and message variety should produce a state space large enough to:
- Consume significant memory
- Generate substantial disk usage
- Stress system resource handling
