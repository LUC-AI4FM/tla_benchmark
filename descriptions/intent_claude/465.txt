# Specification Request: Set Comprehension Semantics Verification

## System to Model

I need a formal specification that serves as a **test harness for verifying the correct behavior of set comprehension constructs** in a TLA+ model checker or evaluator.

## Goal

The purpose is to validate that a TLA+ toolchain correctly implements the two fundamental forms of set construction:

1. **Filtering**: Constructing a set by selecting elements from an existing set that satisfy a predicate
2. **Mapping**: Constructing a set by applying an expression to elements drawn from one or more source sets

## Requirements

The specification should verify correct handling of:

### Basic Filtering Operations
- Filtering elements from a finite set based on a simple comparison predicate
- Proper handling of duplicate elements in the source set (duplicates should be ignored per set semantics)
- Filtering from an empty set (should yield an empty set)

### Filtering with Structured Elements
- Filtering tuples from Cartesian products
- Filtering over infinite domains (like integers) when membership can still be decided

### Mapping Operations
- Mapping an arithmetic expression over multiple bound variables from different sets
- Mapping with variables bound to Cartesian product elements (tuple unpacking)
- Mapping when any source set is empty (should yield an empty set)

### Advanced Constructions
- Set comprehensions involving function spaces
- Nested set constructions using UNION and SUBSET
- Filtering functions based on their behavior at specific arguments

### Set Semantics Validation
- Duplicate elimination in source sets
- Correct cardinality of function spaces
- Equivalence of set expressions that differ only in duplicate source elements

## Correctness Properties

Each test case should assert that:
1. The constructed set equals the expected result, OR
2. A specific element is (or is not) a member of the constructed set, OR
3. The cardinality of the constructed set matches the expected value

If any assertion fails, the system should halt with a clear error indication. If all assertions pass, it should confirm successful validation.
