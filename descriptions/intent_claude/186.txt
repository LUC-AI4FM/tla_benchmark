# Specification Request: Pizza Order Delivery System

## System Overview

I need a formal specification for a distributed pizza ordering system involving multiple clients and a central server. The system should model the complete lifecycle of pizza orders from submission through delivery.

## System Components

- **Clients**: A set of customers who can place pizza orders
- **Server**: A central order processing system that receives and fulfills orders
- **Network**: An unreliable communication medium connecting clients and server

## Required Behaviors

### Order Submission
Clients should be able to submit new orders at any time. Orders are sent as requests over the network to the server.

### Order Processing
The server receives order requests from the network, queues them for processing, and sends acknowledgments back to the originating clients.

### Order Fulfillment
The server processes queued orders in first-in-first-out order, delivering completed orders to the appropriate clients.

## Communication Model

- Messages are transmitted over a network that acts as an unordered pool (modeling potential reordering and persistence of messages)
- Messages are never lost but may be delivered multiple times (the network retains sent messages)
- Both order requests and acknowledgments travel through this network

## Key Correctness Property

**No Duplicate Deliveries**: The system must guarantee that no client ever receives the same order delivered more than once. Each order in a client's delivery history must be unique—if a client has received multiple deliveries, they must all be for distinct orders.

## Modeling Considerations

- The specification should allow any valid order from a predefined set of possible orders
- Multiple clients may place orders concurrently
- The server maintains a queue of pending orders to ensure orderly processing
- Each client has their own delivery history tracking what they have received
