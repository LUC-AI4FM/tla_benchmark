# Specification Request: Leader Election in a Ring Network

## System Description

I need a formal specification of a **leader election algorithm for a unidirectional ring network**, specifically the Chang-Roberts algorithm. The system consists of a fixed number of processes arranged in a ring topology, where each process can only send messages to its successor in the ring.

## What the System Must Do

The algorithm should elect exactly one leader among a set of processes, where:

- Each process has a unique numeric identifier
- Processes are arranged in a ring and can only communicate by passing messages to their immediate successor
- Some subset of processes may initiate the election by sending their identifier around the ring
- When a process receives an identifier larger than its own, it forwards that identifier
- When a process receives its own identifier back (having traveled around the entire ring), it knows it has the highest ID and declares itself the winner

## Key Requirements

1. **Ring topology**: Processes are connected in a circular arrangement with unidirectional message passing
2. **Unique identifiers**: Each process must have a distinct non-negative integer identifier
3. **Message passing**: Messages (containing process identifiers) flow only in one direction around the ring
4. **Distributed initiation**: Any subset of processes may independently decide to start participating in the election

## Correctness Properties

The specification must guarantee:

1. **Safety (Correctness)**: At most one process can ever be elected as the leader/winner
2. **Liveness**: Under fair scheduling assumptions, if processes participate in the election, eventually a leader will be elected
3. **Type correctness**: All data structures maintain their expected types throughout execution (messages are sets of identifiers, process states are well-formed, etc.)

## Testing Considerations

The specification should support verification with bounded model checking, particularly for small ring sizes (e.g., up to 6 processes), to validate that the safety and liveness properties hold across all possible executions and initial configurations.
