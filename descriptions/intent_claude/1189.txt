# Specification Request: TLA+ Record Operations Test Suite

## Goal

Create a test specification that validates the correct behavior of TLA+ record (struct-like) constructs. The purpose is to verify that a TLA+ model checker correctly handles various record operations, including construction, field access, nested records, record updates, and set-of-records operations.

## System Description

This is not a distributed system or algorithm specification, but rather a **test harness** for validating TLA+ language features related to records. The specification should exercise record functionality comprehensively and report success or failure for each test case.

## Requirements

### Record Construction and Access
- Create records with labeled fields and verify field values can be retrieved
- Support both dot notation and string-based bracket notation for field access
- Handle field names that start with digits (non-standard identifiers)
- Support inline record literals with immediate field access

### Nested Records
- Create records containing other records as field values
- Access deeply nested fields through chained field access
- Verify that nested record structures maintain their values correctly

### Record Updates (EXCEPT expressions)
- Modify individual fields of a record while preserving other fields
- Perform nested field updates on records containing records
- Apply multiple updates in a single expression
- Support updates using both dot and bracket notation

### Records with Function-Valued Fields
- Create records where fields are functions (mappings)
- Support multi-argument function fields
- Access function results and then access fields of the returned record

### Sets of Records
- Define sets of records by specifying the domain of each field
- Test membership of specific records in record sets
- Verify subset relationships between record sets
- Correctly compute cardinality of finite record sets
- Support complex field types including functions and power sets

### Parameterized Record Sets
- Define record sets that depend on parameters
- Verify that filtering conditions on function-valued fields work correctly

## Correctness Properties

1. **Field Access Consistency**: Accessing the same field multiple times must return identical values
2. **Update Preservation**: Record updates must only affect the specified fields; all other fields remain unchanged
3. **Nested Access Correctness**: Chained field access must correctly traverse nested structures
4. **Set Membership Accuracy**: Records must be correctly identified as members or non-members of record sets based on field value constraints
5. **Cardinality Correctness**: The computed size of finite record sets must equal the product of the cardinalities of each field's domain (accounting for duplicates)
6. **Subset Relationships**: Subset tests between record sets must correctly account for all field constraints

## Output Requirements

Each test case should clearly indicate success or failure, allowing identification of any record operation that behaves incorrectly.
