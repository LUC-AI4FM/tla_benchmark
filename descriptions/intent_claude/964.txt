# Specification Request: Alternating Bit Protocol

## System Overview

I need a formal specification of the **Alternating Bit Protocol**, a classic reliable data transmission protocol that ensures messages are delivered correctly over an unreliable channel that may lose messages.

## System Description

The system consists of two parties—a sender and a receiver—communicating over two separate unreliable, unidirectional channels: one for data messages (sender to receiver) and one for acknowledgments (receiver to sender). The goal is to reliably transmit a sequence of data values from sender to receiver despite the possibility of message loss.

## Functional Requirements

1. **Message Transmission**: The sender should be able to transmit data values from a given set of possible data values to the receiver.

2. **Acknowledgment Mechanism**: The receiver must be able to acknowledge receipt of messages back to the sender.

3. **Sequence Numbering**: The protocol should use single-bit sequence numbers (alternating between 0 and 1) to distinguish between consecutive messages and detect duplicates.

4. **Retransmission**: When the sender has not received acknowledgment for the current message, it must be able to retransmit that message.

5. **Channel Behavior**: Both channels should be modeled as FIFO queues where any message in transit may be lost at any time. Messages should not be corrupted, reordered, or duplicated by the channel itself.

## Liveness Requirements

The specification should include appropriate fairness conditions ensuring that:
- The sender will eventually retransmit unacknowledged messages
- The receiver will eventually send acknowledgments
- Messages and acknowledgments in the channels will eventually be received (if not lost)

## Correctness Properties

The specification should support verification of:

1. **Type Safety**: All protocol state remains within expected bounds (sequence numbers are bits, queues contain properly formatted messages, etc.)

2. **Reliable Delivery**: The protocol should guarantee that data is correctly communicated from sender to receiver, maintaining consistency between what was sent and what was received.

## Scope

The model should be parameterized by an abstract set of data values that can be transmitted. The focus is on the protocol logic itself, not on the specific content being transmitted.
