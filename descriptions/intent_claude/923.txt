# Specification Request: FIFO Queue with Channel Communication

## System Overview

I need a formal specification for a bounded FIFO (First-In-First-Out) queue system that mediates communication between a sender and a receiver through explicit channel abstractions. The system should model an internal buffer that receives messages from an input channel and forwards them to an output channel while preserving message order.

## System Description

The system consists of three main components:
1. **Input channel**: Receives messages from an external sender
2. **Internal buffer**: A queue that stores messages in FIFO order
3. **Output channel**: Delivers messages to an external receiver

The workflow should support:
- A sender placing messages into the input channel
- The buffer receiving messages from the input channel and enqueueing them
- The buffer dequeuing messages and placing them on the output channel
- A receiver collecting messages from the output channel

## Functional Requirements

1. **Message sending**: An external sender must be able to submit any valid message to the input channel
2. **Buffer receiving**: The internal buffer must be able to accept messages from the input channel and append them to its queue
3. **Buffer sending**: The internal buffer must be able to take the oldest message from its queue and place it on the output channel (only when the queue is non-empty)
4. **Message receiving**: An external receiver must be able to collect messages from the output channel

## Key Correctness Properties

### Type Safety (Primary Invariant)
The system must maintain type correctness at all times:
- The input and output channels must always be in valid states according to their respective channel protocols
- The internal buffer queue must always be a sequence containing only valid messages
- All operations must preserve these typing constraints

## Assumptions

- There is a defined set of valid messages that can flow through the system
- The channels have their own internal protocols for tracking message state (e.g., whether a message is ready to be received)
- The internal queue can grow unboundedly (or has sufficient capacity for the use case)

## Goal

Provide a formally verified specification demonstrating that the type invariant is preserved by all system behaviors—from initialization through any sequence of valid operations, including stuttering steps where no state change occurs.
