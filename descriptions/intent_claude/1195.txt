# Specification Request: Set Equality Test Suite for TLA+ Tooling

## Goal

Create a test harness that verifies a TLA+ model checker correctly evaluates set equality across different syntactic representations of sets. The purpose is to confirm that sets which are mathematically equivalent are recognized as equal, regardless of how they are constructed or expressed.

## System Description

This is not a distributed system or algorithm specification, but rather a **conformance test suite** for TLA+ tooling. It should execute a series of assertions that validate the model checker's handling of set operations and comparisons.

## Requirements

The test suite must verify that set equality holds across the following categories of set construction:

1. **Literal sets with duplicates and reordering**: Sets written with duplicate elements or in different orders should be equal to their canonical form.

2. **Set comprehensions (filtering)**: A set defined by filtering elements from a larger set should equal the equivalent literal set.

3. **Set comprehensions (mapping)**: A set defined by applying a function to elements should equal the resulting literal set, even when the mapping produces duplicates.

4. **Power sets**: The power set operator should produce the correct collection of all subsets, with proper handling of duplicate element notation in subset literals.

5. **Distributed union**: The union of all sets in a collection (including power sets) should produce the expected result.

6. **Binary set operations**: Union, intersection, and set difference should produce correct results.

7. **Subset relationships**: The subset-or-equal operator should correctly identify when one set is NOT a subset of another.

8. **Integer ranges**: Range notation should equal the equivalent enumerated set.

9. **Domain extraction**: The domain of sequences, function mappings, and records should equal the expected index or key sets.

10. **Edge cases**: Empty sets arising from function spaces with empty codomains should be handled correctly.

## Correctness Properties

- Every test case comparing two equivalent set representations must confirm equality
- Every test case checking a non-subset relationship must confirm the relationship does not hold
- All tests must pass for the specification to be considered valid
- The test suite should report progress and clearly identify any failures
