# Specification Request: Circular Constant Definition Detection

## System Overview

I need a formal specification that tests the behavior of a specification language's constant substitution mechanism, specifically to verify how the system handles potentially problematic circular or self-referential constant definitions.

## Goal

The specification should model a minimal system where a constant is defined in terms of an expression that itself depends on system state. This creates a situation where the "constant" is not truly constant, as its value would depend on a variable.

## Requirements

1. **Basic State**: The system should have a single piece of state that is initialized to some constant value and never changes thereafter.

2. **Circular Dependency Setup**: The configuration should attempt to define a constant by substituting it with an operator that references a variable, creating a circular dependency where:
   - The variable is initialized using the constant
   - The constant is defined in terms of the variable

3. **Static Behavior**: After initialization, the system should have no state changes (the specification represents a completely static system).

## Correctness Properties

The primary purpose of this specification is to test the specification checker's ability to:

- Detect when a constant substitution creates an invalid circular dependency
- Properly distinguish between true constants and state-dependent expressions
- Report meaningful errors when constant definitions reference mutable state

This is essentially a test case for tooling behavior rather than a model of a real-world system.
