Specify a system for collecting and recording performance statistics from TLA+ model checking runs.

The system should capture metrics from completed model checking executions and persist them to a CSV file for later analysis. Each recorded run should include identifying information (which specification was checked, which run number, when it occurred), version control metadata about the TLC tool itself (revision timestamp, tag, and date), configuration details (number of worker threads), and key model checking statistics (state space diameter, total states generated, distinct states found, states remaining in queue, and total checking duration).

The system must guarantee that:
1. The CSV file has proper column headers before any data rows are written—headers should be written exactly once, only if the file is empty or newly created.
2. Each model checking run produces exactly one complete record with all fields populated.
3. Statistics are captured at the appropriate moment after model checking completes, reflecting the final state of the checking process.

The intended use case is benchmarking and comparing model checking performance across different specifications, configurations, or tool versions, enabling statistical analysis of how various factors affect checking time and state space size.
