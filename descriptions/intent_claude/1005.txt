# Specification Request: Reliable Broadcast Protocol with Crash Failures

## System Overview

I need a formal specification of a classic reliable broadcast protocol designed to operate in a distributed system where some processes may crash. The protocol should model how a group of processes coordinate to deliver a message reliably, even when a bounded number of processes fail by crashing.

## System Model

The system consists of:
- A fixed number of processes that communicate by message passing
- A known upper bound on how many processes may be faulty (crash)
- A subset of processes that remain correct (non-crashed) throughout execution
- The ability for processes to crash at any point during execution

## Protocol Behavior

The protocol should model a broadcast mechanism where:
- Processes can send broadcast messages to all other processes
- Each process maintains a record of messages it has received
- Processes track which messages have been sent into the network
- The protocol progresses through distinct phases (e.g., initial state, sending, deciding/accepting)

## Key Requirements

### Safety Properties
- **Agreement**: If any correct process delivers (accepts) a message, then all correct processes eventually deliver that message
- **Validity**: If a correct process broadcasts a message, then it eventually delivers that message

### Liveness Properties
- **Termination**: Every correct process eventually reaches a decision state

### Failure Model
- Processes may only fail by crashing (no Byzantine behavior)
- The number of actual crashes must not exceed the declared fault tolerance bound
- Once a process crashes, it takes no further steps
- Correct processes must remain operational throughout the execution

## Correctness Conditions

The specification should include:
- An invariant ensuring the number of crashed processes never exceeds the tolerated threshold
- A property ensuring that if one correct process reaches an "accepted" state, all correct processes can eventually reach that state
- Conditions relating the fault tolerance threshold to the total number of processes (typically requiring a majority of correct processes)

## Purpose

This specification should serve as a foundation for verifying that the folklore reliable broadcast algorithm correctly achieves consensus on message delivery despite crash failures, and can be used for model checking with tools that support bounded verification.
