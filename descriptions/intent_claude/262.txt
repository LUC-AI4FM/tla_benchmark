# Specification Request: Operator Inlining Test Suite

## System Overview

I need a formal specification that serves as a comprehensive test suite for verifying the correctness of an operator inlining transformation in a specification language that supports higher-order operators, nested definitions, and polymorphism.

## Goal

The purpose is to validate that an inlining mechanism correctly handles various patterns of operator definitions and applications. The tests should confirm that after any inlining transformation is applied, expressions still evaluate to their expected results.

## Requirements

The test suite must cover the following scenarios:

1. **Simple local operator definitions** - Basic operators defined within a local scope and applied to arguments should compute correctly.

2. **Global operator definitions** - Operators defined at module scope should work identically to locally-defined ones.

3. **Nested operator definitions** - Operators that define other operators internally, with inner operators referencing parameters from outer scopes.

4. **Linear dependency chains** - Global operators that call other global operators in sequence.

5. **Nullary vs parameterized operators** - Distinguish between operators that take no arguments and those that do, ensuring both are handled appropriately.

6. **Operators passed as arguments** - Operators used as first-class values and passed to fold operations or other higher-order operators.

7. **Anonymous functions (lambdas)** - Lambda expressions passed directly to higher-order operators.

8. **Mixed scoping** - Local operators that capture variables from enclosing scopes when passed to higher-order combinators.

9. **Higher-order operators without lambdas** - Operators that accept other named operators as parameters.

10. **Double higher-order nesting** - Chains where higher-order operators receive other higher-order operators.

11. **Polymorphic operators** - Operators with generic type signatures that work across different concrete types.

12. **Long definition chains** - Deeply nested sequences of operator definitions where each builds on the previous.

## Correctness Properties

The specification must guarantee that **all test cases evaluate to true**. Each test case asserts that a particular expression involving operator definitions and applications equals an expected concrete value. The invariant is that the conjunction of all test results holds in every reachable state.
