# Specification Request

## System Overview

I need a formal specification that demonstrates and tests the theorem and module instantiation features of TLA+, particularly focusing on how theorems, definitions, and proofs can be referenced across module boundaries with different parameter bindings.

## Goal

Create a test harness that validates the correct behavior of:

1. **Module instantiation with parameter substitution** - The ability to instantiate the same module multiple times with different constant values and verify that references to theorems and definitions correctly reflect those substituted values.

2. **Theorem subexpression referencing** - The ability to reference specific parts of compound theorems using positional notation, and verify these references resolve correctly.

3. **Named vs unnamed instantiation** - Both direct (unnamed) module instantiation and named instantiation should work correctly, with proper scoping of theorem references.

## Requirements

### Functional Requirements

- Support a simple counter variable bounded by a constant, where the counter increments modulo the bound
- The system should initialize with the counter in a valid range and continuously cycle through values
- Demonstrate fairness by ensuring the counter eventually returns to zero

### Verification Requirements

The specification must verify:

1. **Invariant preservation** - The counter always remains within its valid range (0 to the upper bound)

2. **Liveness** - The counter repeatedly reaches zero (infinitely often)

3. **Theorem instantiation correctness** - When a module is instantiated with a specific parameter value, theorems from that module that reference the parameter should evaluate consistently with that binding

4. **Cross-module theorem references** - Theorems defined in instantiated modules should be accessible and their subexpressions should be extractable

### Key Properties to Test

- Assumptions that should hold true when modules are instantiated with matching parameters
- Assumptions that should be false when modules are instantiated with different parameters
- Correct resolution of nested instantiation references (instance within instance)
- Proper handling of theorem labels and positional subexpression access

## Dependencies

This specification requires companion modules that define theorems with parameter-dependent truth values, allowing the main module to verify that instantiation correctly propagates parameter bindings to theorem evaluation.
