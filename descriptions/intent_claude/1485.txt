# Specification Request: Consensus Protocol

## System Overview

I need a formal specification for a basic consensus protocol where a system must choose exactly one value from a set of possible values. This models the fundamental problem in distributed systems where multiple processes must agree on a single value.

## Functional Requirements

1. **Initial State**: The system starts with no value chosen.

2. **Value Selection**: The system may select any single value from a predefined set of acceptable values. Once a value is selected, the selection process is complete.

3. **One-Shot Decision**: After a value has been chosen, no further changes to the decision are permitted.

## Correctness Properties

### Safety Properties

1. **Agreement**: At most one value can ever be chosen. The system must never be in a state where multiple different values have been selected.

2. **Validity**: Any chosen value must come from the predefined set of acceptable values (not invented or corrupted).

### Liveness Properties

1. **Termination**: Under fair execution (where the system is given sufficient opportunity to act), if no value has been chosen and there exists at least one possible value to choose from, eventually some value will be chosen.

## Assumptions

- The set of possible values is non-empty (otherwise termination cannot be guaranteed).
- The set of possible values is known in advance and fixed.

## Purpose

This specification captures the essence of the consensus problem: ensuring that a distributed system can irrevocably commit to exactly one value. This serves as a foundation for understanding more complex consensus algorithms like Paxos or Raft.
