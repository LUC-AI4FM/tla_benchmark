# Specification Request: Two-Phase Handshake Protocol

## System Overview

I need a formal specification of the **two-phase handshake protocol**, a fundamental hardware synchronization mechanism used for coordinating alternating actions between two processes.

## System Description

The system consists of two processes:
- A **Producer** that initiates communication
- A **Consumer** that responds to the Producer

These processes communicate through two single-bit signals: one controlled by the Producer and one controlled by the Consumer. The protocol ensures that the Producer and Consumer take turns performing actions, with the Producer always going first.

## Behavioral Requirements

1. **Strict Alternation**: The Producer and Consumer must alternate their actions—the Producer acts, then the Consumer acts, then the Producer again, and so on.

2. **Producer Priority**: The Producer must be the first to act when the system starts.

3. **Synchronization Mechanism**: The processes coordinate by comparing their signal values:
   - The Producer can act only when both signals have the same value
   - The Consumer can act only when the signals have different values

4. **Signal Toggling**: Each process toggles its own signal after completing its action, which enables the other process to proceed.

5. **Extensibility**: The specification should be parameterized to allow arbitrary application-specific actions to be performed by each process during their respective turns, beyond just the synchronization logic.

## Correctness Properties

1. **Safety**: The two-bit signals must always remain valid (binary values only).

2. **Refinement**: The protocol must correctly implement a simple alternating specification—specifically, it should be provable that this two-phase implementation refines a more abstract specification where a single variable simply alternates between two states to control whose turn it is.

## Deliverables

The specification should include:
- The protocol's state and transitions
- An invariant capturing valid states
- A refinement mapping showing how the two-phase signals correspond to a simple alternation variable
- A proof that the protocol implements the abstract alternating behavior
