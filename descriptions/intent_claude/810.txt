# Specification Request: Majority Vote Algorithm

## System to Model

I need a formal specification of the Boyer-Moore majority vote algorithm (also known as the majority element algorithm). This is a streaming algorithm that determines whether a sequence contains a majority element—an element that appears more than half the time—and if so, identifies that element.

## What the Algorithm Must Do

The algorithm should process a sequence of elements one at a time, maintaining minimal state (a current candidate and a counter). As it scans through the sequence:

- It should track a potential majority candidate
- It should maintain a count that gets incremented when seeing the candidate and decremented otherwise
- When the count reaches zero, the next element becomes the new candidate
- After processing all elements, the candidate should be the majority element if one exists

## Key Correctness Properties

The specification must guarantee:

1. **Partial Correctness**: If a majority element exists in the sequence (an element appearing more than ⌊n/2⌋ times where n is the sequence length), then upon termination the algorithm's candidate must be that majority element.

2. **Termination**: The algorithm must eventually finish processing any finite input sequence.

3. **Invariant Preservation**: Throughout execution, the algorithm maintains the invariant that the true majority element (if one exists) cannot have been "canceled out" by the counting mechanism.

## Model Checking Scope

For verification purposes, the model should be checkable over:
- A small finite set of distinct values (e.g., three different elements)
- All possible sequences up to a configurable bounded length
- This allows exhaustive verification of correctness across all input combinations within the bounds
