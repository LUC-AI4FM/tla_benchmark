# Specification Request: Processor Register File Interface

## System Overview

I need a formal specification for a register file interface in a multi-processor system. The system models how processors interact with their register files, where each processor has its own set of registers that can hold different types of values.

## System Components

The system should model:
- Multiple processors, each with its own dedicated set of registers
- Registers that can be addressed and hold values
- A clear distinction between different states a register can be in

## Register States

Each register in a processor's register file should be capable of being in one of three states:
1. **Holding a pending read request** - indicating a read operation targeting some address with an expected value
2. **Holding a pending write request** - indicating a write operation targeting some address with a value to be written
3. **Free/available** - indicating the register is not currently involved in any pending operation

## Key Requirements

1. **Per-processor isolation**: Each processor should have its own independent register file that other processors cannot directly access

2. **Uniform register structure**: All registers across all processors should have the same structure, tracking an address, a value, and the type of operation (read, write, or free)

3. **Well-formedness**: The register file must always maintain proper structure - every processor maps to a complete set of registers, and every register contains a valid register value

## Correctness Properties

The specification must guarantee:
- **Type safety**: The register file structure is always well-typed, with each processor having a properly structured mapping from registers to valid register values

## Purpose

This appears to be a foundational interface specification, likely intended to be extended or composed with other specifications that model the actual operations on the register file (allocation, request handling, completion of memory operations, etc.).
