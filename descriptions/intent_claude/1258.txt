# Specification Request: TLA+ Counterexample Visualization Export

## System Overview

I need a utility that automatically exports TLA+ model checker counterexamples to a visual graph format (specifically DOT/GraphViz format) for easier debugging and analysis of specification violations.

## Goal

When the TLA+ model checker (TLC) finds a counterexample (a trace demonstrating a property violation), the system should automatically convert that counterexample into a directed graph visualization and save it to a file. This makes it easier to understand and communicate how the system reached an error state.

## Requirements

### Core Functionality

1. **Counterexample Detection**: The system should detect when TLC has produced a counterexample trace.

2. **Graph Construction**: Convert the counterexample into a directed graph where:
   - Each node represents a state in the error trace
   - Each edge represents a transition (action) between states
   - Edges should be labeled with the name of the action that caused the transition

3. **State Visualization**: Each state node should display all state variable values in a readable format, with each variable on its own line.

4. **File Export**: Write the resulting graph in DOT format to a user-specified file path.

### Behavioral Requirements

- If no counterexample exists (the model check passed), the system should do nothing and succeed silently.
- If counterexample output has been explicitly disabled, the system should also do nothing.
- The output file should be completely overwritten if it already exists.
- The system should confirm successful writing by printing a message with the output file path.

### Configuration

- The user must be able to specify the output file path as a constant parameter.

## Correctness Properties

1. **Completeness**: The exported graph must faithfully represent the entire counterexample trace—all states and all transitions.

2. **Accuracy**: Action labels on edges must correspond to the actual actions that TLC identified as causing each transition.

3. **Non-interference**: This visualization utility should not affect the model checking results themselves; it's purely an output/reporting mechanism.
