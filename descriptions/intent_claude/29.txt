# Specification Request: TLA+ Language Feature Coverage Test Suite

## System Overview

I need a formal specification that serves as a comprehensive test harness for verifying that a TLA+ toolchain (particularly a type checker) correctly handles the full breadth of TLA+ language constructs. This is not a specification of a real distributed system, but rather a catalog of language features organized for testing purposes.

## Goal

Create a specification that exercises all major TLA+ language constructs to ensure:
1. A type checker can process every construct without failing
2. All expressions can be properly annotated with types
3. The full range of TLA+ syntax is covered in a single module

## Required Language Constructs to Cover

### Primitive Types and Literals
- String, integer, and boolean literals
- The standard sets: integers, naturals, booleans, and strings

### Logical Operators
- Equivalence, implication, conjunction, disjunction, and negation
- Existential and universal quantification over sets
- Quantification over tuple-typed elements (destructuring in quantifiers)

### Set Operations
- Set enumeration (including empty sets)
- Record sets and sequence sets
- Membership and non-membership tests
- Subset relations and power sets
- Union, intersection, difference, and Cartesian product
- Set filtering and mapping (set comprehensions)

### Functions and Records
- Record construction with named fields
- Tuple construction
- Function application (including record field access)
- Function domain extraction
- Function constructors over single and multiple domains
- Function update (EXCEPT notation)
- Recursive function definitions

### Control Flow
- Conditional expressions (IF-THEN-ELSE)
- Case expressions with and without OTHER clause

### Definitions and Abstraction
- User-defined operators with parameters
- LET-IN expressions with local operator definitions
- Lambda expressions (anonymous operators)
- CHOOSE expressions (both bounded and unbounded)

### Arithmetic
- All integer operations: negation, addition, subtraction, multiplication, integer division, modulo, exponentiation
- Comparison operators: less than, less than or equal, greater than, greater than or equal
- Range construction (dot-dot notation)
- Real division

### Sequences (from standard library)
- Head, tail, append, concatenation
- Length, subsequence extraction
- Filtering sequences with predicates

### Finite Sets (from standard library)
- Finiteness testing
- Cardinality computation

### State and Actions
- Primed variables (next-state references)
- Stuttering and non-stuttering action notation
- UNCHANGED for variable tuples
- Action composition

### Temporal Operators
- Always (box) and eventually (diamond)
- Leads-to and guarantees operators
- Weak and strong fairness conditions

### Module-Level Features
- Constant declarations with assumptions
- Variable declarations
- Type aliases for documentation/tooling

## Correctness Properties

This specification should:
1. Be syntactically valid TLA+
2. Include type annotations that are internally consistent
3. Cover edge cases like empty sets with explicit types
4. Demonstrate proper scoping in nested definitions

## Notes

The specification should include at least one state variable and demonstrate how actions and temporal formulas relate to that state, even if the actual state transitions are trivial. The focus is breadth of coverage rather than modeling any meaningful behavior.
