# Specification Request

I need a formal specification to help me understand and verify properties related to the TLA+ `ENABLED` operator in the context of a simple state machine.

## System Description

Model a minimal two-variable system where:
- One variable toggles between two values (alternating between 0 and 1)
- A second variable remains constant throughout execution

The system should start with both variables initialized to zero, and only the first variable changes during execution.

## Purpose

The primary goal is to create a test bed for exploring how the `ENABLED` predicate behaves under different conditions. Specifically, I want to compare:

1. Whether a particular state transition (setting specific values to both variables) is *ever* possible from the current state, considering only the primed variables
2. Whether that same transition remains possible when additional constraints involving current-state values are added to the action formula

## Properties to Investigate

- Under what conditions is a hypothetical action "enabled" when it only constrains next-state values?
- How does adding a precondition (a constraint on current-state values) affect whether an action is considered enabled?
- What is the relationship between these two enablement conditions as the system evolves?

## Requirements

- The specification should support both safety analysis (what behaviors are possible) and liveness analysis (ensuring the system continues to make progress via weak fairness)
- The model should be simple enough to clearly illustrate the semantics of `ENABLED` without confounding complexity
