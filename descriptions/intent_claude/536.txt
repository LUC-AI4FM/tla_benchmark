# Specification Request: Maximum Element Finder with Nondeterministic Iteration

## System Overview

I need a formal specification for an algorithm that finds the maximum value in a sequence of integers. The key characteristic is that the algorithm should process elements in a **nondeterministic order** rather than strictly left-to-right, allowing us to verify correctness regardless of which order elements are examined.

## Input and Configuration

- The system operates on a collection of integer sequences (tuples)
- A sentinel "minimum value" is provided that is strictly less than any element that could appear in the input sequences
- The algorithm should work correctly for any valid input sequence from the collection, including the empty sequence

## Functional Requirements

1. The algorithm must examine each element of the input sequence exactly once
2. The order in which elements are examined is not fixed—any ordering should lead to a correct result
3. The algorithm must track the largest value seen so far during processing
4. The algorithm must eventually terminate after processing all elements

## Correctness Properties

Upon termination, the algorithm must guarantee:

1. **Empty sequence case**: If the input is empty, the result should be the sentinel minimum value

2. **Non-empty sequence case**: The result must satisfy both:
   - The result equals some element that actually appears in the input sequence
   - The result is greater than or equal to every element in the input sequence

## Liveness Requirements

- The algorithm must always terminate (no infinite loops)
- Progress must be guaranteed—the system cannot stall indefinitely

## Purpose

This specification serves to verify that a maximum-finding algorithm is correct under all possible nondeterministic execution orders, demonstrating that the final result is independent of the order in which elements are processed.
