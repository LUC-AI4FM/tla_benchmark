# Specification Request: Binary Relation Properties Library

## Goal

Create a reusable library module for reasoning about binary relations over finite sets. The library should provide definitions for checking fundamental properties of relations and computing common closures, enabling formal verification of systems that depend on ordering, equivalence, or graph-like structures.

## System Description

The module should support binary relations defined over a finite set, where a relation determines whether pairs of elements are related. The library must provide predicates to test whether a given relation satisfies various mathematical properties, as well as operations to compute derived relations.

## Required Capabilities

### Basic Relation Properties

The library must be able to determine whether a relation is:

1. **Reflexive** — every element is related to itself
2. **Irreflexive** — no element is related to itself
3. **Symmetric** — if x is related to y, then y is related to x
4. **Antisymmetric** — if x is related to y and y is related to x, then x and y are the same element
5. **Asymmetric** — it is never the case that both x is related to y and y is related to x
6. **Transitive** — if x is related to y and y is related to z, then x is related to z

### Ordering Properties

The library must provide predicates to recognize standard ordering structures:

1. **Strict partial order** — irreflexive, antisymmetric, and transitive
2. **Partial order** — reflexive, antisymmetric, and transitive
3. **Strict total order** — a strict partial order where any two distinct elements are comparable
4. **Total order** — a partial order where any two elements are comparable

### Closure Operations

The library must compute:

1. **Transitive closure** — the smallest transitive relation containing the original relation
2. **Reflexive transitive closure** — the smallest reflexive and transitive relation containing the original relation

### Connectivity Analysis

The library must determine whether a relation makes a set **connected**, meaning there exists a path (through the reflexive transitive closure) between any two elements.

## Interface Requirements

For each property predicate, the library should support two usage patterns:
- Checking a relation provided as an explicit function from pairs to booleans
- Checking a relation defined implicitly by a binary operator expression

This dual interface allows convenient use with both pre-computed relation tables and inline comparison expressions.
