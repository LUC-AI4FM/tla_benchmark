# Specification Request: Type Annotation Parser with Embedded Comments

## System Description

I need a formal specification for a type annotation parsing system that can handle structured type declarations containing embedded comments. This is specifically for validating that a type annotation parser correctly processes type definitions even when those definitions include inline commentary.

## Requirements

The system should model a type annotation mechanism where:

1. **Structured type declarations**: The system must support defining types as sets of records or individual record types, where records have named fields with associated types (such as integers or sequences).

2. **Comment tolerance**: The parser must correctly handle type annotations that contain embedded comments (using a comment syntax like `//`) interspersed within the type definition structure.

3. **Multi-field records**: The system should support record types with multiple fields, where comments may appear between field definitions.

## Key Correctness Properties

1. **Parse correctness**: Type annotations containing comments should be parsed identically to equivalent annotations without comments—the comments should be treated as whitespace/ignored content.

2. **Structural preservation**: The presence of comments within a type annotation must not alter the resulting type structure that the system recognizes.

3. **Regression safety**: The specification should serve as a regression test to ensure that previously broken behavior (where comments inside type annotations caused parsing failures) remains fixed.

## Goal

The primary goal is to verify that the type annotation parsing logic is robust enough to handle real-world annotation styles where developers include explanatory comments within complex type definitions, ensuring these comments don't break the type checking or annotation processing pipeline.
