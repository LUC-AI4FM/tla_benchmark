# Specification Request: Test Suite for Standard Sequences Library

## Goal

Create a verification harness that tests the correctness of a standard sequences library implementation. The purpose is to validate that fundamental sequence operations behave according to their expected semantics when applied to various inputs, including edge cases.

## System Description

This is not a dynamic system but rather a static test suite that validates sequence operations. The specification should check that a library providing sequence manipulation primitives produces correct results for a comprehensive set of test cases.

## Operations to Verify

The test suite must validate the following sequence operations:

1. **Sequence membership**: Determining whether a tuple qualifies as a sequence over a given element type (e.g., sequences of natural numbers should not contain negative integers)

2. **Concatenation**: Joining two sequences together, including cases with empty sequences

3. **Length**: Computing the number of elements in a sequence, including for empty sequences

4. **Append**: Adding a single element to the end of a sequence, including appending to an empty sequence

5. **Head**: Extracting the first element of a non-empty sequence

6. **Tail**: Extracting all elements except the first, including the case where the result is empty

7. **Subsequence extraction**: Extracting a contiguous portion of a sequence given start and end indices, including edge cases where the range is empty

8. **Filtering**: Selecting elements from a sequence that satisfy a given predicate, including cases where all, some, or no elements match

## Correctness Properties

Each test case must either:
- Confirm that the operation produces the expected result and report success, or
- Halt with an assertion failure if the operation produces an unexpected result

The specification should cover:
- Normal cases with typical inputs
- Edge cases involving empty sequences
- Boundary conditions (single-element sequences, filtering that removes all elements)
- Type constraints (distinguishing natural numbers from integers)

## Requirements

- All tests must pass for the specification to be considered valid
- Test results should be observable (printed) during model checking
- Any failing test must cause immediate assertion failure with identification of which test failed
