Specify the Two-Phase Commit protocol in TLA+. A single transaction manager (TM) coordinates a fixed set of resource managers (RMs) to reach a consistent commit-or-abort decision. Each RM begins in a working state and may either prepare (signaling readiness to commit) or spontaneously choose to abort. The TM collects Prepared messages from RMs; once it has heard from all of them it may broadcast a Commit decision, or at any point while still in its initial state it may spontaneously broadcast an Abort decision. Upon receiving the TM's broadcast, each RM moves to the corresponding committed or aborted state. Model message passing as a grow-only set of sent messages, so receiving a message is equivalent to that message existing in the set.

The key safety invariant is type correctness: RM states are drawn from a fixed four-value set, the TM state from a three-value set, and all messages conform to their expected structure. Beyond type safety, the specification must implement the Transaction Commit correctness condition: no two RMs ever reach different final decisions, and an RM may only commit if every RM has prepared. The specification covers safety only; no liveness properties are required.
