# Specification Request

## System to Model

A test case for verifying correct behavior when performing nested function updates (EXCEPT operations) on lazily-evaluated functions whose domains are non-reducible sets.

## Goal

Demonstrate and detect a specific bug related to function domain preservation when:
1. A function is defined over a computed set (such as all functions from one set to another)
2. The function is updated at one point using an EXCEPT expression
3. The resulting function is then updated again at a different point using another EXCEPT expression

## Requirements

The specification should:

1. **Define a base function** over a domain that forces lazy evaluation (a set of functions rather than a simple enumerable set)

2. **Perform chained updates** where:
   - The first update modifies the base function at one specific domain element
   - The second update modifies the result at a *different* domain element

3. **Verify domain integrity** by checking that the final function's domain equals the original intended domain set

## Key Correctness Property

After performing nested EXCEPT operations on a lazily-evaluated function, the resulting function must retain its complete original domain. The domain should not be incorrectly reduced to only those elements that were explicitly updated.

## Expected Behavior

The invariant should confirm that the domain of the doubly-updated function contains all elements from the original domain set, not just the subset of elements that were touched by EXCEPT operations.
