# Specification Request: TLA+ Proof System Backend Interface

## System Overview

I need a formal specification for a **proof assistant backend interface** that enables TLA+ specifications to invoke various automated theorem provers and SMT solvers to discharge proof obligations.

## Goal

Design a system that allows proof authors to direct proof obligations to different automated reasoning backends, with configurable timeouts and tactics. The system should support multiple categories of provers and allow fallback strategies when one prover fails.

## Core Requirements

### Backend Prover Support

The system must support invoking the following categories of automated provers:

1. **SMT Solvers**: Multiple SMT solvers that can handle first-order logic, set theory, functions, and records. Support should include at least CVC3, Yices, veriT, and Z3.

2. **First-Order Theorem Provers**: Support for superposition-based provers (like SPASS) and tableau-based provers (like Zenon).

3. **Interactive Theorem Provers**: Integration with Isabelle, including the ability to specify different proof tactics (auto, force, blast, clarsimp, etc.).

4. **Temporal Logic Provers**: Support for propositional linear-time temporal logic reasoning.

### Configuration Options

- Each prover invocation must support configurable **timeout values**
- Isabelle invocations must support specifying **proof tactics**
- Support for **combined strategies** that try multiple provers in sequence until one succeeds

### Fundamental Theorems

The system must provide access to key foundational results:

1. **Set Extensionality**: Two sets are equal if and only if they contain the same elements
2. **No Universal Set**: No set contains all possible elements

### Temporal Logic Proof Rules

The specification should reserve support for temporal logic reasoning rules, including:

- Invariance rules for proving properties hold in all states
- Weak and strong fairness rules for liveness reasoning
- Simulation rules relating different specifications
- Lattice rules for temporal implication

## Correctness Properties

1. **Soundness**: Any proof obligation discharged by a backend must be logically valid
2. **Timeout Compliance**: Provers must respect specified timeout bounds
3. **Fallback Correctness**: Multi-prover strategies must succeed if any constituent prover succeeds
4. **Tactic Isolation**: The choice of prover/tactic for one obligation must not affect others

## Usage Model

Proof authors should be able to cite specific backend strategies within their proofs, either requesting a specific prover or allowing the system to try multiple approaches automatically.
