# Specification Request: TLA+ UNCHANGED Operator Semantics Test Suite

## System to Model

A test harness for validating the semantic behavior of TLA+'s `UNCHANGED` operator across various expression forms and contexts.

## Goal

Create a specification that exercises and verifies the correct interpretation of the `UNCHANGED` operator when applied to different types of expressions, ensuring that the TLA+ model checker correctly evaluates unchanged conditions for:

- Tuples and sequences of variables
- Individual array/function elements accessed by index
- Records constructed from variable components
- Quantified expressions (existential and universal)
- Choice expressions (deterministic selection)
- Set comprehensions (both mapping and filtering forms)
- Domain extraction from functions
- Nested set constructions containing variables
- Sets containing both constant and variable elements

## Requirements

1. **Initial State**: The system should begin with a function mapping indices to values and a simple scalar variable.

2. **Behavior**: Each test case should:
   - Hold all state variables constant (no actual state change)
   - Verify that applying `UNCHANGED` to various derived expressions correctly evaluates to true when the underlying variables haven't changed
   - Report success for each passing test

3. **Expression Coverage**: The test suite must verify `UNCHANGED` semantics for:
   - Direct variable references in tuple form
   - Indexed access to function elements (universally quantified)
   - Compound record expressions built from variable values
   - Boolean expressions involving quantifiers over variable values
   - Expressions using `CHOOSE` over variable domains
   - Set-builder expressions that map over variables
   - Set-filter expressions with predicates referencing variables
   - The domain of a function-valued variable
   - Singleton sets containing a variable
   - Mixed sets with constants and variables

4. **Correctness Properties**: Each test should confirm that when variables remain unchanged between states, the `UNCHANGED` operator correctly recognizes this for all tested expression forms, including complex derived expressions that depend on those variables.
