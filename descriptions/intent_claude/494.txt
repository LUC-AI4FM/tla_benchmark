# Specification Request: Unreliable Network Message Passing Infrastructure

## System Overview

I need a formal specification for a message-passing network layer that can be used as a building block for distributed system models. The network should realistically capture the behavior of asynchronous communication channels where messages can be duplicated or lost.

## Functional Requirements

The system should model a pool of in-flight messages between distributed components, supporting the following operations:

1. **Sending a message**: A component can dispatch a message into the network, where it becomes available for eventual delivery.

2. **Receiving/discarding a message**: A component can consume a message from the network, removing one copy of it from the pool of in-flight messages.

3. **Request-response exchange**: A component can atomically consume an incoming request while simultaneously dispatching a response, modeling typical RPC-style interactions.

4. **Message duplication**: The network itself may spontaneously create additional copies of any message currently in transit, modeling real-world packet duplication.

5. **Message loss**: The network may spontaneously lose any message currently in transit, modeling dropped packets or network failures.

## Key Modeling Requirements

- Multiple copies of identical messages must be trackable independently (if the same message is sent twice, both copies should exist and be independently deliverable or droppable).
- The system should start with no messages in transit.
- Message delivery should be asynchronous with no ordering guarantees.
- The specification must be compatible with theorem-proving tools (avoiding constructs that such tools don't support).

## Intended Use

This module should serve as reusable infrastructure that other distributed algorithm specifications can import to model their communication layer, rather than being a complete system specification on its own.
