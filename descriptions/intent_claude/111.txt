# Specification Request: Message Set Filtering with Cardinality Constraint

## System Overview

I need a formal specification for a simple system that manages collections of messages across multiple rounds, with the ability to filter messages while maintaining a minimum quantity constraint.

## System Description

The system maintains a mapping from round numbers (0, 1, and 2) to sets of messages, where messages are drawn from a fixed alphabet of three possible values. The system should be initialized with an arbitrary assignment of message sets to each round.

## Behavioral Requirements

The system should support an operation that filters the messages associated with a specific round (the final round) by selecting a subset of the current messages. However, this filtering operation must preserve at least a minimum number of messages—specifically, at least two messages must remain after any filtering operation.

## Key Correctness Properties

1. **Minimum Cardinality Preservation**: After any transition, the message set for the designated round must contain at least 2 elements. The system should never be able to reduce a message set below this threshold.

2. **Monotonic Reduction**: The filtering operation can only remove messages or keep them the same—it cannot add new messages that weren't already present.

3. **Selective Modification**: Only one specific round's message set can be modified; other rounds remain unchanged throughout execution.

## Purpose

This specification appears to be designed to model scenarios where distributed systems or consensus protocols must maintain quorum-like properties—ensuring that a sufficient number of messages or votes are always retained even as the system evolves or filters its state.
