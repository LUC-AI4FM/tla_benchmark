# Specification Request

## System Overview

I need a formal specification for a simple integer counter system that can both increment and negate its value. The system should help me understand and test how TLA+ model checking behaves when exploring states that might violate constraints or invariants.

## System Description

The system maintains a single integer value that starts at zero. At each step, the system can either:
1. Negate the current value (flip its sign)
2. Increment the value by one

## Correctness Requirements

The primary safety property is that the counter value should always remain non-negative (greater than or equal to zero).

## Exploration Constraints

The model checker should be configured to only explore states where the counter value is a natural number. This is important for understanding how state constraints interact with invariant checking—specifically, whether the model checker can still detect invariant violations that occur in transitions leading to constrained-out states.

## Testing Goals

The specification should be suitable for verifying that the model checker correctly identifies counterexamples when the negation operation is applied to a positive number, which would produce a negative result and violate the non-negativity property. I want to confirm that specific error traces are generated, particularly traces that show the system incrementing to a positive value and then negating it to produce an invalid negative state.
