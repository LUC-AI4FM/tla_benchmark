# Specification Request: TLA+ Language Feature Coverage Test Suite

## Goal

Create a comprehensive test specification that exercises the full range of TLA+ language constructs and operators. The purpose is to validate that a type checker or analysis tool correctly handles all standard TLA+ features without failing, and that every expression can be properly assigned a type.

## System Description

This is not a specification of a real system or algorithm. Instead, it is a **language feature demonstration module** that serves as a test harness. It should include representative examples of every major category of TLA+ syntax and semantics.

## Requirements

The specification must include examples covering:

### Basic Types and Literals
- String, integer, and boolean literals
- References to built-in sets (integers, naturals, booleans, strings)

### Operators and Expressions
- Equality and inequality comparisons
- User-defined operators with parameters
- Operator application
- Deterministic choice from sets (both bounded and unbounded)
- Local definitions within expressions
- Higher-order operators (operators that take operators as arguments)
- Anonymous functions/lambdas

### Logical Connectives
- Equivalence, implication, conjunction, disjunction, negation
- Existential and universal quantification over sets
- Quantification over tuples (destructuring bind)

### Set Operations
- Set enumeration (including empty sets)
- Record and sequence type sets
- Membership and non-membership tests
- Subset relations and power sets
- Union, intersection, and difference
- Cartesian products
- Set filtering and mapping (set comprehensions)
- Cardinality and finiteness checks

### Functions and Records
- Record construction with named fields
- Tuple construction
- Function application (by index and by field name)
- Domain extraction
- Function construction over sets
- Function update (EXCEPT notation)

### Control Flow
- Conditional expressions (IF-THEN-ELSE)
- Case expressions with and without default (OTHER) clauses

### Sequences
- Head, tail, append, concatenation
- Length and subsequence extraction
- Filtering sequences by predicate

### Arithmetic
- Unary negation
- Binary operations: addition, subtraction, multiplication, integer division, modulo, exponentiation
- Comparison operators
- Integer range construction
- Real division

### State and Assumptions
- Constant declarations with assumptions/constraints
- Trivial initial state and next-state relations (for syntactic completeness)

### Type Annotations
- The specification should include type annotations where needed to guide type inference, particularly for higher-order operators, empty collections, and polymorphic functions

## Correctness Properties

1. **Syntactic Validity**: Every construct must be valid TLA+ syntax
2. **Type Consistency**: Every expression must be assignable a consistent type
3. **Tool Compatibility**: The specification should be processable by type checkers and model checkers without errors
