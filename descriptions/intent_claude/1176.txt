# Specification Request

I need a formal specification for a minimal test system designed to verify TLC model checker behavior when processing problematic configuration files or temporal formulas.

## System Description

The system should model an extremely simple state space with a single piece of state that can hold a constant value. This serves as a minimal baseline for testing TLC's error detection and reporting capabilities.

## Purpose

This specification is intended as a test harness to:
1. Confirm that TLC properly detects and reports errors in model configuration files
2. Verify that TLC correctly identifies invalid temporal formula constructs (specifically, temporal formulas containing actions that don't conform to the required `<>[]A` or `[]<>A` patterns)

## Requirements

- The specification itself should be syntactically valid TLA+
- The specification should be minimal—just enough structure to allow TLC to attempt processing
- The actual errors being tested are expected to come from the model configuration or from temporal properties specified externally, not from the base specification itself

## Expected Behavior

When checked with appropriately constructed test models:
- One model configuration should trigger a TLC configuration file error
- Another model configuration should trigger TLC's error message about temporal formulas containing actions needing to be in specific forms
