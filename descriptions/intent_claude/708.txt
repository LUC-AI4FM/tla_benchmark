# Specification Request: Bag (Multiset) Extended Operations Library

## System Overview

I need a formal specification for a library of extended operations on **bags** (also known as multisets). A bag is a collection like a set, but where elements can appear multiple times with associated counts.

## Core Functionality Required

The library should provide the following operations on bags:

### Basic Bag Manipulation
- **Add element**: Add a single occurrence of an element to a bag
- **Remove element**: Remove a single occurrence of an element from a bag (if present)
- **Remove all occurrences**: Remove all occurrences of a specific element from a bag

### Fold/Reduce Operations
- **Fold over bag**: Apply a binary operator across all elements of a bag (respecting multiplicities), starting from a base value. For example, folding addition over a bag containing two 1s, one 2, and three 3s should yield 1+1+2+3+3+3 = 13
- **Map-then-fold**: A generalized fold that first maps elements before combining them
- **Sum**: Compute the sum of all elements in a bag of integers (with multiplicities)
- **Product**: Compute the product of all elements in a bag of integers (with multiplicities)

### Conversion Operations
- **Bag to set**: Extract the underlying set of distinct elements from a bag

## Correctness Properties

The operations must satisfy these properties:

1. **Addition consistency**: Adding an element should be equivalent to combining the bag with a singleton bag containing that element

2. **Removal consistency**: Removing an element should be equivalent to subtracting a singleton bag; removing a non-existent element should leave the bag unchanged

3. **Fold correctness**: The fold operation must correctly handle element multiplicities—each element must be processed according to its count in the bag

4. **Arithmetic correctness**: Sum and product operations must produce mathematically correct results considering all multiplicities

5. **Large multiplicity handling**: Operations must work correctly even with large multiplicities (e.g., an element appearing 1000 times) without requiring explicit enumeration

6. **Error handling**: Operations should produce appropriate errors when given invalid inputs (e.g., non-bag arguments, or bags with invalid counts like negative numbers)

7. **Short-circuit behavior**: Product should correctly handle zeros without necessarily computing all multiplications
