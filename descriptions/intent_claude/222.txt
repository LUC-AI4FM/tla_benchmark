# Specification Request: Lossy Message Transmission System

## System Overview

I need a formal specification for a message transmission system that models communication from a sender to a receiver through a lossy transmission medium. The system should capture the realistic scenario where messages can be lost in transit.

## System Description

The system consists of three components:
1. **Sender**: Holds a finite set of messages that need to be transmitted
2. **Transmission Medium**: An intermediate channel that carries messages but may lose them
3. **Receiver**: Collects successfully delivered messages

## Required Behaviors

The system should model the following operations:

1. **Sending**: The sender can transmit any of its pending messages to the medium, removing it from the sender's queue
2. **Dropping**: The medium can lose any message currently in transit (modeling unreliable transmission)
3. **Receiving**: A message in the medium can be delivered to the receiver; importantly, receiving should not remove the message from the medium (modeling the possibility of multiple copies in transit)

## Initial Conditions

- The sender starts with all messages (a predefined finite set of values)
- The receiver starts empty
- The transmission medium starts empty

## Correctness Property

The key safety property to verify is that **the system never reaches a state where all components are simultaneously empty**. In other words, at least one of the following must always hold:
- The sender still has messages to send, OR
- There are messages in transit in the medium, OR
- The receiver has received at least one message

This property ensures that not all messages can be lost—at least some evidence of the original messages must persist somewhere in the system.

## Additional Notes

- The set of message values should be configurable (e.g., integers 0 through 6)
- The property violation (if reachable) should be detectable within 2×N steps for N messages
- The non-removal of messages on receive intentionally increases state space complexity
