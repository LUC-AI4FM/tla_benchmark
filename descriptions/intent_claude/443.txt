# Specification Request: ENABLED Operator Semantics with Variable Substitution

## System Overview

I need a formal specification that explores the semantic behavior of TLA+'s `ENABLED` operator, particularly how it interacts with variable substitution and parameterized action definitions.

## Goal

Create a test specification that demonstrates and verifies the correct handling of `ENABLED` when:

1. An operator takes both a variable and an action expression as parameters
2. The same variable appears in multiple contexts (as a parameter and as a free variable)
3. Primed and unprimed versions of variables interact within disjunctive action expressions

## Requirements

The specification should define:

1. **A parameterized operator** that checks enabledness of a composite action formed by:
   - A passed-in action expression
   - A stuttering-like step on a passed variable
   - A swap-like step between variables

2. **A composed action** that combines:
   - A constraint on one variable remaining unchanged
   - An invocation of the parameterized operator with specific arguments

## Correctness Properties

The specification should help verify that:

- The `ENABLED` operator correctly evaluates when its argument contains disjunctions of different action patterns
- Variable binding and substitution work correctly when the same identifier appears as both a formal parameter and a module-level variable
- The semantics remain consistent when primed variables appear in multiple branches of a disjunction within an `ENABLED` context

## Purpose

This is a semantic test case for a TLA+ tool implementation, ensuring that subtle interactions between `ENABLED`, variable substitution via parameters, and action composition are handled according to the expected TLA+ semantics.
