# Specification Request: Set and Function Equality Verification

## System to Model

I need a formal specification that serves as a test harness to verify that a TLA+ model checker correctly identifies equivalent representations of sets and function spaces as identical states.

## Goal

The specification should demonstrate that mathematically equivalent but syntactically different representations of the same collections are recognized as a single state by the model checker. This is essentially a sanity check for set-theoretic equality semantics.

## Requirements

1. **State Components**: The system should maintain several different types of collections:
   - A set of integers
   - A set of strings
   - A set of records (with multiple integer-valued fields)
   - A set of functions (from integers to integers)

2. **Initialization**: All collections should be initialized to specific, well-defined values.

3. **State Transitions**: The system should include a transition that rewrites a set using a redundant representation (e.g., including duplicate elements or reordering elements) that should be mathematically identical to the original.

4. **Key Correctness Properties**:
   - The system must have exactly **one distinct reachable state** — the initial state should be the only state, since transitions that produce equivalent collections should not create new states.
   - An invariant should verify that all collections remain equal to their initial values throughout execution.

## Purpose

This specification validates that the model checker properly implements set equality semantics (where `{1, 2, 3}` equals `{3, 3, 2, 1}`) rather than treating syntactically different representations as distinct states. This is important for ensuring the state space is not artificially inflated by equivalent representations.
