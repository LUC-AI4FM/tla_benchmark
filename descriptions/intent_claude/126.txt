# Specification Request: Set-to-Sequence Folding Verification

## System to Model

I need a formal specification that verifies the behavior of a **fold operation over a set that produces a sequence**. Specifically, I want to confirm that when you fold over a finite set by appending each element to build a sequence, the result is a valid permutation of the set's elements.

## Goal

The primary goal is to establish a **static property verification** rather than model a dynamic system. I want to verify that a fold operation that accumulates set elements into a sequence will produce one of the possible orderings of those elements.

## Requirements

1. **Fold semantics**: The fold operation should process each element of a given set exactly once, appending each element to an accumulating sequence that starts empty.

2. **Non-deterministic ordering**: Since sets have no inherent order, the fold may process elements in any order. The specification should account for all possible processing orders.

3. **Correctness property**: When folding over a specific test set (containing the integers 1, 2, and 3), the resulting sequence must be exactly one of the six possible permutations of those three elements. The result should:
   - Contain each element exactly once
   - Have the same length as the set's cardinality
   - Be a valid permutation of the original set

## Context

This is essentially a **sanity check specification** to verify that a fold-set-to-sequence primitive behaves correctly—that it doesn't drop elements, duplicate elements, or introduce spurious values. The system state itself is trivial; the real specification work is in the invariant that constrains the fold operation's output.
