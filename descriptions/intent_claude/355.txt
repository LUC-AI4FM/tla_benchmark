# Specification Request: TLA+ Tuple and Cartesian Product Semantics Verification

## System to Model

I need a test harness that verifies the correct behavior of TLA+'s tuple and Cartesian product operations. This is essentially a conformance test suite for the TLA+ language semantics around these constructs.

## Goal

Create a specification that validates the TLA+ model checker correctly handles:

1. **Cartesian products** of finite sets, including nested products of two or more sets
2. **Tuple membership** testing against Cartesian products
3. **Cartesian products involving infinite sets** (like the integers) combined with function spaces and sequence types
4. **Sequence type membership** testing
5. **Tuple construction** via function mapping syntax and its equivalence to direct tuple notation
6. **Tuple indexing** and domain extraction

## Requirements

The specification must verify the following properties:

### Cardinality of Finite Cartesian Products
- The size of a Cartesian product of finite sets equals the product of their individual sizes

### Membership in Cartesian Products
- Tuples with the correct structure and element types should be recognized as members
- Tuples with incorrect element values (even if types match) should not be members
- Products involving infinite sets (integers), function spaces, and sequence types must correctly accept valid tuples

### Sequence Type Semantics
- Finite tuples of integers should be recognized as members of the sequence-of-integers type
- Membership should respect element constraints (e.g., sequences over restricted subsets of integers)

### Tuple/Function Equivalence
- A function mapping from {1, 2, ..., n} should be equal to the corresponding tuple
- Equality comparison must be element-wise correct

### Tuple Indexing
- Indexing into a tuple should produce the expected elements
- The set of indexed values should match expected results

## Correctness Properties

All test cases must pass, meaning:
- Expected memberships hold
- Expected non-memberships hold
- Expected equalities hold
- Expected inequalities hold
- Cardinality calculations are accurate

The specification should fail (via assertion) if any semantic behavior deviates from the expected TLA+ language semantics for tuples and Cartesian products.
