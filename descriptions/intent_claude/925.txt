# Specification Request: FIFO Queue System for Model Checking

## System Overview

I need a formal specification of a FIFO (First-In-First-Out) queue system that can be verified using a model checker. The system should model the core behavior of a bounded queue where messages or items are processed in the order they arrive.

## Functional Requirements

The system should implement a standard FIFO queue with the following capabilities:

1. **Enqueueing**: Items can be added to the back of the queue
2. **Dequeueing**: Items can be removed from the front of the queue in the order they were added
3. **Order preservation**: The queue must maintain strict FIFO ordering—the first item inserted must be the first item removed

## Model Checking Considerations

Since the queue could theoretically grow without bound (leading to an infinite state space), the specification must support:

1. **Configurable queue length limit**: The maximum queue size should be parameterizable so that different model sizes can be checked without modifying the core specification
2. **State space constraint**: A mechanism to restrict the model checker to only explore states where the queue length does not exceed the configured maximum

## Correctness Properties

The specification should guarantee:

1. **FIFO ordering**: Items are always removed in the same order they were added
2. **No message loss**: Items in the queue are not lost or corrupted
3. **No duplication**: Each enqueued item appears exactly once in the queue

## Design Goals

- Keep the core queue specification clean and reusable, separate from model-checking-specific constraints
- Allow the queue bound parameter to be set externally (e.g., via configuration) rather than hardcoded
- Enable verification of the queue behavior across different bounded sizes to gain confidence in the unbounded system's correctness
