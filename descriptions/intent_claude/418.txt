# Specification Request: Test Suite for Natural Number Arithmetic Operations

## System to Model

A test harness that validates the correctness of arithmetic operations on natural numbers as provided by a standard library.

## Goal

Create a specification that serves as a unit test suite to verify that fundamental arithmetic operations on natural numbers behave according to their mathematical definitions. The tests should execute when the specification is checked and report success or failure for each operation being validated.

## Operations to Verify

The test suite should validate the following arithmetic operations:

1. **Exponentiation** - Verify that raising numbers to powers produces correct results, including edge cases like any base raised to zero and zero raised to positive powers

2. **Addition and Subtraction** - Confirm basic arithmetic works correctly, and verify that subtracting a larger number from a smaller one does not yield a natural number

3. **Multiplication** - Verify multiplication of multi-digit numbers

4. **Comparison operators** - Test strict less-than, strict greater-than, less-than-or-equal, and greater-than-or-equal relations

5. **Integer division and modulo** - Verify that the division-remainder relationship holds (dividend equals quotient times divisor plus remainder), and test edge cases including division by 1, modulo of 0, and modulo by 1

6. **Integer range construction** - Verify that constructing a range from a larger number to a smaller number yields an empty set, and that valid ranges produce the expected set of consecutive integers

7. **Negative number arithmetic** - Verify correct behavior when operations involve negative intermediate results, including multiplication of negative numbers and modulo with negative dividends

## Correctness Properties

- Each arithmetic operation must produce mathematically correct results
- The specification should halt with an assertion failure if any test fails
- The specification should print confirmation messages for passing tests
- All tests must pass for the invariant to hold

## Requirements

- The test suite should be structured as a static check (no meaningful state transitions)
- Results should be observable through printed output during model checking
- Failed tests must cause the model checker to report an error
