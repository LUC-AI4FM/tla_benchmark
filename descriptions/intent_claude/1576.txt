Specify a concurrent queue system shared among multiple processes, where the queue supports both enqueue and dequeue operations from either end. There is a fixed set of values that can be enqueued and a set of concurrent processes, each of which repeatedly performs one of the following: enqueue a chosen value at the back of the queue, enqueue a chosen value at the front of the queue, report the queue as full without modifying it, dequeue from the front of the queue, dequeue from the back of the queue, or report the queue as empty when no elements are present. Each operation produces a result (success, the dequeued value, "full", or "empty") that is visible briefly before being cleared. The system should be modeled with weak fairness so that every process continues to make progress. A state constraint should bound the queue length to at most N elements to keep the state space finite during model checking. No additional safety or liveness properties beyond the fairness and state constraint need to be verified; this is primarily a demonstration of a nondeterministic double-ended concurrent queue with multiple processes.
