# Specification Request: Asynchronous Communication Channel

## System to Model

I need a formal specification of a simple asynchronous communication channel that allows a sender and receiver to exchange data values without a shared clock. This should model a basic handshaking protocol where both parties coordinate through signaling to ensure reliable data transfer.

## Functional Requirements

The system should support two operations:

1. **Sending data**: A sender should be able to place a data value into the channel when the channel is ready to accept new data.

2. **Receiving data**: A receiver should be able to acknowledge receipt of data when new data is available.

The protocol must ensure proper alternation—the sender cannot send new data until the previous data has been acknowledged, and the receiver cannot acknowledge unless there is new unacknowledged data waiting.

## Handshaking Mechanism

The channel should use a two-phase handshaking protocol where:
- The sender signals that new data is available
- The receiver signals acknowledgment of receipt
- These signals toggle back and forth, allowing the parties to stay synchronized without a global clock

The channel starts in an idle/synchronized state where both parties agree no data is pending.

## Correctness Properties

The specification must guarantee:

1. **Type safety**: The channel state must always consist of a valid data value and valid signaling bits.

2. **No data loss or duplication**: The handshaking ensures each sent value can be received exactly once before the next value is sent.

3. **No deadlock in the protocol logic**: The alternating signal mechanism should allow indefinite continued operation (though the specification need not require progress).

## Data Model

The specification should be parameterized over an arbitrary set of data values that can be transmitted through the channel.
