# Specification Request: Alternating Bit Protocol with Correctness Verification

## System to Model

I need a formal specification of the **Alternating Bit Protocol**, a fundamental reliable data transfer protocol that operates over unreliable communication channels. The protocol should ensure reliable message delivery between a sender and receiver despite the possibility of message loss or corruption in the underlying channels.

## System Description

The system consists of:
- A **sender** that transmits data messages along with a single-bit sequence number
- A **receiver** that accepts messages and sends acknowledgments back to the sender
- **Two unreliable channels**: one for data messages (sender to receiver) and one for acknowledgments (receiver to sender)

The protocol works by having the sender attach an alternating bit (0 or 1) to each message. The sender retransmits the current message until it receives an acknowledgment with the matching bit, at which point it flips its bit and moves to the next message. The receiver similarly tracks which bit it expects and only accepts messages with the correct bit.

## Requirements

1. **Reliable delivery**: Every message that the sender commits to sending must eventually be received by the receiver
2. **No duplication**: The receiver should not deliver duplicate copies of the same logical message
3. **Order preservation**: Messages should be delivered in the order they were sent

## Key Correctness Properties

1. **Liveness (Leads-to property)**: When the sender has a message to transmit and is waiting for acknowledgment, that message must eventually be successfully received by the receiver

2. **Refinement correctness**: The protocol implementation should correctly implement a higher-level specification of reliable data transfer—the sequence of values received should match the sequence of values sent

3. **Type safety**: All protocol variables should maintain their expected types and value ranges throughout execution

## Model Checking Constraints

For practical verification, I need the ability to bound the lengths of both message and acknowledgment queues to enable finite-state model checking while still exploring meaningful protocol behaviors.
