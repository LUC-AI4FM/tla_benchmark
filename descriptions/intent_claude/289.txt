# Specification Request: Clock Synchronization with Uniform Advancement

## System Description

I need a formal specification for a distributed system consisting of a fixed set of processes, where each process maintains its own local clock. The system should model how these clocks evolve over time and track the relative drift between every pair of process clocks.

## Functional Requirements

1. **Initial State**: Each process starts with some non-negative integer clock value. The pairwise drift between any two processes should be computed as the difference between their respective clock values.

2. **Clock Advancement**: The system should model a scenario where all process clocks advance uniformly—that is, in each step, every clock increases by the same positive amount. After clocks advance, the drift values between all pairs should be recalculated based on the new clock values.

## Key Correctness Property

The critical invariant this system must maintain is **drift preservation**: when all clocks advance uniformly by the same amount, the relative drift between any pair of processes must remain unchanged. In other words, if process A's clock was 5 units ahead of process B's clock before the advancement, it should still be exactly 5 units ahead after the advancement.

## Purpose

This specification is intended to serve as a performance benchmark for comparing different implementation approaches to state updates—specifically, comparing direct functional construction of new state versus iterative fold-based construction. The correctness property should hold regardless of which computational approach is used to implement the clock updates.
