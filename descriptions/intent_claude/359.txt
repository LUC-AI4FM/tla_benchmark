# Specification Request: TLA+ Model Checker Prime Expression Handling Test Suite

## System to be Modeled

A test harness for validating that a TLA+ model checker correctly evaluates expressions containing primed variables (next-state references) in various syntactic contexts.

## Goal

Create a specification that exercises the model checker's ability to properly handle primed variable expressions across different TLA+ language constructs. The system should transition through a minimal number of states while verifying that primed variables are correctly evaluated in conditionals, set operations, function applications, and other expression forms.

## Functional Requirements

1. **Minimal State Space**: The system should produce exactly two distinct states—an initial state and one successor state—to keep verification simple while still exercising the prime-handling logic.

2. **Deterministic Transition**: The transition from the initial state to the successor state should have a predictable, known outcome that can be verified against expected values.

3. **Expression Contexts to Test**: The specification should verify correct handling of primed variables in:
   - Conditional expressions (IF-THEN-ELSE)
   - Equality and inequality comparisons
   - Set membership and set construction
   - Function application and function update expressions
   - Quantified expressions (existential and universal)
   - CHOOSE expressions
   - CASE expressions
   - Implication expressions
   - Set operations (SUBSET, UNION, set comprehension)
   - Function domain expressions
   - Operator arguments

4. **Failure Detection**: Each test case should include an assertion that fails if the primed expression evaluates incorrectly, allowing the model checker's behavior to be verified through successful completion without assertion violations.

## Correctness Properties

1. **No Assertion Failures**: The model checker should complete without triggering any assertion failures, indicating all primed expressions were evaluated correctly.

2. **State Reachability**: The system should reach exactly the expected number of distinct states, confirming the transition logic is working as intended.

3. **Invariant Preservation**: A trivially true invariant should hold throughout execution, ensuring the model checker processes the entire state space.
