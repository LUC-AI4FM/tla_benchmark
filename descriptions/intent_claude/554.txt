# Specification Request: N-Process Peterson's Mutual Exclusion Algorithm

## System to Model

I need a formal specification of Peterson's mutual exclusion algorithm generalized to N processes. This is a classic software-based solution for ensuring that multiple concurrent processes can safely access a shared critical section without hardware support for atomic operations.

## System Description

The system consists of N processes that repeatedly cycle through three phases:
1. A **non-critical section** where they perform local work
2. An **entry protocol** where they compete for access to the critical section
3. A **critical section** where they have exclusive access to shared resources
4. An **exit protocol** where they release their claim

The N-process generalization uses a "filter lock" approach where processes must pass through N-1 levels of competition before entering the critical section. At each level, processes indicate their interest and defer to others if they were the last to arrive at that level.

## Key Requirements

### Functional Requirements
- Processes should be able to enter the critical section by progressing through multiple levels of contention
- At each level, a process must wait if another process is at the same or higher level and the current process was the last to register at that level
- Upon exiting, a process must release its claim so others can proceed

### Correctness Properties

**Safety (Mutual Exclusion):**
- At most one process may be in the critical section at any given time

**Liveness (Starvation Freedom):**
- Under fair scheduling, any process that wishes to enter the critical section will eventually do so
- No process should be indefinitely bypassed by other processes

## Assumptions
- N is a positive integer representing the number of processes
- Processes are numbered from 0 to N-1
- Individual read and write operations to shared memory are atomic
- Processes may fail only in the non-critical section (or we assume no failures)
