# Specification Request: Type Error Detection in Operator Arguments

## System to Model

A simple state machine that exercises a scenario where an operator receives an argument of the wrong type—specifically, where an integer is passed to an operation that expects a set.

## Goal

The purpose of this specification is to test or demonstrate how the model checker handles type mismatches at runtime. It simulates a common user error where a primitive value (like an integer) is mistakenly provided in place of a structured value (like a set or the domain of a sequence).

## Requirements

1. The system should have a single state variable that starts at an initial value.

2. The transition should invoke a helper operation that internally attempts to treat its argument as a set (by iterating over its subsets).

3. The specification should trigger an error condition when the operation is called with an integer instead of a set, mimicking mistakes such as passing a raw integer where the domain of a sequence was intended.

## Key Correctness Properties

The primary concern is not a temporal property to verify, but rather observing how the system behaves when operators are applied to values outside their expected types. The specification serves as a test case for tooling behavior around:

- Detection of type errors during evaluation
- Quality of error messages and stack traces when such errors occur
- Proper handling of invalid inputs to set-theoretic operations
