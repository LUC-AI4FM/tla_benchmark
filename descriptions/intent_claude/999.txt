# Specification Request: Simple Resource Allocator

## System Overview

I need a formal specification for a **resource allocation system** where multiple clients can request, receive, and return shared resources from a common pool. This is a classic mutual exclusion problem applied to resource management.

## System Description

The system consists of:
- A fixed set of **clients** that compete for resources
- A fixed set of **resources** that can be allocated to clients
- A pool of **available resources** that are not currently held by any client

## Required Operations

The system must support three types of operations:

1. **Request**: A client can request a set of resources they wish to obtain
2. **Allocate**: Resources can be allocated to a client from the available pool (the client receives resources they requested that are currently available)
3. **Return**: A client can return some or all of their currently held resources back to the available pool

## Key Correctness Properties

The specification must guarantee the following safety properties:

### 1. Type Safety
All state variables must maintain proper types throughout execution:
- The set of pending requests for each client must always be a valid subset of resources
- The set of allocated resources for each client must always be a valid subset of resources
- The available pool must always be a valid subset of resources

### 2. Mutual Exclusion on Resources
**No resource may ever be allocated to more than one client simultaneously.** This is the critical safety property: at any point in time, the resources held by any two distinct clients must be completely disjoint. There must be no overlap in resource ownership.

## Intent

This specification models a fundamental resource allocation pattern that appears in operating systems (memory allocation, device management), distributed systems (lock services), and cloud infrastructure (capacity allocation). The goal is to have a formally verified model that provably maintains exclusive ownership of resources while allowing dynamic allocation and deallocation.
