# Specification Request: Message Ordering with Ballot Monotonicity

## System Overview

I need a formal specification for a message-based system where messages are tagged with sequence numbers and ballot numbers. The system should model how new messages are added to a message set over time.

## System Description

The system maintains:
- A collection of messages, where each message contains a sequence number and a ballot number
- A counter tracking the current/next sequence number to be assigned

## Behavior Requirements

The system should support an operation that:
- Creates a new message with the current sequence number and some ballot number
- Adds this message to the existing collection
- Advances the sequence number counter

## Initial State Requirements

The system should start in a state where:
- Some messages may already exist in the collection
- All existing messages have sequence numbers strictly less than the current counter value
- This represents a valid "history" of previously sent messages

## Correctness Property

The key property to verify is **ballot monotonicity with respect to sequence ordering**: for any two messages in the system, if one message has a strictly higher sequence number than another, then it must also have a ballot number that is at least as large.

In other words, as sequence numbers increase, ballot numbers must never decrease. This captures a consistency requirement where later messages (by sequence) reflect knowledge of at least as recent a ballot as earlier messages.

## Purpose

This specification is intended to test whether the message-sending operation preserves ballot monotonicity, or whether it's possible for the system to violate this ordering invariant. The goal is to find counterexamples or confirm that the property holds under the given constraints.
