# Specification Request: TLA+ Operator Alias Definability Test

## Goal

Create a test specification to verify that the TLA+ tooling (specifically TLC model checker) correctly handles user-defined operators that use symbolic/mathematical operator aliases as their names.

## System Description

This is not a real distributed system or algorithm—it is a **language feature test harness**. The specification should define a minimal state machine that exercises the ability to:

1. Define custom binary operators using various mathematical symbol aliases available in TLA+ syntax
2. Use those custom operators in state transitions
3. Successfully model-check specifications that employ these operator definitions

## Requirements

The test should:

- Define multiple custom binary operators using different symbolic notations, including:
  - Circle-based mathematical symbols (circled plus, minus, dot, slash, times)
  - Composition operator
  - Modulo symbol
  - Comparison/ordering symbols (less-than-or-equal, greater-than-or-equal)

- Each operator definition should be trivial (e.g., simply return one of its arguments) so that the test focuses on *parseability and definability* rather than semantic correctness

- Include a simple state machine that invokes each defined operator, ensuring the model checker must process these operator applications during exploration

## Correctness Properties

The primary "correctness property" here is implicit: **the specification should parse, typecheck, and model-check without errors**. The test aims to expose any bugs in the toolchain related to handling operator aliases, particularly cases where certain symbols may be incorrectly processed or cause tool failures.

## Notes

Document any operators that are known to cause issues with specific tool versions, as this specification serves as a regression test for tooling compatibility with TLA+'s full operator syntax.
