# Specification Request: Extended Finite Set Operations Library

## Overview

I need a formal specification that defines and validates a library of extended operations on finite sets. This library should provide utility functions that go beyond the standard finite set operations, with a focus on correctness and computational efficiency.

## Required Operations

### 1. Counting with Predicates
An operation that counts how many elements in a set satisfy a given boolean predicate. This should be equivalent to computing the cardinality of the filtered subset, but must be implemented in a way that avoids constructing intermediate sets—allowing it to work efficiently on very large sets (millions of elements) without exceeding memory limits.

### 2. K-Subsets
An operation that returns all subsets of a given set that have exactly k elements. This should:
- Return the empty set when k is negative or exceeds the set's cardinality
- Be equivalent to filtering the powerset by cardinality, but much more efficient
- Handle edge cases like k=0 (returning the set containing only the empty set)

### 3. Fold/Reduce Over Sets
An operation that combines all elements of a set using a binary operator and an initial value. This must handle large sets efficiently without stack overflow issues.

### 4. Unique Choice
An operation that selects the unique element from a set satisfying a predicate, with the requirement that exactly one such element exists. It should produce an error if:
- No element satisfies the predicate
- Multiple elements satisfy the predicate
- The set is empty

### 5. Symmetric Difference
An operation that computes the symmetric difference of two sets (elements in either set but not in both).

### 6. Numeric Aggregations
- Sum of all elements in a numeric set
- Product of all elements in a numeric set
- General reduction with a custom binary operator and initial value

### 7. Set Flattening
An operation that takes a set of sets and returns their union (flattening one level of nesting).

## Correctness Properties

1. **Equivalence to naive definitions**: Each optimized operation must produce results identical to the straightforward mathematical definition (e.g., k-subsets must equal the filtered powerset)

2. **Boundary conditions**: Operations must handle edge cases correctly (empty sets, out-of-range parameters, singleton sets)

3. **Scalability**: Counting and folding operations must work on sets far larger than could be explicitly enumerated

4. **Set normalization**: Operations must handle sets with duplicate element specifications correctly (duplicates should be automatically eliminated per set semantics)

5. **Commutativity of equality**: Results should compare equal regardless of which side of the equality they appear on (verifying proper value representation)
