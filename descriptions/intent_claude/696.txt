# Specification Request: JSON Serialization Utility Library

## Overview

I need a utility library for TLA+ that provides JSON serialization and deserialization capabilities. This library should allow TLA+ values (records, tuples, sequences, and scalar values) to be converted to JSON string representations and enable reading/writing JSON data to files.

## Goals

The primary purpose is to bridge TLA+ data structures with the JSON format, enabling:
1. Conversion of TLA+ values into human-readable JSON strings for debugging or output
2. File-based persistence of TLA+ values in JSON format
3. Loading external JSON data into TLA+ specifications

## Required Functionality

### String Conversion

- **Generic conversion**: Convert any TLA+ value to its JSON string equivalent, automatically detecting whether it should be represented as a JSON object or array
- **Explicit array conversion**: Force conversion of a value to a JSON array format (square brackets with comma-separated elements)
- **Explicit object conversion**: Force conversion of a value to a JSON object format (curly braces with key-value pairs)

### Type Mapping

The conversion should follow these mappings:
- TLA+ records → JSON objects (with string keys and corresponding values)
- TLA+ tuples/sequences → JSON arrays (ordered list of values)
- TLA+ scalar values (strings, numbers, booleans) → Their natural JSON representations
- Empty structures should produce empty JSON objects `{}` or arrays `[]` as appropriate

### File Operations

- **Serialize to file**: Write a TLA+ value to a specified file path in standard JSON format
- **Deserialize from file**: Read a JSON file and return the corresponding TLA+ value
- **Newline-delimited JSON support**: Support for NDJSON format where multiple JSON values are stored one per line, both for reading and writing

## Key Requirements

1. The library should handle nested structures correctly
2. Record field names should become JSON object keys (as strings)
3. The conversion functions should work with any valid TLA+ value that has a reasonable JSON representation
4. File operations should use absolute file paths
5. Deserialization should reverse the serialization mappings (JSON objects → records, JSON arrays → tuples)

## Usage Context

This is a utility module intended to be imported by other TLA+ specifications. It provides helper functions rather than modeling a system with state transitions. The functions should be usable within TLA+ expressions for debugging output, test data generation, or integration with external tools.
