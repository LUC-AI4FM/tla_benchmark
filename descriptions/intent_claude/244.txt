# Specification Request: Type Alias Validation in a Type System

## Overview

I need a formal specification for testing the error detection capabilities of a type checker that supports type aliases. Specifically, the system should verify that the type checker correctly identifies and reports errors when type aliases are referenced but never defined.

## System Description

The system under consideration is a type checker for a specification language that supports:
- User-defined type aliases (custom named types)
- Type annotations on operators/functions
- Parameterized types (like sets of a given element type)

## Requirements

1. **Type Alias Declaration Requirement**: When a type annotation references a custom type name (a type alias), that alias must be explicitly declared somewhere in the specification.

2. **Error Detection**: The type checker must detect and report an error when:
   - A type annotation uses a type alias name
   - That type alias has no corresponding definition in the module

3. **Scope of Checking**: The validation should cover type annotations on all operators and functions in the module.

## Key Correctness Properties

- **Completeness of Type Definitions**: Every type name referenced in any type annotation must either be a built-in type or have a corresponding type alias definition.

- **Error Reporting**: The system must not silently accept specifications that reference undefined type aliases—it must produce a clear complaint/error message.

## Goal

Create a test case that exercises the type checker's ability to catch missing type alias definitions, ensuring the type system properly enforces that all referenced types are well-defined before proceeding with type checking.
