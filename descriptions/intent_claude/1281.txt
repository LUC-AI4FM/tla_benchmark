# Specification Request: Cyclic Counter Systems with Bidirectional Transitions

## System Overview

I need formal specifications for cyclic counter systems where a single state variable can be modified by two different transition mechanisms that move in opposing or overlapping directions. The goal is to explore how fairness assumptions on one type of transition affect guarantees about the other.

## Systems to Model

### System 1: Three-State Cycle with Forward and Nondeterministic Transitions
- A counter that cycles through three possible states (0, 1, 2)
- One transition type increments the counter in a fixed forward direction (wrapping around)
- Another transition type can set the counter to any valid state nondeterministically
- The system starts in the initial state (0)

### System 2: Four-State Cycle with Opposing Transitions
- A counter that cycles through four possible states (0, 1, 2, 3)
- One transition type moves the counter forward (incrementing with wraparound)
- Another transition type moves the counter backward (decrementing, with wraparound from the initial state to the maximum)
- The system starts in the initial state (0)

## Key Questions to Investigate

The primary purpose is to analyze the relationship between fairness and liveness:

1. **Fairness Transfer**: If we guarantee that one transition type is taken fairly (infinitely often when enabled), does this imply the other transition type must also occur infinitely often?

2. **Liveness Under Opposing Forces**: When two transition types can "undo" each other's effects, what liveness properties can be guaranteed under various fairness assumptions?

3. **Progress Properties**: Under what fairness conditions can we guarantee the system repeatedly returns to specific states or that specific transitions keep occurring?

## Correctness Properties to Verify

- Whether weak fairness on nondeterministic/backward transitions implies weak fairness on deterministic/forward transitions
- Whether weak fairness on one direction guarantees that the other direction's transitions occur infinitely often
- Whether the system eventually returns to its initial state repeatedly
- Basic responsiveness: if the system leaves a particular state, it eventually changes again

The specifications should allow checking both positive properties (what holds) and their negations (to find counterexamples demonstrating what fails).
