# Specification Request: TLA+ Parser Test Suite for Infix Operator Handling

## Goal

Create a comprehensive test suite to verify that a TLA+ parser correctly handles all infix operator symbols when they are passed as arguments to higher-order operators. The system should validate that user-definable infix operators, built-in operators, and special temporal/action operators are all parsed and resolved correctly.

## System Description

The test suite should verify the parser's ability to:

1. **Accept operator symbols as first-class arguments**: When a higher-order operator takes an operator parameter (e.g., a binary operator), the parser must correctly recognize and pass any valid infix operator symbol.

2. **Handle user-defined infix operators**: The full set of TLA+ infix operator symbols that users can define (approximately 78 different symbols including arithmetic, relational, set-theoretic, and miscellaneous symbols) should all be usable as operator arguments.

3. **Handle built-in operators**: Standard boolean operators (implication, equivalence, conjunction, disjunction) and set operators (membership, subset, intersection, union, difference) should work correctly when passed as arguments.

4. **Handle temporal and action operators**: Special operators used in temporal logic specifications should be recognized in operator parameter contexts.

5. **Support alternative syntax forms**: Where multiple notations exist for the same operator (e.g., different spellings or ASCII vs. symbolic forms), all variants should be handled consistently.

## Key Requirements

- Every user-definable infix operator symbol must be passable as an argument to a higher-order operator
- Built-in operators with fixed meanings must evaluate correctly when passed as arguments
- Operators from external modules (such as TLC-specific operators for function construction) must work in this context
- The parser must handle whitespace variations around operator symbols
- Symbolic notation and backslash-command notation (where both exist) must be treated as equivalent

## Correctness Properties

1. **Completeness**: All valid TLA+ infix operator symbols are recognized in operator-argument positions
2. **Semantic preservation**: When an operator is passed as an argument and then applied, it produces the same result as direct application
3. **Syntax equivalence**: Alternative notations for the same operator behave identically
4. **No false positives**: Invalid operator symbols are rejected appropriately
