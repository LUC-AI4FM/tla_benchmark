# Specification Request

## System Overview

I need a formal specification for a simple state machine with two numeric counters that demonstrates various transition patterns and includes computationally expensive invariant checking.

## System Description

The system maintains two state components: a primary counter and a secondary counter. The primary counter starts at a small positive value (between 1 and 3), while the secondary counter starts at zero.

## Required Behaviors

The system should support several types of transitions:

1. **Increment**: The primary counter can be incremented by one while the secondary counter remains unchanged.

2. **No-op**: A transition that leaves both counters unchanged (essentially a stutter step that's always enabled when counters are natural numbers).

3. **Type change**: Under a specific condition (primary counter equals 42), the system can transition both counters to boolean values, representing a kind of "mode switch" or type violation scenario.

4. **Decrement**: The primary counter can non-deterministically decrease to any value between zero and its current value.

5. **Unreachable transitions**: Several transitions that are guarded by an impossible condition (primary counter being negative, which cannot happen from valid initial states) - these exist to test specification coverage analysis.

## Correctness Properties

The specification should verify that both counters always remain natural numbers. This property should catch the type-change transition if it ever becomes enabled.

## Additional Requirements

- Include a state constraint to bound exploration (primary counter below 20) for finite model checking.
- The invariants should include deliberately expensive computations (iterating over power sets) to support performance analysis and coverage/cost measurement of invariant checking.
- Include multiple equivalent formulations of unchanged-variable expressions and invariant conditions to test tooling's handling of syntactic variations.

## Purpose

This specification appears designed for testing a model checker's coverage analysis, cost attribution, and handling of unreachable code paths, rather than modeling a real-world system.
