# Specification Request: Hour Clock System

## System Overview

I need a formal specification of a simple hour clock that tracks time in a 12-hour format. The clock should model the basic behavior of an analog clock's hour hand, cycling through valid hour values.

## Requirements

### Basic Behavior

The system should represent a clock that:
- Maintains the current hour as its state
- Advances through valid hour values over time
- Wraps around appropriately when reaching the end of its cycle (e.g., after 12 comes 1)

### State Constraints

- The hour value must always be within the valid range for a 12-hour clock (typically 1 through 12)
- The clock should be able to start at any valid hour

### Transitions

- The clock advances by incrementing the hour
- When the maximum hour is reached, the next transition should wrap back to the minimum valid hour
- The system may also allow the clock to stutter (remain unchanged) to model real-time behavior

## Key Correctness Properties

### Invariant Preservation

**The most critical property**: Once the clock is initialized with a valid hour, it must *always* remain in a valid state. Specifically:

- The hour value must remain within the valid range (1-12) throughout all possible executions
- This validity property must be an invariant that holds in every reachable state
- The property should be preserved by every possible state transition, including both normal tick operations and stuttering steps

## Verification Goals

The specification should support proving that the validity invariant is maintained by:
1. Showing the initial state satisfies the invariant
2. Showing every transition preserves the invariant (inductive step)

This ensures the clock can never enter an invalid state where the hour falls outside the acceptable range.
