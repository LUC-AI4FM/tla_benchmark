# Specification Request: Set Element Addition and Removal System

## System Overview

I need a formal specification for a simple system that manages a collection of elements, where elements can be dynamically added to or removed from the collection over time.

## System Description

The system should model a set data structure that starts empty and evolves through discrete steps. At each step, the system can either:

1. Add a single element from a predefined universe of possible values (if not already present), or
2. Remove a single element from the current collection (if any elements exist)

The universe of possible elements should be configurable as a parameter to the specification.

## Requirements

- The collection must start empty
- Only elements from the predefined universe can be added
- Adding an element that's already in the collection should not be possible (standard set semantics)
- Removing an element requires it to be present in the collection
- Each step modifies the collection by exactly one element (either adding or removing)

## Correctness Property to Verify

The key property I want to check is **reachability of completeness**: I want to verify whether the system can ever reach a state where the collection contains every element from the universe.

Specifically, the invariant should assert that the collection is never complete (i.e., never equals the full universe of values). This invariant is expected to be **violable** — the model checker should find a counterexample demonstrating that completeness is indeed reachable.

## Purpose

This specification serves as a test case for verifying that a model checker correctly handles set union operations and can find the minimal path to a target state. The counterexample should demonstrate that starting from an empty set, exactly N steps are required to reach a complete set of N elements.
