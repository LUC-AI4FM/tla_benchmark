# Specification Request: Recursive Function Definition Test Suite

## Overview

I need a TLA+ specification that serves as a test harness for verifying that the TLA+ model checker correctly handles recursive function definitions, particularly those with complex structures involving nested arrays and multiple indices.

## Goal

The purpose is to validate the TLA+ tooling's ability to evaluate recursive functions that:
1. Return array/function values (not just scalars)
2. Use single-parameter recursion with nested array results
3. Use multi-parameter recursion (functions indexed by tuples)
4. Have recursion that depends on a global variable

## Requirements

### Recursive Function Patterns to Test

1. **Single-index recursion returning nested arrays**: A recursive function indexed by one parameter that returns a two-dimensional structure, where the recursive call may appear in different branches depending on index values.

2. **Single-index recursion with variable-sized domains**: A recursive function where the returned array's domain depends on the index, and the function incorporates a global state variable in its computation.

3. **Multi-index recursion**: A recursive function indexed by a pair of parameters that returns an array, with recursion occurring along different dimensions based on conditional logic.

### Correctness Properties

The specification must verify through invariant checks that:

- Specific computed values match expected results (e.g., particular index lookups yield known integers)
- Domain expressions are correctly computed (the set of valid indices for returned arrays matches expectations)
- Multi-dimensional indexing works correctly (accessing nested structures via chained or tuple-based indexing)
- The interaction between recursion and a mutable variable produces correct results

### Test Coverage

The test suite should include approximately 12 distinct checks covering:
- Scalar value lookups at various indices
- Domain verification for nested function results
- Domain verification for tuple-indexed functions
- Equality checks against explicitly constructed array values
- Deep indexing through multiple levels of nesting

## Constraints

- The system state can be minimal (essentially static) since the focus is on function evaluation, not state transitions
- All recursive functions should be defined over small finite domains (e.g., 0 to 5) to ensure tractable evaluation
- Test results should be clearly reported with pass/fail output for each case
