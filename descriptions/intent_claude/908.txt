# Specification Request: Asynchronous Communication Channel

## System to Model

I need a formal specification of a simple asynchronous communication channel that allows a sender and receiver to exchange data values without a shared clock. This should model a basic handshaking protocol for reliable point-to-point communication.

## Functional Requirements

The system should support two fundamental operations:

1. **Sending data**: A sender should be able to transmit a data value through the channel, but only when the channel is ready to accept new data (i.e., the previous transmission has been acknowledged).

2. **Receiving data**: A receiver should be able to acknowledge receipt of data, but only when there is unacknowledged data waiting in the channel.

The protocol should alternate between these operations—the sender cannot send again until the receiver has acknowledged the previous message, and the receiver cannot acknowledge unless there's something new to acknowledge.

## Key Correctness Properties

The specification must guarantee:

1. **Type safety**: The channel state must always consist of valid data along with proper signaling bits for the handshake mechanism.

2. **No data loss or duplication**: The handshaking mechanism should ensure that each sent message is received exactly once before the next message can be sent.

3. **No spurious operations**: Send and receive operations should only occur when appropriate—sends only when the channel is idle, receives only when data is pending.

## Additional Context

The channel should use a toggle-based signaling approach (rather than explicit "full/empty" flags) to coordinate between sender and receiver. This models a classic hardware-style handshaking protocol where matching signal values indicate an idle channel, and mismatched values indicate pending data.
