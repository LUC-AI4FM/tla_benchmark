# Specification Request: TLA+ Operator Precedence and Associativity Verification

## Goal

Create a test suite that verifies the correct implementation of operator precedence and associativity rules in a TLA+ parser or model checker. The purpose is to ensure that expressions containing user-definable infix operators are parsed according to the language's specified grammar rules.

## System Description

The system under test is the TLA+ language parser's handling of infix operators. TLA+ allows users to define custom infix operators using a variety of symbolic tokens, and each operator has defined precedence levels and associativity rules that determine how expressions are grouped when parentheses are omitted.

## Requirements

### What Must Be Tested

1. **Left associativity of arithmetic operators**: Standard operators like subtraction should associate left-to-right (e.g., `3 - 2 - 1` should equal `0`, not `2`).

2. **Left associativity of user-defined operators**: A broad set of definable infix operators (including symbols like `|`, `&`, `$`, `++`, `--`, `**`, and many LaTeX-style operators like `\oplus`, `\sqcap`, `\bullet`, etc.) should associate left-to-right when chained.

3. **Non-associative operators**: Certain operators should not allow chaining without explicit parentheses.

4. **Relative precedence between operators**: When operators of different precedence levels are mixed in an expression without parentheses, higher-precedence operators should bind more tightly than lower-precedence ones. This includes testing interactions between:
   - Arithmetic-like operators at various precedence levels
   - Comparison/relational operators
   - Range-like operators
   - Multiplicative vs. additive operator classes

### Correctness Properties

1. **Associativity correctness**: For any left-associative operator `op`, the expression `a op b op c` must parse as `(a op b) op c`.

2. **Precedence correctness**: For operators where `op1` has higher precedence than `op2`, the expression `a op1 b op2 c` must parse as `(a op1 b) op2 c`.

3. **Consistency**: The parsing behavior must match the documented TLA+ operator precedence table across all tested operator symbols.

### Scope of Operators

The test should cover the full range of TLA+ user-definable infix operators, including:
- ASCII symbol operators (single and doubled forms)
- Circled operators (oplus, ominus, odot, otimes, oslash)
- Set-theoretic operators (sqcap, sqcup, subset, supset variants)
- Relational operators (prec, succ, sim, approx, etc.)
- Special operators (wr, propto, doteq, etc.)
