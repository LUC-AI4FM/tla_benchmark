# Specification Request: User State Machine System

## Overview

I need a formal specification for a system that manages user lifecycle states. The system should model how users transition through different states in their lifecycle within an application or service.

## System Description

The system tracks the state of multiple users, where each user can be in one of several possible states (such as inactive, active, suspended, etc.). Users should be able to transition between states according to defined rules that govern valid state changes.

## Requirements

1. **Multi-user support**: The system must handle a configurable set of user identifiers, allowing multiple users to exist simultaneously in the system.

2. **State tracking**: Each user has an associated state that the system maintains and updates over time.

3. **State transitions**: Users can move between states according to a defined state machine. The specification should capture all valid transitions and ensure invalid transitions cannot occur.

## Key Properties to Verify

1. **State validity**: Every user must always be in a valid, well-defined state.

2. **Transition integrity**: Only legal state transitions should be possible—users cannot jump arbitrarily between states.

3. **Type safety**: The system state must always conform to the expected structure (valid user IDs mapped to valid states).

## Goals

The specification should allow verification that:
- The user state machine behaves correctly for any number of users
- No user can ever reach an invalid or undefined state
- The system maintains consistency across all state transitions
