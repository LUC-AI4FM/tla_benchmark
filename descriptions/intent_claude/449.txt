# Specification Request: Cartesian Product Operator Validation

## System to Be Modeled

I need a test harness that validates the correctness of Cartesian product operations in TLA+. This is essentially a verification suite for the `\X` (cross product) operator to ensure it behaves correctly across various use cases.

## Requirements

The test suite must verify the following behaviors of Cartesian products:

### Basic Cartesian Product Construction
- The Cartesian product of two finite sets should produce the correct set of ordered pairs
- Products should work correctly with sets of different types (e.g., integers crossed with strings)

### Membership Testing
- Tuple membership in Cartesian products over infinite sets (like natural numbers and integers) must be correctly evaluated
- Both 2-tuples and longer tuples should have correct membership semantics

### Function Definition Over Products
- Functions defined over Cartesian product domains (using tuple parameters) must evaluate correctly
- This includes products of infinite sets like Nat × Int

### Higher-Arity Products
- Cartesian products of three or more sets should produce flat tuples of the appropriate length (not nested pairs)
- Membership and function evaluation should work correctly for these higher-arity products

### Interaction with Other Set Operations
- Products should interact correctly with function spaces, intersection, subset relations, and other set constructs

### Empty Set Behavior
- Any Cartesian product involving an empty set must yield the empty set
- This must hold regardless of which position the empty set appears in
- Various ways of constructing empty sets (filtering with unsatisfiable predicates, empty ranges, set differences that eliminate all elements, etc.) should all be recognized as empty and behave consistently in products

### Record Types with Empty Domains
- Record type constructors with empty field domains should all be equal (since they all represent the empty set of records)

## Correctness Properties

1. **Enumeration correctness**: Finite Cartesian products enumerate exactly the expected tuples
2. **Membership correctness**: Tuple membership tests return the mathematically correct result
3. **Function evaluation correctness**: Functions over product domains compute correctly when applied to tuple arguments
4. **Empty set propagation**: Products involving empty sets always equal the empty set
5. **Associativity of notation**: Multi-way products produce flat tuples as expected by TLA+ semantics
