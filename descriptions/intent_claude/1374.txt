# Specification Request

## System to Model

A test harness for verifying TLA+ module instantiation behavior, specifically focusing on how name resolution works when identifiers in an instantiated module conflict with identifiers (variables or constants) in the parent module.

## Goal

Demonstrate and verify that TLA+ correctly distinguishes between local definitions and definitions imported from instantiated modules, even when they share the same names. This is essentially a test case for the TLA+ tooling's scoping and namespace resolution mechanisms.

## Requirements

1. **Name collision scenario**: The specification should set up a situation where:
   - The main module declares a variable with a particular name
   - An instantiated submodule contains a definition with that same name
   - The main module also uses a constant that may be overloaded differently in the submodule

2. **Proper scoping behavior**: When accessing a name directly, it should resolve to the local variable. When accessing the same name through the instantiated module's namespace, it should resolve to that module's definition.

3. **Observable verification**: The specification should output diagnostic information showing that:
   - The local variable has its expected value
   - The instantiated module's definition (accessed via qualified name) has its distinct expected value
   - Constants behave similarly, with local and instantiated versions maintaining separate values

## Correctness Properties

The system should satisfy whatever behavioral specification is defined within the instantiated module, demonstrating that the instantiation mechanism correctly substitutes parameters while maintaining proper namespace separation.
