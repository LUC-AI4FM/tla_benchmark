# Specification Request: Asynchronous Communication Interface

## System Overview

I need a formal specification for a simple asynchronous communication interface between two components—a sender and a receiver—that exchange data values without relying on a shared clock.

## System Description

The system should model a basic handshaking protocol where:

1. A sender can transmit data values from some set of possible data items
2. A receiver can accept and consume these data values
3. The two parties coordinate using control signals to ensure reliable data transfer

## Functional Requirements

- The sender should be able to place a data value on the channel and signal that it is ready
- The receiver should be able to observe when data is available and acknowledge receipt
- The protocol should alternate properly between sending and receiving phases
- Both parties must coordinate so that data is neither lost nor duplicated

## Correctness Properties

The specification should guarantee:

1. **No data loss**: Every value sent is eventually received
2. **No duplication**: Each transmission results in exactly one reception
3. **Proper synchronization**: The sender does not overwrite data before the receiver has acknowledged it, and the receiver does not read stale or invalid data
4. **Progress**: The system can continuously transfer data (no permanent blocking under fair scheduling)

## Additional Notes

The data set should be treated as an abstract parameter—the specification should work for any finite collection of data values that might be transmitted. The key insight is modeling how two independent processes synchronize through simple binary signaling without any global clock or atomic shared operations beyond reading and writing individual signals.
