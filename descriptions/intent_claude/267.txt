# Specification Request: Record Type Membership Validation

## System to Model

A type checking or validation system for record (struct) data structures, specifically focusing on how record values are checked against record type specifications.

## Goal

Create a formal specification that explores the semantics of record type membership testing, particularly examining cases where a concrete record value is tested against a record type schema that may have different fields than the record itself.

## Requirements

The specification should model:

1. **Record value construction**: The ability to create record values with named fields containing specific values (e.g., integers, strings).

2. **Record type schemas**: Type specifications that define expected field names and their corresponding value domains.

3. **Membership testing**: A mechanism to test whether a given record value belongs to a specified record type.

## Key Scenarios to Explore

The specification must address the behavior when:

- A record value has fewer fields than the type schema specifies (the record lacks a field that appears in the type)
- A record value's field values may or may not fall within the type's specified domains for those fields
- There is a mismatch between what the record contains and what the type requires

## Correctness Properties

The specification should help determine:

1. **Type safety**: What should happen when accessing or validating records against type schemas with mismatched fields?

2. **Well-formedness**: Under what conditions should a record be considered a valid member of a record type?

3. **Field correspondence**: Must a record have exactly the fields specified in a type, or are partial/superset relationships permitted?

This specification is intended to explore edge cases in record typing semantics and identify potentially ill-typed operations.
