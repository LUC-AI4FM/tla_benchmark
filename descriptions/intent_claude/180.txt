# Specification Request: Function Set Membership Validation

## System Overview

I need a formal specification to verify that a model checker correctly handles **nested function sets** — specifically, sets that contain functions whose codomains are themselves function sets.

## Goal

The purpose of this specification is to serve as a **regression test** for a model checking tool's ability to represent and reason about complex nested mathematical structures. The system should demonstrate that the tool can correctly:

1. Construct sets containing higher-order functions (functions that map to other functions)
2. Select elements from such nested function sets
3. Maintain these structures through state transitions

## Requirements

### Data Structure
The specification must involve:
- A set containing functions where:
  - The domain consists of sequences of boolean values
  - The codomain consists of functions from integers to integers
- This creates a two-level nesting: a set of functions, where each function's range is itself a set of functions

### Behavior
- The system should initialize by non-deterministically selecting one element from a small, finite set of these nested function structures
- The system should also track a boolean flag
- After initialization, the state should remain unchanged (a "stutter" specification)

### Correctness Property
The specification should include a simple invariant that can be checked to verify the model checker processes the state space correctly. The specific property being verified is less important than confirming the tool can handle the complex type structure without errors.

## Context

This is specifically intended to catch regressions in tools that perform symbolic model checking, where the internal representation of nested function sets may be handled differently than simple sets or single-level function sets.
