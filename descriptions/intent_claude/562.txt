# Specification Request: Transaction Commit Protocol

## System Overview

I need a formal specification for a distributed transaction commit protocol involving multiple resource managers. The system should model how a set of independent participants coordinate to reach a consistent decision about whether to commit or abort a transaction.

## System Description

The system consists of a fixed set of resource managers (participants) that must collectively decide the outcome of a distributed transaction. Each resource manager independently progresses through states as it participates in the commit protocol.

## Required Behavior

1. **Initial State**: All resource managers begin in an active/working state, participating in the transaction.

2. **Preparation Phase**: Any working resource manager may signal that it is ready to commit by moving to a prepared state.

3. **Commit Decision**: A resource manager that has prepared may decide to commit, but only if all resource managers in the system have either already committed or are prepared to do so. This ensures unanimous readiness before any commit occurs.

4. **Abort Decision**: A resource manager may decide to abort if no resource manager has yet committed. This can happen whether the manager is still working or has already prepared.

## Key Correctness Properties

The specification must guarantee:

1. **Consistency**: The system must never reach a state where one resource manager has committed while another has aborted. All participants must ultimately agree on the transaction outcome.

2. **Commit Safety**: A commit can only occur when all participants have demonstrated readiness (reached the prepared state). No premature commits are allowed.

3. **Abort Safety**: Once any participant has committed, no other participant may abort. The abort option is only available while the transaction outcome remains undecided.

## Purpose

This specification should serve as a foundation for understanding distributed commit protocols and verifying that the coordination rules prevent inconsistent transaction outcomes across participants.
