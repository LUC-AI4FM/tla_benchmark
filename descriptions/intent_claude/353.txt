# Specification Request: TLA+ Function and Domain Operator Semantics Test Suite

## System to Model

I need a formal specification that serves as a **test harness for validating the behavior of TLA+'s function constructs**, specifically focusing on the `DOMAIN` operator and function set expressions (the `[A -> B]` notation).

## Goal

The purpose is to verify that a TLA+ model checker correctly implements the semantics of:

1. **The DOMAIN operator** - extracting the domain from various kinds of functions
2. **Function set membership** - determining whether a given function belongs to a set of functions `[A -> B]`
3. **Function set cardinality** - correctly computing the size of function spaces
4. **Multi-argument function domains** - handling functions with tuple-based domains

## Requirements

The specification should validate the following correctness properties:

### Domain Extraction
- The domain of a function defined over integers should include all integers
- The domain of a function defined over a finite set should have the correct cardinality
- The domain of a function defined over a power set should recognize set elements as valid domain members
- The domain of a record-style function should be a set of field name strings
- The domain of a multi-argument function should be the Cartesian product of the argument sets

### Function Set Membership
- A tuple/sequence belongs to a function set `[1..n -> S]` if and only if it has exactly the right length AND all values are in S
- Functions with incorrect domain size must not be members
- Functions with values outside the codomain must not be members
- Functions with non-matching domain types must not be members

### Cardinality of Function Sets
- The cardinality of `[A -> B]` should equal `|B|^|A|` for finite sets
- Filtered function sets should have appropriately reduced cardinality

### Expression Simplification
- Equivalent expressions (like `1+1` and `2`) should be treated identically when constructing function sets

## Correctness Properties

The specification must guarantee that all semantic tests pass, meaning:
- Every expected membership relation holds
- Every expected non-membership relation holds  
- Every computed cardinality matches the expected value
- Domain extraction produces exactly the expected sets

This is essentially a **conformance test** ensuring the model checker's implementation matches the mathematical semantics of TLA+'s function theory.
