# Specification Request: Nano Cryptocurrency Protocol

## System Overview

I need a formal specification of the Nano cryptocurrency protocol, which is a distributed ledger system where each account maintains its own blockchain (a "block-lattice" architecture). The system should model how nodes create, sign, and propagate blocks representing balance transfers between accounts.

## Core Requirements

### Account and Block Structure
- Each account is controlled by a private/public key pair
- Accounts maintain individual chains of blocks recording their transaction history
- Blocks must be cryptographically linked through hashes, forming immutable chains
- There should be a genesis state establishing initial account balances

### Operations to Model
- **Send transactions**: An account holder creates a block reducing their balance and designating a recipient
- **Receive transactions**: A recipient creates a block on their own chain to claim a pending incoming transfer
- **Block propagation**: Nodes broadcast blocks to other nodes in the network
- **Ledger updates**: Nodes incorporate validated blocks into their local view of the distributed ledger

### Distributed Network Behavior
- Multiple nodes participate in the network, each maintaining their own copy of the ledger
- Nodes receive and process blocks from other nodes
- The specification should capture the asynchronous nature of block propagation

## Correctness Properties

### Type Safety
- All data structures maintain their expected types throughout execution
- Blocks conform to the required structure with valid references and signatures

### Safety Invariants
- **Conservation of funds**: The total balance across all accounts remains constant (no creation or destruction of value)
- **No double-spending**: An account cannot spend more than its available balance
- **Chain integrity**: Block references must form valid chains with no cycles or dangling references
- **Ownership**: Only the holder of an account's private key can create blocks for that account

## Additional Considerations

The specification should handle hash computation for blocks in a way that maintains the cryptographic linking property—each block references its predecessor, and this chain of references must remain consistent across all nodes' views of the ledger.
