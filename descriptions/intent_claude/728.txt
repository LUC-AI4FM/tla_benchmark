# Specification Request: Undirected Graph Operations Library

## System Overview

I need a formal specification for a library that provides fundamental operations on undirected graphs. The library should support reasoning about graph structure, particularly path-finding and connectivity analysis.

## Core Functionality Required

### Graph Representation
The system should work with undirected graphs consisting of nodes and edges, where each edge connects exactly two distinct nodes.

### Path Finding
The library must be able to compute all simple paths within a graph. A simple path is a sequence of nodes where no node appears more than once. This should handle:
- Empty graphs (no nodes, no edges)
- Graphs with isolated nodes (nodes with no connecting edges)
- Graphs with edges connecting some nodes

### Connectivity Analysis
The library must provide:

1. **Connected Components**: Identify all maximal sets of nodes where any two nodes in the same set are reachable from each other through edges. Isolated nodes should each form their own singleton component.

2. **Pairwise Connectivity**: Determine whether two specific nodes are connected to each other (i.e., belong to the same connected component).

3. **Strong Connectivity Check**: Determine whether an entire graph is strongly connected, meaning all nodes belong to a single connected component.

## Key Correctness Properties

1. **Simple Path Validity**: Every path returned must visit each node at most once, and consecutive nodes in the path must be connected by an edge in the graph.

2. **Component Completeness**: The union of all connected components must equal the full set of nodes in the graph.

3. **Component Disjointness**: Connected components must be mutually exclusive—no node belongs to more than one component.

4. **Connectivity Consistency**: Two nodes are connected if and only if they appear in the same connected component.

5. **Strong Connectivity Equivalence**: A graph is strongly connected if and only if it has exactly one connected component containing all nodes.

6. **Edge Cases**: The specification must correctly handle empty graphs and graphs with no edges (returning appropriate empty sets or singleton components).
