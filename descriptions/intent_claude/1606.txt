# Specification Request: Concurrent Factorial Computation with Mutual Recursion

## System Overview

I need a formal specification of a concurrent system where multiple independent processes each compute the factorial of a number using mutually recursive procedures. The goal is to verify that the recursive factorial algorithm produces correct results even when multiple processes execute concurrently with interleaved steps.

## Functional Requirements

### Computation Model
- The system should compute factorial using two procedures that call each other in alternation (mutual recursion). Each procedure multiplies the current argument into a running product, then calls the other procedure with the argument decremented by one. The recursion terminates when the argument reaches zero.

### Concurrency
- Multiple processes should execute simultaneously, each computing its own factorial independently.
- Each process maintains its own separate result accumulator.
- Processes should be able to interleave their execution steps arbitrarily.
- The system should include a mix of process types (e.g., a set of similar processes plus an additional distinct process) to ensure the specification handles different process identification schemes.

### Input
- Each process computes the factorial of 5 (expected result: 120).

## Correctness Properties

### Safety Property
- Upon completion, each process's result must equal the correct factorial value (120 for input 5).
- This should be verified via assertions that each process checks after its computation completes.

### Liveness Property
- All processes must eventually terminate.
- The system should guarantee progress under fair scheduling—no process should be starved indefinitely.

### Isolation
- The concurrent execution of multiple processes must not cause interference; each process's computation must remain independent despite shared execution infrastructure.

## Purpose

This specification serves to verify that:
1. Mutually recursive procedure calls correctly implement factorial computation
2. The procedure call/return mechanism (including stack management) works correctly
3. Concurrent execution of the algorithm across multiple processes preserves correctness
4. Fair scheduling ensures all processes complete their computations
