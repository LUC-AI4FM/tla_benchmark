# Specification Request: TLA+ Module Instantiation Semantics Verification

## System to Model

A test harness for verifying the correct behavior of TLA+ module instantiation with parameter substitution, specifically focusing on how substitution interacts with primed variables and nested operator arguments.

## Goal

Demonstrate and verify that TLA+ module instantiation correctly handles a subtle semantic case: when a module is instantiated with a variable substitution, and operators from that module are invoked with arguments that themselves contain primed expressions, the substitution and expression evaluation must be handled consistently.

## Requirements

1. **Simple State Space**: The system should have a minimal state that alternates or changes in a predictable pattern, providing a concrete context for testing the instantiation behavior.

2. **Module Instantiation**: The specification must instantiate an external module, substituting a local variable for the imported module's parameter.

3. **Operator Comparison**: Define a local version of an operator that attempts to replicate what the instantiated operator should compute, allowing direct comparison between:
   - Invoking an operator through the instantiated module interface
   - Manually constructing what that operator invocation should expand to

4. **Correctness Property**: The specification must verify that the instantiated operator and its manually-constructed equivalent always produce identical results throughout all behaviors of the system.

## Key Correctness Properties

- **Substitution Consistency**: When accessing an operator via instantiation, the variable substitution must correctly apply to both primed and unprimed occurrences within the operator's definition.

- **Semantic Equivalence**: The instantiated operator invocation must be semantically equivalent to manually performing the same substitution, even when the operator receives complex arguments containing state-transition expressions.
