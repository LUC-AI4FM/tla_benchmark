# Specification Request: Injective Hash Function Verification

## System Overview

I need a formal specification to verify that a hash function mapping a small set of string identifiers to fixed-length bit strings is collision-free (injective).

## Context

We have a hash function that takes string inputs from a known, finite set and produces 6-bit binary strings as output. The goal is to exhaustively verify that this hash function never produces the same output for two different inputs.

## Requirements

### Input Domain
- The hash function accepts exactly five distinct string identifiers as valid inputs
- These represent a small, enumerable set of keys

### Output Domain
- The hash function produces 6-bit binary strings (sequences of 0s and 1s of length 6)

### Correctness Property

The specification must verify **injectivity**: for any two distinct inputs from the allowed set, the hash function must produce distinct outputs. In other words, there should be no hash collisions among the allowed input strings.

## Verification Goal

Rather than modeling dynamic system behavior, this specification should enable exhaustive checking across all possible hash function assignments. The model checker should explore every possible way the hash function could map the five allowed strings to 6-bit outputs, confirming that only collision-free mappings are considered valid.

## Purpose

This serves as a verification harness to confirm that a hash function implementation (or the constraints defining it) guarantees uniqueness of outputs for the given input domain.
