# Specification Request: TLA+ Prime Operator Scoping Semantics

## System to Model

A test harness that validates the correct semantic behavior of TLA+'s prime operator (`'`) when applied in various syntactic contexts involving operator definitions, LET expressions, and variable references.

## Goal

Create a specification that systematically exercises and verifies how the prime operator (which refers to the next-state value of a variable) interacts with different language constructs. The specification should confirm that a TLA+ model checker correctly interprets priming in potentially ambiguous or confusing situations.

## Requirements

The specification must test the following semantic scenarios:

1. **Priming inside operator definitions**: When an operator's body contains a primed variable, verify that the prime refers to the next-state value at the point of use.

2. **Priming an entire operator application**: When the prime operator is applied to an operator call (rather than inside the operator), verify that variables within the operator body are correctly evaluated in the next state.

3. **Priming with parameters**: Distinguish between priming an operator that takes a variable as a parameter versus priming the argument itself before passing it.

4. **Priming LET-bound names**: When a LET expression binds a name to an expression involving variables, verify correct behavior when priming the bound name versus priming the original expression.

5. **Priming operator applications with arguments**: For operators that combine state variables with parameters, verify that priming the application correctly affects the variable references but not the parameter values.

6. **Nested LET with operators**: Verify correct prime semantics for locally-defined operators within LET expressions.

## Correctness Properties

- Each test case must evaluate to the expected boolean result based on the formal semantics of TLA+'s prime operator
- The prime operator must distribute correctly through operator definitions and LET bindings
- Variable confusion must not occur: parameters and state variables must be distinguished correctly even when they share evaluation contexts
- The specification should complete successfully with all test validations passing
