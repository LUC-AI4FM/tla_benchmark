# Specification Request: Record Field Access Safety Checker

## System Overview
I need a formal specification that demonstrates type safety properties for record (struct) data structures, specifically focusing on field access operations.

## Requirements

### Data Model
- The system should define records with named fields, where each field has an associated type (such as strings and integers)
- Records should have a fixed schema defining which fields exist and their types

### Operations to Model
- Field access operations that retrieve values from records by field name

### Key Correctness Properties

The specification should demonstrate and help verify:

1. **Type Safety for Field Access**: Accessing a field that exists in a record's schema should be valid and return a value of the expected type

2. **Detection of Invalid Access**: Attempting to access a field that does not exist in a record's schema should be identifiable as a type error

### Purpose
This specification serves as a test case for a type checking system. It should include both:
- A well-typed record with valid field definitions
- An intentionally ill-typed operation that accesses a non-existent field

The goal is to verify that static analysis tooling (such as a TLA+ type checker) correctly identifies unsafe record field access patterns and reports appropriate type errors when code attempts to access fields that are not part of a record's defined structure.
