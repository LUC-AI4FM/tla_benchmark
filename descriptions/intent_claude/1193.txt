# Specification Request: TLA+ Prime Expression Evaluation Test Suite

## System Overview

I need a formal specification that serves as a **test harness for verifying correct evaluation of primed expressions** in a TLA+ model checker. The system should exercise the model checker's ability to correctly handle the prime operator (which denotes next-state values) in a wide variety of expression contexts.

## Goal

The specification should systematically test that a TLA+ model checker correctly evaluates expressions involving primed variables across many different language constructs. This is essentially a conformance test suite for prime expression handling.

## Requirements

### Basic Behavior
- The system should have a simple state transition that increments a counter from 1 to 2
- This creates exactly two distinct states, providing a controlled environment where the current value and next-state value are both known

### Test Coverage
The specification must verify correct prime expression evaluation in the following contexts:

1. **Conditional expressions**: Using primed values in IF-THEN-ELSE conditions and branches
2. **Equality and inequality**: Direct comparisons involving primed variables
3. **Set membership**: Testing whether primed values are elements of sets
4. **Set construction**: Building sets that contain or are parameterized by primed values
5. **Set comprehension**: Filter and map expressions using primed variables
6. **Quantifiers**: Universal and existential quantification over sets involving primed values
7. **CHOOSE expressions**: Selection from sets containing primed values
8. **Set operations**: SUBSET and UNION operations with primed expressions
9. **Function definitions**: Recursive/parameterized functions that reference primed state
10. **Function application**: Using primed values as function arguments and in domains
11. **EXCEPT expressions**: Function updates where primed values appear in indices or new values
12. **Function set construction**: Arrow notation with primed values in domain or range
13. **Implication**: Logical implication with primed antecedents
14. **CASE expressions**: Pattern matching on primed values
15. **Operator parameters**: Passing primed expressions through user-defined operators

### Correctness Properties

Each test case should:
- Only succeed (allow the transition) when the model checker correctly evaluates the primed expression
- Fail with an assertion and descriptive message if the model checker produces an incorrect result
- The failure branches should be unreachable if the model checker is working correctly

### Expected Outcome
When run against a correct model checker implementation:
- The state space should contain exactly two reachable states
- No assertion failures should occur
- The system should terminate normally after exploring all states
