# Specification Request: Alternating Action System

## System Overview

I need a formal specification for a system that strictly alternates between performing two distinct types of actions. The system must enforce a rigid "first one, then the other" pattern indefinitely.

## Functional Requirements

1. **Alternating Execution**: The system must alternate between two different actions (call them Action-0 and Action-1). Action-0 always executes first, followed by Action-1, then Action-0 again, and so on.

2. **Parameterized Actions**: The specification should be generic and reusable. The actual behavior of each action should be left as parameters that can be instantiated later for specific use cases. Each action may modify some application state, and the specification should allow defining:
   - What constitutes a valid initial state for the application data
   - What each of the two alternating actions actually does to the application data

3. **Initial Condition**: The system should start in a state ready to perform Action-0 (not Action-1).

## Correctness Properties

1. **Strict Alternation**: It must be impossible for either action to execute twice in a row. The execution sequence must always be: Action-0, Action-1, Action-0, Action-1, ...

2. **No Skipping**: Neither action type can be skipped in the sequence.

## Design Notes

- The alternation control mechanism is internal bookkeeping and could conceptually be hidden from external observers—only the effects of the two actions on application state need to be visible.
- The specification should be structured so that different applications can plug in their own definitions of what the two alternating actions accomplish.
