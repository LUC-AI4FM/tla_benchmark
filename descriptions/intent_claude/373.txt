# Specification Request: TLA+ Parser Keyword Handling Test

## System to Specify

A test suite for a TLA+ syntax analyzer (parser) that verifies the parser correctly distinguishes between keywords used in their syntactic role versus the same identifiers used as record field names.

## Goal

Verify that a TLA+ parser implementation correctly handles all reserved keywords when they appear as record field accessors or in record update expressions. The parser must recognize that while certain tokens are keywords in specific syntactic contexts, they should be valid identifiers when used as record field names.

## Requirements

1. **Field Access Compatibility**: The parser must accept all TLA+ keywords as valid record field names when accessed using dot notation (e.g., accessing a field whose name matches a keyword).

2. **Record Update Compatibility**: The parser must accept all TLA+ keywords as valid field names within record update (EXCEPT) expressions.

3. **Comprehensive Keyword Coverage**: The test must cover the complete set of TLA+ keywords, including:
   - Proof-related keywords (proof structure, tactics, proof steps)
   - Module structure keywords (module declaration, imports, definitions)
   - Expression keywords (conditionals, quantifiers, set operations)
   - Temporal operators and fairness keywords
   - Declaration keywords (constants, variables, assumptions)

4. **Syntactic Validity**: The resulting specification must be syntactically valid and parseable by the TLA+ tools without errors.

## Correctness Properties

1. **Parsing Success**: The parser must successfully parse the module without syntax errors when keywords are used as field names.

2. **No Ambiguity**: The parser must unambiguously distinguish between keyword usage in syntactic positions versus identifier usage in field name positions.

3. **Consistent Treatment**: All keywords must be treated uniformly—if one keyword works as a field name, all keywords should work as field names.
