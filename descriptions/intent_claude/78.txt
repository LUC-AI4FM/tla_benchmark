# Specification Request: Record Field Update System

## System Overview

I need a formal specification for a simple state machine that manages a single record value with a boolean field. The system should model basic record operations including preservation of the current state and in-place field updates.

## Functional Requirements

The system should:

1. **Initialize** with a record containing a boolean field set to true
2. **Support two transitions**:
   - Maintain the current record value unchanged (stuttering/idle behavior)
   - Update the boolean field within the record to true (even if already true)

## Behavioral Properties

The specification should capture:

- A deterministic initial state with a well-defined record structure
- Non-deterministic choice between keeping the state unchanged or performing a field update
- The ability to modify individual fields within a record while preserving the record structure

## Purpose

This specification serves as a minimal test case for verifying that formal verification tools correctly handle record types, particularly when there may be discrepancies between declared type annotations and actual record field assignments. The focus is on ensuring proper handling of record field updates and type compatibility in the model checker.

## Correctness Considerations

The specification should be amenable to type checking and model checking, with particular attention to how record types are declared versus how they are used in state transitions.
