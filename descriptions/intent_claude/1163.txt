# Specification Request: Bounded Event Counter for Model Checking

## System Overview

I need a formal specification for an event counting mechanism that can be used to limit the number of certain actions in a system model. This is primarily a utility for controlling model checking scope rather than modeling a real-world system.

## Purpose

The goal is to create a reusable component that tracks how many times designated "interesting" events occur during system execution. This counter serves as a mechanism to bound infinite behaviors when model checking, allowing verification to complete on systems that would otherwise have unbounded state spaces.

## Requirements

### Core Functionality

1. **Event Tracking**: The system should maintain a count of events that have occurred, starting from zero.

2. **Configurable Limit**: There should be a configurable maximum number of events allowed. The system must support two modes:
   - **Bounded mode**: Events are counted up to a specified maximum, after which no more counted events can occur
   - **Unlimited mode**: No actual counting occurs (to avoid infinite state spaces during model checking)

### Behavioral Requirements

1. When operating in unlimited mode, the counter should remain unchanged regardless of how many events occur—this keeps the state space finite.

2. When operating in bounded mode:
   - Each event should increment the counter by one
   - Events should only be permitted while the counter is below the maximum
   - Once the maximum is reached, no further counted events may occur

## Key Properties

- The event count should never exceed the configured maximum (when a maximum is set)
- The event count should never be negative
- The counter should provide a clean guard condition that other parts of a specification can use to conditionally enable or disable actions

## Usage Context

This component is intended to be composed with other specifications, where certain actions are tagged as "counted events" and become disabled once the limit is reached, ensuring finite model checking while still exploring meaningful system behaviors.
