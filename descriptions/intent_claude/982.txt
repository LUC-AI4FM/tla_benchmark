# Specification Request: Leader Election Using the Yo-Yo Algorithm

## System Overview

I need a formal specification of the Yo-Yo distributed leader election algorithm operating on an arbitrary connected graph topology. The algorithm should elect a single leader (specifically, the node with the minimum identifier) from among a set of uniquely identified nodes that can only communicate with their immediate neighbors.

## System Description

The system consists of a fixed set of nodes connected by edges forming an undirected graph. Each node has a unique identifier, and nodes can only exchange messages with their direct neighbors. The algorithm proceeds in rounds, with each round consisting of two phases that propagate information through the network in a "yo-yo" fashion—first outward in one direction, then back.

## Behavioral Requirements

1. **Two-Phase Communication**: The algorithm should operate in alternating phases:
   - One phase where information flows in one direction along oriented edges
   - A return phase where responses flow back in the opposite direction

2. **Edge Orientation**: The algorithm maintains a logical orientation of edges between neighbors, which may change as the algorithm progresses based on the relative identifiers of nodes.

3. **Message Passing**: Nodes communicate by sending messages to neighbors via mailboxes. Messages should propagate minimum values through the network to identify the global minimum.

4. **Distributed Execution**: Nodes operate based only on local information and messages received from neighbors—no global knowledge is permitted.

## Correctness Properties

1. **Safety - Single Leader**: At most one node should ever be elected as the leader.

2. **Liveness - Eventual Election**: The algorithm must eventually terminate with exactly one leader elected.

3. **Correctness of Leader**: The elected leader must be the node with the minimum identifier in the network.

4. **Agreement**: All nodes must agree on who the leader is (either they are the leader, or they know they are not).

## Configuration Requirements

The specification should be parameterized by:
- The set of nodes (with their unique identifiers)
- The edge relation defining the graph topology

The specification should work for any connected graph topology, with example configurations for testing purposes.
