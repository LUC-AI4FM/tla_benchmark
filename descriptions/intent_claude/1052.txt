# Specification Request: Token Ring Mutual Exclusion Protocol

## System Overview

I need a formal specification of a token ring protocol for distributed mutual exclusion. The system consists of a fixed number of processes arranged in a logical ring topology, where access to a shared resource (or the ability to perform a critical action) is controlled by the possession of a "token" that circulates around the ring.

## System Requirements

### Structure
- The system should model N processes organized in a ring, where each process can only communicate with its immediate neighbor in one direction.
- Each process maintains local state that determines whether it currently holds the token.
- The token detection mechanism should be based on comparing local state between adjacent processes in the ring.

### Behavior
- Exactly one process should be considered to "have the token" at any given time, giving it the right to enter a critical section or perform a privileged operation.
- The token should be passable from one process to the next in ring order.
- The protocol should ensure fair circulation of the token around the ring, eventually giving every process an opportunity to hold it.

### Parameters
- The number of processes (N) should be configurable.
- The protocol may use a finite state space per process (with M possible values) to implement the token-passing mechanism.

## Correctness Properties

### Safety
- **Mutual Exclusion**: At most one process may hold the token at any instant. There must never be multiple simultaneous token holders.

### Liveness
- **Token Circulation**: The token must eventually reach every process in the ring. No process should be permanently starved of access to the token.
- **Progress**: The system should not deadlock; it must always be possible for the token to move.

## Additional Considerations

The specification should be suitable for model checking with finite instances, allowing verification that the safety and liveness properties hold for concrete values of the system parameters.
