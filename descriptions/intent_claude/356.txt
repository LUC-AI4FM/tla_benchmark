# Specification Request: TLA+ Conditional Expression Evaluation Test Suite

## System to Model

A test harness for validating the correct evaluation of conditional expressions in TLA+, specifically focusing on nested `IF-THEN-ELSE` constructs, `CASE` expressions (including those with `OTHER` fallback clauses), and nested disjunctive/conjunctive logical formulas.

## Goal

Create a specification that serves as a conformance test suite to verify that a TLA+ model checker correctly evaluates complex conditional expressions according to expected semantics. The system should confirm that:

1. Nested `IF-THEN-ELSE` expressions evaluate branches in the correct order based on their conditions
2. `CASE` expressions select the appropriate branch when exactly one condition is true
3. Nested `CASE` expressions (a `CASE` as the result of another `CASE` branch) evaluate correctly
4. The `OTHER` fallback clause in `CASE` expressions activates when no explicit condition matches
5. When multiple conditions in a `CASE` are true, the result is non-deterministically one of the matching branches
6. Nested disjunctions and conjunctions with mixed boolean conditions short-circuit and evaluate correctly

## Requirements

The specification must verify the following behaviors:

- **Nested conditionals**: When conditionals are nested three levels deep, evaluation should proceed from outermost to innermost, selecting the correct branch at each level
- **CASE with nested CASE results**: When a `CASE` branch yields another `CASE` expression, the inner expression must be fully evaluated
- **OTHER clause semantics**: The `OTHER` clause should only match when all explicit conditions are false
- **Non-determinism in CASE**: When multiple conditions are simultaneously true, the specification should accept any of the corresponding results as valid
- **Complex boolean formulas**: Disjunctions of conjunctions should evaluate correctly, with the overall formula being true if any complete conjunctive branch is satisfied

## Correctness Properties

The test suite must guarantee that all test cases pass—meaning each conditional expression evaluates to its expected value. Any deviation from expected evaluation semantics should trigger an assertion failure, while correct behavior should be logged as passing.
