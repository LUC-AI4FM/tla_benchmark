# Specification Request: Coffee Can Bean Problem

## System Description

I need a formal specification of the classic "Coffee Can Problem" (also known as the "Bean Can Problem"), a mathematical puzzle involving colored beans in a container.

## Problem Setup

A coffee can contains some number of black beans and white beans. The total number of beans is bounded by some maximum capacity. The system models a process where beans are repeatedly removed and potentially replaced according to specific rules.

## Operations

The process repeatedly performs the following: randomly select two beans from the can and apply these rules:

1. **Two black beans selected**: Remove both black beans, then add one black bean back to the can (net effect: one fewer black bean)

2. **Two white beans selected**: Remove both white beans, then add one black bean to the can (net effect: two fewer white beans, one more black bean)

3. **One black and one white bean selected**: Remove both beans, then add the white bean back (net effect: one fewer black bean)

The process continues until only one bean remains in the can.

## Key Correctness Properties

The specification must guarantee:

1. **Type Safety**: The can state always consists of valid non-negative counts of black and white beans within the defined structure.

2. **Bounded Bean Counts**: The number of each color of bean, as well as the total count, must never exceed the maximum capacity and must never go negative. This is particularly important because one operation increases the black bean count, which could potentially violate bounds if not carefully constrained.

3. **Termination Condition**: The process should be able to terminate when exactly one bean remains.

## Goal

The formal specification should model this bean selection process and prove that the type invariant is preserved throughout all possible executions—specifically that the bean counts remain within valid bounds at every step despite operations that both increase and decrease individual color counts.
