# Specification Request: Parallel Die Hard Water Jug Puzzle

## System Overview

I need a formal specification for a generalized version of the classic "Die Hard" water jug puzzle, where multiple independent jug systems operate in parallel, and the goal is to measure a specific target amount of water.

## Problem Description

The original Die Hard puzzle involves using unmarked jugs of known capacities to measure an exact quantity of water through filling, emptying, and pouring operations. I want to model an **interleaved composition** of multiple such jug systems running concurrently, where each system has its own set of jugs with potentially different configurations.

Specifically:
- There should be support for multiple independent jug systems (e.g., two separate tables, each with their own jugs)
- Each system can have a different number of jugs and different capacities
- The systems operate independently but are composed together in an interleaved fashion
- The goal is to reach a target water measurement in any jug across any of the systems

## Example Configuration

As a concrete test case, consider:
- **System 1**: Two jugs with capacities 5 and 3 gallons
- **System 2**: Three jugs with capacities 5, 3, and 3 gallons
- **Goal**: Measure exactly 4 gallons in any jug

## Operations

Each jug system should support the standard water jug operations:
- Fill any jug completely from an unlimited water source
- Empty any jug completely
- Pour water from one jug to another (stopping when the source is empty or the destination is full)

## Correctness Property

The key property to verify is a **reachability question**: Can the target amount ever be achieved? 

The specification should include an invariant stating that the goal has *not* been reached, so that model checking will produce a counterexample trace demonstrating a solution when one exists.

## Purpose

This specification should enable automated exploration of the state space to find solution sequences for various jug configurations, demonstrating how interleaved concurrent systems can be composed and analyzed together.
