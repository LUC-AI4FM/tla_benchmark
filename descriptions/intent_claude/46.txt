# Specification Request: Module System with Type Annotations and Nested Instantiation

## System Overview

I need a formal specification that tests the behavior of a module system supporting type annotations, module extension, and module instantiation—including nested and chained instantiation patterns.

## Core Requirements

The system should model a hierarchical module architecture where:

1. **Base utility module**: A foundational module that defines a typed operator (specifically, an operator that takes a function mapping integers to integers and returns an integer by applying that function to a specific input).

2. **Module extension**: One module should extend the base utility module using an inheritance-like mechanism, creating a wrapper around the base operator.

3. **Module instantiation**: Another module should import the base utility module through direct instantiation (without extension), also wrapping the base operator.

4. **Nested instantiation**: A third module should instantiate the extending module, creating a chain of module dependencies.

5. **Multiple instantiation patterns in a single context**: The top-level specification must combine:
   - Direct instantiation of the extending module
   - Named instantiation of the instantiating module
   - Instantiation of the nested-instantiation module

## Key Correctness Properties

The specification must verify that:

1. **Type annotation preservation**: Type annotations declared in a base module must be correctly propagated through both extension and instantiation mechanisms.

2. **Operator accessibility**: Operators defined in base modules remain accessible through multiple layers of extension and instantiation.

3. **No conflicts**: Multiple instantiation patterns coexisting in the same module context do not create naming conflicts or semantic ambiguities.

4. **Consistent semantics**: The same underlying operator behaves identically whether accessed through extension, direct instantiation, named instantiation, or nested instantiation chains.

## Goal

This specification serves as a regression test to ensure that a module system correctly handles the interaction between type annotations and various module composition mechanisms, particularly when these mechanisms are combined in complex ways.
