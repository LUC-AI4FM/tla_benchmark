Please write a formal specification for a **TLA+ proof system constraint checker** that validates the proper use of proof directives.

## System Description

The system should model the rules governing how facts and theorems can be referenced within TLA+ proof constructs, specifically focusing on the `USE` and `HIDE` directives that control which facts are available during proof steps.

## Requirements

1. **Theorem References**: The system must allow referencing previously declared theorems by name within proof directives.

2. **Subexpression Restrictions**: When a theorem defines a compound expression (like a tuple or sequence), the system must enforce rules about whether components of that expression can be individually referenced using subexpression notation (e.g., extracting the first element of a tuple-valued theorem).

3. **Literal Expression Restrictions**: The system must prevent arbitrary literal expressions (such as boolean constants or raw values) from being used directly as facts in proof directives.

4. **Assumption Context**: Within proof structures that have assumptions, the system must validate what can be referenced, distinguishing between the proof's own assumptions and external theorems.

## Key Correctness Properties

1. **Well-formedness**: Only valid theorem names and properly-formed references should be accepted in `USE` and `HIDE` directives.

2. **No Arbitrary Expressions**: Raw expressions that are not theorem references must be rejected as invalid facts.

3. **Subexpression Validity**: Subexpression extraction from theorems should only be permitted when semantically meaningful (not arbitrary decomposition of theorem values).

4. **Error Detection**: The specification should identify precisely which usages constitute errors versus valid references.
