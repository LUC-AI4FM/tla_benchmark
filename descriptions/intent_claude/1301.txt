# Specification Request: Expression Caching in Model Checker Evaluation

## System Overview

I need a formal specification that demonstrates and verifies the behavior of an expression caching mechanism in a model checker. The goal is to ensure that expensive or side-effect-producing expressions are evaluated exactly once, even when they are referenced multiple times across different parts of a specification.

## Requirements

### Core Functionality

The system should support defining expressions that are cached after their first evaluation. When the same cached expression is referenced again—whether in assumptions, initial state predicates, or transition relations—it should return the previously computed result without re-evaluating the underlying expression.

### What Must Be Modeled

1. **Cached definitions**: Two related set expressions where one depends on the other (a derived definition that references the base definition)
2. **Multiple reference points**: The cached expressions should be referenced in:
   - Assumption checks (evaluated at specification load time)
   - Initial state computation
   - Next-state transitions
3. **Evaluation counting**: A mechanism to track how many times the underlying expressions are actually evaluated

### Key Correctness Properties

1. **Single evaluation guarantee**: Each cached expression must be evaluated exactly once total, regardless of how many times it is referenced throughout the specification

2. **Value correctness**: The caching mechanism must return the correct cached value for each distinct expression—it must not confuse or swap cached values between different expressions

3. **Cross-context consistency**: The same cached value must be returned whether the expression is referenced in an assumption, the initial state predicate, or the next-state relation

### Verification Approach

The specification should include assertions that:
- Confirm specific expected values are present (or absent) in the computed sets to detect value mix-ups
- Verify the total evaluation count equals exactly the number of distinct cached expressions (not the number of references)

## Purpose

This specification serves as a test case for verifying that a model checker's caching feature works correctly—ensuring computational efficiency through caching while maintaining semantic correctness of the cached values.
