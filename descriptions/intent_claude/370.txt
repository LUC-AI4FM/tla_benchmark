# Specification Request: TLA+ Subexpression Selector and Label Reference System

## System Overview

I need a formal specification for a **subexpression selection and label referencing mechanism** within a formal specification language. This system allows users to navigate into and extract specific parts of complex expressions using a hierarchical path notation, including the ability to reference labeled subexpressions by name.

## Core Functionality

The system must support:

1. **Label Definitions**: Users should be able to attach named labels to arbitrary subexpressions within definitions, quantified formulas, and local operator definitions.

2. **Subexpression Navigation**: Users must be able to navigate into composite expressions (sets, tuples, records, function definitions, conditionals, quantified expressions, etc.) using a path-based selector syntax that identifies which component to extract.

3. **Higher-Order Operator Extraction**: The system should allow extracting operators defined locally within expressions (such as infix operators defined in LET clauses) and passing them as arguments to higher-order operators.

4. **Parameterized Label References**: When expressions contain bound variables or parameters, the selection mechanism must allow instantiating those parameters when navigating to labeled subexpressions.

5. **Module Instantiation Compatibility**: The extraction mechanism must work correctly with module instantiation, allowing subexpression paths to be used on imported definitions.

## Key Correctness Properties

1. **Referential Consistency**: Extracting a subexpression and evaluating it with given arguments must yield the same result as evaluating the full expression and selecting the corresponding component.

2. **Parameter Binding Correctness**: When a label is parameterized by bound variables, supplying values for those parameters must correctly substitute them throughout the labeled subexpression.

3. **Composability**: Multiple levels of subexpression selection must compose correctly—navigating into a subexpression and then further into its components must be equivalent to direct deep navigation.

4. **Operator Extraction Validity**: Extracting a locally-defined operator must produce a valid operator that, when applied, behaves identically to invoking that operator in its original context with the same arguments.

5. **Coverage**: The mechanism must handle all expression forms including sets (enumerated, filtered, mapped), tuples, records, functions, conditionals (IF-THEN-ELSE, CASE), all quantifier forms (universal, existential, temporal), and CHOOSE expressions.
