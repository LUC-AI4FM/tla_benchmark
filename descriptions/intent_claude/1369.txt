# Specification Request: Bounded Counter with Fairness

## System Overview

I need a formal specification for a simple system with two state components: a primary counter and a secondary unchanged component. The system should model a counter that increments within a bounded range.

## Behavioral Requirements

1. **Initial State**: Both components start at zero.

2. **Counter Behavior**: The primary counter increments by one on each step, but only while its value remains within the range 1 through 10. Once it would exceed this bound, no further transitions should be possible.

3. **Secondary Component**: One component never changes throughout execution—it remains constant at its initial value.

4. **Fairness Requirement**: The system should guarantee that if the counter increment action is continuously enabled, it will eventually be taken. This is a weak fairness condition.

## Key Properties to Verify

1. **Enabling Condition**: The counter increment action should be enabled in reachable states (until the bound is reached).

2. **Liveness Check**: The specification should be subjected to liveness verification to ensure the fairness conditions interact correctly with the state space.

## Purpose

This specification is designed to test how a model checker handles fairness conditions when the fairness constraint references only a subset of the system's state variables, while the overall specification includes additional unchanged variables. The goal is to verify correct behavior when there's a mismatch between which variables are modified by an action and which variables appear in the fairness condition's scope.
