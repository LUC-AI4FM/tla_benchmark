# Specification Request: Concurrent Counter with Barrier Synchronization

## System Overview

I need a formal specification of a simple concurrent system where multiple processes collaborate to increment a shared counter, then synchronize before completing.

## System Description

The system consists of exactly four concurrent processes that share access to a single counter (initially zero). Each process performs the following sequence of operations:

1. Increment the shared counter by one (via a procedure call)
2. Wait until the counter reaches exactly four before finishing

## Key Requirements

### Functional Requirements

- There must be exactly four processes running concurrently
- All processes share a single integer counter that starts at zero
- Each process must increment the counter exactly once
- After incrementing, each process must block until the counter reaches four
- The increment operation should be encapsulated as a callable procedure (to test procedure call mechanics without parameters)

### Synchronization Behavior

- The counter increment is not atomic with respect to the blocking wait—these are separate steps
- A process can only proceed past its wait point when all four processes have completed their increments
- This creates a barrier synchronization pattern where all processes must contribute before any can finish

## Correctness Properties

### Liveness

- **Termination**: Under fair scheduling, all four processes must eventually complete. No process should be stuck indefinitely waiting at the barrier.

### Safety (Implicit)

- The counter should only ever reach values between 0 and 4
- Each process contributes exactly one increment

## Purpose

This specification serves as a test case for modeling concurrent procedure calls without parameters, demonstrating barrier synchronization, and verifying that fair execution guarantees termination in a multi-process coordination scenario.
