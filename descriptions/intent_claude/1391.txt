# Specification Request: Modular Ring Counter with Parameterized Instantiation

## System Overview

I need a formal specification for a **circular counter** (ring buffer index or modular arithmetic counter) that can increment and decrement while wrapping around at boundaries. The specification should demonstrate how to define this as a reusable, parameterizable module that can be instantiated with different ring sizes.

## Functional Requirements

The system should model a counter that:

1. **Operates within a bounded range**: The counter value must always be a member of a finite set determined by the ring's size (e.g., for size 7, valid values are 0 through 6).

2. **Supports increment with wrap-around**: When incrementing past the maximum value, the counter should wrap to zero.

3. **Supports decrement with wrap-around**: When decrementing below zero, the counter should wrap to the maximum value.

4. **Provides modular arithmetic operations**: Include a custom operator for modular addition within the ring.

## Parameterization Requirements

The specification must demonstrate:

1. **Parameterized module instantiation**: The ring size should be a parameter, allowing the same module definition to be reused with different sizes.

2. **Multiple ways to compose specifications**: Show how to reference the parameterized module's definitions (initialization, transitions, custom operators) from an outer specification.

3. **Fairness conditions**: Support both weak and strong fairness constraints on the counter's transitions.

## Correctness Properties

The specification should allow verification of:

1. **Liveness/progress**: Under appropriate fairness assumptions, the counter should eventually cycle—specifically, it should infinitely often transition from the maximum value back to zero.

2. **Sanity checks on arithmetic**: The modular addition operator should produce results that remain within the valid range.

3. **Distinguishing correct from incorrect behaviors**: Include both valid cycle detection (max to zero) and an incorrect variant (max to one) to test that the specification correctly identifies improper transitions.

## Purpose

This specification serves as a test case for tooling that handles parameterized module instantiation, including proper resolution of custom infix operators, temporal properties, and fairness conditions across module boundaries.
