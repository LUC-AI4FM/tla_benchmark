# Specification Request

## System Description

I need a formal specification to test the behavior of a model checker when handling **distinct uninterpreted types** (model values). The system should be minimal—just a simple state machine that transitions from an initial state to a next state.

## Goal

The primary purpose of this specification is to verify that a model checker correctly **rejects comparisons between values of different abstract types**. This is essentially a test case for type safety in specifications that use multiple distinct model value sorts.

## Requirements

1. **Two distinct abstract types**: The system should declare two constants belonging to different uninterpreted/model value types. These types should be fundamentally incompatible for comparison purposes.

2. **Minimal state machine**: A trivial two-state system that initializes some set-valued variables and transitions once. The actual state machine behavior is not the focus—it just needs to be well-formed enough to run.

3. **Type-violating invariant**: The specification must include an invariant that attempts to compare two values of different model value types for equality.

## Expected Correctness Property (Intentionally Flawed)

The invariant should assert that two constants of different types are equal. This property is **expected to cause a type error or failure** in a type-aware model checker, rather than being evaluated as true or false.

## Purpose

This specification serves as a **negative test case** to ensure that tooling properly enforces type separation between different sorts of model values and does not silently allow meaningless cross-type comparisons.
