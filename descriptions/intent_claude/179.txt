# Specification Request: Option Type Library for TLA+

## System Overview

I need a formal specification for an **Option type library** that provides a standard way to represent and manipulate optional values in TLA+ specifications. This is analogous to Option/Maybe types found in functional programming languages, where a value can either be present ("Some" containing a value) or absent ("None").

## Core Requirements

### Data Representation
The library must support two kinds of optional values:
- A "present" variant that wraps an arbitrary value
- An "absent" variant representing no value

### Required Operations

The library should provide the following functional operations on optional values:

1. **Mapping**: Apply a function to transform the wrapped value if present; leave absent values unchanged.

2. **Flat mapping / Chaining**: Apply a function that itself returns an optional value, supporting monadic composition where operations can fail at any step.

3. **Case analysis / Pattern matching**: Given handlers for both the present and absent cases, extract a result value by applying the appropriate handler.

4. **Default value extraction**: Retrieve the wrapped value if present, otherwise return a specified default.

5. **Conversion to collections**: Convert an optional value to either a set or a sequence (yielding an empty collection for absent, or a singleton for present).

6. **Non-deterministic selection from sets**: Given a set, produce an optional value that is absent if the set is empty, or contains some element of the set if non-empty.

7. **Function application lifting**: Apply a function to an optional argument, propagating absence.

8. **Partial function construction**: Given a total function defined on some domain, extend it to a larger domain where out-of-domain inputs yield absent results.

## Correctness Properties

The library operations must satisfy standard Option/Maybe laws:

- Mapping over an absent value yields absent
- Mapping preserves the present/absent status appropriately
- Flat mapping propagates absence from any step in a chain
- Conversions to collections preserve the presence/absence of values correctly
- Set selection from an empty set is always absent; from a non-empty set, the result is always a member of that set

## Purpose

This library is intended to be reused across TLA+ specifications to cleanly handle partial operations, optional data, and computations that may fail, without relying on special sentinel values or undefined behavior.
