# Specification Request: Simple Sequential Computation with Nondeterministic Choice

## System Description

I need a formal specification for a simple sequential program that performs arithmetic operations with one nondeterministic choice point. The program should model a straightforward computation that initializes values, makes a random selection from a small set, performs additions based on that selection, and then conditionally updates the result.

## Behavioral Requirements

The system should:

1. **Initialize** two numeric accumulators to zero
2. **Set** the first accumulator to a fixed constant value (specifically, 3)
3. **Nondeterministically choose** a value from a small set (either 1 or 2), store it in the second accumulator, and add it to the first accumulator
4. **Conditionally update** the first accumulator based on which value was chosen in the previous step—if 1 was chosen, increment by 1; otherwise, add the chosen value again
5. **Terminate** after completing all steps and output the final result

## Correctness Properties

The specification should verify:

1. **Termination**: The program must always eventually complete its execution
2. **State exploration verification**: The model checker should explore exactly the expected number of states—specifically, there should be exactly 2 distinct states at the conditional step (corresponding to the two possible nondeterministic choices), and exactly 1 execution path where the value 2 was selected

## Purpose

This specification serves as a simple test case for verifying TLA+/PlusCal tooling behavior, particularly around nondeterministic choice, state counting, and execution path tracking. It demonstrates how branching from a nondeterministic selection affects the state space and how to write properties that verify the model checker is exploring the expected execution paths.
