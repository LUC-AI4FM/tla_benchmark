# Specification Request

## System Description

I need a formal specification for a simple cyclic counter system. The counter should increment through a fixed sequence of values and then wrap around to restart the cycle indefinitely.

## Behavioral Requirements

The system consists of a single integer counter that:
- Starts at zero
- Increments by one on each step until it reaches a maximum value (specifically, up to 3)
- Resets back to zero after reaching the maximum, creating a repeating cycle (0 → 1 → 2 → 3 → 0 → ...)

## Correctness Properties

I want to explore and verify temporal properties related to the counter's incrementing behavior:

1. **Liveness (Expected to Hold):** The system should guarantee that it is always eventually possible for a genuine increment action to occur—meaning the counter actually changes by increasing by one. This should be satisfied since the counter regularly increments during most of its cycle.

2. **False Liveness (Expected to Fail):** As a counterexample for learning purposes, I want to express a property claiming that eventually the counter will *forever* only perform increment actions. This property should be violated because the counter must eventually wrap around (reset to zero), which is not an increment.

## Purpose

This specification is intended as an educational example demonstrating how to express temporal properties over actions (as opposed to just state predicates) in a formal specification language, and to illustrate the difference between properties that hold versus those that are violated in cyclic systems.
