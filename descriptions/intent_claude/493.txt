# Specification Request: Client-Server Session Management Protocol

## System Overview

I need a formal specification for the client-side behavior of a session-based client-server communication protocol. The system models multiple clients that can establish sessions with a server, send commands over those sessions, and gracefully close sessions when done.

## Functional Requirements

### Session Lifecycle
- Clients should be able to open a session with a server. A client that does not currently have an active session may request one.
- Clients should be able to close their session. Only clients with an active session may request to close it.
- The system must track whether each client currently has an active session.

### Command Submission
- Clients with an active session should be able to send commands to the server.
- Each command should have a unique, monotonically increasing identifier to distinguish different requests.

### Response Handling
- When a client receives confirmation that a session was opened, it should record its new session identifier.
- When a client receives confirmation that a session was closed, it should clear its session state.
- Clients should properly handle responses to their command requests.

## Communication Model

The protocol should use asynchronous message passing between clients and the server. Messages should identify:
- The type of request or response
- The source and destination of the message
- Session identifiers where applicable
- Command identifiers for command requests

## Key Properties to Verify

1. **Session Integrity**: A client should only send commands or close-session requests when it has an active session.
2. **Session Exclusivity**: A client should only request to open a session when it does not already have one.
3. **Command Uniqueness**: Command identifiers should never repeat across requests.

## Scope

This specification covers only the client-side logic. It assumes the existence of a separate server module that handles session creation/destruction and command processing, as well as a messaging infrastructure for communication.
