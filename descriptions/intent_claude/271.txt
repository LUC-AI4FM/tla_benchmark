# Specification Request: Sequence Operations Test Suite

## System Overview

I need a formal specification that serves as a comprehensive test suite for sequence (ordered list) operations in a formal verification tool. The goal is to verify that all standard sequence manipulation operations behave correctly according to their expected semantics.

## Purpose

This specification should validate the correctness of a sequence library implementation by encoding expected behaviors as invariants that must hold. It's essentially a unit test framework expressed as a formal specification, where a trivial state machine serves only as a vehicle to check that all test assertions pass.

## Required Sequence Operations to Test

The specification must verify correct behavior for the following operations on finite sequences of integers:

1. **Basic Access**: Getting the first element, getting all elements after the first, and indexing into a sequence by position
2. **Length and Domain**: Computing sequence length and determining valid index positions
3. **Construction**: Creating empty sequences and sequences with specific elements
4. **Subsequence Extraction**: Extracting contiguous portions of a sequence by start and end positions
5. **Appending**: Adding a single element to the end of a sequence
6. **Concatenation**: Joining two sequences together
7. **Folding/Reduction**: Applying a binary operation across all elements to produce an aggregate result (left-to-right)
8. **Sequence Generation**: Creating sequences by applying a function to index positions
9. **Filtering**: Selecting elements that satisfy a predicate
10. **Function-to-Sequence Conversion**: Converting a function with integer domain into a sequence representation
11. **Element Update**: Modifying a single element while preserving sequence structure

## Key Correctness Properties

The specification must verify:

- Undefined behavior is handled appropriately for operations on empty sequences (head/tail of empty) and out-of-bounds access
- Length computations are accurate for empty, single-element, and multi-element sequences
- Domain sets correctly reflect valid indices (1-based indexing)
- Subsequence extraction handles edge cases including empty results
- Append and concatenation preserve existing elements and produce correct lengths
- Fold operations correctly accumulate values and handle empty sequences
- Sequence generation produces expected element values and lengths
- Filtering preserves order while selecting qualifying elements
- Sequence equality and inequality work correctly after transformations
- Element updates preserve length and domain

## Approach

The system should use a degenerate state machine (always true transitions) so that all test conditions can be expressed as state invariants. If any operation behaves incorrectly, the invariant check will fail, indicating which operation is broken.
