# Specification Request: I/O Utilities Library Verification

## System to be Modeled

I need a formal specification that verifies the correctness of an I/O utilities library for a model checker or specification language runtime. The library provides functionality for interacting with the operating system environment and serializing/deserializing data structures.

## Core Functionality Requirements

### Environment Variable Access
The system must provide a mechanism to read environment variables from the operating system. This feature should:
- Return string values for environment variable lookups
- Support standard identifier-style variable names through direct field access
- Support arbitrary variable names (including those with special characters like hyphens) through bracket notation
- Not append trailing newlines or other artifacts to retrieved values
- Ensure all variable names in the environment are strings, and all values are strings

### String-to-Integer Conversion
The system must provide a function to convert string representations of integers to actual integer values. This should:
- Correctly parse positive integers
- Correctly parse negative integers
- Handle zero (including "-0" as equivalent to 0)
- Produce appropriate error messages for empty strings
- Produce appropriate error messages for non-numeric strings

### Number Formatting
The system must provide zero-padding functionality for numbers. This should:
- Pad numbers with leading zeros to reach a specified width
- Return the number unchanged (as a string) if it already meets or exceeds the specified width
- Handle zero as an input value correctly

### Binary Serialization/Deserialization
The system must support serializing complex data structures to files and deserializing them back. This should:
- Handle strings, sets, integers, ranges, and records
- Preserve exact structure and values through a round-trip (serialize then deserialize)
- Be able to deserialize string values that the runtime has never previously encountered in the specification (no dependency on internal string interning)

## Key Correctness Properties

1. **Environment Access Integrity**: Environment variable reads must return exactly the value set in the OS, without modification
2. **Type Safety**: Environment operations must maintain proper string typing throughout
3. **Parsing Correctness**: String-to-integer conversion must be mathematically accurate for all valid inputs and fail gracefully for invalid inputs
4. **Serialization Round-Trip**: Any serialized value must deserialize to an exactly equal value
5. **String Independence**: Deserialization must work for arbitrary string values regardless of whether they appear elsewhere in the specification
