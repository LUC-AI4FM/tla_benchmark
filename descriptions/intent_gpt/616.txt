Model a Tendermint-style Byzantine fault-tolerant consensus protocol for a fixed set of N processes that proceeds in asynchronous rounds with three protocol steps per round (propose, prevote, precommit). The model should capture a single-shot decision on a value chosen from a finite set of values (some values may be invalid). The system must tolerate up to T Byzantine (arbitrary) faulty processes and assume the remaining processes are correct and follow the protocol. Include a rotating proposer selection for rounds. Specify message types for proposal, prevote, and precommit, and allow faulty processes to send arbitrary messages including equivocations; correct processes only send messages according to the protocol.

The specification must express the following functional requirements and correctness properties:

- Safety (Agreement): No two correct processes may decide different valid values. If a correct process decides a value v, then no other correct process may ever decide a different value v'.
- Validity: Any value decided by a correct process must be valid (from the set of valid values), and a correct proposer must be able to make proposals that can lead to decision.
- Fault tolerance: Safety must be preserved despite up to T Byzantine processes behaving arbitrarily, including equivocation and omission.
- Liveness under eventual synchrony assumptions: If communication eventually becomes reliable and a correct proposer proposes a valid value, then all correct processes should eventually decide that value (unless prevented by permanent faults beyond T).
- Locked/polled safety constraints: Processes should use the usual locking and valid-value exchange semantics so that prevote/precommit quorums prevent conflicting decisions.
- Traceability: The model must record messages so that one can check quorum thresholds for prevote and precommit and reason about equivocations and evidence.

Do not prescribe implementation structure; instead specify the states, allowed message exchanges, round progression rules, proposer behavior, and the invariants expressing the properties above to enable formal verification.
