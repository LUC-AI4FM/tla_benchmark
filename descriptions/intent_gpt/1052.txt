Specify a parameterized token-passing ring of N processes that run a repetitive protocol for holding and transferring a single token. The model should treat N and the maximum counter value M as parameters. Each process maintains a local integer counter in a bounded range 0..M. Exactly one token exists in the system at any time. When a process holds the token it may increment its counter modulo (M+1) and then pass the token to its clockwise neighbor; other processes do not change their counters except when they receive the token. The protocol must allow a process to momentarily keep the token (perform a local counter update) before forwarding it, but must not allow token duplication or token loss.

Specify initial states: all counters may start at arbitrary values in 0..M but exactly one process initially holds the token. Define the asynchronous interleaving semantics where, at each step, one process that currently holds the token performs its local update and transfers the token to the next process.

State the safety properties to verify:
- Mutual exclusion for the token: at most one process holds the token in every reachable state.
- Conservation of the token: the number of tokens remains exactly one (no creation or destruction).
- Counter bounds: every counter remains within 0..M.

State the liveness properties to verify:
- Token circulation: for every process and every reachable state, the token will eventually be held by that process (fairness assumption permitting progress).
- Progress on update: whenever a process holds the token infinitely often, it will eventually perform its counter update and pass the token.

Allow proving invariants and temporal properties for all N > 1 and M ≥ 0. Provide a clear notion of neighbor relation on the ring and parameterized proofs that do not rely on concrete N or M values.
