Specify a formal TLA+ model of the alternating bit protocol for reliable delivery over unreliable channels. The model should represent two endpoints, a sender and a receiver, exchanging data messages and acknowledgements over lossy, possibly reordering channels with bounded queue capacity. The sender repeatedly transmits items from an unbounded stream of application data, attaching a one-bit sequence number; the receiver accepts in-order data only and returns acknowledgements carrying the bit of the last correctly received packet. If a message or acknowledgement is lost or delayed, the sender will retransmit until it receives the expected acknowledgement matching the current bit; the receiver must discard duplicate deliveries. The environment may arbitrarily drop or reorder messages but must preserve message contents.

Specify safety properties:
- No spurious application deliveries: the receiver must deliver only items actually sent by the sender.
- In-order delivery modulo duplicates: delivered application items must appear in the same order they were originally sent.
- Sequence correctness: acknowledgements and data are only accepted when their sequence bit matches the protocol expectations; duplicates are detected and not redelivered.

Specify liveness properties:
- Eventual delivery under fair retransmission: for every sent data item, if the sender continues to retransmit under weak fairness of its send action, then the item is eventually delivered to the receiver.
- Progress fairness: if messages are continuously enabled to be sent and the network does not permanently drop all copies, then acknowledgements eventually arrive enabling sender progress.

Require parameters for channel capacities and the data domain. Do not prescribe an implementation strategy; instead describe the abstract actions, allowed failures, and the correctness invariants and temporal guarantees the specification must enforce.
