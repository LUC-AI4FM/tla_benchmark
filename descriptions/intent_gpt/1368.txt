Specify a simple system in which a single shared state component holds a set of elements that may be observed or manipulated by a separate module. Model the state as a single mutable container whose value is always a set. The system must start with the container empty. The model should allow arbitrary evolution steps that do not change the state (i.e., stuttering steps are permitted), but it should also be clearly capable of being extended later with actions that modify the set.

Require and check the following properties: (1) Initialization: the container is initially the empty set. (2) Type safety: the value of the container is always a set. (3) Stuttering safety: an arbitrary sequence of steps that leave the container unchanged is a valid behavior. (4) Compositional observation: a separate component (a module that observes the container) should be able to access the current value of the container as a parameter without modifying it. Specify the system so it can be instantiated or composed with such an observer module in a configuration that binds the observer’s view to the container’s current value.

Express these requirements independently of any particular implementation, leaving room to later add concrete state-changing actions, invariants about contents, or liveness properties.
