Specify a formal model of Lamport’s Bakery mutual-exclusion algorithm for N concurrent threads vying for a single critical section. The model should treat the set of threads as a parameter and allow an upper bound on ticket values for model checking. Each thread repeatedly executes the standard protocol: indicate it is choosing a ticket, determine the maximum observed ticket among peers, take a ticket one greater than that maximum, finish choosing, wait until no other thread has priority (either because the other’s ticket is zero, has a larger ticket, or has the same ticket but a higher thread id), enter the critical section, then reset its ticket and repeat.

The specification must capture asynchronous interleaving and allow arbitrary scheduling: any enabled thread may take a step. The model should record enough local state per thread to represent choosing flags, ticket numbers, and any temporary variables needed to implement the waiting protocol, but the exact implementation choices are not part of the requirement.

The key correctness properties to require and check are:
- Safety (mutual exclusion): at most one thread may be in the critical section at any time.
- Liveness (starvation-freedom or progress): every thread that repeatedly attempts to enter the critical section will eventually enter it, assuming fair scheduling of threads (state the fairness assumption used).
- Boundedness: ticket values remain within the declared upper bound used for model checking.
- Absence of deadlock: the system should never reach a global state where no thread can make progress while some thread is trying to enter the critical section.

Also request invariants and temporal properties expressing the above (safety as an invariant; liveness as a fairness-based temporal formula), and include parameters for number of threads and maximum ticket to facilitate model checking.
