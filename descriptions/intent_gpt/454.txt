Specify a timed-event controller that coordinates a repeating hourly heartbeat with a monotonically increasing real-valued clock. The model should capture the following abstract system and correctness properties.

Model a continuous-time clock that always increases (no time reversal) and may advance by arbitrary positive real amounts. The clock value must be a real number drawn from a bounded domain. The system schedules a periodic heartbeat event intended to occur roughly once per hour: when the heartbeat triggers it resets a local timer to zero; while no heartbeat occurs the timer increases by the same amount that the global clock advances. The heartbeat is allowed to occur only when the local timer is within a tolerance window centered on the nominal hour interval. The timer must always remain within specified minimum and maximum bounds relative to the hourly target, accounting for the given tolerance.

Allow nondeterminism in when the heartbeat control signal may toggle, but ensure fairness so that time is not indefinitely stalled and the clock eventually exceeds any finite real threshold (no Zeno executions). Also require a weak fairness condition preventing the controller from forever deferring clock progress beyond any fixed bound.

State the initial conditions: the timer starts at zero, the clock starts at some real value, and the heartbeat-related control state is initialized to allow the first timing cycle. Formalize liveness properties ensuring that the heartbeat condition from an external module (treated as an abstract component) eventually holds according to its specification, and that the timer and clock invariants are always preserved. Specify temporal properties forbidding pathological behaviors such as a state that permanently avoids reaching certain clock values when those values are enabled.
