Specify a formal model of a language parser and operator-resolution subsystem that must accept and correctly interpret user-defined infix operator symbols (including multi-character and Unicode/math-symbol forms) in expressions and declarations. The model should treat operators as first-class binary connectors that can be declared by the user and then used as arguments to higher-order constructs, passed to parameterized templates, and composed in nested expressions. The system must correctly resolve which token sequences constitute defined infix operators versus built-in operators or ordinary identifiers, preserve operator identity when operators are passed as parameters, and allow operator symbols to be used in place of ordinary function names in parameter positions.

Model the behavior of operator application and equality testing of operator values, ensuring that expressions using user-defined operators evaluate consistently with their declared semantics (for example, reducing to results determined by the operator’s definition). Include handling of collisions and precedence only insofar as the resolution policy deterministically picks the intended operator symbol. The model must also support built-in boolean and set operators unchanged, and correctly interoperate user-defined operators with those built-ins. Key correctness properties: defined operator symbols are recognized and treated uniformly across declaration, application, parameterization, and comparison; no ambiguity leads to mis-parsing of operator uses; and the semantics of expressions using these operators is preserved under substitution and instantiation.
