Specify a formal model of a small typed record system and an operation that accesses a field from a record instance. The model should treat records as maps from field names to values with explicit typing for each field present. It must allow construction of a record value with two fields: one numeric and one string. The system must also express an access attempt to a field that is not present in the record and capture the intended semantics for such an access.

The specification should state what it means for a field-access expression to be well-typed and when it is ill-typed or undefined. Include a scenario where an access reads a missing field and require the model to clearly classify whether that expression is permitted, results in an error, or yields a default value. Require invariants that distinguish valid accesses (accessing declared fields with compatible types) from invalid accesses (accessing absent fields or mismatched types). Also include an existential property that demonstrates the presence of a record instance and an attempted access to the absent field, so the spec can be used to check whether such accesses are allowed or flagged as errors by the modeled semantics.
