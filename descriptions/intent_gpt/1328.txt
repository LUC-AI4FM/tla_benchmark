Specify a concurrent system that simulates multiple independent processes each repeatedly performing an action that updates shared state, with a mechanism to bound the number of steps explored. The model should allow an arbitrary finite set of processes that repeatedly execute a loop: each process non-deterministically chooses to perform an enabled action that modifies the shared state, or to remain idle. The shared state is a sequence or record that can be changed by process actions; no two processes may perform the same atomic update simultaneously. The system must include a global step counter that prevents infinite exploration by enforcing a maximum depth for behaviors. The specification must capture fairness options so both weak and strong fairness of process actions can be checked. Key correctness properties: (1) Safety — invariants on the shared state must hold after every step (for example, a value never decreases below a given lower bound, and no two processes concurrently obtain the same exclusive resource). (2) Progress — if a process is continuously enabled, it eventually performs its action (liveness under the chosen fairness). (3) Absence of deadlock — from any reachable state, at least one process can make a progress step unless the global bound is reached. The model should permit checking of these properties under varying numbers of processes and different maximum step limits.
