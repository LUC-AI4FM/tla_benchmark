Specify a formal model of a language extension mechanism that allows users to define new binary and unary infix and prefix operators with arbitrary symbol names (including punctuation, Unicode math symbols, and multi-character operator sequences), and to use those operators uniformly in expressions. The model should describe the syntax and typing rules for operator definitions and operator application, ensuring that:

- Any user-declared operator name can be parsed unambiguously in expressions (including when symbols overlap or when plain punctuation also has built-in meaning).
- Both binary and unary forms are supported; prefix notation for binary operators is allowed and equivalent to the usual infix form when appropriate.
- Operator arity and position (prefix vs infix/postfix) are enforced so expressions are well-formed; application of an operator with the wrong arity is invalid.
- Operator definitions are first-class in the sense that they can produce values, be passed to other operators, and be referenced uniformly.
- Built-in operators and user-defined operators coexist without ambiguity; common built-ins like set membership and union retain their semantics unless explicitly shadowed.
- Parsing and resolution are deterministic: given an environment of operator declarations and a concrete expression, the model yields a single abstract syntax and semantic interpretation.
- Simple algebraic consistency: applying an operator to concrete argument values yields the operator’s defined result.

State correctness properties: syntactic validity implies determinism of parsing and unique typing; well-typed expressions evaluate to a unique value according to declared operator semantics; and built-in operator semantics remain preserved unless shadowed. Include assumptions about a finite set of operator declarations and a deterministic lexical grammar for tokens.
