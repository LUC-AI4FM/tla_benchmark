Specify a formal model of Dijkstra’s ring termination-detection problem. The system consists of N processes arranged in a directed ring. Each process may be active (performing local computation) or inactive, and may send activation messages to other processes. A special circulating token is used to detect global quiescence: when the token returns to a designated leader process in a particular neutral state, the leader should be able to conclude that every process is inactive.

Model the processes, message deliveries, and the token as separate concerns: processes can locally change between active/inactive, send messages to other processes (potentially activating them), and change an internal “color” state that indicates whether they have generated activity that could affect termination detection. Messages may be sent asynchronously, and delivery may happen later; sending a message to a higher-indexed process must mark the sender as having generated potential forward activity. A process may initiate a token-based probe when it holds the token and certain color conditions hold; the token may be passed around the ring, and its “color” must reflect whether any process colored itself in a way that makes the round inconclusive.

Require these correctness properties:
- Safety: If the token returns to the leader in the neutral (white) state and the leader is passive/white, then every process must be inactive (the detection is sound).
- Liveness: If globally all processes eventually stop generating new activity (i.e., no new messages are generated after some point), then the token-based mechanism must eventually detect termination (the detection is complete).
- Invariant: capture and prove the standard inductive invariant that relates token position, node colors, and token color ensuring that an active process ahead of the token implies the token/colored conditions prevent a false detection.

Do not prescribe a concrete algorithmic encoding; instead specify the allowed state space, nondeterministic actions (local computation, send, receive, token initiation and passing, deactivation), and fairness assumptions needed to guarantee liveness.
