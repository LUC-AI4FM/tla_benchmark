Specify a formal model of a single-decree consensus protocol using asynchronous message-passing processes comprised of proposers and acceptors. The model should capture protocol behaviors that allow proposers to initiate proposals with monotonically increasing ballot numbers and acceptors to record promises and accepted proposals, exchanging three kinds of messages: prepare requests, prepare responses (including any previously accepted proposal info), and accept requests/responses. The system must permit concurrent proposers and unreliable delivery (messages can be delayed, duplicated, or lost), but not corrupted.

The model must ensure safety: at most one value may be chosen for the single consensus instance (i.e., any two values that become chosen must be equal). It must encode the quorum intersection requirement that guarantees safety, and express the invariant that proposers must pick values consistent with earlier accepted values observed in responses. It must also maintain acceptor invariants: acceptors never claim to have accepted two different values for the same ballot, and they only accept requests consistent with previously promised ballot numbers.

Additionally, specify a type and message-validity invariant describing allowed message formats and the relation between messages and acceptor local state, and a liveness-friendly notion of progress (optional): if a proposer repeatedly tries with higher ballots and a majority is responsive, then eventually a value is chosen. Do not prescribe implementation details such as exact actions, variable names, or code structure—only the required components, behaviors, and correctness properties.
