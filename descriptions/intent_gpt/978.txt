Specify a system that repeatedly alternates between two distinct kinds of state updates, called action A0 and action A1. The system maintains a control token that enforces strict alternation: each step must perform the other action from the one performed in the previous step. On startup the control token is set so that A0 is the first action to occur. The system also maintains an auxiliary payload component that represents the application state modified by A0 and A1. Each occurrence of A0 must transform the payload from a value satisfying the valid precondition for A0 to a value satisfying the valid postcondition for A0; likewise each occurrence of A1 must transform the payload from a value satisfying the valid precondition for A1 to a value satisfying the valid postcondition for A1. The initial state must satisfy the payload’s allowed initial condition.

Model the system as a discrete-state transition system with nonblocking progress: from any state where the control token indicates the next action, there must exist at least one legal transition implementing that indicated action and updating the payload accordingly. Require safety properties: the control token must always alternate and the payload transitions must always conform to the action-specific correctness relation. Require liveness: both A0 and A1 occur infinitely often (no permanent starvation). The specification should abstract the concrete payload semantics by parameterizing initial and action-correctness predicates so different payload models can be substituted.
