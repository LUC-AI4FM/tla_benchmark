Specify a formal TLA+ model of Safra’s distributed termination-detection algorithm for a unidirectional ring of processes with asynchronous point-to-point message channels. The model should treat two message kinds: regular payload messages that processes send and receive during normal computation, and a circulating token used for detecting global quiescence. The system must permit processes to be independently active or passive, to send payload messages to arbitrary other processes while active, to receive payload messages (which makes them active) and to locally change color to record whether they have sent messages “forward” since the last time they were visited by the token. The token must carry a numeric counter and a color bit; when a passive process holds the token it may forward it to its predecessor, adding its local contribution to the token’s counter and possibly turning the token black if the process is black. A process may initiate a new round by sending a white token with counter zero when it holds a black token but its local state or in-flight messages indicate nontermination.

Model the communication channels as FIFO buffers that can contain at most a small bounded number of messages for model-checking, and allow the environment to nondeterministically deliver or drop regular payload messages only via receive actions. The specification must guarantee the following correctness properties:

- Safety: The token is always unique (at most one token message exists in the entire system).
- Termination detection soundness: If the token completes a full circulation and returns to the origin white with counter zero, then no process is active and no payload messages are in transit — i.e., the system is truly quiescent.
- Progress/liveness: If the system is quiescent (no active processes and no in-flight payloads), then the protocol eventually detects termination (the origin will eventually observe a white token with counter zero).
- Invariants: local counters accurately track numbers of outstanding payload sends; colors correctly reflect whether a process has sent any payload “forward” since last token visit.

Do not encode procedural implementation details; specify the abstract state, allowed events (send, receive, deactivate, token forwarding, token initiation), their preconditions and effects, and assert the invariants and liveness properties above.
