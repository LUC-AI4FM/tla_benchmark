Specify a distributed ordering system with multiple clients and a single server that receives, queues, and delivers client orders. The model should represent clients that can independently issue new order requests at any time; a network that can carry messages between clients and the server; a server that receives order requests from the network, enqueues them in a single FIFO queue, and sends acknowledgements back to the requesting client; and a delivery process that removes orders from the head of the server queue and records them as delivered to the originating client.

The specification must capture asynchronous communication where messages may be in transit in the network until processed, and the server queue enforces a global ordering of accepted orders. It must permit arbitrary interleavings of client sends, message delivery to the server, and server deliveries, reflecting realistic concurrency.

Key correctness properties to require:
- Safety: no client should ever receive the same order identifier more than once (no duplicate deliveries per client).
- Delivery integrity: every delivered order must originate from a valid client request and match a previously sent order message.
- FIFO queueing: orders accepted by the server must be delivered in the same order they were enqueued.
- Liveness (optional): if a client issues a request and the network and server eventually process messages, the corresponding order will eventually be delivered.

Do not prescribe internal variable names or implementation structure; describe only the external behaviors and invariants above.
