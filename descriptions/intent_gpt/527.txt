Specify a finite-state protocol in which a single client repeatedly issues requests to a single server and waits for responses before issuing another request. Model the client and server as concurrent processes communicating via unreliable message channels that may nondeterministically drop messages but do not duplicate or reorder them. Each request carries a monotonically increasing identifier; the server must reply with the same identifier to allow the client to match replies to requests.

The system must ensure that the client never mistakes a reply for a different outstanding request and that every reply the client accepts corresponds to a request it actually sent. Allow the client to retransmit a request if it has not received a matching reply within an arbitrary delay; retransmissions reuse the same request identifier. The server must be allowed to ignore duplicate requests but must eventually honor at least one of the client’s requests when messages are delivered.

Specify fairness assumptions minimal enough to avoid trivial deadlock (e.g., weak fairness for message delivery and for server processing) and allow liveness reasoning: if the communication channel delivers messages often enough, then every request that continues to be retransmitted eventually elicits a matching reply which the client accepts.

State safety properties: reply-matching (client accepts only replies with the same identifier as its current request) and integrity (every accepted reply corresponds to a sent request). State liveness properties: eventual response under fair delivery and absence of livelock when retransmission is used. Provide the model with a bounded number of identifiers and messages so it is suitable for model checking.
