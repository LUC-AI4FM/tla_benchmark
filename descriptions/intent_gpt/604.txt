Specify a concurrent metadata service that manages locks and writes for a small key-value table accessed by multiple clients. The model should describe clients that each have an assigned primary key but may attempt transactions that read or modify other keys. The system must support atomic transactions composed of lock acquisition, read and write operations, commit, and abort, with clients able to retry on conflicts. Locks may be exclusive or shared as appropriate; the protocol must prevent two clients from concurrently performing conflicting writes to the same key.

Model the concurrency of clients and a storage layer that persists values per key. The specification must include possible network or scheduler interleavings and nondeterministic client decisions (e.g., when to abort or retry). It should capture that locks can be taken and released, that commits apply their writes atomically, and that aborted transactions leave storage unchanged.

State the correctness properties to verify: safety (no two committed transactions produce a write-write conflict on the same key; committed reads reflect a consistent view respecting lock semantics), atomicity (a committed transaction’s writes appear all-or-nothing), and absence of lost updates (if a transaction commits, its updates remain unless overwritten by a later committed transaction). Also require progress liveness under bounded fair scheduling: if a client repeatedly attempts a transaction without external failure, eventually either it commits or another progress condition prevents starvation.
