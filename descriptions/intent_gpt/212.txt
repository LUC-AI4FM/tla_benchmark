Model a distributed token-circulation protocol on a unidirectional ring of a fixed number N > 1 of processes. The ring has exactly one logical token that moves between neighboring processes. The token carries a small integer counter and a color bit from the set {white, black}. The system must support asynchronous moves of the token: at any step, the token may be handed from its current holder to its clockwise neighbor, optionally updating the counter or flipping the color according to allowed local rules. Specify the legal state space, the initial condition (token owned by process 0, counter zero, color black), and the allowed state transitions for the token movement and local updates.

Require and formalize the following correctness properties:
- Safety: At all times exactly one token exists and the token’s position is always a valid ring process identifier.
- Invariant bounds: The counter remains within a specified integer range (for example, nonnegative and bounded above by a constant).
- Liveness: From any reachable state, the token will eventually visit every process infinitely often (strong fairness or eventual circulation).
- Color consistency: If the color is used to detect a global condition (e.g., termination detection), express the intended relationship between colors and counter values that must hold when the token returns to a designated coordinator process.
- Absence of deadlock: No reachable nonterminal state should have no outgoing transition.

Do not prescribe implementation details such as data structures or atomic steps; describe only the abstract token, processes, initial configuration, transition relation, and the above correctness properties to be checked.
