Model a distributed mutual-exclusion algorithm based on logical (Lamport) clocks for a fixed set of processes. The specification should describe processes that use logical timestamps to request exclusive access to a critical section, broadcast requests and acknowledgements to other processes, and grant entry when it is safe. The model must capture asynchronous message delivery (messages can be delayed and reordered but not duplicated or corrupted), per-process logical clocks that are incremented on local events and updated on message receipt, and the requirement that request messages carry the sender's timestamp.

Specify the safety and liveness requirements the algorithm must guarantee:
- Mutual exclusion: at most one process may be in the critical section at any time.
- Request ordering: a process may enter the critical section only after it has received acknowledgements (or implicit permission) from all other processes for requests with lower or equal timestamps, ensuring global ordering by timestamp and tie-breaking by process id.
- Progress under fair channels: if a process repeatedly tries to enter the critical section and the network eventually delivers messages, then it will eventually enter (no permanent starvation under fair delivery).
- Clock monotonicity: logical clocks are nondecreasing per process and updated correctly on message receive.

Describe the allowed actions at a high level: sending a request, receiving a request, sending/receiving acknowledgements, and entering/exiting the critical section. Do not prescribe implementation details such as exact message formats, queue representations, or loop structure; instead state the abstract message types and the conditions under which messages are sent and consumption changes process state. Include parameters for the number of processes and an upper bound used only for model-checking if needed.
