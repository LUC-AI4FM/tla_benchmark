Specify a formal model of a translator that takes a high-level, procedure-and-process-based algorithm description (an abstract syntax tree of a small procedural language with named procedures, optional parameters, local and global variable declarations, labeled statements, control constructs like if/then/else, either/when/with, while, call/return and goto, and a distinction between uniprocess and multiprocess algorithms) and produces a corresponding TLA+ specification describing the algorithm’s operational semantics. The model should treat the input as an abstract syntax tree (not raw text) and capture how that tree denotes an initial state and a next-state relation for the algorithm: how variable initializations are established; how control flow progresses between labeled statements; how procedure calls, returns, and stacks behave; how process instances are represented and interleave (for multiprocess algorithms); and how guarded and nondeterministic constructs (either/when, choice, with) are resolved into enabled actions.

The model must guarantee correctness properties that the translation preserves the algorithm’s intended semantics: (1) reachable states and enabled transitions in the generated semantics correspond exactly to those implied by the AST; (2) procedure-local scoping and parameter passing behave atomically with respect to calls and returns; (3) nondeterministic choices and fairness options (none, weak/strong per-action or whole-step) are represented so that liveness assumptions hold as specified; (4) label-based control flow (including goto and labeled blocks) and while loops terminate or iterate according to their tests; and (5) the translation never conflates distinct labels or variables and reports an error condition when the AST violates semantic constraints (e.g., duplicate declarations or illegal uses). The model should be abstract about output formatting and focus on preserving semantics and detecting translation errors.
