Specify a small state machine that models the lifecycle of a single task progressing through three abstract phases: an initial unstarted phase, an in-progress phase, and a completed phase. The system starts in the initial phase. It must allow a well-defined transition from initial to in-progress, and from in-progress to done; once done, no further changes occur. The specification should treat the three visible phases as the external observable states, and should permit abstracting any concrete representation of these phases to the three visible values.

Model the safety requirement that the state is always one of the three allowed phase values. Model the liveness requirement that if the system is not yet in the final phase, it is possible for it to eventually advance (i.e., progress is not permanently blocked) — expressed as a fairness condition on the transition relation to ensure progress from non-final states is not indefinitely postponed. Also provide an abstract specification that can be instantiated with different concrete encodings of the phase variable, and a refinement property asserting that any such concrete encoding implements the abstract three-phase behavior.

Finally, include checks for (a) absence of deadlock, (b) that the refinement relation holds between concrete and abstract specifications, and (c) both a trivial temporal property (always true) and a nontrivial temporal property that composes the refinement safety with the trivial liveness, so tools can validate constant-level, state-level, and temporal-level properties.
