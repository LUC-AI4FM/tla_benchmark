Model a distributed consensus protocol in an asynchronous message-passing system where a fixed set of processes repeatedly try to agree on a value in successive rounds. The model should capture that processes send and receive three kinds of information: proposals for a value, confirmation-like pre-votes, and combined messages that carry both a proposal and an identifier. Processes may fail by crashing and messages may be delayed, reordered, duplicated, or lost, but no Byzantine (arbitrary malicious) behavior occurs.

Specify the protocol’s progress: in each round, a correct (non-crashed) leader may propose a value; other correct processes may support or pre-vote that proposal and later adopt a proposal when they have sufficient evidence. The system must allow leaders to change across rounds and must permit a process to carry forward evidence from earlier rounds into later rounds to preserve safety.

State the correctness properties to be verified:
- Safety (Agreement): No two correct processes ever decide different values.
- Validity: Every decided value must have been proposed by some process.
- Integrity/No duplication: Once a process decides a value in some round it never decides a different value later and does not decide more than once.
- Liveness under partial synchrony: If a period of sufficient synchrony occurs and a majority of processes are correct, then the protocol eventually decides.
- Monotonic evidence: Evidence for a value (e.g., a quorum of supporting messages) collected in a round that leads to adoption must not be invalidated by later rounds.

Define the model components abstractly (processes, rounds, message types, quorums, proposals, identifiers) and the allowed transitions (send, receive, crash, advance round, decide). Do not commit to a particular message encoding or leader-election implementation; allow the verifier to instantiate quorum sizes and timing assumptions.
