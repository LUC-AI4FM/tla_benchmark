Specify a system that models the rules for substituting operators into a parameterized module instance in a specification language that distinguishes Leibniz (substitutable) from non‑Leibniz (non‑substitutable) operators. The model should represent modules that declare operator parameters and allow instantiation of those parameters with either local operator definitions, lambda expressions, or operators imported from other module instances. The system must enforce the semantic constraint that only Leibniz (context‑independent) operators may be substituted for parameters that expect Leibniz behavior; attempting to instantiate a parameter with a non‑Leibniz operator must be rejected. It must also permit legal combinations such as substituting a Leibniz operator defined locally, a lambda producing a Leibniz operator, or an operator imported from another instance that is provably Leibniz. The model should capture operators that use state priming or other non‑Leibniz constructs and ensure they are treated as non‑substitutable. Specify properties that (1) every allowed instance satisfies the module’s parameter typing constraints, (2) every disallowed substitution is detected and flagged as illegal, and (3) composition and chaining of instances preserve the Leibniz/non‑Leibniz classification so that legality decisions are compositional. Include assertions or invariants that check these correctness properties.
