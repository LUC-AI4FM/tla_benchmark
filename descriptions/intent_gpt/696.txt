Specify a formal model of a JSON serialization/deserialization library that handles nested structured data and newline-delimited JSON. The model should treat in-memory composite values as either ordered tuples (arrays) or key‑value records (objects), and must support scalar values as leaf elements. It should provide operations to: (1) convert any in‑memory value to its JSON text representation, (2) parse JSON text back into the corresponding in‑memory value, (3) write a single JSON value to a file, and (4) read a single JSON value from a file, as well as (5) write and read a sequence of JSON values separated by newlines (ndJSON). The specification must not commit to any particular encoding algorithm or traversal order for object keys, but must require that for arrays the element ordering is preserved. It must define when a conversion or file operation is valid (e.g., empty records/tuples map to "{}" and "[]", respectively) and must specify deterministic semantics for parsing and serialization: serializing a value then parsing it back yields an equivalent in‑memory value up to any permitted object key ordering; ndJSON read/write must preserve sequence boundaries. Key correctness properties to verify: round‑trip fidelity for single values and for ndJSON sequences, preservation of array ordering, and type discipline (objects ↔ records, arrays ↔ tuples, scalars ↔ scalars). Also specify error conditions for malformed input and require that deserialization either returns a defined error or a value, with no silent undefined behavior.
