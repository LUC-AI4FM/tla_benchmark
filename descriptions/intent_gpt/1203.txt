Specify a formal model of a parametric function library and its use sites, where the library exposes a single opaque n-ary operator and several simple wrapper and transformation functions that call or reshape its results. The model should treat the library operator as an uninterpreted constant with arity five and allow client code to pass arbitrary values to it. The system should capture the following requirements:

- The library operator can be invoked with any combination of values drawn from the global domain; its semantics are unspecified beyond being a deterministic mapping from a 5-tuple to a result value.
- Several client-level functions should be modeled that either forward arguments directly to the library operator, pair a single argument with a fixed tag, construct small tuples, or compute set comprehensions that filter a trivial finite domain and map elements to tuple or constant results. One client function should demonstrate a let-binding that locally defines a tuple decomposition and returns a constant.
- The model must allow reasoning about all possible results produced by library calls and by the wrappers regardless of the library's internal behavior.
- Safety properties: no client function may produce values outside the union of the global value domain and results of the opaque operator; all composed constructions must preserve determinism (same inputs yield same outputs).
- Specify invariants that capture the wrappers’ structural shapes (e.g., tagged pairs, fixed-length tuples, finite sets) so properties of clients can be proven without knowing the library internals.

Do not commit to any particular implementation strategy for the wrappers; present only the interface-level behavior and the correctness obligations above.
