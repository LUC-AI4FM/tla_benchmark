Specify a concurrent producer-consumer system with a single shared buffer that can hold zero or more items drawn from a fixed finite set of possible values. The model should describe two types of events: producing an item and consuming one or more items. Producing may add exactly one item from the allowed value set into the buffer and must indicate that the buffer is no longer empty. Consuming may occur only when the buffer is nonempty, and it may remove any nonempty subset of the items currently in the buffer; consuming can remove one or many items but may not create new items. After a consume step, the model must correctly reflect whether the buffer has become empty.

Specify an initial state with an empty buffer and an explicit empty flag. The specification should allow any sequence of produce and consume actions subject to the above constraints. Formalize the key correctness properties to verify: (1) safety — items removed by consume were previously produced (no creation of arbitrary new values), (2) the empty/nonempty flag always correctly corresponds to whether the buffer contains any items, and (3) absence of illegal consumes — no consume can occur when the buffer is empty. Also express liveness requirements ensuring that produce and consume actions can continue to occur (no deadlock) under allowed choices.
