Specify a formal model of a single-node transaction processing system that supports both read-only transactions and regular (read-write) operations, with bounded history to prevent unbounded growth. The model should describe a node that receives requests, processes them, and produces responses, tracking a history of transactions and responses up to a configurable limit. It must allow concurrent interleaving of incoming requests and outgoing responses while ensuring the node never records more history entries than the bound.

The specification should capture the actions for: accepting a read-only transaction request, producing a read-only transaction response, performing ordinary node actions that represent the internal processing and state updates for read-write operations, and advancing the system step when none of these occur. The system must preserve safety properties: responses correspond only to previously accepted requests, read-only responses return values consistent with the node’s state at some linearization point, and the history length invariant is maintained (never exceeds the configured cap). Also specify liveness assumptions or fairness to ensure requests that are admitted will eventually receive responses, subject to the bounded history constraint. Provide a clear definition of initial conditions and the transition relation that enforces these requirements.
