Specify a formal TLA+ model of the classic Two-Phase Commit (2PC) protocol between one transaction coordinator (the transaction manager) and a fixed set of resource managers (participants). The model should capture the asynchronous exchange of three message types: participant "prepared" notifications to the coordinator, and coordinator "commit" or "abort" broadcasts to participants. The system must allow participants to enter a local prepared state or to unilaterally abort before coordination, and the coordinator must decide to commit only after receiving prepared from every participant, otherwise it may decide to abort.

Model the global state as the collection of each participant’s local decision state (at least: working, prepared, committed, aborted), the coordinator’s decision state (at least: initial, committed, aborted), the set of participants the coordinator believes are prepared, and the multiset or set of outstanding messages. Allow nondeterministic delivery/observation of messages and interleaving of participant and coordinator steps. Include actions for a participant to prepare, for a participant to choose to abort, for the coordinator to record receipt of a participant’s prepared, and for participants to receive a coordinator’s commit or abort message. The coordinator may broadcast commit only when every participant has signaled prepared; it may abort at any time from the initial state.

Require and specify these correctness properties:
- Safety (consistency): no participant may end up committed while any participant is aborted; the system must never reach a state with both a committed and an aborted participant.
- Type invariants: state variables and message kinds remain within their declared domains.
- Liveness/decision guarantees are optional but, if included, must be stated explicitly (e.g., eventual decision under fair delivery).

Do not prescribe implementation details such as particular variable names or a specific coding of actions; specify only the states, message types, permitted transitions, and the invariants the model must satisfy.
