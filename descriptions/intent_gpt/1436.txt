Specify a model of a simple program control structure with an infinite loop and no loop body, treated as an abstract execution environment. The model should represent program execution as a sequence of steps where a single thread repeatedly evaluates the loop condition and, when the condition is true, performs the loop iteration even though there is no observable body effect. The system must capture stuttering steps, termination behavior, and fairness considerations for infinite looping constructs.

Requirements:
- Represent the loop condition as a persistent predicate that may be true forever, true only for a bounded number of iterations, or become false eventually; the model must allow all three scenarios.
- Allow steps that correspond solely to evaluating the loop condition and progressing to the next iteration, producing no state changes when the body is absent.
- Support both weak and strong fairness assumptions about scheduling of loop-evaluation steps.
- Specify liveness properties: if the condition eventually becomes false, the loop must exit; if it remains true and fair scheduling holds, the model should reflect infinite execution rather than a stuck or terminated state.
- Specify safety properties: absence of unexpected state changes during iterations with an empty body, and preservation of invariants across iterations.

Include formal properties expressing eventual exit when the condition becomes false, nontermination when it remains true under fairness, and that no internal variables are altered by iterations with an empty body.
