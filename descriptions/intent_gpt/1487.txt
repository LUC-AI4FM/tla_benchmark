Specify a formal TLA+ model of a proof-management subsystem that tracks and applies backend proof strategies (provers/tactics) to obligations. The system should accept a catalog of available backends and configurable methods, allow associating pragmas or strategies with proof obligations, and maintain an ordered context so the most recently applied pragma takes precedence. It must support invoking multiple backends in sequence or composition, support per-backend timeouts and options, and allow grouping common multi-backend workflows (macros) that run several backends with specified ordering and fallback behavior. The model must permit rules for combining backends (e.g., run short SMT first, then stronger theorem provers), specify when an obligation is considered discharged, and represent failure, timeout, and retry semantics. Key correctness properties: (1) Soundness — only mark obligations proved if a backend run (or composition thereof) reports success; (2) Precedence — the active pragma context used for checking an obligation is the most recent applicable one; (3) Deterministic outcome given fixed backend results and timeouts; (4) Liveness — if a prover declared as last resort is available and does not fail, any obligation that is provable under the available provers will eventually be discharged by the configured workflow; (5) No silent loss — failures, timeouts, or skipped provers are recorded. Include invariants capturing context ordering, and temporal properties for eventual discharge under retry policies.
