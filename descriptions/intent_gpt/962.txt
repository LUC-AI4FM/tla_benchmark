Specify a formal model of an alternating-bit reliable data-transfer protocol between a single sender and a single receiver communicating over an unreliable channel that may lose, duplicate, or reorder messages but preserves message contents (no corruption). The system should allow the sender to transmit a (possibly infinite) sequence of data items drawn from a given set. The sender tags each outgoing message with a one-bit sequence number and retains the most recent outstanding message until it receives an acknowledgment carrying the matching bit. The receiver accepts a data item only when its sequence bit differs from the receiver's last-delivered bit, delivering each item at most once, and returns an acknowledgment carrying the bit of the last accepted message. Messages or acknowledgments may be lost arbitrarily, but if either kind of message is repeatedly sent, delivery will eventually occur (fair-loss assumptions captured as fairness conditions).

Model the protocol at the level of states and transitions without prescribing particular implementation steps. The model must permit the sender to initiate transmission of a new data item only when the sender believes the previous one has been acknowledged. It must permit the receiver to update its delivered-value and sequence-bit only when a fresh message arrives. Key correctness properties to guarantee:

- Safety: Each data item that the receiver delivers must equal a value previously sent by the sender, and no data item is delivered more than once (no duplication).
- Liveness: Under the fairness assumptions, every data item that the sender starts to send will eventually be delivered to the receiver.
- Agreement on sequence bits: The acknowledgment bits and receiver state evolve so that acknowledgments match the receiver's last delivered bit when appropriate, preventing deadlock.

Also specify type invariants for all state components and state fairness assumptions ensuring progress of receiving and acknowledging actions.
