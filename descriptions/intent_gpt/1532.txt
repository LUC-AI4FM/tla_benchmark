Model a simple shared-memory server that services read and write requests from a fixed set of clients. The model should capture an abstract request/response protocol where each client can be in one of three local states: ready to issue a request, waiting while its request is being executed, or having completed and awaiting acknowledgement. Clients submit atomic memory requests (reads or writes) which the server executes against a small, finite address space of memory. A submitted write should update the server memory at the specified address; a submitted read should produce the value currently stored at the requested address. The protocol must ensure that a client’s request is buffered at the server until the server executes it and that a client does not issue a new request while a previous one is in progress.

Specify initial conditions, including initial memory contents, all clients in the ready state, and empty buffers. Specify actions for: (a) a client issuing a request that is accepted and placed in the server’s per-client buffer and moves the client into the waiting state; (b) the server executing a buffered request, atomically performing a write or reading the memory to produce a response value, clearing or replacing the buffer entry appropriately, and moving the client to the completed state; and (c) the client receiving the response and returning to the ready state. Do not prescribe internal implementation details of the server beyond these observable behaviors.

State the following correctness properties to be checked: safety invariants asserting well-typedness of memory, client states, and buffers; that writes deterministically update the addressed location only when executed; that reads return the current memory value at the time of execution; and that a client cannot advance to a new request without having received its previous response. Also require liveness: every request that is issued is eventually executed and the client eventually receives a response (no permanent starvation or deadlock).
