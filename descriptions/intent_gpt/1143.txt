Specify a model of the algorithm that maps a highlighted region of a source specification to one or more highlighted regions of generated code. The model should accept as input: a structured description of the source text that identifies token spans and a nested parenthesis-like grouping structure (so that tokens lie inside matching begin/end markers and there may be "break" markers separating non-adjacent groups), and a user-selected source region. The mapping must compute which token(s) correspond to the selection (preferring tokens overlapping the region, otherwise choosing the nearest token), then determine the smallest enclosing syntactic unit(s) in the structured source by finding appropriate matching left and right group boundaries at a computed parenthesis depth. Finally, the algorithm must produce the sequence of code regions (one or more contiguous spans) that should be highlighted in the generated code corresponding to that syntactic unit, splitting at break markers according to their depth.

Require the model to enforce invariants: the input structure is well-formed (properly matched begin/end markers, tokens ordered by source position, tokens that are flagged as expression tokens are parenthesized), token-to-region selection is deterministic as specified, computed depths and matching parentheses are consistent with the nesting, and the produced output regions cover exactly the spans delimited by chosen parentheses and any intervening breaks. Specify safety properties asserting that computed indices and depths remain within bounds and that any asserted preconditions in the mapping (e.g., existence of required tokens or matching parens) never fail. Also state the liveness goal that the algorithm terminates producing a concrete finite sequence of result regions.
