Model a message-passing consensus protocol based on Paxos (classic Paxos without explicit leader or separate learners). The model should represent multiple acceptors that communicate by sending and receiving messages in unreliable networks and should allow proposers to initiate ballots. The system must support multiple ballot numbers and a fixed small set of possible values to be chosen.

Specify the protocol’s allowed message types and the conditions under which messages may be sent and accepted: (a) a proposer may announce the start of a ballot; (b) an acceptor that observes a ballot announcement may promise not to accept lower-numbered ballots and reply with information about any prior highest-numbered vote it cast; (c) a proposer may propose a value for a ballot only when it has evidence from a quorum that that value is safe at that ballot; and (d) an acceptor may accept a proposal for a ballot only if it has not promised to a higher ballot.

Formalize quorums (intersecting sets of acceptors), ballots, acceptor state that records promises and prior accepted votes, and an explicit message set representing all messages that can be sent. Do not assume reliable delivery; model safety only via permitted message receipts and allow nondeterministic receipt.

State the core correctness properties to verify:
- Safety (Agreement): at most one value can ever be chosen — if any two quorums of acceptances (or any two accepted ballot/value pairs at possibly different ballots with quorum support) imply the same chosen value.
- Consistency of acceptor state: acceptors never accept a value in a ballot after promising a strictly higher ballot.
- Validity of proposals: any value proposed as safe for a ballot must be consistent with prior accepted votes reported by a quorum.
Also specify a type invariant and initial conditions, and include a liveness requirement describing the messages that must be received (or retransmitted) to make progress (e.g., that proposers can eventually collect quorum replies).
