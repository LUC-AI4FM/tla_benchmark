Specify an asynchronous Byzantine binary consensus and reliable broadcast system for N processes with up to T tolerated faults and up to F actual Byzantine processes (with T ≥ F and N > 3T). The system should model processes that initially privately propose either 0 or 1 and then exchange two message types (call them ECHO and READY) asynchronously over unreliable links where Byzantine processes may send arbitrary messages. The model must capture message sending and reception counts without assuming FIFO delivery; messages can be lost only insofar as Byzantine processes can withhold or forge messages, but correct processes’ sends are eventually delivered to nonfaulty recipients subject to asynchrony.

Require the protocol to satisfy these correctness properties:
- Safety (Agreement): If any nonfaulty process decides a value, then every nonfaulty process that eventually decides must decide the same value; no two correct processes decide different values.
- Validity/Unforgeability: If all correct processes initially propose 0 (respectively 1), then no correct process ever decides 1 (respectively 0).
- Termination/Liveness under weak fairness: If enough messages from correct processes are eventually delivered and processes are not permanently blocked by Byzantine activity, then every nonfaulty process eventually decides (or every run that makes progress leads to decision).
- Byzantine resilience: The above properties must hold despite up to F Byzantine processes and under the given bounds N > 3T and T ≥ F.

Additionally specify guards for when a correct process may send ECHO or READY based on thresholds of received ECHO/READY messages, and when it may decide based on receiving READY from a qualified majority. Do not prescribe an implementation; model only the asynchronous message exchange, threshold-based state transitions, Byzantine behavior, and the stated safety and liveness requirements.
