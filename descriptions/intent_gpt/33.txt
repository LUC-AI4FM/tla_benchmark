Specify a formal TLA+ model of an option (maybe called "optional" or "maybe") abstraction and the standard operations on it. The model should treat option values as either "present" with an associated payload or "absent" with no payload. It must include: a constructor for present values, a canonical representation for absence, a predicate to test presence/absence, and a total elimination (case-analysis) operator that dispatches to one of two continuations depending on presence. Build higher-level operators in terms of these primitives: map (apply a pure function to the payload if present), flatMap/bind (sequence a function that itself returns an option), get-or-default (extract payload or return a supplied default), conversion to singleton sequence and to singleton set, nondeterministic choice from a set yielding an option (None if the set is empty), application of a total function to the payload yielding an option, and lifting a total function to a partial-function-like mapping that returns options for every input. The specification must state the intended semantics for each operator (when it returns present vs absent and what payload it returns), and must assert key correctness properties: map and flatMap obey functor/monad laws (identity and composition/associativity), get-or-default is a left inverse of the present constructor, conversions preserve membership (present payload appears in the sequence/set exactly when present), the nondeterministic chooser returns None iff the input set is empty, and the lifted partial-function returns None exactly on the declared undefined inputs and Some(f(x)) otherwise. Do not prescribe a particular implementation strategy; express only the abstract types, semantics, and these invariants and properties to be verified.
