Specify a formal TLA+ model of an unbounded shared-snapshot object supporting two kinds of concurrent processes: writers that repeatedly update their own component of a shared array, and readers that repeatedly obtain a consistent global snapshot of all writers' components. The model should capture asynchronous interleaving of steps by any process and allow arbitrarily many updates (unbounded counter values) per writer.

Requirements:
- Writers must be able to begin an update, perform an atomic increment of their own component, and finish the update. Each writer maintains a monotonically increasing sequence number or version to distinguish successive updates.
- Readers must be able to start a snapshot operation, perform repeated scans of writers’ components and any auxiliary per-writer metadata, and then produce a snapshot result that represents a single global state of all writers at some logical instant (not necessarily a single atomic point in time).
- The snapshot algorithm must ensure linearizability: each completed read returns values that correspond to some global state consistent with the real-time ordering of completed operations (each read should appear to take effect at some point between its invocation and response).
- The model should allow readers to detect inconsistencies between successive scans and retry or use auxiliary writer-provided snapshot information, but must guarantee progress for reads and writes under the usual asynchronous assumptions (no Byzantine failures). Specify invariants that relate reader-observed values, writers’ version numbers, and the memory array to ensure safety.
- State the initial conditions (all writer components zero/uninitialized) and specify the transition relation only by high-level read and write steps; do not prescribe particular implementation routines. Include formal safety properties (consistency/linearizability) and liveness expectations (non-blocking progress of reads/writes).
