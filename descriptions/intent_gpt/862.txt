Specify a model of a client-server authentication and message-routing system that includes a coordinator (server), multiple clients, and at least one adversarial actor. The system must capture the following behavior and requirements:

- Clients initiate authenticated sessions with the server using credentials (login identifiers and keys). The authentication protocol must allow the server to verify client identity and establish an association between a client and some logical session state (e.g., a mapped client address/port or session id).
- The server accepts inbound messages from authenticated clients and forwards or delivers messages according to configured routing rules (including matching on addresses/ports). The server must also handle unknown or wildcard match conditions according to a configurable policy.
- The network may perform address translation or source rewriting (NAT behavior) and may drop, reorder, or replay messages; the model must capture these nondeterministic network effects.
- An adversary may inject, replay, or forge packets from arbitrary network addresses and may attempt to impersonate clients or disrupt routing. The model must capture both honest and malicious actions, but must not assume trust in the network.
- Key correctness properties to verify:
  - Authentication integrity: the server never accepts a message as originating from a client unless the client’s credentials have been correctly presented and verified.
  - Authorization and isolation: messages from one authenticated client must not be delivered to another client’s session/state unless explicitly allowed by routing rules.
  - Replay resistance: previously seen messages (or authentication tokens) cannot be reused by the adversary to gain access or cause unauthorized deliveries.
  - Liveness: an honest client that follows the protocol and the network eventually delivers its request and receives a response under fair scheduling assumptions.
  - Robustness under NAT: when NAT is enabled, session mapping and route selection still preserve authentication and authorization invariants.

Describe the system components, their allowed message formats and state, the network adversary capabilities, and the properties above to be checked with model checking.
