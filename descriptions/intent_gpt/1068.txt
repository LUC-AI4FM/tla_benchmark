Specify an asynchronous distributed termination-detection protocol for a fixed set of processes communicating by message passing. The model should express processes that can be active or passive, send and receive messages asynchronously, and transition between active/passive states based on internal computation and message handling. The system must detect global quiescence: when every process is passive and no in-flight messages remain, some designated detector eventually learns this fact. The model should capture as requirements:

- Safety: The detector must never declare termination unless the system is actually quiescent (no active processes and no outstanding messages).
- Liveness: If the system reaches a quiescent state, the detector must eventually detect and declare termination (progress despite asynchrony).
- Type and invariants: process states and message counts remain within expected domains and any bookkeeping variables used to detect termination maintain consistency across transitions.
- Asynchrony and fairness: message delivery is asynchronous and non‑lossy; fairness assumptions (weak fairness for the termination-detection action or for enabled detection steps) required to guarantee eventual detection should be stated explicitly.
- Stability: once termination is correctly detected, the detected state remains true thereafter.

Do not constrain the solution to a particular implementation technique (e.g., token circulation, credit/reduction counters, or spanning tree); instead, specify the abstract behaviors, state predicates (active/passive, in-flight messages, detected flag), transitions allowed (send, receive, local compute, detect), and the correctness properties above so various termination-detection algorithms can be validated against them.
