Specify a formal model of the single-decree Paxos consensus algorithm (the algorithm described in "Paxos Made Simple") suitable for model checking. The model should represent an asynchronous message-passing system with a fixed set of acceptors and a notion of proposers/leaders that propose ballot numbers. It must support message types for prepare, promise, propose, and accept responses, and allow arbitrary ordering and delivery of messages (including duplicates and reordering), but need not model message loss explicitly beyond nondeterministic receipt.

The model must capture the following behavior and constraints:
- Leaders may initiate a ballot by broadcasting a prepare for a ballot number; acceptors promise not to accept lower-numbered proposals after promising a higher ballot.
- When a leader receives promises from some quorum, it may choose a value to propose. If any acceptor in that quorum has previously accepted a value with the highest accepted ballot, the leader must propose that value; otherwise it may propose any value.
- Acceptors accept a proposed value for a ballot only if they have not already promised a higher ballot; they then record their accepted ballot and value and respond.
- Quorums are sets of acceptors with the property that any two quorums intersect; quorums and acceptors are parameters.

State the safety property to prove: Agreement — at most one value may become chosen (i.e., a value accepted by a quorum) across all ballots. Also state liveness desiderata informally: if ballots eventually stop increasing and a majority of acceptors eventually respond, then a value is eventually chosen. The specification should define chosen precisely (value accepted by every member of some quorum) and include type invariants for messages and state. Do not constrain implementation details (process decomposition or exact message-representation).
