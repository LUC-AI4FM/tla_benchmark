Model a value-comparison component that represents and compares structured values (functions, records, tuples, and sets) built from integers and booleans. The model should define the kinds of values allowed (integers, booleans, finite functions with finite integer domains, records with named fields, tuples of fixed length, and sets of such values) and the rules that determine when two values are considered equal, ordered, or incomparable. It must capture type mismatches and partial incompatibilities: comparisons between values of different kinds or of incompatible domains/field sets must be rejected or yield “not comparable” rather than produce incorrect equality or ordering. For function and record comparisons, the semantics should treat missing keys/indices as incompatible unless the domains/field sets are equal; for tuples, length must match; for sets, element types must be consistent. Specify correctness properties including type-safety (comparisons never equate values of different kinds or incompatible domains), symmetry and reflexivity where appropriate (equality is an equivalence relation on comparable values), and that ordering (if defined) is antisymmetric and transitive on the set of comparable values. Also specify that the system reliably reports precise error information when attempting to compare values with mismatched element types (e.g., boolean vs integer).
