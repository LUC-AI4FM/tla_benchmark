Specify a formal model of TLA+ level checking for expressions and operator definitions. The model should represent modules, operator definitions, declarations (constant and variable), operator parameters (including higher-order/operator parameters), let-in expressions, instances (with substitutions), and expression forms whose semantics impose level restrictions (constants, state expressions, actions, temporal formulas). It must capture how the syntactic constructs of a module constrain the allowed “level” of subexpressions and operator arguments without committing to a particular implementation method for checking.

Requirements:
- Define the notion of expression level (four levels: constant, state, action, temporal) and how compound constructs determine the required maximum level of their operands (for example, priming, ENABLED, action contexts, temporal operators, and constructs that require non-temporal arguments).
- Represent level constraints on formal parameters and operator parameters, including constraints that an operator parameter must accept arguments of certain minimal levels for each of its positions.
- Capture how the level of an operator application depends on the operator’s declared/derived level and weights, and how operator definitions impose constraints on their parameters (including conservative approximations required for second-order parameters).
- Model how instance substitution and parameter instantiation propagate and combine constraints across module boundaries, and how to detect violations: an instantiation or expression is illegal if constraints require a parameter to be instantiated by an expression whose level exceeds allowed limits.
- Specify key correctness properties: soundness (if the model accepts an expression as level-correct then every expansion that replaces defined operators by their bodies produces an expression that meets the informal level rules), conservative safety for higher-order parameters (disallowing instantiations that could produce illegal levels), and termination/decidability of the checking algorithm on finite module forests.
