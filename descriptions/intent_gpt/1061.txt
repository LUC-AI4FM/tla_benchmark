Specify a synchronous distributed termination-detection protocol for a fixed set of N processes that communicate in synchronous rounds. The model should represent each process as either active or passive and allow processes to send and receive work tokens or messages that can cause activity to propagate. The system must start with an arbitrary subset of processes active and should permit local computations that consume or produce messages according to nondeterministic choices, but all communication happens in synchronous rounds with reliable delivery within the same round.

Require the protocol to detect global termination: termination occurs when every process is passive and there are no in-transit messages. The specification must include a termination-reporting mechanism that eventually sets a global termination flag exactly when the system is globally quiescent, and never before. The detector may be centralized or distributed, but must not rely on external oracles.

Key correctness properties:
- Safety: The termination flag is set only in states where every process is passive and no messages are outstanding.
- Liveness: If the system reaches a state with all processes passive and no messages, then the termination flag is set within a finite number of synchronous rounds.
- No false resets: Once the termination flag is set, it stays set (unless the system is explicitly reinitialized).
- Progress: Active behavior and message exchanges can continue indefinitely if processes keep generating work; the detector must not falsely declare termination in such runs.

Also specify invariants and fairness assumptions needed to prove the liveness property, and allow parameter N to be instantiated.
