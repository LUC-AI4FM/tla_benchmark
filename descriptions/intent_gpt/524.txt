Specify a reliable single-bit alternating acknowledgment protocol over an unreliable FIFO channel used to transfer application data from a sender to a receiver. The system has a sender that may generate application data items and places them into a local outbound queue. The sender repeatedly transmits a message that carries the current data candidate together with a one‑bit sequence number. The receiver repeatedly reads messages from the incoming channel; when it observes a message with a sequence bit different from its last accepted bit, it accepts that data (updating its stored state) and remembers the new bit. The receiver also sends back acknowledgments consisting of the last accepted bit. The sender advances to the next data item only after receiving an acknowledgment matching the bit it most recently sent; when advancing it flips the bit and installs the next queued data as the new candidate for transmission.

Model message channels that may lose messages nondeterministically but preserve ordering for remaining messages (i.e., messages can be dropped arbitrarily). Assume the receiver’s acknowledgments are single bits. Allow the environment to nondeterministically append new application data to the sender’s queue whenever sender and receiver states agree.

Specify the protocol behavior as a state machine and require these correctness properties:
- Safety: the receiver never accepts a data item out of order or duplicates an already accepted sequence number without an intervening advancement at the sender; accepted data must come from the sender’s generated data set.
- Liveness: every data item that is eventually enqueued by the sender while the protocol makes progress is eventually delivered and accepted by the receiver (despite arbitrary message loss), provided the sender and receiver continue to take steps (i.e., eventual delivery under fair scheduling).
- Invariant: sender and receiver each maintain a one‑bit sequence state that starts equal and flips only on successful advancement; the receiver’s stored data equals some previously sent data associated with its current bit.
- Channel property: losses may remove any message but do not reorder remaining messages.

Do not prescribe internal implementation details such as specific variable names or step decompositions; describe only behaviors, transitions, channel semantics, and the required invariants and liveness guarantees.
