Specify a formal model of a single-node replicated ledger service that exposes a transaction submission, execution, observation, and commit/notification API. The model should capture the externally visible history of requests, execution events, and responses, and an abstract set of append-only ledgers representing what a leader might have produced in each view. The system must allow clients to submit read-write transactions, allow the node to execute submitted transactions by appending them to any existing ledger branch, and allow the node to produce responses that indicate which ledger entry executed the transaction and which prefix of that ledger the client observed. The model must also allow the node to emit status notifications that a transaction is committed, subject to the requirement that the notified commit corresponds to an entry that actually exists in the most recent ledger branch and is not contradicted by any previously recorded invalidation. Ledgers must be append-only (no rollbacks), and transactions should not be duplicated into a ledger if they already appear there. The specification must express initial conditions, the possible external-history events (requests, responses, status messages), and the invariants to be checked: type-correctness of history and ledgers, monotonicity of ledgers, uniqueness of transaction identifiers where required, and the property that committed status messages refer to real, non-invalidated ledger entries.
