Specify a formal model of a library of finite sequence operations and utilities, and assert their expected behaviors as invariants over purely functional inputs. The model should treat sequences as finite ordered lists (allowing duplicates and empty sequences) and sets as unordered collections without duplicates. It must define and validate operations including: conversion between sequences and sets, sorted conversion from a set using a provided total or user-defined comparator, membership testing, reversing, removing all occurrences of a value, replacing all occurrences of a value, inserting and removing at positions, replacing at a given index, cons (prepend), taking the front (all but last) and last element, prefix and suffix tests (strict and non-strict), enumerating all prefixes, computing common prefixes and longest common prefix of a set of sequences, folding/left/right reductions, flattening a sequence of sequences by concatenation, zipping two sequences into a sequence of pairs, enumerating all contiguous subsequences (subseqs), finding the first index of a subsequence, and replacing the first occurrence of a subsequence with another sequence.

For each operation, specify precise preconditions and postconditions: domain and type constraints, length and element-order relationships, preservation of multiset or set semantics where applicable (e.g., SetToSeq outputs a sequence whose set of elements equals the input set), and behavior on edge cases (empty sequences, duplicate elements, indices out of range). State key correctness properties as invariants: conversions round-trip where appropriate, sorted outputs respect the comparator, membership and remove/replace operations are consistent, prefix/suffix relations are logically sound, folding yields the expected aggregate, flatten and zip preserve element order, and subsequence replacement only affects the first matching occurrence.
