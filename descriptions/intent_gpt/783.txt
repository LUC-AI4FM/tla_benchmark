Specify a replicated append-only log service for a fixed set of nodes and a fixed set of transaction identifiers. The system should allow any node to propose (append) a new transaction to the global log and should allow every node to execute transactions in log order. The model must ensure the log is a sequence of transactions that only grows by appending, and that each node maintains a local progress counter measuring how many prefix entries it has executed. Propose actions that append a transaction (allowed only when the proposer’s progress counter equals the current log length) and that allow a node to execute the next pending transaction (allowed only when its progress counter is less than the log length). The specification must state that the initial log is empty and every node’s progress counter starts at zero.

Require the following correctness properties: (1) Safety: no node may execute beyond the current log length (local progress never exceeds the log length); (2) Type invariants: the log is always a finite sequence of transactions and every progress counter is a natural number; and (3) Convergence (liveness): under appropriate fairness assumptions, every node’s progress counter eventually equals the log length (all nodes eventually catch up to all appended transactions). Describe what fairness assumptions are sufficient to guarantee convergence (for example, fairness for executing actions or for write actions, or both) and note which weak fairness assumptions are insufficient. Do not prescribe an implementation strategy beyond these behavioral requirements.
