Specify a formal model of vector-clock based causal ordering for messages in a distributed system. The model should represent a system of processes that generate, send, and receive messages, where each process maintains a vector clock reflecting its local logical time for every process in the system. The system must support: (1) local events that increment the sender’s own clock component; (2) message send events that attach a copy of the sender’s current vector clock to the message; and (3) message receive events that update the receiver’s clock by taking the pointwise maximum of its current clock and the message’s attached clock, then incrementing the receiver’s own component.

Express the causal relation induced by vector clocks: a message or event A causally precedes B iff A’s vector is less-than-or-equal-to B’s vector and at least one component is strictly less. The model must be able to determine whether two events are concurrent when neither vector is less-than-or-equal-to the other.

State the requirements to verify:
- Preservation of causality: if an event e1 happens-before e2 in the system execution (per message passing and local events), then the vector clock attached to e1 is less-than the vector for e2.
- Soundness: if a vector clock of e1 is less-than the vector clock of e2, then e1 can be ordered before e2 in the happens-before relation induced by executions.
- Concurrency detection: concurrent events must produce incomparable vector clocks.
- Monotonicity: every process’s own clock component strictly increases on its local events and non-decreases on receive events.
- Closure under composition: the vector clock updates must be associative and idempotent when combining multiple messages/events in sequence.

Include the ability to check these properties on finite traces (logs) of timestamped messages and events, and to assert counterexamples when properties are violated. Do not commit to a particular encoding of vectors or log file format.
