Specify a model of an automated benchmarking harness that runs a sequence of independent command-line experiments (benchmarks) and monitors their outcomes. The model should represent repeated experiment trials, a finite set of benchmark names, and a small set of allowed concurrency levels for each trial. Each trial starts by launching an external process with arguments derived from the benchmark name and concurrency level, records a timestamp, and associates each run with a log file path. The harness must capture the possible completion outcomes of each launched process: successful completion, a safety-failure code, a liveness-failure code, or other unexpected exit codes. For each outcome the model should record a trace message identifying the run, benchmark, and concurrency and must preserve run identity and parameters after the process outcome is observed. The model must allow multiple runs with different benchmarks and concurrency levels but should run one external process at a time (sequential execution of launches). Correctness properties to guarantee: (1) every started trial eventually reaches one of the completion outcomes (no indefinite internal blocking of a launched process); (2) the harness never silently loses or mutates run metadata when processing outcomes; (3) the only observable terminal exit codes are the specified success, safety, liveness, or other categories; and (4) no two launches overlap (sequential launch invariant). Also specify invariants expressing that recorded timestamps and log file names are consistently derived from the run id, benchmark, and concurrency.
