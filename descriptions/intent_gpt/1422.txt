Specify a simple two-component concurrent system in which one component is a binary flag and the other is a two-valued data token. Model the system's possible initial states, the allowed state changes, and the liveness and safety requirements that the system must guarantee.

The model should treat the first component as a flag that initially has a fixed value (for example, false/0) and may nondeterministically take either of its two values at each step. The second component is a token that initially has a fixed value drawn from a two-element set (for example, "a") and may nondeterministically take either of its two values at each step as well. The system must allow independent, possibly simultaneous updates of the two components subject only to those domain constraints.

Express safety properties ensuring that the system only ever takes values from the specified domains and that no illegal combinations or values occur. Express a liveness fairness assumption that prevents trivial stuttering of enabled state changes (e.g., weak fairness for the transition relation as a whole or for the flag's transitions), so nonblocked choices can eventually occur.

Also specify at least one liveness requirement that is nontrivial: if the flag ever becomes one particular value (e.g., the noninitial value), then thereafter the token must remain equal to a particular value (e.g., its initial value) forever. Additionally include a tautological leads-to property (a trivial property used for testing) to exercise the leads-to proof machinery.
