Model a simple reactive control flow that repeatedly calls a short subroutine which increments a shared integer and then returns, while the caller immediately jumps past an unused labeled block and then decrements the integer, forming a loop. The system should capture procedure invocation and return semantics (including preserving a return target), unconditional jumps (gotos) between labeled program points, and the effect of statements on a single integer state. Specify initial state, the allowed atomic state transitions for: invoking the procedure (saving the return target), executing the procedure body (increment and return to saved target), executing the caller’s skip-over behavior (jumping to the label after the call), executing the label that changes the integer to a fixed constant (this label is unreachable in correct execution but should be representable), and executing the decrement and loop back to the call site. Require that the model allows infinite repetition of this call/jump/decrement cycle.

The correctness properties to guarantee:
- Safety: the integer never takes values outside the integers reachable by the described operations (no spurious nondeterministic assignments).
- Control-flow integrity: calls always return to the stored return target; gotos land exactly at defined labels; there are no unmatched returns or lost return targets.
- Liveness: the system cannot get stuck in a state with no enabled transition (the loop can always continue), and the procedure call always eventually completes (returns).
- Optional invariant: the integer’s value equals the number of completed calls minus the number of completed decrements from the loop (i.e., overall arithmetic balance matches the program structure).
