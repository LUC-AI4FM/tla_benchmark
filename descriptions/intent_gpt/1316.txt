Model a distributed mutual exclusion algorithm for a fixed finite set of nodes that communicate only by asynchronous point-to-point message passing. Each node repeatedly alternates between a noncritical section and attempting to enter a single critical section. When a node wishes to enter, it must acquire a logical ticket (a pair consisting of a sequence number and the node id) that gives it a total ordering relative to other contenders; nodes exchange messages to learn others’ tickets and to acknowledge receipt. The algorithm must allow nodes to broadcast their current ticket to all others and to reply with acknowledgements; messages may be delayed but are neither duplicated nor lost, and receive actions are local to the destination. Nodes must release the critical section by broadcasting a zero (or sentinel) ticket to indicate they are no longer competing.

Specify the system state (local ticket numbers, knowledge of others’ tickets, per-pair message queues, and per-process control states) and a step relation capturing asynchronous sending, receiving, and local state updates. Require these correctness properties:
- Safety (Mutual Exclusion): at most one node may be in the critical section at any time.
- Liveness (Starvation-Freedom under fairness): if a node begins the entry protocol (reaches the entry point), then under weak fairness for the node’s actions (and fairness for message-delivery processes) it will eventually enter its critical section.
- Type invariants: message queues and local state variables always satisfy their intended domains (e.g., ticket numbers are natural numbers, queues store only allowed message types).
Do not encode implementation-specific control-flow labels; state the model abstractly in terms of processes that send and receive messages to implement the ticketing and acknowledgement protocol.
