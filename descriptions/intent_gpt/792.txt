Specify a formal model of a replicated key-value store that supports multi-key atomic transactions with snapshot isolation semantics, and that permits nondeterministic client and transaction scheduling. The system should allow clients to read and write keys, begin and commit transactions, and abort transactions; reads inside a transaction must observe a consistent snapshot of committed values as of the transaction’s start, plus that transaction’s own prior writes. Concurrent transactions may execute in overlapping intervals, but the commit protocol must ensure that committed transactions produce a serializable ordering consistent with snapshot isolation: each committed transaction sees a snapshot that reflects some prefix of committed transactions, and no two concurrently committing transactions may both violate commit-time write-conflict rules.

Specify the possible states and transitions abstractly (clients, transactions, key-value mappings, transaction-local buffers, start/commit/abort operations) without prescribing a particular implementation or communication protocol. Require safety properties: (1) Snapshot consistency for reads inside transactions; (2) Atomic visibility of a transaction’s writes upon commit; (3) Write-conflict prevention so that conflicting concurrent commits cannot both succeed; and (4) Invariant that nontransactional reads and writes behave consistently with committed state. Also state liveness goals: transactions that do not conflict should be able to commit eventually, and the system should not deadlock under fair scheduling. Provide assertions to detect invariant violations and a notion of symmetry reduction over transaction identifiers to aid model checking.
