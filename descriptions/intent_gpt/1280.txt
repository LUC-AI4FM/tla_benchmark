Specify a formal model of a finite multiset (bag) abstraction and its standard operations. The model should represent bags as finite mappings from elements to integer multiplicities (which may be nonnegative or allow integers where needed for intermediate definitions), and support an explicit empty bag and conversion to and from ordinary sets treated as single-occurrence bags. Include operations to query whether a value is a bag, to obtain a bag’s domain (the set of elements with nonzero multiplicity), to get the multiplicity (copies) of a particular element, and to compute the total cardinality (sum of multiplicities).

Model the following bag operations and algebraic laws without prescribing an implementation: bag addition (multiset union with multiplicities summed), bag subtraction (pointwise difference, clamped at zero for multiplicities if required), and the union of a set of bags. Include a partial order "subbag" that expresses elementwise multiplicity less-than-or-equal, and a higher-order operation that applies a function to every element of a bag producing a new bag whose multiplicities reflect images of elements (i.e., map and fold behavior).

Specify key correctness properties and invariants:
- Representations correspond: converting a finite set to a bag yields multiplicity 1 for each member and converting back yields the original set.
- Cardinality and copies relations: cardinality equals the sum of multiplicities; copies queries give 0 for elements outside the domain and correct counts inside.
- Algebraic identities: neutral element behavior for empty bag; commutativity and associativity where applicable for addition; subtraction cancels identical bags; bag union over a multiset of identical bags returns that bag; subbag reflexivity and transitivity and correct relation to addition/subtraction.
- Mapping: mapping the identity function preserves the bag and mapping a constant predicate yields expected multiplicities.

State any domain restrictions (finite domains, element type constraints) and require that proofs/temporal checks avoid relying on particular concrete elements so properties hold parametrically.
