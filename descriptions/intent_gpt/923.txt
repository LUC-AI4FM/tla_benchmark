Specify a formal model of a two-stage FIFO messaging pipeline consisting of an input channel, an internal buffer, and an output channel. The system accepts asynchronous send events from an external sender into the input channel and asynchronous receive events by an external receiver from the output channel. The internal buffer holds messages in FIFO order between the channels. Model the following abstract behavior and correctness requirements, without prescribing implementation details:

- The system maintains three abstract components: the input endpoint (accepts incoming messages), an internal bounded/unbounded buffer that stores a sequence of messages, and the output endpoint (delivers messages). Messages are drawn from a fixed type Message.
- The input endpoint must allow messages to be enqueued into the buffer (possibly via an input channel abstraction). The output endpoint must allow messages to be dequeued from the buffer and delivered to the receiver (possibly via an output channel abstraction).
- The system must permit four kinds of atomic steps: sending into the input endpoint, receiving from the input channel into the buffer, sending from the buffer into the output channel, and receiving from the output endpoint. Also allow stuttering (no-op) steps.
- Safety property: types are preserved — at all times channels and buffer contain only values of the Message type and the buffer is a sequence (i.e., well-formed). The FIFO ordering of messages must be preserved: messages are delivered in the same order they were accepted.
- Liveness desiderata (optional to include): any message accepted into the input endpoint should eventually be delivered to the output endpoint, assuming the environment does not permanently block sends/receives.

Provide invariants expressing type correctness and FIFO semantics and prove (or set up to prove) that they hold inductively from the initial state and are preserved by each atomic step.
