Model a system that constructs nested, possibly partial maps (finite functions) over structured keys and then updates them, where some keys are represented by non-reducible or abstract values so that domains can differ in subtle ways. The system should allow creating an initial outer domain of maps, initializing inner maps with default values, and then performing targeted updates that replace an inner entry with a function-valued mapping or replace an outer entry with a concrete value. The specification must capture that some keys or maps are intentionally non-reducible (opaque) so equality and domain computations may behave differently than syntactic expansion.

Specify the allowed states, the initial construction of the nested maps, and the permitted update operations. Require a safety property asserting that the set of outer keys of a particular resulting map is not equal to a given reference domain (i.e., that an update can change the domain in a detectable way). Also require observability of the domains of interest so the model checker can report them. Do not prescribe particular implementation strategies for representing non-reducible keys or lazy function values; instead, require that the model preserve their abstractness and ensure the correctness property about domain inequality holds in all reachable states.
