Specify a generator for valid HTML documents and fragments as an abstract specification. The system should accept high-level components (document head, body, styles, scripts, and nested UI elements) and produce well-formed HTML strings that, when concatenated, form a complete HTML document. It must support parameterized templates where placeholders inside element templates can be replaced by supplied values, and it must allow concatenation of sequences of strings with configurable separators. The model must include commonly used constructs: style sheets composed of named classes with attribute lists, script inclusions and embedded script blocks, link tags, meta and title elements, generic containers (divs) with ids, classes, inline styles, simple text spans, SVG containers with attributes, and utility fragments such as line breaks and size attributes. It should permit composing higher-level elements from lower-level pieces (e.g., boxes, grids, circles) and assembling lists of script or class entries. Correctness properties to guarantee: (1) Well-formedness — every generated opening tag has a matching closing tag and the overall document begins with a DOCTYPE and html root; (2) Deterministic composition — given the same inputs, the generator always returns the same string; (3) Placeholder safety — all placeholders in templates are replaced by concrete values or result in a detectable error when missing; (4) Idempotent concatenation semantics — concatenating sequences of fragments with a separator yields the same result regardless of associativity; (5) Referential integrity — elements referencing ids in script fragments or lines refer only to ids present in the assembled document. Model inputs and outputs abstractly (strings, sequences, maps) and specify these invariants without prescribing a particular implementation strategy.
