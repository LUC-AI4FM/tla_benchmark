Specify a formal model of the single-decree Paxos consensus protocol (classic Paxos without explicit distinguished leader or learner processes) suitable for model checking. The model should describe a system of proposers and acceptors exchanging the standard Paxos messages (phase-1a, phase-1b, phase-2a, phase-2b) over an abstract asynchronous unreliable network (messages may be delayed, duplicated, or never delivered). The model must allow multiple concurrent ballots (proposal numbers) and arbitrary interleaving of proposer and acceptor steps.

The specification must capture the following functional behavior and constraints:
- A proposer may initiate a ballot by sending a phase‑1a prepare for a ballot number.
- An acceptor receiving a prepare for a ballot greater than any it promised must promise not to accept lower ballots and reply with its highest accepted ballot/value if any.
- A proposer that collects replies from a quorum may propose a value in phase‑2a that is safe according to Paxos rules (use the highest-numbered accepted value among replies, or any value if none).
- An acceptor receiving a phase‑2a for a ballot not less than its promise may accept the value and inform others.

Specify the safety properties to verify:
- Safety (Agreement): At most one value can ever be chosen (no two different values chosen in any executions).
- Validity: Any chosen value must have been proposed by some proposer.
- Integrity: Once an acceptor has accepted a value for a ballot, it does not accept a different value for the same ballot.

Also specify basic type and invariant constraints (finite sets of ballots, acceptors, values, and quorums) and a notion of votes/choices derived from accepted messages so that model checking can be applied to prove safety. Do not prescribe a particular implementation strategy for message delivery or leader election.
