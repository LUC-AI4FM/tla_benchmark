Specify a system that exports a directed graph representation of an execution trace (counterexample) produced by a model checker. The model must accept as inputs a finite set of states and a finite sequence of actions that together describe a failing execution, where each action associates a source state, a target state, and a descriptive label. The system should produce a graph structure whose nodes are the states present in the trace and whose directed edges correspond to the actions, preserving the source→target relation and attaching the action label to the corresponding edge.

Model the generation of a textual serialized graph (for example, DOT or plain text) from that graph structure. The serialization must include node identifiers and edge lines that include the action labels, and must deterministically produce the same output for a given trace. The model should permit an option to suppress output when no trace is provided or when an output-to-console flag is disabled.

Key correctness properties:
- Soundness: every action in the input sequence yields exactly one corresponding directed edge in the graph with the correct source, target, and label.
- Completeness: every state that appears in any action appears as a node in the graph.
- Deterministic serialization: the same input trace and same formatting options always yield identical serialized text.
- Output control: when the trace is empty or output is disabled, no file is produced and no serialization occurs.
- Successful write: when serialization is performed, the model reports a successful write result.

Do not commit to specific variable names or procedural steps; focus on the abstract mapping from trace to graph and the properties above.
