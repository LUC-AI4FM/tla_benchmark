Specify a TLA+ model of a state-machine-based system that represents a single authorized client (a single user identity) interacting with a server-side state machine. The model should capture initialization and an ongoing step relation in which only that single user may drive transitions. The system must model the state space of the server and the permitted user-driven actions abstractly (for example: request submission, state transition, and response production), but the specification should not prescribe a particular implementation of those actions.

Requirements:
- The model must impose that there is exactly one valid user identity and that only actions attributed to that identity can trigger state transitions.
- Initialization must produce a well-formed initial server state.
- The step relation must allow the single user to perform any of the abstract allowed actions that change server state; steps by any other identity must be disallowed.
- The model must include safety properties: invariant that the server state always satisfies a consistency predicate (e.g., no conflicting resources, maintained invariants), and that only authorized operations are performed.
- The model must include liveness guarantees: whenever the single user repeatedly attempts an enabled action, the system eventually makes progress (i.e., an enabled user action is eventually executed).
- Specify the state, actions, and properties independent of naming or implementation details so the resulting TLA+ specification can be used to verify both safety and progress for a single-client scenario.
