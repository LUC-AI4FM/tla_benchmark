Model the Two-Phase Commit protocol for a single transaction coordinated by a transaction manager and a fixed set of resource managers. The model should abstractly represent each participant’s local state and the messages exchanged (Prepared, Commit, Abort) but need not prescribe a particular encoding for messages. The system must allow arbitrary interleavings: resource managers may independently prepare, fail to prepare, and react to coordinator decisions; the coordinator may collect Prepared notifications and then decide to Commit or Abort based on which RMs reported prepared; messages may be delayed, duplicated, or reordered but not corrupted.

Specify the safety and liveness goals the protocol must guarantee:
- Safety: No resource manager may commit unless the coordinator has decided Commit, and once any resource manager commits, no resource manager may subsequently abort that same transaction. The coordinator must never decide Commit if some resource manager has irrevocably aborted.
- Agreement: All non-faulty resource managers that reach a final decision must agree on the same final outcome (all Commit or all Abort).
- Termination (weak liveness): If all participants and the coordinator are non-faulty and messages are eventually delivered, the protocol must reach a final decision (Commit or Abort) within finite steps.
- Fault tolerance constraint: If some resource managers fail and recover, ensure the protocol still preserves safety (no contradictory final outcomes) and that a decision is possible whenever sufficient information is available (e.g., coordinator has received Prepared from all live RMs).

Allow expressing failure and recovery of components and eventual delivery separately, and enable checking of invariants that capture the above properties.
