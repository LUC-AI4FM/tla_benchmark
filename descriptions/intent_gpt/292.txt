Model a distributed clock synchronization service for a fixed set of five processes. The system must represent each process holding a local integer clock and maintain pairwise integer drift estimates between clocks. Specify an initialization that assigns concrete integer values to every process clock and to every drift estimate. The model should allow asynchronous, nondeterministic steps in which a single process updates its own clock value and may adjust its drift estimates with respect to others; concurrently, no other process state changes in that step. Updates may be arbitrary integers but must preserve simple invariants (for example, drift between two clocks must equal the difference of those clocks within the specified model semantics, or any allowed residual must be recorded consistently). Include operations for reading another process’s clock value (observations that can be stale) and for computing a new local clock using observed values and current drifts.

State key correctness properties to prove: safety (no two processes ever conclude inconsistent global time ordering that contradicts recorded drifts), bounded drift (the absolute value of any drift estimate remains within a fixed finite bound at all times), and convergence liveness (if processes repeatedly exchange observations and update, then eventually all drift estimates stabilize to values consistent with the actual clock differences). Also specify invariants ensuring absence of deadlock (some update action is always enabled unless quiescent), and robustness to a single faulty process (faults may arbitrarily change that process’s clock but must not violate the bounded-drift property for non-faulty pairwise estimates).
