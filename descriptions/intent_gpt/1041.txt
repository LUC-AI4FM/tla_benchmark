Specify a system that models a classic distributed mutual exclusion algorithm for three processes competing to enter a critical section. The model should represent an asynchronous setting where each process can execute steps independently and may be delayed arbitrarily; there is no global clock. Processes communicate only via shared variables (no message passing), and all actions are atomic. Each process repeatedly alternates between noncritical and critical sections, using the algorithm to coordinate access.

The specification must state the safety requirement that at most one process is in the critical section at any time (mutual exclusion). It must also state liveness requirements: from any reachable state in which some processes continually attempt to enter the critical section, eventually one of them succeeds (no permanent starvation for all contenders), and the system as a whole does not deadlock (if some process is enabled, some process eventually makes progress). The model should allow arbitrary scheduling of enabled actions and must permit modeling fairness assumptions needed to prove liveness properties. Provide invariants and temporal properties sufficient to verify safety and liveness of the mutual exclusion protocol for the three participating processes.
