Specify a formal model of a transactional storage system that defines executions of transactions over a key-value state and formalizes client-centric isolation levels. The model should treat a transaction as a sequence of read and write operations over keys, and an execution as a total order in which transactions are applied to produce a sequence of states starting from an initial state. The system should allow non-deterministic interleaving of transactions by considering all permutations of a given set of transactions and the resulting parent states for each transaction.

Require the model to define, for each operation, the set of possible states from which that operation may read (including writes performed earlier in the same transaction). Using that notion, specify for a given execution when each transaction has valid read states for all its operations, and when a single state is “complete” for a transaction (i.e., every operation of the transaction can read from that state). Also define a transaction’s write set and a notion of write-conflict between a transaction and a candidate read state.

Formulate commit tests that characterize standard isolation levels: Serializability, Snapshot Isolation, Strict Serializability (with an external timestamp order), Read Committed, and Read Uncommitted. For each level, require the existence of an execution (a permutation of the transactions from the given initial state) such that every transaction satisfies that level’s commit test. State these correctness properties as existential or universal requirements on executions, without prescribing how the system schedules or implements transactions.
