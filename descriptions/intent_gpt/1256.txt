Specify a formal model of a general-purpose model-checker runtime library that provides deterministic, observable helper operations used by a state space explorer. The model should describe services that a model checker makes available to specifications and checks, not the internals of any particular algorithm. The system must supply:
- a way to print or log values for debugging and progress reporting;
- an assertion facility that can fail a check and optionally emit diagnostic information without prescribing error-handling strategy;
- a source of nondeterministic numerical time or step counters for use in timed measurements;
- a per-worker mutable storage array with get and set operations, where each worker has an independent view after initialization, but an initial global setting can initialize all workers’ views;
- an operation that chooses an element uniformly (or nondeterministically) from any nonempty set for randomized simulation or sampling;
- operations to query lightweight runtime metrics such as number of distinct states discovered, queue length, elapsed time, current exploration depth, and maximal depth seen so far;
- utility operators for common functional manipulations: overriding maps, merging maps, producing permutations of a finite set, and stable sorting of finite sequences consistent with a provided binary comparison relation.

Require that all operations are abstract: they may be nondeterministic but must always yield values of the expected type and must not deadlock. The get/set storage semantics must ensure that sets performed before worker activation affect all workers, while later sets affect only the actor’s local view. The sampling operation must always return an element from the provided nonempty set. Specify invariants expressing these behavioral contracts and liveness assumptions sufficient for model checking client specifications that rely on these services.
