Model a Byzantine-tolerant round-based consensus protocol for a fixed set of processes (n) with up to t faulty processes. The system should capture repeated asynchronous rounds in which a designated proposer for each round suggests a value, and honest processes execute a voting phase that includes at least two message steps (a prevote and a precommit), with the ability to lock on values and carry forward "valid" values across rounds. Specify the following behavior and guarantees, without prescribing an implementation:

- Each round has a single proposer who may propose a value (which may be valid or invalid). Honest processes may only propose, prevote, and precommit according to the protocol rules that depend on their current round, step, locked value/round, and previously observed votes.
- Processes may receive and broadcast messages asynchronously; messages may be delayed, duplicated, or reordered but not forged. Faulty processes can behave arbitrarily.
- Processes maintain a notion of locking: once an honest process precommits a value in some round, it may refuse to prevote conflicting values in later rounds unless unlocking conditions are met.
- Processes maintain information about a "valid" value and its round, which can influence what they propose or prevote in later rounds.

Specify safety and liveness properties to prove:
- Safety (Agreement): No two honest processes decide different values.
- Validity: Any value decided by an honest process must be in the set of globally valid values.
- Locked-value consistency: If an honest process locks a value at some round, no honest process can later decide a conflicting value unless the protocol’s unlocking condition is satisfied.
- Termination under partial synchrony (or eventual stability): If after some Global Stabilization Time messages are eventually delivered and the proposer selection is fair, then all honest processes eventually decide.

Also specify the system parameters (n, t, set of valid values), message types (proposal, prevote, precommit), and the quorum thresholds needed for prevote/precommit decisions. Do not fix proposers statically; allow arbitrary proposer assignment per round.
