Specify a formal TLA+ model of a distributed account-based ledger that uses account-specific chain structures (one chain per account) and cryptographic signatures to authorize state changes. The model should represent nodes that can create and propagate signed blocks of several kinds: an initial genesis allocation, account-opening blocks that claim prior send blocks, send blocks that decrease an account balance and mark funds as transferable to a destination account, receive blocks that claim a prior send and credit the recipient account, and change-representative blocks that update an account’s representative. The system must model a network in which nodes maintain local ledgers, exchange proposed signed blocks, validate signatures and block references, and append validated blocks to their local account chains. Hashing must be modeled abstractly so block identities (hashes) can be calculated and used as immutable references.

Require the model to enforce safety properties: signatures must validate against the public key controlling an account, an account may only be opened once, a receive may only consume a send that has not already been received, send amounts must not exceed the sender’s current balance, and the sum of all account balances never exceeds the initial genesis total. Also require type invariants for well-formed state. Do not prescribe specific implementation details for message delivery or hash/signature encodings beyond abstract operations and their intended semantics.
