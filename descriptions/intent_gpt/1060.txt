Specify a concurrent token-passing system on a fixed ring of N processes. The system repeatedly circulates a single token; a process holding the token may change its local state (color) and then pass the token to its successor. The model should allow processes to be either active or inactive; only active processes may hold and forward the token, but inactive processes remain in the ring and can be reactivated later. Each process maintains a color value drawn from a finite set (represented as strings). One distinguished variable represents the token’s current color and position. The specification must capture initial conditions, token circulation, local color updates by the token-holder, and activation/reactivation of processes.

The correctness properties to guarantee are:
- Safety: At most one token exists; the token’s position always refers to exactly one process.
- Liveness: If a process is active, then eventually it will receive the token (no active process is permanently starved).
- Consistency of token color: When a process updates its local color while holding the token, the token color and the process’s local color must remain synchronized according to the update rule.
- Invariant: The set of active processes and the token’s position must always be within the index range 0..N-1.

Specify parameters (ring size N and finite color set) and state these properties formally so they can be checked by a model checker.
