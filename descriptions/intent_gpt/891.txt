Specify an asynchronous single-bit handshake interface between a sender and a receiver that transfers arbitrary data values reliably without a shared clock. The model should treat data items as coming from a fixed finite set. The sender may present a new data value at any time, and toggles a one-bit ready line to indicate a new value is available. The receiver samples the ready line asynchronously and, when detecting a change, toggles its one-bit acknowledge line to indicate it has consumed that value. The protocol must allow repeated transfers of data items, possibly with the sender changing the data before the receiver acknowledges, and must not lose or corrupt data values.

Model the system as two independent agents (sender and receiver) interacting only via the ready and acknowledge bits and the data channel. Specify initial conditions where ready and acknowledge are in a consistent state and the data channel holds a valid data value. Describe behaviors where (1) the sender may non-deterministically choose a new data value and flip the ready bit only when ready and acknowledge match, and (2) the receiver may flip the acknowledge bit only when ready and acknowledge differ. Ensure the model admits fair patterns of progress so transfers can complete.

State and assert these correctness properties: type safety (ready/acknowledge bits and data always stay within their domains), preservation of data integrity (values delivered are exactly those produced by the sender, not corrupted), and absence of deadlock (if sender issues a new value, the receiver can eventually acknowledge it). Include an invariant that alternation of the two handshake bits correctly indicates pending vs. consumed data and a liveness property guaranteeing eventual acknowledgement of each send.
