Specify a model of a distributed termination-detection protocol for a unidirectional token-passing ring of N processes. The system should allow processes to be active or inactive, to send ordinary messages that can activate other processes, to maintain local counters of sent work, and to circulate a special probe/token message that carries an ownership id, a cumulative counter, and a color bit used to detect outstanding work. The protocol must support an initiator that occasionally starts probe rounds to determine global quiescence, and processes that on receipt of the token update the token’s cumulative count and color based on local state. Model optional protocol variants controlled by a set of feature flags that can permit (1) passing the token even when the holder or token is “tainted”, (2) using local or incoming taint information to decide passing, and (3–4) aborting a token round early by returning the token immediately to the initiator when the holder or the token is black. The model must allow an external environment to perform arbitrary message sends and activations to represent workload.

Require the specification to guarantee safety and liveness properties: (a) the detection is sound—when the protocol signals termination, there are no active processes and no messages in transit; (b) detection is eventual—if the system truly becomes quiescent, an initiated probe eventually causes the initiator to detect termination; and (c) absence of false positives—the protocol must not report termination while activity remains. Also require metrics collection: count rounds, probe and token actions, sends/receives, and the number of steps between the environment becoming quiescent and the initiator detecting termination to compare efficiency across feature-flag variants.
