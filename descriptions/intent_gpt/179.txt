Model a generic Option (maybe) type library and its utility operations so that the following behaviors and correctness properties can be formally specified and checked.

Specify an abstract optional-value type that can either contain a value or represent absence. Provide operations to:
- Map a function over an optional value, yielding absence when applied to an absent input and applying the function to produce a new optional when present.
- Fold a binary operation across a finite set producing an optional result that is absent for the empty set and returns the aggregation wrapped in an optional otherwise. The fold must allow a custom binary combiner that can safely operate with an initial absent state.
- Case-elimination (pattern match) that applies one function when a value is present and a different zero-argument function when absent, returning the result of the chosen function.
- Convert between optionals and standard containers: convert an optional to a sequence (empty sequence for absence, singleton when present) and to a set (empty set or singleton).
- FlatMap (bind): apply a function returning an optional and flatten the nested optional structure, preserving absence semantics.
- A nondeterministic/choice operation that returns an optional containing some element from a given finite set, or absence for the empty set; when it returns a present value, that value must belong to the input set.
- Function application and partial function lifting: given a total function and an optional argument, apply the function when the argument is present and return absence otherwise; given a partial function defined on a domain, produce a total function that returns an optional—Some(result) on the defined domain and None elsewhere.

State the expected behaviors (examples) as invariants or properties: mapping increments, folding to compute maximum produces None on empty and the maximal element when nonempty, case-expression returns branch results, conversions produce empty or singleton containers appropriately, flatMap composes to produce nested results or None, choice picks a member or None for empty, function-application behaves like application-with-absence, and partial-lifted functions return Some for defined inputs and None for undefined inputs.

Require proofs or model checking assertions that these properties hold for all admissible inputs.
