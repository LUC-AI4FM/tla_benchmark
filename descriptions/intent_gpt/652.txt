Specify a TLA+ model of a light-client verification protocol that fetches and verifies compact proofs (light blocks) of a replicated append-only ledger produced by a set of validators. The model should describe a network of a fixed set of validators where a bounded fraction may be Byzantine (faulty) and may equivocate or omit messages. The light client repeatedly attempts to advance its verified ledger height up to a target by fetching candidate proofs from different validators, checking signatures/commitments, and applying liveness/time constraints. The client has an internal notion of trusted height (a base checkpoint) and a trusting period after which prior checkpoints expire. Clocks are imperfect: each node and the client have local clocks that can drift within specified bounds and the client must use timestamps and timeouts that account for clock drift and a bounded real drift. The client should probe multiple peers, maintain a cache of fetched proofs, and decide when to accept, reject, or wait for more information.

Specify safety properties: the client must never accept a proof for a height unless a correct quorum of validators (over the non-faulty set) could have signed a valid commit for that height consistent with the ledger; once a height is accepted it remains accepted (monotonic verification); the client must not regress verified height. Specify liveness properties under appropriate assumptions: if a correct primary (or enough correct peers) provide valid proofs within the trusting period and network delivery is timely, the client eventually advances to the target height. Specify robustness properties: the protocol tolerates up to the configured fraction of faulty validators, protects against equivocation, and avoids accepting proofs after the trusting period has elapsed. Include invariants about the interaction between clock drift, trusting period, and verification deadlines to ensure no acceptance based solely on stale checkpoints.
