Specify a formal TLA+ model of a two-region replicated storage system that supports standard Raft replication and a coordinated merge operation between two co-located regions. The model should describe multiple stores, each storing two independent Raft groups (one per region). For each Raft group the model must capture leaders, follower replication state, logs (distinguishing normal vs. administrative log types used for merge: pre-merge, merge, rollback), commit and apply indices, and per-leader match indices. The system must allow ordinary client requests that append normal logs to the region being merged, the usual AppendEntries and AppendEntriesReply RPCs, leader-driven advancement of commit index when a quorum acknowledges entries, and application of committed entries to the state machine.

Additionally, specify a merge protocol initiated by appending a pre-merge admin entry on one region which causes the leader to propose a merge by copying a contiguous suffix of logs into the other region as merge admin entries, then applying those merge entries and marking the source region tombstoned when merge completes. Include a possible abort path implemented by a rollback admin entry that cancels the in-progress merge and restores region state. The model must express quorum behavior, message delivery and processing, and allow limited follower lag.

State the key correctness properties to verify: single leader per group, messages for AppendEntries originate only from the leader and replies target the leader, followers’ logs are always prefixes of the leader’s logs and do not exceed what leaders know replicated, apply_index never exceeds commit_index, and that stores which have applied the same log prefix agree on region state and count of applied normal logs. Also assert that when the merge completes (both stores mark the merged region tombstone), they have identical applied-normal-log counts for that region.
