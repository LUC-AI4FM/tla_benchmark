Model a family of distributed system experiments that explore how variants of a token-based probe protocol behave under different node counts and feature subsets. The model should represent a network of identical processes (nodes) that can send and receive messages, initiate probes, pass a token, and deactivate/reactivate components. It must support parametrization by:
- the set of participating nodes (varying sizes),
- a selection of optional features that alter behavior or enable/disable protocol actions,
- multiple randomized or enumerated runs per configuration for statistical collection.

The system should simulate asynchronous message delivery with no global clock, allowing arbitrary interleavings and possible message loss or delays if a feature set specifies such faults. It must allow a process to initiate a probe, forward or respond to probes, pass a token to coordinate activity, and deactivate itself while preserving safety invariants. Correctness properties to guarantee for all configurations and runs:
- Safety: no two nodes concurrently hold conflicting authoritative state (e.g., at most one token holder, no duplicate probe initiations causing inconsistent decisions).
- Integrity: messages and probes, when processed, lead to well-formed state transitions; deactivated nodes do not corrupt global invariants.
- Progress/Liveness under fair scheduling when required by enabled features: probes eventually terminate and tokens are eventually passed or reclaimed, absent permanent faults.
- Termination or stable quiescence detection: the protocol can detect when no further meaningful actions remain.

Additionally, the model should produce per-run statistics (counts of probe initiations, token passes, sends/receives, deactivations, and execution length) for each node and feature combination for later analysis.
