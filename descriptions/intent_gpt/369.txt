Specify a parametric operator library and its usage contract for symbolic binary and unary operators so that a consumer can instantiate and apply any operator variant uniformly. The model should describe an abstract family of binary and unary operations identified by distinct symbolic names (including multi-character and punctuation-like symbols), where applying an operator to concrete arguments yields a structured, inspectable representation that encodes the operator identity and the argument values. The system must allow operators to be instantiated from a parameter module and then invoked in client modules with the same semantics. Requirements:
- Each binary operator, when applied to two concrete operands, must produce a deterministic tuple-structured result that includes a unique operator tag and the two operands in a fixed order.
- Each unary operator, when applied to one operand, must produce a deterministic tuple-structured result that includes a unique operator tag and the operand.
- Operator identity must be preserved under instantiation: an operator instantiated from the parameter module must produce the same tagged result as defined in the parameter.
- Distinct operator symbols must map to distinct tags so collisions cannot occur.
- The model must support a broad set of operator names (including punctuation and Unicode symbols) and demonstrate correctness by showing sample applications produce the expected tagged tuples.
- Include invariants asserting determinism, tag uniqueness, and instantiation fidelity; and a property that any application result is a tuple whose first element is the tag and remaining elements are the supplied arguments in order.
