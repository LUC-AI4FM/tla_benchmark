Specify a two-phase protocol for a single shared register updated by a producer and read by a consumer. The system has a producer that prepares and commits updates in two logical phases and a consumer that may read the register at any time. Model the register's initial value and the producer’s two-phase update behavior (prepare then commit) as abstract state transitions, without prescribing a particular coding structure. The protocol must ensure atomic visibility of committed updates: a consumer must never observe a partially prepared update. Allow the consumer to read concurrently with producer actions and permit the producer to retry or reprepare before committing. Capture nondeterministic scheduling and asynchronous steps of both parties.

Specify safety properties: (1) reads return either the initial value or some fully committed value produced by the producer; (2) the prepare phase must not make new values visible until a matching commit occurs; (3) once a value is committed it remains visible to subsequent reads unless overwritten by a later commit. Also specify liveness expectations: eventual progress of committed updates under fair scheduling (if the producer continuously attempts to commit, some commit should eventually occur), and absence of indefinite blocking of the consumer. Provide invariants and temporal properties that formalize these safety and liveness requirements.
