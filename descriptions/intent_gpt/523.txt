Specify a reliable alternating-bit style value-proposal protocol between a single proposer and a single acceptor connected by two FIFO channels with bounded capacity. The proposer repeatedly receives new proposed values from an external source and sends them, tagged with an alternating bit, to the acceptor. The acceptor acknowledges messages back with the bit it believes current. The protocol must tolerate message loss and reordering only to the extent that channels are FIFO and may drop messages; it must not assume shared memory or instantaneous delivery.

Model the system so that the proposer may buffer a small bounded sequence of incoming proposals and may retransmit the latest outstanding proposal until it receives an acknowledgment matching its current bit. The acceptor must deliver values to its application only when it has accepted a new proposal (i.e., when it observes a message with a bit different from the last accepted bit), and must ignore duplicates. Both forward and backward channels have a fixed maximum length; the environment may inject new proposals arbitrarily but limited by the buffer bound.

Specify correctness properties:
- Safety: the acceptor never delivers a value labeled with a bit unless that value was actually proposed, and it never delivers two different values for the same alternating bit; in other words, acceptance is consistent and non-corrupting.
- No spurious acceptance: if the acceptor’s last acknowledgment bit equals the proposer’s current bit, then the proposer's current value equals the acceptor’s last delivered value (preventing out-of-order acceptance when bits match).
- Liveness: if messages sent are eventually delivered (i.e., channels stop losing messages and are fair), then every proposed value is eventually either accepted or superseded by a later proposal that is accepted; furthermore, when the proposer stops issuing new proposals, its current proposal is eventually accepted by the acceptor and acknowledged.
Also state the system invariants to check: channel length bounds, type invariants for all state components, and that message sequences maintain a constrained “two-values” pattern when bounded buffering allows at most two distinct consecutively present messages per channel.
