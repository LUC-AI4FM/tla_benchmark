Model a simple discrete-state system with two integer state components and nondeterministic one-step transitions that may change one or both components. The system should start from an initial state where both components equal 1. Transitions must allow the first component to increase by one, and the second component may either remain unchanged or be set deterministically to 1 depending on the chosen transition. Transitions must permit branching so some choices make only the first component change while others also constrain the second component based on the new value of the first.

Specify the following correctness requirements to check properties about expressions that refer to next-state values:
- Safety: the second component must always be a valid integer and never take undefined or invalid values during any transition.
- Conditional consistency: whenever the first component’s new value equals 2 in a transition that updates the second component, the second component’s new value must be 1.
- No contradictory next-state constraints: the transition relation must not introduce impossible equalities (e.g., simultaneously requiring the first component’s new value to equal two different integers).
- Well-formedness of set- and function-valued expressions involving next-state values: membership, subset, domain, and functional updates that reference next-state values must behave consistently and not produce illogical results.
- Assertions embedded in guarded choices should be enforceable so that any branch violating an assertion is disallowed.

Also include liveness-oriented exploration (nontrivial reachable-state enumeration) so that the model checker can demonstrate there are at least two distinct reachable states. The specification should leave nondeterministic choice explicit so different transition branches can be explored.
