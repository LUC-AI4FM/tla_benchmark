Specify a formal model of an asynchronous point-to-point communication channel that carries discrete data items from a single sender to a single receiver. The channel must allow the sender to place one datum into the channel and the receiver to read and consume that datum later. The channel should maintain an internal state that records the value stored (which may be one of a fixed finite set of data items) and control flags enabling coordination: the sender must be able to indicate that new data is ready and the receiver must be able to acknowledge receipt. The model must permit concurrent interleavings where sender and receiver actions may occur in any order, including delays, and must not assume atomic simultaneous updates unless explicitly required by an action. Specify transitions for: writing a datum when the channel is empty or when overwriting is permitted only when the previous datum has been acknowledged; reading a datum only when data is ready; and acknowledging receipt. Define safety properties that forbid data loss (the receiver must never claim to have received a datum that was never written), data corruption (the value read must equal a value previously written), and race-condition violations (e.g., the sender must not overwrite unacknowledged data). Define liveness properties ensuring progress: if the sender repeatedly writes a datum, eventually the receiver will read and acknowledge it, and the channel does not remain permanently stuck in an intermediate state when both sides are enabled. Allow parameters for the finite set of data values and for initial ready/ack states so the model can be instantiated with concrete values for model checking.
