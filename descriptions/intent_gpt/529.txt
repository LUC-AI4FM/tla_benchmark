Specify a distributed protocol that builds and maintains a sequence of proposals with monotonically increasing proposal numbers and associated values, where multiple proposers may concurrently propose and multiple acceptors persist decisions. The system must support proposing values, collecting promises from a majority of acceptors, optionally learning previously accepted values, and then issuing accept requests that must be accepted by a majority to decide a value for a given proposal number. Ensure safety: no two different values can be decided for the same proposal slot, and once a value is decided it is immutable. Ensure liveness under weak assumptions: if a single proposer eventually continues alone and accepts messages are delivered reliably, it can complete a proposal and cause a decision. Model acceptors’ persistent state (highest promised proposal number and the last accepted proposal-number/value pair) and proposers’ temporary state used to gather responses and select values consistent with prior accepted requests. Allow for failures and message loss, but require majority-based quorums for progress. Specify invariants enforcing that acceptors never accept a proposal lower than their promised number, that accepted values carried forward determine the proposers’ chosen values when necessary, and that any decided value was accepted by a majority. Include safety proofs as properties to check.
