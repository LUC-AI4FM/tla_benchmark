Specify a formal model of a logical timestamp allocator used by a distributed system component that issues monotonically increasing timestamps from a bounded domain. The system receives requests for timestamps and must assign each request a timestamp that is strictly greater than any previously assigned timestamp, subject to an upper bound on the timestamp space. The model should allow two distinct constant label values representing available timestamp identifiers. The allocator must never issue a timestamp equal to or greater than a fixed numeric limit. Concurrent requests may be presented, and the model must capture interleavings and nondeterministic scheduling of request arrivals.

Model goals and required properties:
- Safety: Every assigned timestamp is unique for the lifetime of the modeled run and strictly increases with respect to the previously issued timestamp for that logical sequence of assignments.
- Bound enforcement: No issued timestamp may violate the numeric upper bound constraint.
- Liveness (weak): If requests continue to arrive and the bound has not been reached, the allocator should be able to issue further timestamps (i.e., the model should not deadlock while issuance is still possible).
- Fairness: The model should permit all requests to eventually be served under fair scheduling when the bound allows issuance.

Avoid prescribing an implementation strategy; instead describe the state elements (current highest timestamp, set of available labels) and interactions (request, assign) and the correctness properties above to be checked.
