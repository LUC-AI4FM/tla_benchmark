Specify a model of a live table copy procedure that concurrently copies rows from a source database to a target while the source continues to accept updates. The model should represent a single logical table indexed by integer primary keys, where rows may be present or absent. Model three concurrently running components plus a controller: (1) a data-copy worker that scans primary keys in ascending order and copies existing rows to the target, (2) a binlog applier that reads a sequenced log of committed updates from the source and applies those updates to the target in log order, and (3) the application workload that issues atomic updates, inserts, and deletes to the source and appends corresponding entries to the binlog. The controller must wait for the data-copy worker to finish, then quiesce the application (prevent further writes), record the binlog position to catch up to, and instruct the binlog applier to stop after reaching that position.

The specification must guarantee safety and liveness properties: after the controller completes and all components have terminated, every row present in the source must equal the corresponding row in the target (final source-target equality). The binlog applier must preserve the original ordering of updates and may only apply updates when the expected prior value matches the target (to avoid overwriting unseen concurrent changes). The data-copy worker must read consistent values from the source at the time of its read. The application must be able to extend the logical table length by inserting at increasing keys. To keep verification finite, allow a bounded binlog length and a finite set of possible record values, but require that the model still exhibits interleavings where copy, application update, and binlog apply can occur in all three meaningful orders for any given row: copy-before-update-before-binlog, update-before-copy-before-binlog, and update-before-binlog-before-copy.
