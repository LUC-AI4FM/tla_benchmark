Specify a formal model of a language feature tester that checks extraction and naming of nested subexpressions within complex expressions. The model should represent expressions built from standard constructs (constants, tuples, records, sets, functions, LET/IN, CHOOSE, quantifiers, CASE, conditional, function application, EXCEPT, and operator instantiation) and support referring to arbitrarily nested parts of those expressions by labeled subexpressions and by positional selectors. The system must allow defining reusable operators and higher-order operators that accept other operators as parameters, and it must permit selecting subexpressions from operator bodies and from values returned by operator applications. It must also model labeling inside LET and inside comprehension and demonstrate that labels uniquely identify the intended subexpression even when nested or shadowed.

Key correctness properties to guarantee:
- Every valid selector (label-based or positional) applied to a well-formed expression yields the same subexpression value as the corresponding direct structural traversal would.
- Labels are properly scoped: a label refers only to the subexpression in the syntactic scope where it appears, and label-based selectors cannot escape or ambiguously refer across unrelated scopes.
- Selection operations are total wherever syntactically valid and produce a well-defined error or undefined result when the selector is invalid (e.g., selecting a nonexistent field or applying a positional selector to a non-tuple).
- Higher-order operator instantiation and operator-parameter selections preserve semantics: selecting inside an instantiated operator body corresponds to selecting inside the original operator definition with appropriate parameter substitution.

Model should allow asserting and checking example scenarios that exercise nested labels, LET-bound local operators, comprehensions with labeled internal expressions, and combinations of !, @, positional, and label selectors to validate these properties.
