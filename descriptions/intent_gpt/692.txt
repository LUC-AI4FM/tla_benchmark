Specify a model of a labeled directed graph construction service that produces DOT-format representations for visualization. The model should treat an abstract set of nodes and a multiset of directed edges; nodes and edges carry arbitrary labels (strings or symbols). The service accepts dynamic requests to add or remove nodes and to add or remove directed edges between existing nodes. It must reject operations that would create edges referencing non‑existent nodes. For any valid current graph, the service must produce a DOT description that faithfully lists all nodes with their labels and all directed edges with their labels and arrow directions, suitable for consumption by graphviz. The DOT output must be stable: repeated requests with no intervening modifications yield the same DOT text. The model must guarantee that concurrent and interleaved add/remove operations result in a consistent graph state with no lost updates or dangling edges, and that all accepted operations are eventually reflected in the DOT output (liveness). Specify invariants ensuring node uniqueness, edge endpoints refer only to present nodes, label preservation, and that DOT output contains exactly the current nodes and edges. Also specify progress properties indicating that submitted modifications are eventually applied and reflected in output.
