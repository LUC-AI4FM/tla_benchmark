Model a non-blocking atomic commitment protocol for N distributed processes that may fail by crashing and that use unreliable failure detectors. The model should capture the voting phase (each process initially votes YES or NO), the message-sending phase where processes send their votes to others, crash events, and asynchronous message reception. The failure detector yields per-process suspicions (alive or suspected crashed) and may change nondeterministically; it is not assumed to be perfect. The protocol must ensure the usual atomic commitment guarantees:
- Agreement: No two non-crashed processes decide differently (commit vs abort).
- Validity: If all processes vote YES and no new crash suspicions prevent progress, then the system may decide commit; if any process votes NO then no correct process may decide commit.
- Termination (non-blocking progress): If a sufficiently strong eventual accuracy condition holds for the failure detector (weak fairness or eventual suspicion stabilization), then every non-crashed process must eventually decide (commit or abort).

The specification should abstract away implementation details: model message send and receive as sets of delivered messages, model crashes as irreversible local faults, and model the failure detector as a per-process Boolean oracle. Specify safety properties (agreement and validity) as invariants and liveness properties (every live process eventually decides under the stated detector assumptions) using temporal formulas. Allow initial scenarios where some or all processes vote YES.
