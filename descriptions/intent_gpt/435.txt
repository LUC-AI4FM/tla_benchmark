Specify a small formal model of an abstract algebraic expression language that supports binary operators with alternative symbolic names (aliases) but treats them as simple unordered pairing constructors. The model should describe expressions built from atomic identifiers and a set of binary operator tokens; different token symbols may be declared as aliases of the same underlying binary constructor so that using any alias yields the same constructed value. Define the allowed syntactic forms, how operator aliases map to the same semantic constructor, and how equality and membership of constructed expressions are determined when aliases are present. The system must permit construction of pairs from two subexpressions and must guarantee that any two expressions constructed with the same operands but with different alias symbols are semantically equal and interchangeable in contexts such as set membership and comparison. Specify invariants that ensure no alias introduces additional structure (for instance ordering or multiplicity) and that aliasing is reflexive and symmetric. Include properties to check that alias declarations do not conflict and that the language semantics remains deterministic and consistent under substitution of aliases.
