Specify a concurrent system of a fixed collection of processes that cooperatively increment a shared counter by invoking a non-parameterized procedure. The system has one distinguished process and several identical worker processes. Each process repeatedly calls the same procedure that atomically increments the global counter by one and then returns. After a process returns from the procedure it proceeds to a local checkpoint where it waits until the counter reaches a specific target value (four). When the counter reaches that target, each waiting process completes and stops executing. The model should allow interleaving of calls and returns: multiple processes may call the procedure at arbitrary times, the procedure executes atomically (increments the shared counter exactly once per call), and processes can be preempted between actions.

Model goals and correctness properties:
- Safety: The counter is always a natural number and only increases by one on each completed procedure invocation; no other transitions modify the counter.
- Liveness: If processes repeatedly take enabled actions, every process eventually reaches its waiting checkpoint and, once the global counter attains the target, every process eventually terminates (no livelock prevents termination).
- Termination: From the initial state, the system can reach a state in which all processes have completed (terminated) and thereafter only stuttering steps occur.
- Fairness: Specify fairness constraints so that enabled calls and returns are not indefinitely postponed, ensuring the above liveness and termination properties.

Do not commit to a particular implementation structure (call stack encoding, program counters, or label names); instead describe the abstract operations (call, atomic increment, return, wait-for-target, terminate) and their enabled/atomic relationships.
