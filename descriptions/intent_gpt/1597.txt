Specify a parameterized mutual‑exclusion algorithm for N concurrent processes that implements a fast path with a backup waiting protocol. The model should treat processes symmetric except that one may be distinguished only for description; do not assume any specific implementation details. Each process repeatedly tries to enter a critical section, using only a small set of shared variables and per‑process local flags to coordinate. The protocol must allow a process to take a fast entry when no competitor is active, but when contention is detected it must withdraw to a backup protocol that waits for others’ indicators and then safely enter the critical section if permitted.

Model requirements:
- Processes repeatedly attempt, possibly concurrently, to enter and exit the critical section forever.
- Shared state includes a global indicator that some process is in the fast doorway and an array of per‑process flags that mark intent; processes may set and clear their flags and read the global indicator.
- The backup waiting protocol must allow a contending process to wait until all earlier‑indexed or currently flagged processes have cleared their flags (or equivalent condition) before proceeding.
- If a process detects that it lost the fast race, it must eventually either reattempt from start or succeed via the backup protocol.

Correctness properties to guarantee:
- Safety (mutual exclusion): at most one process is in the critical section at any time.
- Progress/liveness: eventually some process enters the critical section (weak fairness for each process’s actions or a liveness condition that ensures the system is not permanently stuck).
- No deadlock: the protocol should not allow all processes to be permanently blocked outside the critical section.

Parameterize by N (number of processes) and state the assumptions on atomicity: individual reads/writes of shared variables are atomic; process steps are atomic.
