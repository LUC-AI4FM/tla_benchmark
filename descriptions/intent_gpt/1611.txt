Specify a formal model of the mergesort algorithm that sorts an array of integers. The model should treat the array as an arbitrary fixed-length sequence of integer-valued elements (length parameterized) and should capture the algorithm’s divide-and-conquer behavior: repeatedly split subarrays into halves, recursively sort each half, and then merge the sorted halves into a single sorted subarray. The model must allow any valid initial contents for the array, and must permit in-place updates only through well-specified read/write operations on array indices.

Require the model to guarantee two key correctness properties:
- Safety (sortedness): Once the algorithm terminates, the array is nondecreasing: for every pair of indices i < j, array[i] ≤ array[j].
- Preservation (permutation): The multiset of elements in the final array equals the multiset of elements in the initial array (no elements are lost, duplicated, or invented).

Also require liveness: the model should show termination of the algorithm for every valid finite input array (i.e., the algorithm eventually reaches a terminal state indicating completion).

Do not prescribe internal control-flow encoding; instead describe the algorithm abstractly (recursive calls, local temporary storage used for merging) so multiple concrete implementations (in-place, auxiliary-array, iterative stack-based) can be represented. Include a means to reason about and assert the correctness of the merging step (that it produces a sorted concatenation of two sorted subarrays while preserving their combined multiset).
