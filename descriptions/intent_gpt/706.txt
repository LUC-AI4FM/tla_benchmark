Specify a system that runs a suite of command-line integration tests for a Unix-like environment and reasons about their outcomes. The model should represent a test harness that can invoke external programs, supply input and arguments, capture standard output and exit status, and validate observed results against expected values. It must allow tests that depend on common Unix utilities (shell interpreter, file utilities, stream tools) and on Unix path conventions, including relative and absolute paths, executable lookup, and redirection semantics.

The model must permit composing tests into sets that may share setup and teardown steps (creating temporary files, directories, and symbolic links) and must ensure isolation between tests so side effects do not leak. It must express nondeterminism in process scheduling and I/O timing, and model failures such as missing executables, permission errors, and unexpected exit codes.

Key correctness properties: (1) Deterministic test verdicts—each test set must either pass or fail based on specified assertions about program output and status, regardless of interleavings; (2) Isolation—invariants ensure no persistent state remains after teardown; (3) Coverage—every declared test must be executed; (4) Error detection—any deviation from expected output, exit code, or filesystem state must lead to a test failure. Include liveness guarantees that test execution eventually terminates or reports a timeout.
