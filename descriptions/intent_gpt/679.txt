Specify a model of a small CSV file I/O service and its expected behavior for use by a verifier. The model should treat files as abstract sequences of text rows and provide operations for writing formatted values, appending records with optional header handling, reading files into sequences of records given column names, and querying the number of rows in a file. The service must ensure that formatted writes append a single row produced by applying a format template to a sequence of values. Appending a record must optionally emit a header row containing the record field names the first time data is written to an empty file, and always append a data row containing the record's field values in a stable, well-defined order. Reading must take an ordered sequence of column names and return a sequence of records (map from column name to string value) corresponding one-to-one to file rows; when a header row exists it should not be treated as data unless the caller requests raw rows. The row-count query must reflect the current number of rows, return zero for non-existent or empty files, and update correctly after writes/appends. Specify invariants: writes and appends are atomic with respect to the abstract file state, no partial rows may ever appear, and concurrent sequences of operations must produce results consistent with some serial order (linearizability). Also specify error behavior for malformed input (mismatched template placeholders, wrong number of columns) as nondeterministic failures that leave files unchanged.
