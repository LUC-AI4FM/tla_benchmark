Model a Software-Defined Perimeter (SDP) access-control system that mediates client access to a protected server using single-packet authorization (SPA) on a control plane and dynamic ACL configuration on a data plane. The model should include clients that request access, an SDP controller that authenticates SPA messages and programs the network firewall, a firewall that enforces ACLs on TCP connection attempts, an attacker that can sniff and replay or spoof SPA messages and can initiate TCP probes, and the protected server that accepts TCP connections only when permitted by the firewall.

Specify the allowed behaviors and interactions without prescribing implementation details: SPA messages must carry authenticated, integrity-protected, replay-resistant bindings between a particular client’s access intent and the TCP 4‑tuple for the target service; the controller must validate SPA messages, detect and log replay/spoof attempts, and install ephemeral ACL rules to allow the corresponding TCP handshake when authorization succeeds; the firewall must only forward TCP packets that match installed ACL rules otherwise drop and log them. The attacker may observe SPA and/or TCP traffic, craft forged SPA messages, or reuse captured data to attempt unauthorized access. Requirements and correctness properties: legitimate clients who send fresh, valid SPA messages and then complete the TCP handshake are eventually able to establish connections; no attacker without possession of the client key may cause the firewall to accept a TCP connection to the protected server (safety); replayed or out‑of‑sync SPA messages must not enable unauthorized data access; if the controller installs an ACL for a given SPA, it must be tied to the authenticated 4‑tuple and be short‑lived (no permanent exposure). Also state liveness goals: the controller and firewall together must permit a legitimate handshake within bounded steps after a valid SPA is received.
