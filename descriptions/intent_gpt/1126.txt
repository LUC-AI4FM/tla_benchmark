Specify a formal model of a two-phase commit protocol for a distributed transaction coordinator and a fixed set of resource managers. The model should describe the allowed states of each participant, the coordinator’s decisions, and the two high-level actions: asking resource managers to prepare and then deciding to commit or abort. It must capture the safety-critical invariants that every state transition must preserve: (1) each resource manager’s state is always one of a small, well-defined set of protocol states (type safety); (2) no two resource managers can end up in conflicting terminal outcomes (for example, one committed while another aborted) — i.e., the protocol must maintain global consistency of final decisions; and (3) decisions to commit may occur only when all resource managers have signaled preparedness to commit, while aborts may be taken when any resource manager refuses to prepare. The model should allow for stuttering steps and for actions that leave the global state unchanged. The specification must express an initial condition and a next-state relation such that starting from the initial state, every reachable state satisfies the type-safety and global-consistency invariants at all times (safety property). Do not commit to any particular implementation mechanism (for example, avoid encoding a specific program loop or per-participant code); instead describe the abstract protocol behavior and the invariants to be proved over its state-transition relation.
