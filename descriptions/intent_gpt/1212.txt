Specify a formal model of a proof-checking environment for a temporal logic that distinguishes temporal and non‑temporal reasoning contexts. The model should represent proofs, assumptions, theorem declarations, and module instantiation/signature matching, but not their concrete implementation; instead, describe what the system must permit and forbid.

Requirements:
- The system must classify formulas as temporal (contain next, always, until, etc.) or state (non‑temporal) formulas, and enforce context rules: non‑temporal proof steps, goals, and theorems must not contain temporal formulas; temporal proof steps may contain temporal formulas.
- When introducing assumptions or ASSUME/PROVE blocks for proving a non‑temporal goal, the system must prevent instantiating declared constant parameters with temporal formulas.
- Module instantiation must check that parameters declared as constants are only instantiated with allowed (non‑temporal) expressions when used in non‑temporal contexts; signal an error otherwise.
- Proof rules such as CASE, HAVE, WITNESS, BY, and QED must be validated w.r.t. temporal/non‑temporal context: e.g., CASE branches proving a non‑temporal conclusion may not use a temporal intermediary; WITNESS must produce a state value when the goal is a state existential.
- The model should capture error conditions (rejections) for each rule violation and accept valid proofs. Specify key correctness properties: soundness of context classification (no accepted proof contradicts temporal/non‑temporal constraints) and completeness of error detection (all illegal temporal occurrences in non‑temporal contexts are rejected).
