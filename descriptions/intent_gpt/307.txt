Specify a formal TLA+ model of the classic binary-search algorithm that takes a sorted array of integers and a search key and returns either an index of a matching element or a negative value encoding the insertion point. The model should treat inputs and arithmetic as machine-width integers (with a given bit width), so addition, subtraction, and mid-point computation may wrap according to the chosen integer width. Model the algorithm at the level of observable state: the current inclusive low/high bounds of the search interval, whether the algorithm has terminated, the returned value, and a step counter; do not prescribe a particular code-level translation.

The specification must require:
- The input sequence is sorted in nondecreasing order (or explicitly allow unspecified behavior if not sorted).
- Indexing conventions (array indices vs. returned indices) are clearly accounted for so results map correctly to array positions.
- All array accesses are within bounds for every transition.

Correctness properties to guarantee:
- Safety: When the algorithm reports termination, if the input is sorted then the reported value is correct: if the key exists, the return is a nonnegative index pointing to a matching element; if the key does not exist, the return is negative and encodes an insertion point consistent with the usual binary-search contract.
- Progress/termination: The search interval strictly shrinks on nonterminating steps (or the step counter eventually forces termination), ensuring termination under bounded-width arithmetic assumptions.
- Robustness under wraparound: Midpoint computation and bound updates respect machine-width semantics, and the model forbids array accesses that could result from overflow.

Include invariants that relate low/high to array length and to the semantics of the returned value, and state explicitly any assumptions about index numbering and integer ranges.
