Specify a synchronous termination-detection protocol for a distributed computation running on a fixed set of processes connected by reliable point-to-point channels. The model should describe process-local states and a global notion of whether a process is "terminated" (it has no internal work and has sent no outstanding messages) and a global flag indicating whether termination has been detected. The system must allow processes to perform local actions that send and receive messages, locally become terminated, and perform a dedicated detection action that can set the global detection flag when the system is in a safe termination state.

Requirements:
- Initially no process is terminated and the termination-detected flag is false.
- Processes may asynchronously send and receive messages; message channels have reliable FIFO delivery semantics (or equivalent reliable delivery) and messages in transit prevent global termination.
- A process may change its local status to terminated only when it has no pending local work and has no outstanding outgoing messages.
- Termination detection must be enabled precisely when every process is terminated and no messages are in transit.
- Once termination is detected, the detection flag becomes true and remains true forever (safety).
- If the system reaches a state where all processes are terminated and no messages are in transit, then under weak fairness for the detection action the detection flag will eventually be set (liveness).
- Type and invariant constraints should ensure well-formed process states and channel contents.

State the safety properties (type correctness, detection correctness, monotonicity of the detected flag) and the fairness/liveness property that detection eventually occurs when the system is quiescent.
