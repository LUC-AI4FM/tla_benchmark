Specify a concurrent key-value store with atomic per-key transactions and multiple clients. The model should capture a finite set of keys and a fixed set of clients; each client repeatedly issues transactional updates that target a designated primary key but may read and write other keys. Transactions must commit or abort; committed transactions atomically apply their writes to the store, while aborted transactions leave the store unchanged. The system must allow concurrent transactions from different clients and must model possible interleavings, conflicts, and non-deterministic scheduling.

Require the specification to guarantee serializability: every concurrent execution must be equivalent to some serial order of committed transactions. Ensure atomicity: partial effects of transactions are never visible. Ensure isolation in the presence of concurrent operations, and durability: once a transaction commits, its effects persist in the global state. Model correctness properties including safety (serializability, atomicity, isolation) and liveness under weak fairness assumptions: if a client continually attempts a transaction and there is no permanent conflict, it eventually commits.

Include the ability to express and check properties about which client holds which primary key, and support verifying the above properties under all interleavings for the given finite sets of keys and clients.
