Specify a model of a replicated user account state manager that accepts concurrent requests from a fixed set of clients and applies a finite set of operations to each user’s account state. The system manages an atomic per-user state (for example: NEW, ACTIVE, SUSPENDED, CLOSED) and supports client-initiated transitions and queries. Model the set of users as a given finite universe and model client actions that propose valid state transitions and read current state. The model should permit concurrent proposals, possible message delays, and nondeterministic scheduling, while ensuring deterministic effect of each applied operation.

Require the specification to guarantee safety properties: every applied transition must be allowed by a user-state transition relation (no invalid jumps), and no two conflicting transitions may be applied simultaneously to the same user (atomicity per user). Guarantee invariants: every user’s state is always one of the defined finite states; once a user reaches CLOSED it is terminal (no further transitions). Also require liveness: if a client repeatedly proposes a valid transition for a user and the system continues to make progress, eventually one of those proposals will be applied (weak fairness). Finally, specify an abstract fairness model for scheduling client requests and a means to detect invariant violations for model checking.
