Specify a formal model of a simple typed-constant environment and the operations that inspect and use those constants. The system should represent a fixed collection of named constants, each of which has an associated static type annotation drawn from a small type language (including at least integer, sequences of integers, and finite sets of records with integer fields). The model should allow reading a constant and querying its declared type, and it should allow an evaluator that checks at runtime whether a given value conforms to the declared type of a named constant.

The specification must state the intended typing rules of the type language and what it means for a value to conform to a type (e.g., sequence elements have the required element type; records have exactly the required fields with the required types; sets contain only elements of the specified record type). It must require that every named constant present in the environment has a well-formed type annotation from this type language.

Correctness properties to guarantee:
- Type Preservation of Lookup: reading a constant returns a value that the type-checker accepts as conforming to its declared type.
- Type Soundness of Conformance Check: the conformance predicate is precise — it accepts exactly those values that satisfy the declared type rules.
- Environment Invariance: the set of constants and their declared types are immutable; operations do not alter the environment.
- Exhaustiveness: queries for a constant that is declared must succeed; queries for undeclared names are rejected.

Do not model any particular implementation syntax for annotations or comments; focus on the abstract notion of constants with types and a conformance relation.
