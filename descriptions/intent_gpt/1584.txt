Specify a concurrent nondeterministic initialization-and-update protocol for three integer-valued components so that a formal model can be written and checked.

The system starts with three counters all zero. In the first phase exactly one of three mutually exclusive choices is taken: set the first counter to 1 and proceed to the next phase; or set the second counter to 1 and proceed; or set the third counter to 100 and proceed. After that, the system executes a second phase that updates only the third counter, with the update chosen from two guarded alternatives: if the first counter is currently zero, increment the third counter by 1; if the first counter is currently equal to 2, increment the third counter by 3. The second phase then terminates the run.

Require that every legal execution respects two safety properties at the moment the second-phase update occurs: (1) either the sum of the first two counters equals 2, or else the third counter becomes exactly 101 and the sum of the first two counters is 0; (2) if the new value of the third counter is less than 100 then it must equal the first counter plus one.

Also require liveness that the system always eventually reaches termination (the run ends after the second-phase update), and that the model allows the nondeterministic selection of any of the permitted first-phase and second-phase choices when their guards hold. The model should state initial conditions, transitions, invariants to check, and a termination property; do not prescribe an implementation strategy.
