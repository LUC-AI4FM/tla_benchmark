Specify a model of a set of independent chains, each of which manages a bounded collection of clients and assigns each client an integer "height" that can evolve over time. The model should support a fixed finite set of chain identifiers, a constant upper bound on the number of clients per chain, and a constant maximum allowed height for any client. Each chain must maintain a counter used to allocate client slots (or client identifiers) up to the configured maximum, and an indexed collection mapping each client slot to its current height. Client heights are nonnegative integers with a distinguished zero value representing an unused or null slot; active heights lie in the range 1..MaxClientHeight.

Model the allowable state space (initial states and state transitions) so that:
- All chains start with every client slot unused (height = 0) and each chain’s allocation counter initialized to 0.
- Every state preserves the invariant that per-chain allocation counters and client heights remain within their prescribed finite ranges.
- Transitions may create, activate, update, or leave client slots unchanged subject to the bounds: new assignments must not exceed the maximum number of clients per chain, and any assigned height must be between 1 and the maximum allowed height; unused slots must remain representable by the null height 0.
- The model should permit independent operation of chains (no global interdependence required).

State the key correctness properties to be checked:
- Type-safety: all variables always inhabit their declared finite domains.
- Allocation safety: no chain ever allocates more than the allowed number of client slots.
- Height bounds: no client’s height ever falls outside 0..MaxClientHeight.
- Persistence of null representation: the null height consistently represents unused slots and is never confused with a valid active height.

Provide these requirements as a formal specification target (initial conditions, allowed transitions, and invariants) suitable for mechanized verification.
