Specify a formal model of a module-import and visibility mechanism for a specification language. The model should describe a collection of named modules that may export constants, operators, and theorems, and a mechanism by which a module can import selected items from another module either by bringing them into scope (use) or by suppressing their visibility (hide). The model must enforce the rule that only module names and specific named definitions or structured selection expressions are permitted in import and hide clauses; arbitrary expressions, facts, or theorems must not be usable as arguments to these visibility directives. The model should also capture scoping rules that determine which identifiers become available after an import, how qualified names and selective import lists behave, and how hiding interacts with later references and name resolution. Key correctness properties: 1) syntactic restrictions — any import or hide clause that attempts to reference non-module identifiers, expressions, or proof-level constructs is rejected; 2) preservation — import and hide operations do not change the semantics of the target module except for name visibility; 3) determinacy — name resolution yields a unique binding when imports, hides, and local definitions interact; and 4) soundness — references that are accepted by the visibility rules refer to actual existing exported definitions or operators in the referenced module. Include invariants asserting that illegal import/hide forms are not admitted and that resolved names correspond to declared exports.
