Model a buffered random-access file abstraction that provides the same externally visible behavior as an unbuffered random-access file but uses an in-memory fixed-size buffer to coalesce reads and writes. The model should capture a single-threaded client interacting with a file via the operations: seek (move file cursor), read (advance cursor and return bytes), write (store bytes at cursor and advance), setLength (resize file), and flush (write any modified buffer contents back to disk). The buffered implementation must maintain an in-memory buffer window that maps to a contiguous region of file offsets; reads and writes within that window operate on the buffer without immediate disk I/O, writes mark the buffer dirty, and flush synchronously updates the underlying disk contents for the buffered region. Seeks that move the cursor outside the current window must (if necessary) ensure dirty buffer contents are flushed before reading a new window from disk. setLength must correctly truncate or extend the logical file and adjust the cursor and buffer relevance accordingly. The specification should treat undefined bytes introduced by extending the file as arbitrary symbols.

Correctness properties to guarantee:
- Internal invariants: the buffer always reflects a contiguous slice of logical file contents, the cursor lies within the buffer window when required, and a dirty flag correctly indicates when buffered contents diverge from disk.
- Behavioral refinement: all executions of the buffered implementation must refine the behavior of a canonical unbuffered random-access file (same observed reads, writes, cursor positions, and file contents).
- Operation-level refinement: each buffered operation (seek, read, write, setLength, flush) must individually behave as its unbuffered counterpart with respect to the abstract file interface.
- Liveness prerequisites for restoring buffer invariants: whenever the invariant that the cursor lies in the buffer window must be re-established, it must be possible to restore it by flushing (if dirty) followed by loading the appropriate window.

Do not commit to internal variable names or a particular encoding; specify the abstract goals and properties above so they can be formalized and model-checked.
