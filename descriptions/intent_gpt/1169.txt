Specify a formal model of a cluster worker/agent and its interaction with a central dispatcher that manages containerized tasks. The model should describe how each worker maintains a connectivity status (connected/disconnected) to the dispatcher and how the dispatcher and worker jointly advance tasks through a fixed lifecycle of states (e.g., assigned → accepted → preparing → ready → starting → running → complete/failed/shutdown/orphaned/remove). The system must allow the dispatcher to observe worker connectivity changes, assign tasks to workers, and update task desired states (including shutdown and removal). The worker must be able to progress tasks toward their desired states when connected, reject assigned or in-progress tasks prior to entering running, report container exits (mapping exit outcomes to final states and treating forced shutdown specially), and shut down any tasks that are no longer included in an assignment after reconnection. The model must also capture long-term disconnect behavior that causes the dispatcher to mark tasks orphaned, and a worker reconnecting to receive fresh assignment sets. Specify safety properties: tasks must never move to states beyond their declared desired state, ownership semantics must ensure only the responsible worker can perform certain transitions, and orphaning should be the only case where the worker might not have advanced a task past assignment. Specify liveness guarantees: when a worker is connected and progress is possible, progress actions eventually occur; worker connectivity changes (down/up) should be possible; and container exits and rejects should eventually be processed. Include requirements to count or record notable events for external observation.
