Specify a formal TLA+ model of a concurrent mutual-exclusion algorithm for N identical processes using ticket numbers (a bakery-style algorithm). The model should abstract processes as indexed threads that repeatedly alternate between noncritical work, entry protocol to acquire a ticket, a critical section, and an exit protocol to release the ticket. Capture asynchronous interleaving and allow arbitrary scheduling, but assume reliable local operations (no crashes).

The system must ensure the following functional behavior:
- Every process can eventually attempt to enter the critical section by executing the entry protocol, obtain a ticket, and progress to the critical section unless permanently disabled by the scheduler.
- Tickets are allocated so that each contender gets a numeric ticket greater than or equal to others’ tickets observed at allocation time; ties are broken deterministically to yield a strict global order.

Key correctness properties to guarantee:
- Mutual exclusion: at most one process is in the critical section at any time.
- Deadlock-freedom (progress): if some process tries to enter the critical section, some process will eventually enter the critical section (no system-wide lockout).
- Bounded waiting (fairness): any process that begins the entry protocol will enter the critical section within a bounded number of other processes’ entries (no starvation).

Also specify initial states, the domains of process-local data (flags, numeric tickets, local program counters), and a safety invariant showing that the ticket ordering enforces the selection order. State liveness properties using temporal formulas and parameterize the model by N.
