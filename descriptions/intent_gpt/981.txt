Specify a model of a two-party alternation protocol in which a Producer and a Consumer take turns performing actions, with the Producer always going first. The system should include a shared state component representing some payload or data value that both parties may read and update when they act. The protocol must enforce that at any given time exactly one party is enabled to perform its action: when the parties are synchronized in phase, the Producer is enabled; after the Producer acts, the Consumer becomes enabled; after the Consumer acts, the Producer becomes enabled again, and so on, alternating indefinitely.

Model the initial condition, the allowed actions of each party on the shared payload (abstracting the payload update as a parameterized relation), and the handshaking control that ensures strict alternation. The model should allow the payload update relation to be any relation satisfying an initialization predicate and per-step transition relation so proofs about control flow do not depend on a concrete payload implementation.

State the safety properties: the control variables always remain within the two permitted phases, and the alternation invariant that exactly one of the two actions is enabled at each step and the roles alternate after each action. Also specify a refinement property: show that the two-party handshaking system implements an abstract alternating-binary-state specification by mapping the concrete control state to a single abstract bit that toggles on every action. Include liveness goals that the system can always make progress (no deadlock) assuming the payload relation allows the corresponding party to perform its update.
