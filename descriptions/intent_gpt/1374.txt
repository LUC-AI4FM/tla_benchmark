Specify a formal model of a simple system that combines an independent local component and an instantiated external module, ensuring their names and constants do not interfere. Model two components: a primary component that maintains a single state variable initialized to a particular string and never changes, and a secondary, separately defined component that is instantiated with its own constant and state value. The system must allow the primary component to reference the instantiated component's exported values and to assert properties about them, while preserving that bindings supplied at instantiation override any external defaults without affecting the primary component's own state. The model must capture initial conditions for both components, the fact that the primary component’s variable is invariant, and the instantiated component’s specification (as an imported module) must be treated as an independent specification that can be checked as a safety property of the combined system. Specify assertions that the system prints or records the primary component’s local value, the instantiated component’s value, and the constants visible in each component, showing they can differ. Key correctness properties: (1) the primary component’s state variable remains constant (invariance), (2) the instantiated component’s specification holds within the combined system, and (3) there is no name or constant collision — each component observes its own bindings as supplied at instantiation.
