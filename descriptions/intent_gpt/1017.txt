Specify a formal model of a coordinated voucher transfer protocol in which a central coordinator orchestrates a two‑phase commit that moves a set of vouchers from a group of source holders to a group of destination holders. The model should represent independent holders that can independently decide to prepare for the transfer or to abort, and a coordinator that collects "prepared" acknowledgements from both all source and all destination holders before deciding to commit (transfer) or to abort. The model must allow the coordinator to: record received preparations, broadcast a commit decision when all required preparations have been received, and broadcast an abort decision (which may occur spontaneously). Holders must be able to react to coordinator broadcasts: upon receiving a commit they must transition to a state representing successful transfer (sources relinquish, destinations obtain), and upon receiving an abort they must transition to an aborted state. The specification should ensure type correctness for all state components and messages, and must guarantee safety properties: no source can end in a transferred state while any destination ends in an aborted state, and conversely no source can end aborted while any destination ends holding the transferred voucher. Also require that the protocol implements the externally specified voucher life‑cycle—that is, every allowed execution of the coordinated transfer must satisfy the abstract life‑cycle specification’s observable behaviors. Do not prescribe implementation details of message buffering or internal steps beyond these behavioral requirements.
