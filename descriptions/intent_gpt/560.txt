Specify a formal model of a replicated commit protocol that uses independent instances of Paxos to agree, for each resource manager, whether that resource manager’s action is "prepared" or "aborted", and then combines those instance results into a global commit/abort decision. The model should describe the possible asynchronous messages between leaders and acceptors, the independent progression of each Paxos instance, and the ways resource managers can locally prepare or decide to abort. It must allow multiple potential leaders and unreliable communication (messages may be delayed but not duplicated beyond being recorded once). Do not model leader election; instead allow any process that believes it is leader to initiate ballots and to propose values when it has sufficient responses.

The specification must ensure safety properties only: (1) For each resource manager instance, Paxos must never choose two different values; (2) A global Commit may be announced only if every resource manager instance has chosen "prepared"; (3) A global Abort may be announced only if at least one instance has chosen "aborted"; and (4) once a resource manager is marked committed it cannot later be aborted, and vice versa. Model actions for acceptors that respond to phase‑1 and phase‑2 messages in accordance with Paxos safety (tracking promised ballots and accepted values). Represent messages as sent events that persist in a global history set used to enable later actions. Do not prescribe implementation details such as exact variables or procedural steps; state only the roles, allowed events, and invariants the protocol must maintain.
