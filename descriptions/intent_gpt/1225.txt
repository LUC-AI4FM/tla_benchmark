Specify a concurrent request-issuing system where a fixed set of processors may create memory access requests (reads or writes) and append them into per-processor per-processor queues. The model should represent each request as a tuple containing a target address and a value (and whether it is a read or write) and should represent an ordering relation that records a partial order among individual requests.

Requirements:
- Processors may nondeterministically issue requests to registers, causing a new request record to be appended to that processor’s queue.
- The ordering relation must be monotonic: it can only grow as new requests are issued (no deletions), and must always be a strict partial order (irreflexive and transitive).
- Within each processor, requests must be ordered by their issuance sequence: if a processor issues request A before request B, then A must be ordered before B.
- The model must enforce a constraint bounding queue lengths (e.g., each per-processor queue has length less than a given limit).
- Types must be respected: queues contain only valid request records; the ordering relation relates only existing request identifiers.

Correctness properties to specify and check:
- Invariant: the ordering relation remains a strict partial order and contains all per-processor program-order pairs.
- Invariant: queue length bounds are never violated.
- Safety: no request identifier is related to itself.
- Monotonicity: once an ordering pair holds it persists in all future states.

Do not include implementation details such as concrete variable names or step-by-step procedural code; describe only the abstract state (per-processor queues and a partial order over requests), the permitted state transitions (issuance of requests that append to queues and extend the order), and the invariants above.
