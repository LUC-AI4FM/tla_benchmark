Model the single-decree Paxos consensus protocol for a fixed set of acceptors and ballots, described as an asynchronous message-passing system. The model should treat proposers (ballots) as logical initiators and acceptors as independent processes that respond to received messages. Specify the following behavior and requirements without prescribing implementation details:

- The system must permit proposers to start a ballot by broadcasting a prepare (phase‑1a) request with a ballot number. Acceptors may respond with promise (phase‑1b) messages that record the highest ballot they have promised not to accept lower ballots for and include any prior accepted vote information (ballot and value) if one exists.
- A proposer may issue an accept (phase‑2a) request for a specific value at a ballot only when it has gathered promises from some quorum and can determine the value is safe (i.e., if any acceptor in the quorum previously voted, the proposer must choose the value of the highest such prior vote; otherwise it may pick any value).
- Upon receiving an accept request for ballot b, an acceptor must accept and record the value if it has not promised a higher ballot, and must then send an accepted (phase‑2b) message.

Specify message types, ballot and value domains, and quorums abstractly. Define safety properties: at most one value may ever be chosen (consensus safety), and any two acceptances for the same ballot agree on the same value. Define liveness obligations in abstract terms (e.g., under eventual reliable delivery and a stable proposer with a sufficiently high ballot, progress to choose a value is guaranteed). Also specify an invariant encoding that promises and recorded accepted votes are consistent with messages sent, so that the safety properties are inductively maintained.
