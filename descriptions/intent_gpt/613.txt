Specify a model of a round-based Byzantine fault-tolerant consensus protocol in which a fixed set of processes repeatedly run synchronous voting rounds to agree on a single value. The model should represent processes that may be correct or faulty, a sequence of logical rounds, and three phases per round (propose, prevote, precommit). In each round a designated proposer may broadcast a proposal; processes may prevote and then precommit depending on what they have received and on their local locked or valid state. Processes can lock on values and carry forward locks and valid-value hints between rounds. Faulty processes may behave arbitrarily (including equivocation or sending conflicting messages), but the number of faults is bounded. The system must tolerate up to T Byzantine faults and guarantee the following safety and liveness properties:

- Safety: No two correct processes decide different values; once a correct process decides a value, no other correct process can later decide a different value.
- Agreement on finality: If a correct process decides a value, that value remains decided and is the only value that can be decided in any later or concurrent rounds by correct processes.
- Validity: Only values from a specified set of valid values may be decided.
- Progress under partial synchrony: If proposers keep proposing and message delivery eventually stabilizes (no further partitions and correct proposers continue), some correct process eventually decides (i.e., termination under eventual synchrony).

Also require explicit modeling of message sets for each phase and round, per-process local state for locks and valid hints, and the quorum rules used to move from prevote to precommit and to decision (e.g., thresholds for "two‑thirds" or configurable quorums). Allow configuration of number of processes, fault threshold, set of valid/invalid values, and maximum rounds for model checking.
