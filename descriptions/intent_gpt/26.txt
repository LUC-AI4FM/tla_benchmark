Specify a distributed two-phase commit protocol for a set of independent resource managers (participants) that coordinate to make a unanimous decision to commit a distributed transaction or to abort it. Model only the abstract states each participant may be in and the legitimate transitions between those states; do not prescribe messaging patterns or implementation details.

Requirements:
- Each participant starts in an initial active state indicating it has not yet prepared.
- A participant may move to a prepared state to indicate it is ready to commit.
- At appropriate times a participant must be able to decide to commit or to abort. A commit decision must occur only when every participant has indicated preparedness or already committed. An abort decision may be made by any participant provided no participant has yet committed.
- The protocol must allow interleaving of actions by different participants, and must not assume synchrony or ordering between participants.

Correctness properties to guarantee:
- Safety: It must be impossible for one participant to end up committed while another ends up aborted (no conflicting final decisions).
- Type and state invariants: every participant’s state must always be one of the defined states (initial/working, prepared, committed, aborted).
- Liveness considerations (optional): characterize conditions under which the system can reach a global committed or aborted outcome (e.g., progress if all participants eventually prepare), but ensure safety is primary.

Provide the model as an abstract state machine with a global state mapping participants to their current state and a next-state relation that captures allowed single-participant transitions satisfying the rules above.
