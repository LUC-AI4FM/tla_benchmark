Specify a concurrent resource allocator for a fixed finite set of indistinguishable resources and a fixed set of clients. The system should allow clients to repeatedly request a set of resources, obtain some subset of those requested resources, and later return resources. Model the allowed behaviors and the liveness and safety requirements without prescribing any particular implementation.

Requirements:

- Each client may issue a new request only when it currently holds no resources and has no outstanding request; a request is a nonempty subset of resources.
- The allocator may grant to a client any nonempty subset of resources that are both currently free and part of that client’s outstanding request. Grants need not satisfy the whole request at once.
- A client may return any nonempty subset of the resources it currently holds at any time; returning is voluntary except for a liveness obligation described below.
- Resources are exclusive: no resource may be allocated to more than one client simultaneously.
- Fairness / liveness obligations:
  - If a client has an outstanding request, the allocator must eventually allocate every requested resource to that client (each requested resource will eventually be granted).
  - Once a client’s outstanding request becomes empty (i.e., its entire request has been granted), the client is obliged to eventually return all resources it holds.
  - Additionally require that each client’s outstanding request will be satisfied infinitely often (i.e., every client repeatedly reaches states with no outstanding request).
- Ensure all state variables respect appropriate typing (mappings from clients to subsets of the finite resource set).

State only the system goal and correctness properties (safety: exclusivity and well-formed state; liveness: eventual allocation of requested resources, eventual return after full fulfillment, and repeated satisfaction of requests).
