Specify a formal TLA+ model of a library of purely functional finite-set utilities that operate on finite sets of integers and on finite collections of sets. The model should describe the intended mathematical semantics (not an algorithm or implementation) of the following operators and the properties they must satisfy:

- A generic fold over a finite set that reduces its elements with a binary associative operator and a base value, returning the same result regardless of the order of folding (i.e., fold result depends only on multiset of elements and operator semantics).
- Common derived aggregates: sum and product of elements of a finite integer set, and a generic reduce alias.
- A map-then-fold operator: apply a unary projection to each element and then fold the results; sum-of-projections should equal folding with addition after mapping.
- Flattening a set of sets into their union and the symmetric difference of two sets, with semantics equal to set union and (A ∪ B) \ (A ∩ B) respectively.
- Cardinality-based quantification: count elements of a finite set satisfying a predicate.
- k-subsets: the collection of all subsets of size k, with behaviour compatible with combinatorial counts (empty when k not in appropriate range).
- Operators to compute the maximum and minimum integer of a finite nonempty integer set.
- Choices: given a finite collection of nonempty sets, produce all possible choice-sets formed by picking one element from each input set (cartesian-product/choice-function semantics), and return a singleton empty set for the empty collection.
- A Choose-unique operator that selects the unique element of a finite set satisfying a predicate and fails (is undefined) when zero or multiple elements satisfy it.

For each operator, state preconditions (e.g., finiteness, non-emptiness, well-typedness) and specify correctness properties: determinism where intended, consistency with standard set-theoretic definitions (e.g., Flatten equals UNION), algebraic identities (fold with base and operator for sum/product), and cardinality/counting relationships (Quantify equals cardinality of filtered set; k-subset counts match binomial coefficients when applicable). Also state expected error/undefined behavior when preconditions are violated (e.g., max/min on empty set, choose-unique when not exactly one match).
