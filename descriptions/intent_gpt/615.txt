Specify a formal model of a round-based Byzantine fault-tolerant consensus protocol for a partially synchronous network that resembles Tendermint-style locking and voting. The model should describe a set of processes (some of which may be Byzantine) that repeatedly execute rounds consisting of distinct steps: proposal, prevote, and precommit. In each round a designated proposer broadcasts a proposal value; honest processes decide how to vote based on their current lock (a locked value and the round when it was taken) and any previously observed “valid value” evidence. The protocol must allow a process to lock on a value after receiving sufficient prevotes, to update its valid value after seeing sufficient prevotes for some value, and to decide a value after receiving sufficient precommits. Messages may be delayed, duplicated, or reordered but not forged; faulty processes may send arbitrary messages. The model must capture the possibility of multiple rounds and round change when progress stalls, including carrying forward locked and valid state across rounds.

Specify safety and liveness properties to verify: Safety — no two honest processes ever decide different valid values (agreement, and once decided the decision is fixed). Validity — any decided value must have originated from a proposer’s proposal and must be a member of the set of allowed values. Liveness (under eventual synchrony and with fewer than a threshold of Byzantine faults) — eventually some honest process decides a value. Also specify invariants about locking and valid-value monotonicity (e.g., locks only move to values supported by quorums, valid-rounds are nondecreasing) that must hold in all reachable states. Include parameters for number of processes, fault threshold, set of possible values, and maximum rounds for bounded-model checking.
