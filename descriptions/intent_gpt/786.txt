Model a transactional in-memory key-value store that supports optimistic concurrency via per-transaction snapshots and deferred writes. The system must allow clients to begin transactions, read keys, write keys, and commit or abort transactions. Each transaction operates on a snapshot of the global store taken at transaction start; reads inside a transaction return the snapshot value for keys not yet written by that transaction, and its own written values for keys it has updated. Writes performed by a transaction are buffered locally until commit. A commit must succeed only if no write–write conflict exists with other committed transactions: that is, for every key a committing transaction has written, the current global value must still equal the value in that transaction’s snapshot for that key; otherwise the commit must fail and the transaction should abort. On successful commit, all buffered writes atomically update the global store. Aborts discard a transaction’s buffered writes and leave the global store unchanged.

Specify safety properties: snapshot consistency (a transaction never observes a value that contradicts its start snapshot except its own writes), atomicity of commit (either none or all of a transaction’s writes become visible), and serializability with respect to committed transactions (committed results are equivalent to some serial ordering of successful commits). Specify liveness assumptions optionally: progress for a transaction that encounters no conflicting concurrent commit should eventually be able to commit. Allow arbitrary finite sets of keys, values, and transaction identifiers.
