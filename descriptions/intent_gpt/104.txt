Specify a formal model of a distributed termination-detection algorithm for a unidirectional ring of processes. The model should represent N processes arranged in a ring with a circulating token and asynchronous message-passing and local computation. Processes may be active (performing work) or passive; any active process may send an activation message to any other process (which may re-activate a passive process), and any active process may become passive at any time. The token circulates in a fixed direction; a process that holds the token may pass it to its predecessor under rules that ensure the token’s color can be stained black if it encounters activity that might indicate ongoing computation. A distinguished probe mechanism must allow the protocol to initiate a detection round that attempts to determine global quiescence by sending a white token around the ring; the token’s color and local process colors must record whether any suspicious activity occurred during the round.

Require the model to capture fairness assumptions appropriate for the termination-detection mechanism (fairness of the token-passing actions), and to allow arbitrary asynchronous activations and deactivations by the environment. State correctness properties to verify:

- Safety: whenever a white token returns to the initiator in the expected state, then all processes are passive (the algorithm never falsely declares termination).
- Liveness: if all processes eventually become passive at some point, then eventually a detection round will succeed and the protocol will detect termination.
- Also specify and allow checking auxiliary invariants that prove correctness (for example, an inductive invariant relating token position, token color, and distribution of black/white process marks).

Do not prescribe implementation details like particular variables or action decompositions; describe only the system behavior, the allowed nondeterminism, the fairness assumptions, and the properties to be checked.
