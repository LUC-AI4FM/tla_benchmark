Specify a formal model of a concurrent, lock-free double-ended queue (deque) that supports multiple parallel clients performing push and pop operations at both ends. The model should treat the deque as a linked structure of node objects and a pool of reusable node slots, where allocation can fail when no free slot is available and a background garbage collector may reclaim unreachable nodes. The concurrent operations must behave atomically from the client perspective: pushLeft, pushRight, popLeft, and popRight should each return either success with a value (for pops), success/acknowledgement (for pushes), or a distinguished error code ("full" for allocation failure, "empty" for popping an empty deque). Model the concurrency of many clients and allow interleaving and retries; the deque implementation may use multi-word compare-and-swap (atomic updates to two locations) as a primitive for coordinating concurrent updates.

Require the model to guarantee linearizability of all deque operations with respect to a sequential deque specification: every completed operation must appear to take effect instantaneously at some point between its invocation and response and must preserve FIFO/LIFO ordering semantics appropriate for deque ends. Ensure memory safety: nodes must never be reused while still reachable, and the garbage collector may only reclaim nodes that are provably not reachable from any observable deque state. Specify progress assumptions: clients must be able to make forward progress under fair scheduling (no operation deadlocks the system), and the garbage collector runs nondeterministically but does not violate correctness. Include invariants for structural integrity (no cycles except special sentinels, consistency of head/tail pointers) and safety properties (no value duplication or loss beyond what concurrent semantics permit).
