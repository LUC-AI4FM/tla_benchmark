Specify a model of a statically-known record data structure and operations that create and update records with well-defined field domains. The specification should describe how records are constructed with a fixed set of named fields and values, how updates to records behave when attempting to assign or change a field that is not part of the record's declared domain, and how a new record value produced by an update determines its domain. The system must distinguish between legal updates that refer to existing fields and illegal or ignored updates that refer to non-existent fields, and must state the intended outcome for such cases: either reject the update, leave the record unchanged, extend the record with the new field, or otherwise specify the semantics chosen. The model must allow checking expressions that ask for the set of field names (the domain) of a record and must ensure those queries reflect the chosen semantics for updates. Key correctness properties to guarantee: updates to existing fields preserve and modify values as specified; updates that target unknown fields affect the record domain only according to the declared semantics; and domain queries after updates return exactly the set of fields that the semantics prescribe. Include simple examples of record creation and update behaviors as invariants to validate the model.
