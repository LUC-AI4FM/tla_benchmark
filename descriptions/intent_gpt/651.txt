Specify a TLA+ model of a blockchain light-client protocol that verifies header chains using a set of validators, some of which may be Byzantine. The model should capture a light client that repeatedly attempts to advance its trusted head from a trusted height to a target height by fetching and validating succinct proofs (light blocks) from validators. The system must include nondeterministic network delivery and possible faulty validator behavior, including equivocation and withheld messages, and must model clock drift in both the client's local clock and an external reference clock used for timeouts and trusting-period checks.

The specification must express the protocol’s normal and failure modes: how the client chooses which validators or peers to query, how it aggregates or checks validator votes/signatures to determine sufficient agreement, how it decides to accept or reject a candidate header, and how it falls back or retries when not enough honest responses are available. Correctness properties to guarantee include safety (the client never finalizes a header that contradicts a header that would be finalized by a correct quorum of honest validators within the trusting period) and liveness under assumptions (if fewer than the tolerated fraction are faulty and network delays and clocks remain within modeled bounds, the client eventually advances to the target height). Also specify invariants for monotonicity of the trusted height and that time-based checks respect the trusting period despite clock drift. Include assertions ruling out acceptance based solely on responses from a faulty minority, and temporal properties capturing that once a correct header is accepted, it remains accepted unless a proof of misbehavior is obtained.
