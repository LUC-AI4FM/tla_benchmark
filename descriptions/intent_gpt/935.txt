Specify a concurrent request/response memory-access controller for a fixed set of clients and a shared memory. The system should allow each client to issue a memory request that is either a read or a write to a concrete address, and then later receive a response. The model must include per-client control states with a simple 3-state protocol (ready -> busy -> done -> ready) and a per-client request buffer that, while the client is busy, holds a structured memory request (address, operation, and write value for writes) and otherwise holds either a value read or a distinguished "no-value". The shared memory is a finite map from addresses to values.

The specification must enforce these requirements:
- Safety: Only well-typed values are ever stored in the buffers and memory: addresses come from the address domain and values come from the value domain; while a client is busy its buffer must represent a valid memory request; while ready or done the buffer must be either a valid value or the no-value marker.
- Atomicity of client steps: a request action atomically moves a client from ready to busy and installs a well-formed request; a service action executes a single memory operation for one busy client: on read, it returns the memory value into the client buffer and moves the client to done; on write, it updates memory at the requested address and moves the client to done, storing an appropriate value indicator in the buffer; a response action returns a done client to ready without changing memory.
- Invariant requirement: prove that the typing conditions and the buffer consistency relation (which links buffer contents to the client's control state) hold initially and are preserved by every action (i.e., they are inductive invariants under the system's transition relation).

Do not commit to a particular implementation technique (e.g., locking, interleaving order beyond single-client atomic steps); instead, state the abstract operations and the invariants that must be established and proved.
