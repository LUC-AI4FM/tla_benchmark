Specify a concurrent system that models a single process performing a loop with fairness: the process repeatedly increments a shared counter from 0 until it reaches a specified upper bound (10), then terminates and remains idle. The model should capture that the loop body is executed under a fairness assumption so that if the process remains enabled it eventually makes progress. The system must allow infinite stuttering once termination is reached so termination is not treated as deadlock.

Formalize the state space and transitions so that:
- The counter starts at 0 and only increases by one when the process executes the loop body.
- The process repeatedly chooses to execute the increment step while the counter is strictly less than the bound, and once the counter equals or exceeds the bound the process moves to a terminated/idle state and the counter remains unchanged thereafter.
- Fairness ensures the increment action cannot be postponed forever while it is continuously enabled.

Specify the following correctness properties to verify:
- Safety: the counter never decreases and never skips values (each increment increases the counter by exactly one).
- Progress/termination: eventually the process reaches the terminated state (i.e., the counter reaches the bound and the process stops).
- Liveness checkpoints: it is possible for the counter to take a specific intermediate value (e.g., 5), and it is possible for the transition from the penultimate to the final value (e.g., from 9 to 10) to occur as an atomic step.

Do not commit to a particular implementation structure; express behaviors, fairness, and properties abstractly so different realizations that meet these requirements can be specified and checked.
