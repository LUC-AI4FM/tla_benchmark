Specify a family of independent consensus instances running in parallel, one instance per slot, each deciding a single value from a fixed set of possible commands. The system must allow multiple slots to be decided independently and concurrently: at any step any single slot may make progress toward choosing a value, and different slots’ decisions do not interfere with each other. For each slot, the consensus instance must start with no value chosen and must eventually decide exactly one value from the Commands set (no more than one value per slot and at least one value must be chosen eventually). The system should permit nondeterministic choices of which slot and which command to propose, and it must ensure that once a slot’s value is chosen it remains fixed thereafter.

Model requirements and correctness properties:
- Safety: For every slot, at most one command becomes chosen (no conflicting multiple chosen values for the same slot).
- Liveness: For every slot, some command is eventually chosen (progress/fairness guarantees that no slot remains forever undecided).
- Independence: Consensus decisions for different slots are independent: safety and liveness must hold per-slot regardless of decisions in other slots.
- Fair scheduling: The specification should include a fairness assumption ensuring each slot has the opportunity to make progress (so per-slot liveness can be enforced).
- Parameterization: The model must be parameterized by a finite set of Commands and a finite set of Slots so it can be instantiated with concrete values for model checking.
