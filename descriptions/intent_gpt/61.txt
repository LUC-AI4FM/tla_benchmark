Specify a TLA+ model of a simple two-phase commit coordination between one transaction manager (TM) and a fixed set of resource managers (RMs). The model should represent each RM’s local state (at least “working” and “prepared”), a communication medium that holds unordered messages of three kinds (Prepared(from-RM), Commit, Abort), and a record of which RMs the TM believes are prepared. The system should allow an RM to transition from working to prepared and send a Prepared message, and allow the TM to send a Commit when it has evidence that all RMs are prepared. The model must capture message creation and the ability to observe which Prepared messages have been delivered, without assuming message loss or reordering semantics beyond simple set membership.

Specify the safety properties to be verified: that the system can never contain a Commit message unless every RM has already become prepared (i.e., no premature commit), and that an RM’s state transitions follow the allowed protocol (no other state values or illegal regressions). Also state invariants excluding impossible message types and that message contents correspond to the declared RM identifiers. Do not prescribe internal variable names or the specific step structure—describe only the abstract behaviors, allowed events, and the correctness properties to be checked.
