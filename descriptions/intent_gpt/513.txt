Specify a formal model of a simple two-process message-exchange protocol operating over a lossy, unordered message medium, in which each side repeatedly sends and receives messages that carry a data value and a single-bit sequence number. The model should treat the set of possible data payloads as a fixed finite collection. The protocol must allow both sides to hold a current outgoing message and a current incoming message; each message consists of a data element from the finite set plus a one-bit tag. The system must permit asynchronous steps in which a process may replace its outgoing message with any allowed message, and the medium may nondeterministically deliver or lose messages.

Require the following correctness properties to be specified as invariants and liveness goals: (1) Type safety — at all times both current messages are valid members of the message space. (2) Agreement of tagged messages — whenever the two current messages have the same tag bit, their entire contents must be identical (i.e., same data and same tag). (3) Safety of data values — no message may ever contain a data value outside the fixed finite set. Optionally include a progress property that a given data value can eventually be transmitted and reflected on the other side despite losses. Model should be abstract (not tied to a particular algorithm) so it can be used to check designs that use one-bit sequence numbers for duplicate suppression.
