Specify a formal TLA+ model of a multi-instance Paxos-style replicated state machine that supports dynamic reconfiguration. The model should represent an unbounded sequence of instances (slots) in which commands are proposed and possibly chosen by quorum votes, and it should allow special reconfiguration commands that change the set of acceptors and define new quorum systems. The system must permit multiple overlapping configurations over time, but enforce that reconfiguration commands are applied in a well-ordered way so that configuration changes do not violate safety.

Requirements:
- Model acceptors that can vote, abstain, and learn chosen commands for each instance and ballot number. Voting must be persistent: once an acceptor votes or abstains for a given instance and ballot, that decision cannot be retracted.
- Represent ballots (proposal numbers), instance numbers, commands (including distinct reconfiguration commands), and configurations (each with a configuration number and a set of quorums). Reconfiguration commands must be distinguishable from normal commands.
- Ensure that a command is chosen only when some quorum of the configuration used for that ballot has cast the same vote for that instance and ballot.
- Enforce safety: for every instance, at most one command can be learned (i.e., no two different commands are learned for the same instance).
- Ensure reconfiguration safety: a reconfiguration command that becomes learned establishes a new configuration that can be used only after it is learned; subsequent voting and choosing must respect that earlier learned configuration and prevent conflicting choices across configuration boundaries (no command chosen under a later configuration can retroactively make earlier choices unsafe).
- Express type invariants (e.g., domains and ranges), stability of chosenness and votes, and prove that the safety properties are invariants of the next-state relation.
