Specify a model of a simple event-counting controller that tracks how many occurrences of a particular event have happened and enforces an optional upper bound on those occurrences.

The model should represent a system that maintains a nonnegative integer counter for the number of events that have occurred and supports an action that represents the occurrence of an event. The system must allow starting from zero and, when a finite maximum is configured, must refuse further event occurrences once the counter reaches that maximum. It must also support the case where no maximum is configured (unbounded counting) without introducing infinite-state behavior that prevents model checking; in that case the model should treat the event action as not changing the tracked counter while still allowing events conceptually to occur.

Key requirements and correctness properties:
- Safety: The counter must never exceed the configured maximum when a finite maximum is set.
- Invariant initialization: The counter must start at zero.
- Liveness/possibility: When the counter is below the maximum, it must be possible for an event occurrence action to take place (unless the unbounded-mode policy prevents changing the stored counter).
- Mode semantics: Distinct semantics for bounded mode (counter increments) and unbounded mode (counter remains unchanged for model-checking) must be clearly specified.
- Nonnegativity: The counter must remain a nonnegative integer at all times.

Do not commit to a concrete implementation of the event action; state only these behavioral constraints and properties to be formally specified and verified.
