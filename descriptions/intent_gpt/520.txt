Specify a formal TLA+ model of a simple alternating-bit reliable data transfer protocol between a sender and a receiver communicating over unreliable, lossy FIFO-less channels. The system has a finite set of possible data values. The sender repeatedly attempts to send a message containing a data value together with a one-bit sequence number; the receiver returns single-bit acknowledgments. Messages and acknowledgments may be lost arbitrarily (dropped), reordered is not required to be preserved, and there is no corruption: any delivered message is exactly the sent value/bit. The sender may retransmit the same message (same data and bit) until it observes an acknowledgment toggling the bit, at which point it may choose a new data value and flip its bit. The receiver accepts a data message whose bit differs from its last-seen bit and updates its delivered data and last-seen bit; otherwise it discards duplicates. The receiver sends back the bit of the last accepted message as an acknowledgment. Model an unbounded but finite multiset (or sequence) of in-flight messages in each direction that can have individual elements removed to model loss.

Formalize initial states, atomic step types (sender send, sender receive/handle ack, receiver send ack, receiver receive/handle data, and loss of an individual in-flight message), and fairness assumptions as needed. Specify correctness properties:
- Safety: The receiver only delivers a data value that was previously sent by the sender, and delivered values follow the sender’s committed choices (no spurious data).
- Liveness (under weak fairness for sender and receiver actions but no fairness for loss): If the sender repeatedly tries to send a particular message (data with a given bit) and losses do not persist forever, then the receiver eventually accepts that message; similarly, if the receiver repeatedly sends an acknowledgment and losses do not persist, the sender eventually observes the acknowledgment and may progress.
- Non-duplication: The receiver should not deliver the same data value twice in a row unless the sender intentionally retransmits with the same data after toggling and re-toggling bits.
- Bit alternation invariant: Sender and receiver bits remain consistent with the protocol’s alternating-bit semantics (e.g., receiver only accepts on bit change).

Do not presuppose any particular implementation structure; describe the abstract state components (sender state, receiver state, in-flight messages in each direction), allowed transitions, and the invariants and temporal properties to be proven.
