Specify a simple state-transition system that models a single evolving state value and a collection of operations that may read or observe the future value non-destructively. The system must:

- Represent a mutable state value that may be updated nondeterministically by transitions.
- Provide operations that produce compound observations combining their input parameters with the state value as it will be after the transition (i.e., observations that depend on the next-state value rather than the current-state value).
- Allow some operations to return constructs that pair or tuple an input argument with the post-transition state, and allow others to return tuples containing multiple input arguments plus the post-transition state.
- Also include operations whose executability is determined by whether some guarded action would be enabled, and include at least one operation that can produce a set-valued result derived from primed(s) of arguments.
- Ensure the transition relation is total: from any reachable state at least one allowed operation can occur.
- Specify safety properties: the state evolution must always follow the defined transition relation and operations must preserve type invariants of returned observations (e.g., tuples have the declared arity and components drawn from allowed domains).
- State liveness goals: every enabled operation should eventually occur (or otherwise state fairness constraints that avoid starvation of operations).

Do not prescribe an implementation style; describe only the abstract state, operations, and the correctness properties above.
