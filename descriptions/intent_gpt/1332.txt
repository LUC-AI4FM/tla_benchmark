Model a token-based distributed termination detection protocol running on a fixed ring of N processes. The system must represent each process’s local state (e.g., color, a pending task count, an active/inactive flag, and a local message counter) and a circulating token that carries a position, a numeric field, and a color. Initially, all processes are inactive, white, with zero pending and zero counter, and the token starts at a specified process with a given color and numeric value.

Specify the asynchronous behavior in which processes may become active, generate or complete work (affecting pending and counters), send messages to neighbors, and change color from white to black when they perform actions that may introduce nonlocal work. The token should circulate around the ring; when the token visits a process it must collect or update information (e.g., accumulate counters, observe process colors, and reset local flags as required by the algorithm). The protocol should detect global termination: when the token completes a full pass with cumulative conditions indicating no outstanding work (all processes inactive, no pending counts, token color white, and accumulated counters zero), the system must reach and stay in a terminating state.

Require safety properties: the algorithm must never declare termination while there exists uncompleted work or in-transit messages. Require liveness: if processes stop generating new work, the protocol must eventually detect termination. Also require absence of deadlock (the protocol should not get stuck before termination detection).
