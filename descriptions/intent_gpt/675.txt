Specify a formal model of a testing harness that verifies properties of sequence-manipulation routines by exercising them with a set of generated test cases and checking expected results. The model should describe a test driver that repeatedly constructs input sequences, applies one or more sequence-transforming operations under test, and compares the observed outputs with the oracle results computed by a reference definition. The system must support parametrized test case generation (varying lengths, element values, and edge cases such as empty and singleton sequences), deterministic seeding of generators for reproducibility, and a configurable limit on the number of tests executed.

The specification must guarantee safety properties: every observed output equals the oracle output for the same input; no test execution leads to an undefined or error state; and invariants on generator constraints (e.g., lengths and element domains) are maintained. It must also state liveness-style progress: the driver either eventually finds a counterexample that violates the oracle equivalence or eventually completes the configured number of tests without finding any violation. Additionally, record and expose the first counterexample found (input and mismatching outputs) and a summary count of passed and failed tests. The model should allow enabling/disabling individual operations under test and should keep test executions deterministic when given the same seed and parameters.
