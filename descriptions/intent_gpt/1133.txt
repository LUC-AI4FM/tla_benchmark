Specify a model of a heap-based promise (future) system with garbage collection, where objects live at heap addresses and may contain fields that are values, object references, or sequences thereof. The system must support promises that can be unresolved or resolved; unresolved promises encode either a “when” continuation that waits on another promise’s resolution or a normal continuation that waits on the identity of an object (itself represented by a promise). When a promise becomes ready to be resolved, its associated continuation (a method) is executed using the heap and the resolved input; the continuation produces a result (a value or an object id) and may update the heap. Resolution updates the promise object to a resolved state with the produced value.

Model rules for: (1) when-style promises that fire when their argument promise resolves, invoking the continuation with that argument’s value; (2) non-when promises that fire when the object-id promise resolves, invoking the continuation with the resolved object identity; and (3) safe garbage collection of promises that are resolved and no longer reachable from any live object (reachability should treat promise-internal links specially so that promise links do not create spurious reachability).

Require invariants: heaps never contain dangling references (every referenced id points to an object); promise objects satisfy the intended promise shape; evaluation of continuations may only modify objects reachable from the continuation’s receiver or arguments; promise resolution never creates cycles among unresolved promises; and garbage collection only reclaims resolved promises that are unreachable from program roots (ignoring links internal to promise objects). Also require that executing continuations is deterministic when given the same reachable subheap and preserves the OK-heap properties.
