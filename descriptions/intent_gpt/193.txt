Specify a simple typed functional library containing a single identity function and its use sites. The model should describe a statically typed language environment in which functions have explicit input and output types, and the type checker enforces that function definitions and applications respect those types. The system must allow declaring a function that returns its argument, but must require that the function’s declared type signature matches its implementation and that every call supplies an argument of the declared input type. The specification should capture that overly permissive or mismatched type annotations are disallowed: a declared polymorphic or overly general function type that is not supported by the language’s type system must be rejected by the type checker. Model the process of type checking a function declaration and of type checking several uses of that function in different contexts. Key correctness properties: (1) Soundness — no expression is assigned a type that would permit a runtime type error; (2) Declaration-consistency — a function’s implementation and its uses must conform to its declared type, otherwise the declaration or the uses are flagged as ill-typed; (3) Rejection of unsound generality — any type annotation that would allow the function to be applied to incompatible types without an appropriate polymorphic scheme must be considered invalid. Also express determinism of type checking results (given the same inputs) and termination of the type-checking procedure.
