Specify a discrete, cyclic hour clock abstraction that counts hours modulo 12 and supports asynchronous external adjustments. The model should treat the clock value as an integer in 0..11 representing the current hour. The system must allow two kinds of events: normal ticks that advance the hour by one modulo 12, and external set operations that replace the current hour with any allowed value. Both event types can occur non-deterministically and may occur concurrently from the perspective of the environment, but the model should represent the clock as a single atomic update per event.

Require the following correctness properties:
- Safety: the clock value is always within the valid range 0..11.
- Progress: it is always possible for the clock to eventually change (i.e., ticks are not permanently disabled).
- Deterministic wrap-around: repeated ticks must cycle through the 12-hour sequence and return to the starting value after 12 successive ticks.
- Set consistency: when an external set operation writes a new hour, the resulting value must equal the written value immediately after the operation.
- No lost updates under serial execution: if two update events occur sequentially, the final value reflects the second event (the model need not enforce concurrency control beyond atomic events).

Also state invariants and temporal properties needed to assert the above, and expose the initial condition where the clock starts at some value in 0..11 (not fixed).
