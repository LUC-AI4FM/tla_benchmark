Specify a formal TLA+ model of the classic two‑phase commit protocol (one transaction manager coordinating a fixed set of resource managers). The model should describe the protocol at the message/event level (prepare, prepared, commit, abort) and capture the possible asynchronous interactions and independent failures/choices of participants. The system must allow resource managers to: initially be in a working state, choose to prepare (sending a prepared indication), or unilaterally decide to abort; the transaction manager must start in an initial state, collect prepared indications from resource managers, and either decide to commit when every resource manager has prepared or spontaneously decide to abort; once the TM decides, it must broadcast the corresponding global decision (commit or abort) that resource managers can later receive. Messages can be delayed and delivered in any order; no message loss is assumed.

Require the following key safety properties:
- Consistency: no two resource managers may end up with conflicting final decisions (one committed while another aborted).
- Agreement with global decision: if the transaction manager decides commit (resp. abort), then eventually every resource manager that has not aborted will reach the committed (resp. aborted) final state.
- Validity: a resource manager may commit only if either (a) it prepared and the TM later decided commit, or (b) it received the TM’s commit; it must not commit without those prerequisites.

Also require a type/structure invariant that bounds states and messages, and formulate an initial condition where all RMs are working, the TM is initial, and no messages exist. Include liveness/temporal goals optionally (e.g., eventual delivery of TM’s decision to non‑failed RMs) but ensure safety properties above are mandatory.
