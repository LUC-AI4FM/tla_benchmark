Specify a formal model of a multi-instance consensus service. The system accepts proposals of values from a fixed nonempty value domain and has a fixed nonempty set of independent consensus instances (slots). For each slot, the service must eventually decide at most one value from the set of values proposed system-wide, and once decided a value for a slot it must never be undone.

Model the system as concurrently executing unbounded proposer activity and independent slot decision-making. Proposers may introduce new values at any time; decisions for different slots may occur independently and nondeterministically, but a decision may only choose a value that has previously been proposed. Decisions are final: once a slot has a chosen value it remains chosen forever and cannot change or be removed. At all times each slot may have either no decision or exactly one chosen value; the model must preclude any state in which a slot has chosen more than one value.

State the following correctness properties to be verified:
- Safety: every chosen value for any slot is a value that was proposed at some point; no slot ever has more than one chosen value; chosen values are persistent.
- Liveness: under a fair scheduling assumption that continuously enabled actions are eventually taken, every slot eventually acquires a chosen value.
- Type invariants: represent the set of chosen values per slot as finite subsets of the value domain.

Do not prescribe particular algorithmic steps or message patterns; leave the proposer and chooser behaviors nondeterministic subject to the constraints above so proofs may cover a range of implementations.
