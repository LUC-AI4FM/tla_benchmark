Specify a system that models a simple finite-state processing pipeline that consumes a finite set of distinct items, marks them as processed, and produces corresponding outputs. The model should start from an initial configuration where the input set contains at least three distinct integer items chosen from a small, finite universe, and the set of processed items and the set of outputs are both empty.

Model a step in which the system selects one unprocessed input item, removes it from the input set, adds it to the processed set, and emits exactly one output value that is a deterministic function of the consumed input (specifically, a fixed arithmetic transformation of the input). The system may also reach a quiescent state when no inputs remain, in which case no variables change.

Require these safety properties:
- Processed and input sets are always disjoint (an item cannot be simultaneously unprocessed and processed).
- Processed items are only ever items that were previously in the input set.
- Each step preserves consistency: when a single input is consumed in a step, only that item moves to the processed set and exactly one corresponding output value is added.

Require these liveness / trace properties:
- The system terminates only when the input set is empty.
- Over any execution that starts from the initial state, the final output set equals the image of the initial input set under the defined transformation (i.e., every initial input eventually produces its corresponding output, and no extra outputs are produced).

Do not prescribe an implementation strategy, scheduling policy, or variable naming; focus on the abstract state, allowed state transitions, and the invariants the specification must guarantee.
