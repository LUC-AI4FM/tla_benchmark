Model a two-component concurrent system consisting of a main controller and a reusable subcomponent that can perform a bounded counting task. The subcomponent repeatedly increments its local counter from 0 up to 3, doing one increment per step, and the main controller exposes that local counter as a shared observable value. The combined system should allow either the subcomponent to take its increment step or, if the subcomponent is not enabled, the main controller can stutter (take a step that leaves the observable state unchanged). Require a fairness constraint that ensures the subcomponent’s enabled steps cannot be indefinitely postponed when they remain continuously enabled (weak fairness for the subcomponent’s increment action). The initial observable value must be 0, and the global behavior should be described using persistent step relations and stuttering semantics.

Specify the liveness goal that eventually the observable value reaches 3. Formally state safety requirements (the only state changes are the subcomponent’s increments of the observable value by 1 while enabled; the main controller’s stutter steps do not change the observable value) and the fairness requirement (weak fairness applied to the subcomponent increment action). Require a proof obligation or property to be checked: under these assumptions, the eventual reachability of the observable value 3 holds.
