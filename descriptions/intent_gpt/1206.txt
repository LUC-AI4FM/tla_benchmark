Specify a formal model of a small, statically-typed expression-language semantics and name-resolution system that supports composite values (tuples, records, sequences), functions (including higher-order and lambda expressions), conditionals, case expressions, let-bindings, set and quantified expressions, and basic temporal/well-founded operators. The model should capture how complex expressions are constructed, how subexpressions are selected positionally and by field name, and how attribute-like selectors and updates (immutably producing modified copies) behave. It must also represent operator application, lambda abstraction, and the behavior of shorthand function composition or wrapping. Include mechanisms for scoping and shadowing (local bindings vs global), and for a limited module/constant system where named keywords can appear as identifiers without changing semantics.

The model must ensure correct static resolution of subexpression positions and field names: selecting or updating any valid position or field yields the expected component and preserves the rest of the structure; out-of-range or missing selections are invalid. Function application must evaluate arguments and bind parameters correctly, including nested lambdas and higher-order usage. Conditional, CASE, and LET semantics must follow conventional eager evaluation rules. Quantifiers and set comprehensions should bind variables and produce correct ranges. Specify correctness properties: preservation of value types under selection/update, determinism of evaluation, lexical scoping (no capture of unrelated bindings), and invariants relating composed selectors/updates (e.g., selecting then updating at the same position yields the updated value). Also specify consistency conditions for module-level name binding and that keyword-like identifiers can be treated as ordinary names without changing evaluation.
