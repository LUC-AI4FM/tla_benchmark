Specify a formal grammar-directed parser and validator for a rich specification language used to write concurrent and reactive system modules. The model should treat source text as a sequence of tokens and define the syntactic constructs that complete modules may contain: module headers and footers, import/extends lists, unit-level declarations (constants, variables, operator and function definitions, instances, module definitions), assumptions/axioms, theorems, and nested module bodies. It must support declarations of identifiers and reserved words, numeric and string literal forms, prefix/infix/postfix operator categories (including user-defined operator declarations), tuples and bracketed list forms, quantifiers and bounded quantification, choose/let/case constructs, set and sequence expressions, record and function expressions, EXCEPT updates, temporal operator applications, and the various expression compositions permitted by the language (including operator application, tuple formation, projections, and indexed expressions).

The specification must require that well-formed programs satisfy scoping and binding rules (identifiers are distinct from reserved words; operator and function definitions bind in their lexical scope; instance substitutions respect arity and operator kinds), enforce syntactic constraints on token sequences (e.g., required separators, matching delimiters, and minimum-length header/footer markers), and ensure construct-specific well-formedness (e.g., quantifier bounds must include a target expression, EXCEPT targets must be valid locations, and infix/prefix/postfix operator positions conform to declared forms). Specify key correctness properties: every accepted token sequence corresponds to exactly one abstract syntax tree (unambiguous parsing), all identifier uses are either declared or imported (no free undefined names), and the grammar is closed under composition of modules and instances (imports and substitutions preserve well-formedness).
