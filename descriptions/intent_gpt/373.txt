Model a small proof-management language and checker for structured, human-written proofs (proof scripts). The model should represent proof objects, proof steps, hierarchical proofs with nested obligations, and references to named facts, definitions, and module instances. It must capture the way a script declares and uses theorems, axioms, definitions, and instantiations across modules, allowing local bindings, witness and pick choices, and scopes for hiding or exposing names. The model must express how proof steps generate proof obligations (assume/prove pairs), how steps like TAKE, WITNESS, PICK, CASE, SUFFICES, HAVE, DEFINE, USE, BY, QED, and OBVIOUS transform or discharge obligations, and how proof composition and refinement combine obligations. It must support record-like containers for proof metadata and allow keyword-like identifiers to be used as record fields without affecting semantics.

Correctness properties:
- Soundness: every discharged obligation must be derivable from assumptions, definitions, axioms, and previously proven theorems; the model must forbid marking an obligation proven unless justified.
- Preservation of scope: names introduced locally (via DEFINE, INSTANCE parameters, TAKE, PICK, WITNESS, LET) must not leak outside their scope; uses of hidden names must be rejected.
- Obligation well-formedness: each obligation has clearly specified context (assumptions and visible facts) and a single goal formula; composing steps produces the expected new obligations.
- Termination of proof checking for finite proofs: checking a finite script completes and either accepts (all obligations discharged) or reports remaining obligations.
Specify the abstract judgment rules (not an implementation) for how each proof construct transforms obligations and for module instantiation and name resolution.
