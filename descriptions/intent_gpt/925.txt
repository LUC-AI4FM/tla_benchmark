Model a parameterized inner FIFO queue used inside a concurrent system. The model should describe a single FIFO buffer that holds a sequence of messages (from a given finite message domain), supports enqueue and dequeue operations, and can be instantiated multiple times by clients. The queue must preserve message order (first-in, first-out), never lose or duplicate messages, and correctly handle empty-queue and full-queue conditions. The specification must allow an arbitrary but fixed maximum capacity chosen at instantiation time, and must make explicit which operations are enabled when the queue is full or empty.

Specify the behavioral interface: an enqueue request must either succeed (appending the message to the tail) when capacity permits, or be rejected/blocked when full; a dequeue request must either succeed (removing and returning the head message) when the queue is nonempty, or fail/return an “empty” indication when empty. Model concurrent clients issuing enqueues and dequeues nondeterministically. Include invariants guaranteeing that the sequence of delivered (dequeued) messages is a prefix of the sequence of enqueued messages and that each enqueued message is eventually either retained in the queue or dequeued (no silent loss). Include safety properties: preservation of FIFO ordering, capacity bound, and absence of duplicates. Optionally state liveness properties: progress under weak fairness (e.g., an enabled dequeue or enqueue will eventually execute).
