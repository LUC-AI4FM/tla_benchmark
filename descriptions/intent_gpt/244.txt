Specify a small statically-typed language's type alias system and a type checking component that validates alias definitions and usages. The model should describe how type aliases can be declared, how aliases may refer to other aliases, and how the type checker resolves alias names to concrete types. It must allow alias definitions that name a type expression and must detect and report two classes of errors: references to aliases that have not been declared, and cyclic alias definitions that prevent resolution. Include contexts with multiple alias declarations and type expressions built from basic constructors (e.g., set, function, product) and alias names. The type checker must succeed when every alias referenced in any type expression is declared and the dependency graph of aliases is acyclic, producing a fully resolved type for each alias; it must fail otherwise with an indication of which alias is missing or which cycle exists. Specify key correctness properties: (1) soundness — resolved types contain no undeclared alias names; (2) termination — type checking finishes for any finite set of alias declarations; and (3) error detection completeness — any use of an undeclared alias or any cycle in alias dependencies is reported. Include scenarios with nested and repeated alias uses to exercise resolution.
