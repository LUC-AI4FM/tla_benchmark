Specify a formal model of a block-DAG based distributed ledger used by a set of network nodes that repeatedly propose blocks in discrete rounds under rotating leadership. The model should treat blocks as lightweight records that identify their proposer and the round they were created in, and should include a distinguished genesis block. Describe how each honest node accumulates a directed acyclic graph (DAG) of blocks by adding blocks that may reference prior blocks, so that every DAG contains the genesis block and every path ends at genesis.

The model must provide a deterministic method to extract a linear sequence of blocks from any DAG that is consistent across honest nodes when their DAGs sufficiently overlap: it may use an arbitrary but deterministic ordering of a DAG’s vertices that respects the DAG structure in that earlier leaders’ blocks appear before later leaders’ blocks. Define a notion of a leader block for each round and a way to locate the most recent leader block before a given round inside a DAG.

Specify safety and liveness properties to verify:

- Safety (Agreement): If two honest nodes produce linearizations from DAGs that both contain the same leader blocks up to some round, then those linearizations must be compatible (one is a prefix of the other).
- Liveness (Progress): If honest leaders keep proposing blocks and honest nodes eventually receive those blocks, then the extracted linearization grows (new blocks become finalizable/visible in the sequence).
- Integrity: Extracted sequences contain only blocks that are present in the node’s DAG and include genesis exactly once.

Do not prescribe a particular implementation of message delays, failure model, or ordering beyond the deterministic tie-breaking; allow parametrization of the set of nodes, rounds, and leader assignment.
