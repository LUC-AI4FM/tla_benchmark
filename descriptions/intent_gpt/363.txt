Specify a formal model of a small-language operator-evaluation facility that supports higher-order anonymous functions (lambdas) and parameter binding. The model should capture the semantics of applying an operator to an anonymous function and of instantiating a module with a function-valued parameter. It must allow defining an operator that accepts a function as an argument and then applies that operator to a particular anonymous function, producing the expected result of the function application. It must also allow creating an instance of a module (or component) that receives a function as a parameter and a numeric parameter, and then uses those parameters to compute values; the instance’s computed results must match the application of the supplied function to the supplied numeric argument.

The specification should state the types and domains (e.g., integers, sets) for values and functions, and require that function application is deterministic and follows usual lambda semantics (bound variables are local, capture is avoided). Key correctness properties: (1) Applying the operator to a lambda yields the same value as directly evaluating the lambda; (2) Instantiating a component with a function parameter yields component outputs equal to applying that function to the numeric parameter; (3) Evaluation is type-safe (applications only occur when domains match); (4) No unintended variable capture or aliasing occurs during instantiation or application. Include assertions or invariants that check these properties.
