Specify a formal model of the Fast Paxos consensus algorithm for a system of replicas that may propose and agree on one value per instance. The model should capture two kinds of rounds: “fast” rounds that allow proposers to broadcast proposals directly and require larger quorums, and “classic” rounds that use a coordinator-driven prepare/accept pattern with majority quorums. Do not prescribe an implementation; instead state what the algorithm must accomplish and the invariants it must maintain.

Requirements:
- Model proposers, acceptors, and a coordinator role abstractly; allow concurrent proposals and messages between them.
- Fast rounds: proposers may initiate a fast round that signals “any” value may be accepted, and acceptors may respond with their current proposed value. A value is decided in a fast round when a fast quorum of acceptors report the same value.
- Classic rounds: when conflicts exist (multiple values proposed in a preceding fast round), a coordinator must be able to run a classic round. The coordinator must choose a value according to safety rules: if the fast-quorum responses include a value held by a strict majority of that fast quorum, that value must be chosen; otherwise the coordinator may pick any value from those proposed. Classic acceptance follows the usual majority acceptance rule and decision occurs when a classic quorum accepts the same value.
- Safety properties: (1) Agreement — no two different values can both become decided (in any combination of fast/classic rounds). (2) Nontriviality — only values that were actually proposed by some acceptor can be decided. (3) Valid conflict-resolution rule — when resolving collisions the coordinator must respect the majority-in-quorum rule described above.
- Liveness assumptions: do not model crashes explicitly, but allow asynchronous message delivery; specify fairness conditions sufficient to ensure progress of decision steps when required quorums and messages eventually occur.
- Quorum structure: allow parameterization of replica set, fast-quorum sets, and classic quorum sets, with constraints ensuring intersection properties required for safety (fast quorums intersect each other and intersect classic quorums appropriately).

State clearly the consensus goal (single chosen value per instance) and the correctness invariants above; avoid committing to particular message formats or algorithmic steps.
