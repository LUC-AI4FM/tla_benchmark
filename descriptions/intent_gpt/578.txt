Specify a concurrent distributed-memory system that supports atomic multi-node read-only transactions in the presence of ordinary multi-node read-write transactions. The model should represent multiple nodes that each store disjoint sets of keys, clients that may issue either read-only transactions spanning many nodes or standard read-write transactions, and a communication medium delivering messages between nodes and clients with bounded or asynchronous delays. The system must allow read-only transactions to contact multiple nodes to obtain consistent snapshots without blocking or interfering with concurrent updates beyond standard read-commit semantics.

Require the specification to capture liveness of transaction processing (requests are eventually handled and responses delivered under fair scheduling) and safety properties: serializability (all transactions observe a total order equivalent to some sequential execution), atomicity of read-only transactions (each read-only transaction returns values that reflect a single global snapshot), and write-atomicity with respect to reads (no read observes a write that did not commit in the serialization order). Also require absence of lost or duplicated committed updates, and that reads return only values produced by some committed write. The model should permit modeling of retrying, timeouts, and message reordering, and include invariants to prove that read-only transactions do not violate consistency even when concurrently executing with read-write transactions.
