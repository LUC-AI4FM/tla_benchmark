Specify a TLA+ model of a replicated-state-machine (RSM) leader-based consensus protocol for a small cluster of fixed servers. The model should describe how servers maintain and exchange logs of commands and agree on committed decisions across multiple terms. The system must allow leaders to propose and append entries to their local logs, allow followers to accept or reject append requests, enable term changes via elections, and support log truncation/repair when a follower's log diverges. Include mechanisms for leader election, log replication, commit index advancement, and safety during leader changes (including preventing committed entries from being lost).

The model must guarantee these correctness properties:
- Safety: once a command is committed at a particular index in some term, every server’s log at that index eventually contains the same command and term, and that value never changes (no committed entry is overwritten).
- Leader completeness: a leader that completes an entry has that entry present on a majority of servers.
- Log matching: if two logs contain the same entry at the same index and term, then all preceding entries are identical.
- Term monotonicity: terms are nondecreasing on each server, and leadership is only attributable to the highest-known term.
- Liveness under partial synchrony: assuming a stable period where a majority of servers can communicate, some leader eventually commits new entries.

Model should allow bounded message loss, message reordering, and server crashes/recoveries, and support reasonable bounds on log lengths and term numbers to enable model checking. Do not prescribe internal variable names or concrete algorithmic steps; focus on the protocol goals and invariants to verify.
