Specify a system that models a small, strongly-typed expression language with operators and operator application, and requires static validation that operator definitions are well-formed and consistently applied. The model should represent operators as first-class definitions that accept zero or more typed operands and produce results of specific types. It must forbid ill-formed operator composition where an operator-definition construct is applied to values that are not valid operator descriptors (for example, treating a numeric literal as an operator). The specification should capture how operators are declared, how operator application is resolved, and how operator composition or nesting is validated at definition time.

The system must ensure that every operator application occurring in a program refers to a previously declared operator whose arity and operand types match the use. It must detect and reject attempts to construct an operator by applying a non-operator value. The correctness properties required are: (1) Type safety — all operator applications preserve declared operand/result types; (2) Well-formedness — no program state contains an operator-definition expression that applies a non-operator; and (3) Preservation under evaluation — evaluation steps do not introduce ill-formed operator applications. Also specify invariants and liveness conditions that the static checker terminates and flags all ill-formed constructions.
