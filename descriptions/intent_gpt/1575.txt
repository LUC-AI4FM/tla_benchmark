Specify a formal model of a simple imperative language with nested procedure calls, call-by-value parameters (with defaults), local variables, returns, and a call stack. The model should represent a program composed of multiple procedures that can call each other, including recursive calls, and a main thread that invokes these procedures in sequence. The model must capture parameter passing semantics (actual arguments binding to formal parameters on call), initialization of local variables when a procedure is entered, and restoration of caller state when a procedure returns. It must include the ability for a procedure to return immediately or after making further calls, and for a caller to resume at the correct point with its local variables preserved.

Key correctness properties:
- Parameter and local-variable initialization: upon entering a procedure, its formal parameters must equal the supplied argument values and its locals must be initialized deterministically from those parameters or specified defaults.
- Call-stack discipline: every call pushes a frame containing the caller’s return point and necessary locals; every return pops exactly the corresponding frame and resumes execution at the saved return point with the caller’s locals restored.
- Safety assertions inside procedures: assertions placed inside procedures must hold whenever execution reaches them; violations should be observable as reachable error states.
- Recursion safety and termination liveness: recursive calls must preserve correctness of frames; if the program is intended to terminate, specify and prove eventual termination (that control reaches a designated Done state) under the given inputs.
- Absence of unintended interference: no procedure’s local variables or parameters may be implicitly shared or reused across unrelated frames.

Model these requirements abstractly (without prescribing implementation details like stack encoding), so different implementation strategies can be compared.
