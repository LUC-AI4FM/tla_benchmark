Specify a model of a distributed task lifecycle system that manages creation, assignment, execution, and cleanup of tasks. The model should describe tasks as entities with stable identity and membership in a service, an optional placement (node or slot), a desired terminal state, and a current lifecycle state drawn from an ordered set of states (including a special nonexistence marker). The system must support distinct components (or roles) that are responsible for transitions between lifecycle states (for example: creation, allocation, scheduling/assignment, agent-side progress, and garbage collection), where each component can effect only the transitions assigned to it. Enforce that any transition either advances a task along the state order or explicitly removes or creates it (i.e., transitions to or from the nonexistence marker), and that no two different components are permitted to be the authoritative source of outgoing transitions for the same source state (except explicitly allowed exceptions for removal). Ensure task identity (ID, service, and placement slot) is immutable across updates to the same logical task. Model concurrent operation of components and arbitrary interleaving of their actions on the shared set of tasks. Key correctness properties to verify: safety (tasks never change identity; only allowed state transitions occur; no two components overlap in responsibility for the same source state), invariants about types and allowed placements, and progress (tasks created eventually reach terminal states or are removed; no deadlock where tasks are permanently stuck in intermediate states unless explicitly allowed).
