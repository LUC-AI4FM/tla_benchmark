Specify a simple transition system with two state components that initially are equal to a particular value. The system must allow stuttering (no-change) transitions and also permit a set of candidate assignments to one component that are independent of the other. The model should capture the notion of an action being enabled: whether a proposed next-state relation can be taken from the current state. Include the ability to test enabledness of both concrete assignment proposals (e.g., assign a specific constant) and parametric proposals (e.g., assign any value from a small finite range), as well as composed proposals that combine relations on both components.

The specification must express and check a collection of boolean invariants about enabledness: examples include that some impossible next-state relations are not enabled, that certain syntactically ill-typed relations are not enabled, that predicates on current-state values (not involving a next-state) can be treated as enabled or not, and that enabledness of a conjunction with the system's transition relation behaves as expected. It must also allow creating a parameterized helper that encapsulates an assignment relation and using it in these enabledness checks, including testing enabledness when the helper parameter is a constant, a local binding, or the other state component.

The correctness properties are purely safety/assertion style: every enabledness check asserted to hold must indeed be true in the initial state and preserved by the transition relation; every enabledness check asserted not to hold must be false in the initial state and remain false unless a valid transition enables it. The spec should make these properties explicit so a model checker can verify each enabledness assertion.
