Specify a system that models a simple imperative state machine with two integer state components. The system starts with a constrained initial state for each component and then evolves by repeatedly executing one of several atomic transition kinds. The model should allow transitions that (a) update one component while leaving the other unchanged, (b) update both components, and (c) leave components unchanged subject to guards. Some transitions should be enabled only when numeric conditions hold, and some should be disabled by guards so they are unreachable. The specification must permit expressing both concrete updates (assign specific numeric expressions) and identity/unchanged effects on chosen state components. It must also support grouping components together to express multi-variable unchanged constraints, and allow constraints on the overall execution (for example a bound on one component across all reachable states).

Formally state the initial conditions, the set of next-state alternatives, and a temporal safety property requiring that every step conforms to one of those alternatives. Specify key correctness properties to verify: (1) invariants that certain numeric bounds always hold, (2) that some unreachable guarded transitions are indeed never taken, and (3) that "unchanged" claims correctly mean no change to the intended components (including when components are referenced individually or as a tuple). Additionally, require that the model permit checking coverage of transitions and of specific variable occurrences without prescribing how transitions are implemented.
