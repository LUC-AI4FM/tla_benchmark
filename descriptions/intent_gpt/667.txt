Model a system that manages finite sets of opaque elements and supports operations to build, query, and compare those sets while ensuring safety and consistency. The specification should capture creation of finite sets, insertion of elements, deletion of elements, and membership queries. It must allow multiple concurrently issued operations and specify how conflicting operations are resolved so that sets remain finite and well-formed (no duplicates, elements drawn from a defined universe). The model should express elementary set operators: union, intersection, difference, subset and equality checks, and should show that these operators behave as expected with respect to membership and cardinality.

Specify invariants ensuring that every set in the system is finite, that membership tests reflect the history of successful insertions and deletions, and that set equality and subset relations are consistent with element membership. Specify liveness properties guaranteeing that operations terminate (or complete) under fair scheduling and that eventual consistency is achieved for concurrent updates (e.g., once no new conflicting updates occur, all observers agree on set contents).

Include correctness properties for derived operations (cardinality, empty set detection) and for composite operations such as forming unions of several sets. Allow modeling of a bounded universe of elements and of repeated operations to exercise edge cases (empty sets, full sets, repeated inserts).
