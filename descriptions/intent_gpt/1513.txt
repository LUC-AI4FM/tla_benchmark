Model a token-passing distributed termination-detection protocol for a fixed ring of three processes. The system continuously executes until it reaches a global quiescent state and must detect termination using a circulating token with an associated color bit. Each process can be either active (has outstanding work) or passive (no work). Each process also maintains a local color bit. A single token circulates around the ring and carries its own color bit. The protocol must allow processes to generate and process local work, change local activity and color, and forward the token to the next process; it must ensure the token always resides at exactly one process at a time.

Specify safety properties:
- The token is always at a valid process and its color is always one of the allowed colors.
- No two tokens ever exist concurrently.
- Local states (activity and local color) remain within their allowed domains.

Specify liveness and correctness properties for termination detection:
- If all processes become passive and there is no pending work, the system eventually reaches a configuration in which the token has made a full cycle marking global quiescence and the detector can declare termination.
- The detector must never declare termination while some process is active or while there is potential for new work to be generated.
- If processes repeatedly perform work, termination should not be declared incorrectly (no false positives).

Also require fairness assumptions needed for progress (e.g., eventual token delivery and scheduling fairness) and make termination detection invariant under arbitrary interleavings consistent with those fairness assumptions.
