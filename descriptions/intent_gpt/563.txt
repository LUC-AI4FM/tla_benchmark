Specify a model of a two-phase commit protocol coordinating one transaction manager and a set of resource managers. The system should allow resource managers to progress through the standard lifecycle states (working, prepared, committed, aborted) and allow the transaction manager to initiate and complete a global decision to commit or abort. The model must capture asynchronous, unordered message-passing between participants and permit failures and recoveries only as nondeterministic state changes (no built-in reliable broadcast). It should allow the transaction manager to collect prepare acknowledgements from a subset of resource managers, then decide to commit only if all resource managers that were asked to prepare have responded with "prepared"; otherwise it may decide to abort. Once the transaction manager decides, it must reliably communicate the global decision so that each resource manager eventually reaches the corresponding terminal state (committed or aborted). The specification must assert safety properties: no resource manager may commit unless the transaction manager has decided to commit, and no conflicting terminal states occur (no resource manager is simultaneously committed and aborted). It must also assert liveness properties under fair-message-delivery assumptions: if participants and messages are eventually delivered and processed fairly, then a global decision is eventually made and all non-failed resource managers reach that decision. Include an invariant stating that the set of resource managers known to be prepared by the transaction manager never includes a manager that is already aborted.
