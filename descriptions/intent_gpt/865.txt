Model a Software-Defined Perimeter (SDP) access-control system that separates a control plane (authentication) from a data plane (connection admission) and is resilient to common network attacks. The model should include clients (legitimate users), an SDP controller that verifies single-packet-authentication (SPA) messages, a firewall that enforces short-lived access rules on the data plane, a target service that accepts TCP connections, and an attacker capable of sniffing, replaying, spoofing SPA messages, and probing the service. Specify the expected interactions at a high level: clients perform SPA to request access to a hidden service; the controller validates SPA messages (checking freshness, client credentials, integrity) and, on success, instructs the firewall to open a narrow, time- and 5-tuple-scoped data-plane admission rule that permits the client’s subsequent TCP handshake; the firewall enforces rules and logs dropped packets; the attacker can observe messages on network interfaces and may inject forged SPA or TCP packets and attempt to reuse or spoof captured credentials.

Formalize correctness properties including:
- Authorization soundness: only clients with a valid, non-replayed SPA should be able to complete a TCP handshake to the target service.
- Replay/spoof detection: the controller must detect and reject SPA messages that replay a prior Tstamp or that fail integrity/credential checks, and such incidents must be logged.
- Minimal exposure: firewall rules created by the controller must admit only the specific flow (addresses/ports) authorized by the SPA and must prevent unrelated attacker-initiated flows from being accepted.
- Non-bypassability: an attacker who only observes traffic (and cannot break cryptography) must not be able to gain data-plane access unless a valid SPA corresponding to that data flow was accepted by the controller or the attacker can legitimately impersonate credentials.
- Auditability: all authentication decisions, detected attacks, and created/expired firewall rules are recorded for inspection.

Allow modeling of NAT/shared-IP scenarios, per-session freshness counters, symmetric cryptographic primitives abstractly (with perfect secrecy except for modeled reuse), and nondeterministic network delivery (capture/sniff/inject) so attacks can be explored.
