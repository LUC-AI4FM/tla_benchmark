Model a binary search algorithm that, given an ordered sequence of integers and a search key, repeatedly narrows a bounded index interval until it determines whether the key exists in the sequence and where. The model should accept as parameters any finite sequence of integers and any integer search key; it must not assume particular lengths or specific elements. The algorithm must operate on integer indices into the sequence, maintain a lower and upper index bound that always remain within valid index range for the sequence, and update those bounds according to comparisons of the key with the element at a chosen middle index. The system should terminate either when the key is found (returning an index where the sequence element equals the key) or when the search interval is empty (returning a distinguished "not found" value). The specification must guarantee:

- Safety: bounds never go out of range; comparisons only access valid indices; any returned index, when not the "not found" value, points to an element equal to the key.
- Progress/Termination: the algorithm makes progress on each iteration (the search interval strictly decreases) and always reaches a termination state in a finite number of steps for any finite input sequence.
- Correctness w.r.t. ordered input: if the input sequence is nondecreasing, then the algorithm returns "found" iff the key occurs in the sequence; when multiple equal elements exist, the result may be any index of an occurrence but must reference an actual occurrence.
- Robustness: behavior is defined for arbitrary integer keys and sequences (including empty sequence), and the "not found" return distinguishes absence from any valid index.

Do not prescribe exact code structure; focus on the state, allowed transitions, invariants, and the termination and correctness properties above.
