Specify a TLA+ model of Dijkstra’s ring-based distributed termination detection algorithm for N processes arranged in a directed logical ring. The model should capture: processes that may be active or passive; processes that can become active by receiving a message from another process; point-to-point message sends that can be directed either in the ring’s forward or backward sense (with sending backward being considered “against” the token direction); a circulating single token that is passed around the ring in a fixed direction; and a two-valued coloring scheme (white/black) for both processes and the token used to detect nontermination.

Require that the model permit arbitrary asynchronous interleaving of local computation (processes sending messages and becoming passive) and token-passing steps, with the token moved only when the owner process is allowed by the algorithm’s rules to hand it on. When a process activates another process in the direction opposite the token flow it must mark itself black; when a black process holds the token the token becomes black on passing; processes that pass the token become white. The model should allow any initially typed state and permit repeated probes (token circulations).

Specify and prove the following correctness properties:
- Safety (no false termination): The algorithm must never declare termination (token returns to a designated initiator in a white state with all processes passive) while there exists an outstanding message or any process that can still become active.
- Liveness (detection): If the system truly becomes quiescent (all processes passive and no in-transit messages), then eventually the algorithm will detect termination (the designated initiator will receive a white token and the protocol will stabilize).
- Invariant properties: the token color is black whenever any process can reach the initiator by a path containing an activation that was sent against the token direction and that activation has not been neutralized; and process colors are reset appropriately on passing the token.

Parametrize the model by N>0 and make no assumptions about timing beyond fairness for token-passing steps sufficient to ensure progress of the token.
