Model a distributed spanning-tree construction protocol running on a fixed set of processes with a distinguished root. The system maintains for each process a parent reference (which may be unset), a directed set of outstanding messages between ordered pairs of processes, and local information needed to propose parent assignments and send messages. The protocol must allow a process to send messages only when permitted by the protocol’s send predicate; messages are asynchronous and represented as pairs indicating sender and recipient. A process whose parent is not yet set must not be allowed to originate any outgoing message unless it is the root. When a process receives a message from another process, it may adopt that sender as its parent (if its parent is unset), and adoption must set the parent to a concrete process identifier (not to the sentinel meaning “no parent”). The model should permit actions that leave state unchanged, allow message sends that add a new ordered pair to the message set, and allow parent updates that modify only that process’s parent. Specify initial states, safety properties, and the state-transition relation at an abstract level (not implementation code).

Key correctness properties to guarantee:
- Safety: At all reachable states, every message in the message set was sent by either the root or by a process whose parent is already set (i.e., non-root processes with unset parents have sent no messages).
- Domain: The parent mapping is always defined for every process and any assigned parent is a valid process identifier (not the “no parent” sentinel when set).
- Inductiveness: The invariants above must be preserved by all protocol actions (sending, parent update, and stuttering/idle steps).

Also specify types and a precise state space so the invariants can be mechanically checked and proved.
