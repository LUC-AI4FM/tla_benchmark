Specify a concurrent bounded queue service accessed by a fixed set of clients, where each client repeatedly performs either a single-element enqueue attempt or a single-element dequeue attempt and then clears its local result. The queue has a fixed maximum capacity N and holds values drawn from a given value domain. Enqueue attempts by a client may choose any value from the value domain; an enqueue operation should either append the value at the tail or insert it at the head (both are allowed nondeterministically), and must indicate success or report that the queue was full. Dequeue attempts should remove and return either the head element or the tail element (nondeterministically) if the queue is nonempty, or report that the queue was empty. After each operation a client resets its local return indicator to a neutral state and may repeat. The model must enforce the capacity bound at all times.

Formalize this as a state machine suitable for TLA+: describe shared state (the queue), per-client observable return values, and the allowed transitions for each client’s operation and reset. Specify safety properties: the queue length never exceeds N; elements returned by dequeues are always elements previously enqueued and not already removed (no spurious values or duplication); and an enqueue that reports success actually places that value into the queue. Specify liveness properties: each client’s actions are weakly fair (no client is permanently disabled), and if a client persistently attempts an operation while the queue has available capacity (for enqueues) or contains elements (for dequeues), then eventually some such attempt succeeds. Do not prescribe an implementation strategy or scheduling policy beyond these constraints.
