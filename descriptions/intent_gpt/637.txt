Model a simplified Tendermint-style blockchain and light-client environment in which a set of validators produce a sequence of block headers with commits and validator set changes. The model must represent block heights, monotonically increasing timestamps, per-block validator sets, and the set of validators who committed the previous block. It must allow some validators to be faulty (a non-decreasing set of faulty nodes) and allow the light client to reason about which headers are trustworthy over a finite trusting period measured by a reference clock.

Specify how blocks are considered validly signed: a header may be produced by honest or faulty validators, and a header’s commit is a subset of validators that must represent more-than-two-thirds vote among that block’s validator set to be considered a valid commit. Require a parameterized bound on the allowed fraction of faulty validators in any validator set (given as an exclusive ratio a/b). The model must permit advancing time arbitrarily (subject to nondecreasing timestamps) and must enforce that each block’s timestamp increases but remains within the trusting period relative to the next block.

Express correctness properties for the light-client view: safety (if the light client accepts a header as trusted, then a supermajority of validators for that header were honest according to the faulty-set bound) and liveness (when enough honest validators exist and time permits, an honest header with a valid >2/3 commit will be available). Also state invariants: commits only come from current validators, validator-set transitions are reflected in headers, and the trusting-period condition correctly determines header freshness.
