Specify a family of concurrent user-session systems in which multiple independent users interact with a shared service through sessions. The model should capture an arbitrary but bounded set of user identities and allow parameterization by a small positive integer representing the number of user slots to exercise in particular scenarios. Each user may create, use, and terminate sessions; sessions provide isolation so that operations from different users do not interfere except through the shared service state. The system must support creating new sessions, performing operations within a session, and properly ending sessions, while enforcing that only one active session per user slot exists at a time.

Formally state safety and liveness goals: safety properties should assert that (1) operations attributed to one user never affect the session state visible to another user, (2) session identifiers are unique and not reused while active, and (3) resources allocated to a session are reclaimed on termination. Liveness requirements should ensure that a user who repeatedly attempts to start and use a session will eventually make progress (e.g., obtain a session and complete an operation) provided the system does not permanently block the user. Provide assertions verifying these properties for individual parameter values (for example for two and three user slots) and universally quantify over the small parameter to assert correctness for all chosen values in that range. Do not prescribe an implementation strategy; describe only the system behavior and the properties to be checked.
