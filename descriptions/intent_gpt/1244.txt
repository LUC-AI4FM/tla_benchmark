Specify a formal TLA+ model of the PlusCal-to-TLA+ translation toolchain's translation phase. The model should treat the input as an abstract syntax tree (AST) of a PlusCal algorithm (after parsing and macro expansion) and produce an output TLA+ specification representation or report well-formedness errors. The model must capture the full structure of legal PlusCal programs (uniprocess and multiprocess forms, procedures, processes, labeled statements, control constructs such as if/then/else, either, while, with, assignments, calls/returns, goto, assertions, prints, when, and variable declarations), and the rules that determine whether an AST is a valid PlusCal program. It must check label scoping and uniqueness, that gotos target legal labels in the same context, and that constructs that prohibit labels or final statements do not contain them.

Model the translation semantics at the level of structural transformation: given a validated AST, produce the corresponding abstract TLA+ specification (as a structured value) or an explicit error value when translation is impossible. The TLA+ output should include process encodings, program counters, initial state construction, next-state relations for each atomic step, procedure call/return semantics, and fairness constraints as specified by the algorithm metadata. Specify invariants and correctness properties the translator must guarantee: (1) syntactic preservation—every reachable control point in the source maps to a distinct program-counter state in the output; (2) semantic fidelity—every atomic step allowed by the source semantics corresponds to a next-state transition in the generated TLA+ relation, and no spurious transitions are introduced; (3) label and control-flow soundness—gotos, calls, returns, and procedure boundaries are faithfully represented; and (4) error detection—malformed ASTs or illegal label/goto usages are detected and reported.
