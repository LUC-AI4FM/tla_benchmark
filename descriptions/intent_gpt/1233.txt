Specify a parameterized module that models a shared integer state updated by an external component instance. The system should consist of a main integer state that must always remain within a fixed finite range (for example 0..4). The main system may instantiate a separate reusable component twice: once without parameterization and once with the component’s local parameter bound to the main state. The separate component exposes a behavior specification (a set of allowed state transitions and initial condition) that the main system reuses by instantiation; the main system should import and rely on that external component’s specification in two ways: directly referencing the imported specification and referencing a version of it that has been instantiated with the main state as the component’s parameter.

Model the allowed transitions so that the composed system cannot violate the main-state range invariant under any legal interaction with the instantiated component. The correctness properties are: (1) Safety: the main integer always stays within the prescribed finite range. (2) Compositional consistency: behavior obtained by directly importing the component’s specification must be consistent with behavior obtained from the parameterized instance where the component’s formal parameter is bound to the main state. (3) The model should support checking that the invariant is preserved for all reachable states and both imported/instantiated component usages. Provide initial conditions, transition relation, and the invariants to be checked; do not commit to a particular internal implementation of the component—treat it as a black-box specification that can be instantiated.
