Model a CSV write-and-read verification scenario for a system that serializes structured in-memory records to a file and then reads them back to confirm correct persistence. The model should express writing a single composite value that contains multiple primitive and composite fields (for example: a number, a string, and a map/dictionary) to a CSV file using a given textual template and separator, and then reading back the file to validate that the persisted representation matches expected string-encoded forms of the original fields. The specification should capture operations to (1) construct the output filename deterministically (including a timestamp or other unique suffix), (2) serialize the value according to a format template and chosen separator, (3) write the serialized record as one CSV row to the filesystem, and (4) read the file and parse records using the same separator. Correctness properties to guarantee: exactly one record is present after the write; each column read back equals the expected text encoding of the corresponding original field (e.g., numbers become their decimal string, strings are quoted appropriately, and composite/map values are rendered as their canonical textual representation); and reading a non-existent filename yields zero records. The model should abstract external I/O where needed but preserve the observable behavior required for these checks.
