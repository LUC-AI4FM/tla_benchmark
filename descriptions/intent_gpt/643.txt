Specify a TLA+ model of a fault-tolerant light-client protocol that fetches and verifies compact block headers (light blocks) from a set of validators to advance its trusted chain head. The model should represent a collection of validators, some of which may be Byzantine, and a single light client that periodically queries validators for headers at increasing heights. The system must capture clock drift and message delay uncertainties and allow the client to use timeout and retry logic when responses are missing or conflicting.

The model must enforce that the client only accepts a header as verified when it can cryptographically validate signatures or quorum certificates consistent with the expected validator set and fault threshold. It must guarantee safety: the client never finalizes a header that contradicts a previously verified header (no equivocation-induced rollback). It must guarantee liveness under the assumed fault ratio and timing bounds: if a sufficient number of correct validators respond within trusted timing parameters, the client eventually verifies the target height. The specification should also express monitoring properties: the client records probes, fetch attempts, and produces an explicit verdict when progress stalls or suspected equivocation is detected. Abstract away implementation details like specific message formats, but include parameters for trusted period, trust margin, clock drift bounds, and faulty-fraction bounds.
