Specify a distributed system that manages a single-phase session between a client and a server where the server assigns a unique, incrementing session identifier when the client requests a new session. The model should capture the following behavior and correctness requirements:

- The system must accept a request from a client to start a session and produce a server-assigned session id that is strictly greater than all previously assigned ids.
- The server must never reuse an id once it has been assigned, even across client crashes and restarts.
- The client must be able to learn the session id returned by the server and may perform further operations that refer to that id; those operations must be accepted only if the id was previously issued.
- The protocol must tolerate message loss and reordering: requests and responses may be lost or delayed, but eventual progress should hold under weak reliability assumptions (e.g., if messages between a correct client and a correct server are eventually delivered, the client will eventually obtain a session id).
- Safety properties: session ids are unique and monotonic (no two clients observe the same id as newly issued; each newly issued id is larger than all earlier issued ids), and the server's internal counter does not decrease.
- Liveness properties: a non-faulty client will eventually receive a session id when communicating with a non-faulty server and messages are eventually delivered.

Model the system components, their state spaces, communication channels with possible loss/reordering, failures (crash and recovery) of client and server, and the fairness assumptions necessary to express liveness. Do not prescribe a particular implementation; leave room for different request/response mechanisms that satisfy these properties.
