Model a shared register file abstraction accessed by multiple concurrent clients. The system exposes a fixed set of named registers indexed by logical register identifiers and a fixed set of client processes. Each client may issue read or write requests targeted at a specific register and carrying a value. The register file must also allow registers to be marked as free/unused. Specify the types and allowed request forms, and require that the register file always maps each process to a full mapping from register identifiers to one of: a read request, a write request, or a free marker for that register.

Specify the allowed behaviors for operations that update the register file in response to client actions: issuing a read request, issuing a write request, and clearing or marking a register free. Ensure that clients can only produce well-formed requests and cannot create values or addresses outside the declared domains. Require that any update preserves the structural invariant that every process has an entry for every register and the entry is always one of the allowed request forms.

State safety properties: the register file must never contain malformed entries, and every transition must maintain the type invariant. State liveness goals: every valid client request should eventually be reflected in the register file (no permanent loss), and free markers can be re-used after a bounded time.
