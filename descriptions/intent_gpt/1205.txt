Specify a formal model of a specification-language parser and checker that handles constructs commonly found in a theorem-proving/specification language. The model should represent sequences of top-level declarations (definitions, theorems, lemmas, axioms, instances, modules, and proof blocks) and the scoping rules, name resolution, and syntactic categories those declarations create. It must capture the following requirements:

- Declarations can introduce identifiers of many reserved-word-like syntactic forms; the model must permit using any token as a record/field name or user identifier where the language permits, but still enforce contexts where certain tokens are reserved (for example, keyword positions that cannot be re-used as declarations).
- Proof blocks may contain nested proof constructs (ASSUME, PROVE, TAKE, HAVE, QED, BY, USE, DEFINE, WITNESS, PICK, SUFFICES, CASE, TAKE, WITH, INSTANCE, OBVIOUS, OMITTED, etc.). Model the nesting, allowed sequences, and termination of a proof block, including that QED closes an open proof and that proofs can be declared trivial/obvious.
- Instances and module import/extend semantics: instantiating a module with renaming or parameter substitution must produce accessible names consistent with import rules; hiding or exposing names must be representable.
- Define correctness properties: (1) well-formedness — every sequence of declarations and proof steps must respect syntactic and scoping rules; (2) no name capture — identifiers introduced in nested scopes do not shadow or leak incorrectly into unrelated scopes; (3) termination/consistency of proof closure — every opened proof must eventually be closed by a matching QED (or accepted trivial closing) unless it is explicitly marked omitted; (4) instance consistency — names referred from an instance must resolve to definitions provided by the instantiated module under the given renaming; (5) reserved-keyword safety — tokens used as identifiers only appear where permitted by the language grammar.

Do not encode a concrete parser; model only the abstract syntactic categories, scope rules, and name-resolution constraints and specify invariants that must always hold for any valid sequence of declarations and proofs.
