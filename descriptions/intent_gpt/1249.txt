Specify a formal TLA+ model of a JSON serialization library that converts between an internal typed data model and textual JSON representations, and of its newline-delimited variant. The model should treat values as compositions of scalar values, finite sequences (ordered tuples/arrays), and records/maps (unordered key → value mappings). It must capture both serialization (value → string) and deserialization (string → value) as abstract operations, without prescribing algorithmic details such as recursion order or particular string construction steps.

Requirements:
- Serialization must produce valid JSON strings: arrays for sequences, objects for records, and appropriate representations for scalars. Empty sequences/records must serialize to "[]" and "{}", respectively.
- Deserialization must be the inverse of serialization up to the representation equivalence: deserializing a serialized value must produce a value equivalent to the original (preserving nesting, sequence order, and record key/value associations). For records, treat key ordering as irrelevant.
- For newline-delimited JSON (NDJSON), the library must support serializing a sequence of top-level values separated by newline characters and deserializing a stream of newline-separated JSON values into a sequence of values; the round-trip property must hold per value and for the sequence as a whole.
- The model must specify preconditions and error conditions: ill-formed JSON input should be rejected (modeled as a special error outcome), and attempting to deserialize NDJSON with missing/newline errors should produce an error outcome.
- Specify invariants: serialization never changes the abstract value set or multiplicity of elements; deserialization results are well-typed values (scalars, sequences, records) and preserve cardinalities for finite collections.
- Specify properties to check: round-trip correctness, idempotence of serializing already serialized strings is not required, and order-independence for record keys must be enforced.
