Specify a model of a distributed termination-detection protocol for a fixed-size ring of processes that execute asynchronous work and communicate via point-to-point messages. The model should capture that each process can be either active or inactive, can hold local messages pending delivery, and may send or receive messages that generate further work. Processes may spontaneously become inactive, and messages may be delivered nondeterministically. The protocol must allow a process (an initiator) to periodically start a probe consisting of a circulating token that collects information about activity and outstanding messages to decide global termination.

Require the model to support a family of independent optional protocol features that alter token-handling and initiation rules: (a) allowing an active holder of the token to pass it under certain taint conditions (token or holder marked), (b) allowing early abort of a token round by returning the token immediately to the initiator when a holder is marked, (c) allowing early abort when the token itself is marked, and (d) allowing the initiator to start a probe only when it is inactive. These options must be parameterizable so experiments can enable any subset.

The specification must define termination as every process inactive with no pending messages, and termination-detection as the initiator concluding termination via a successful probe. Key correctness properties: safety — the initiator must never detect termination unless the system is actually terminated; liveness — if the system becomes quiescent, some probe eventually detects termination (assuming random scheduling); and preservation of message-count invariants ensuring the token correctly accounts for outstanding messages so detection is reliable. The model should permit statistical experimentation (randomized scheduling and initial states) to measure how feature choices affect time and number of probes until detection.
