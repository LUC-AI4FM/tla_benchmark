Specify a formal TLA+ model of a distributed voting phase used to choose a single value among multiple proposers (values) by a fixed set of acceptors organized into intersecting quorums. The model should describe acceptors that can repeatedly perform two kinds of local steps: promise to not accept ballots below a given ballot number (raising a local max-ballot), and cast a vote for a value at a ballot number provided certain safety and local conditions hold. Ballots are totally ordered nonnegative integers and quorums are sets of acceptors with the property that any two quorums intersect and every quorum is nonempty.

The model must capture:
- The per-acceptor state recording which (ballot,value) pairs that acceptor has voted for and the acceptor’s current maximum promised ballot.
- The preconditions under which an acceptor may raise its max-ballot or record a vote at a ballot.
- A recursive notion of safety for a (ballot, value) pair: a value is safe at a ballot when either the ballot is the base ballot (0) or there exists a quorum whose acceptors have promised at least that ballot and such that for some earlier ballot (or none) all votes in that quorum at that earlier ballot agree on the same value and no acceptor in the quorum voted in any ballots between that earlier ballot and the ballot in question.
- Liveness assumptions that ensure progress (weak fairness for acceptor actions and a boundedness condition on future ballot attempts).

State the key correctness properties to prove:
- Type invariants for the recorded votes and max-ballot values.
- Safety: at most one value can ever become chosen (i.e., there is never two different values each chosen by some quorum at possibly different ballots).
- Preservation: the safety invariant is inductive under allowed actions.
- If a quorum has all acceptors with promised ballots >= b, then some value is safe at b (existence of a safe value given quorum promises).
- The voting algorithm refines a higher-level consensus specification: any value the algorithm deems chosen satisfies the consensus abstraction’s chosen predicate.

Do not prescribe specific variable names or algorithmic code; specify only the state abstractions, allowed atomic steps, the recursive safety definition, quorum assumptions, and the invariants and liveness properties to be proven.
