Specify a formal model of a parameterized module instantiation mechanism interacting with nested modules, where an outer configuration supplies a value to an inner component. The system should represent two modules: an outer supervisor that initializes and maintains a global state variable with a fixed value, and an inner component that refers to the outer-provided value and exposes an expression that syntactically inspects the next-state of that provided value (i.e., reads the primed form of the parameter). The specification must capture a standard synchronous transition semantics where the outer module does not change its state across steps, while the inner component’s expression is evaluated within the same transition relation.

Require the model to guarantee that:
- The outer state is initialized to a specific constant and remains invariant across all transitions.
- Instantiation correctly binds the outer state into the inner component so that expressions in the inner component reflect the outer binding.
- An invariant property must be checkable that asserts the enabledness or truth of a predicate involving the inner component’s expression (specifically, that the expression comparing the inner primed reference to some constant evaluates to false or to a well-defined Boolean).
- The model should allow inspection of TLC’s internal action naming / counting behavior for stuttering and named actions so tests can observe the number of occurrences of specific action names produced during model exploration.

Do not prescribe implementation details such as variable names, operator names, or the exact action decomposition; focus on the required semantics, initialization, invariants, and observability requirements.
