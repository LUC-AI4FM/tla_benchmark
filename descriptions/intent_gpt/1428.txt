Specify a formal model of a JSON serialization and deserialization facility and its validation harness. The model should describe functions that convert values from the specification's native data structures (booleans, integers, strings, tuples/arrays, ordered sequences, sets, functions/records, nested combinations) into JSON text and back, and a pair of file-based APIs: one that serializes a sequence of JSON values as newline-delimited JSON (NDJSON) and one that serializes a single JSON array or object. The system must reject invalid inputs (for example, attempting to serialize a bare set or a non-sequence where a sequence is required) with well-defined error messages.

The specification must require:
- Deterministic, well-defined textual representations for all supported primitive and composite values (including canonical ordering for sets when represented as arrays, consistent key ordering for objects when needed for tests).
- Lossless round-trip for every supported value that can be represented in JSON: serializing then deserializing such a value must yield an equal value.
- Correct behavior for NDJSON operations: sequences serialized as newline-delimited JSON must be deserializable back to the same sequence of values, and file-based read/write must preserve element order and content.
- Validation tests that assert expected serialized strings for a variety of inputs (empty collections, primitives, nested structures, cross-products), and tests that check both successful round-trips and expected error reports for invalid inputs.

Do not prescribe internal representations or implementation details; specify only the observable input/output behavior, error conditions, and the correctness properties above.
