Model a system that uses a small, fixed collection of abstract, uninterpreted model values (opaque tokens) and reasons about their identity, distinctness, and string representations. The model should initialize a set containing exactly three distinct abstract tokens and then keep that set unchanged. It must treat tokens as atomic, non-comparable except for equality/inequality, and ensure that token equality behaves as true identity: the same token equals itself and different tokens are unequal. The system must also associate each token with a deterministic, printable string representation and guarantee that the string representation for a token is nonempty and stable.

Specify the following correctness properties to verify:
- The set always has cardinality three and contains the three intended distinct tokens.
- Each named token equals itself, and any two differently named tokens are unequal.
- The string representation function maps each token to a consistent, nonempty string, and different tokens may have distinct string representations.
- Attempts to compare tokens of different underlying types (if the model supports typed tokens) should be detectable as type errors; the specification should capture expected error behavior for such illegal comparisons.

Do not constrain how tokens are implemented beyond these observable properties; the goal is to verify identity, distinctness, immutability of the set, and stable, nonempty string naming of tokens.
