Model a replicated multi-slot consensus protocol (Multi-Paxos style) for a fixed set of replicas, a fixed set of slots (sequence positions), and a fixed set of values. The model should capture the interaction between proposers/replicas that prepare and accept proposals and learners that may learn values for each slot. It must allow replicas to propose any value from their per-slot proposal sets and to exchange messages for Prepare, PrepareReply (including information about previously voted proposals), Accept, and AcceptReply. The system should permit concurrent proposals and multiple rounds/ballots per slot, including ballots that may be superseded, but must ensure the usual safety and liveness expectations below.

Specify the following correctness requirements:
- Nontriviality: any value that becomes learned for a slot must have been proposed for that slot.
- Stability: once a value is learned for a given slot it remains learned for that slot thereafter (learned sets are monotonic).
- Consistency (Agreement): at most one distinct value can be learned for any given slot (learners never decide two different values for the same slot).
- Validity of replies: prepare replies must faithfully report prior accepted/voted proposals from the responder.
- Message and state typing invariants: all messages and local state components conform to declared domains (ballot numbers, slot indices, value sets, statuses).

Do not prescribe a particular implementation detail; allow the specification to include arbitrary reliable message passing (message loss acceptable if specified), persistent local state for ballots and accepted votes, and nondeterministic scheduling of actions and message delivery.
