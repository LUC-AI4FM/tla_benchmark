Model a concurrent transactional key-value store that supports optimistic transactions with commit timestamps and primary-key-based coordination. The system has multiple clients executing transactions concurrently against a single table of keys. Each transaction reads and writes keys, selects one of its written keys as a designated primary, and must obtain a commit timestamp for the transaction such that serializability is preserved.

Specify the protocol for committing a transaction: a client proposing a commit must validate that its read-set has not been invalidated by later commits, coordinate with the primary key owner to obtain a commit timestamp, and apply its writes atomically at that timestamp. The protocol must allow non-primary participants to prepare and later accept the commit when the primary assigns the timestamp. Support concurrent commits and ensure that timestamps are strictly increasing and comparable across transactions.

State safety properties: (1) Serializability — the visible outcome of committed transactions must be equivalent to some serial order consistent with commit timestamps. (2) Atomicity of commit — either all writes of a committed transaction become visible at its commit timestamp or none do. (3) No lost updates — if two transactions write the same key, their commit timestamps determine a total order that reflects the final value. (4) Read consistency — a transaction reads values consistent with some prefix of committed transactions up to its commit timestamp. Also specify liveness assumptions: progress under fair scheduling and absence of permanent failures of the primary for a transaction should yield eventual commit or abort.
