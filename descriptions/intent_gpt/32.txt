Specify a distributed key-value store that supports concurrent clients performing read and write operations on keys. The system must accept client requests to read the current value of a key or to write a new value, and it must ensure that every completed read returns a value consistent with a linearizable history of completed writes. Model an arbitrary number of clients and a set of replica servers that together implement the service; clients send requests and await replies, and servers may communicate to replicate updates. The system must tolerate message reordering, duplication, loss, and arbitrary asynchronous delivery delays, but not server Byzantine failures. Servers may crash and later recover with access to persistent stable storage. Recovery must preserve any writes that were acknowledged before the crash. Specifications should permit concurrent, overlapping operations from multiple clients and must ensure that once a write is acknowledged to a client, there exists a total order of acknowledged writes consistent with real-time ordering such that subsequent reads reflect that order.

State safety properties: linearizability of reads and writes (each read returns the value of the most recent write in the total order), write durability across crashes after acknowledgement, and absence of lost updates. State liveness goals: if a majority (or configured quorum) of non-crashed servers are responsive and messages between them eventually arrive, then every client request will eventually complete. Include invariants describing preserved server state and the quorum condition required for progress.
