Specify a simple hour clock system that models a clock limited to a fixed 12-hour cycle and an external increment source. The model should capture an integer-valued hour that always remains within the allowed range 1..12 (or 0..11 if that convention is chosen) and a single external event that advances the hour by one. The system must permit repeated increments and wrap the hour value correctly when the maximum is reached (i.e., incrementing past the maximum produces the minimum). The model must also allow stuttering steps that do not change the hour. Specify the initial condition, the allowed state transitions, and a fairness/assumption about the increment event (for example, it may occur repeatedly but is not required to occur at every step). Require the following correctness properties: (1) invariant: the hour value is always in the allowed cyclic range, (2) functional correctness of wrap-around on increment, and (3) liveness: if increments occur infinitely often, then the hour will visit every value of the cycle infinitely often (i.e., the clock is recurrent). Express these as safety and liveness properties suitable for model checking.
