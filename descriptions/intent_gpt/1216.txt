Specify a simple discrete-state transition system with two integer state components, one intended to represent a counter and one an auxiliary value. The system starts in a specific initial state (counter = 1, auxiliary = 3). At each step the system may either increment the counter by one while leaving the auxiliary unchanged, or stutter (leave both components unchanged). Model nondeterministic choice among several incrementing transitions so that different orchestration conditions can be evaluated on the relationship between the old and new counter values and on expressions built from them.

Require the model to support evaluating predicates and expressions about pre- and post-state values, including: plain expressions of the old state, expressions of the primed (new) state, and expressions where the primed operator is applied to a subexpression. The model must allow local (let-like) definitions that can refer to the current state and must support checking whether such definitions hold in the pre- or post-state.

State the correctness properties to be checked:
- All transitions preserve the auxiliary value unless explicitly allowed to change.
- Every enabled increment transition produces the counter value expected by the increment operation (counter' = counter + 1).
- Logical assertions about combinations of old- and new-state expressions must be verifiable (e.g., that evaluating a predicate on the pre-state versus the post-state yields the intended truth value).
- No specification confusion between pre- and post-state variable references should occur: expressions intended to refer to the primed state must be evaluated against the post-state, and those intended to refer to the unprimed state must be evaluated against the pre-state.
- The system must allow stuttering steps and still satisfy an invariant that the auxiliary remains 3.

Request that counterexamples be produced when any assertion fails, and that the model be amenable to model checking of the listed properties.
