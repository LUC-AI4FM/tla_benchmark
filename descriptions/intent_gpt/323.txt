Specify a concurrent protocol that manages a fixed set of participants cooperating to decide and commit a sequence of numbered proposals (log entries). Model the system at the level of roles and messages, not at the level of sockets or threads. The model should capture processes that can propose values for a given sequence index, exchange messages to learn about prior proposals, and reach agreement on a single value per sequence index despite failures and message reordering or duplication.

Require that for each sequence index the protocol guarantees:
- Safety: At most one value is chosen for that index (agreement/consensus), and once a value is chosen it is immutable (consistency).
- Integrity: Only values proposed by participants may be chosen, and a chosen value must have been proposed previously.
- Persistence: Once a value is chosen for an index, all non-faulty participants eventually learn that value (liveness under eventual synchrony assumptions).

Allow participants to fail by stopping and to recover with their local state preserved or lost as separate scenarios. Model network as asynchronous with possible message loss, duplication, and reordering. Specify invariants for quorums required to ensure safety, and properties that under eventual reliable delivery and a stable leader, the protocol makes progress (decides new indices).
