Specify a system that models the declaration and use of a type alias mechanism in a specification language and the compatibility behavior of an older, deprecated alias syntax. The model should represent two modes of the language: the current, preferred alias syntax and the legacy, deprecated alias syntax. It must allow declarations written in either syntax form, record whether a declaration is accepted, and produce a warning when a deprecated form is encountered. The system should permit later references to an aliased type to resolve correctly regardless of which syntax was used to declare the alias, preserving semantic equivalence between the two forms. It must also model how the environment handles multiple aliases with distinct names, rejection of conflicting redefinitions, and the scoping rules for aliases (local versus global visibility). Correctness properties to verify include: (1) soundness — every resolved alias refers to a well-defined type; (2) compatibility — legacy-syntax aliases are treated as equivalent to modern-syntax aliases for resolution purposes; (3) warning emission — a warning is produced whenever a legacy syntax alias is declared, but warnings do not prevent alias resolution; (4) conflict detection — attempts to declare two different meanings for the same alias name are detected and rejected; and (5) scope enforcement — alias visibility follows the modeled scoping rules. The model should be abstract about actual type contents (uninterpreted types) and focus on alias management and correctness guarantees.
