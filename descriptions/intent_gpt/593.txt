Specify a formal model of a distributed multi-version key-value store that supports transactions with both optimistic and pessimistic concurrency control (Percolator/TiKV-style). The model should represent clients that start transactions, read snapshots, acquire pessimistic locks, prewrite primary and secondary keys, and commit or abort. It must capture a global increasing timestamp oracle used for start_ts, for_update_ts and commit_ts, and model durable per-key state: versioned writes, locks (primary/secondary, optimistic/pessimistic, with optional min-commit-ts), and rollback records. Messages between clients and servers should be abstracted so safety properties about what the server may respond are expressible without requiring liveness of message delivery.

The model must ensure snapshot isolation semantics for optimistic reads and correct behavior for pessimistic reads (reads that observe a for_update_ts), including non-blocking reads when allowed by lock types. It must enforce that commits produce commit records with monotonic timestamps, that prewrites install locks and tentative versions, and that rollbacks and cleanup of stale locks preserve invariants (e.g., rollbacks may be “protected” for certain pessimistic primaries). Key safety properties to verify: no transaction can both commit and be observed aborted; committed versions are visible to reads with commit_ts ≤ read_ts; locks prevent write conflicts appropriately; commit ordering respects min_commit_ts constraints; and the server never reports a successful commit while also recording an abort for the same start_ts. The specification should allow modeling duplicate or lost requests but focus on safety (no inconsistent visibility or double outcomes) rather than progress.
