Specify a concurrent resource allocator for a fixed finite set of clients and a fixed finite set of resources. The system should manage which resources are currently available and which subsets of resources are allocated to each client. Clients may issue three kinds of operations: request a subset of resources, receive an allocation of some subset (only from currently available resources), and return a subset of resources they hold. The allocator must ensure that allocations only assign resources that are available at the time of allocation, and that when a client receives resources those resources are removed from the available pool until returned. Returning resources must put them back into the available pool.

Model the system as an asynchronous discrete transition system where at each step one client may perform one of the operations; the model should allow arbitrary interleavings but enforce that operations respect set membership (clients and resources) and that only legal allocations are performed.

Specify and prove the following safety properties:

- Type invariants: the state always respects domain and range typing (e.g., available is a subset of resources; every client's held set is a subset of resources; allocations are tracked for all clients).

- Mutual exclusion of resources: at all times, the sets of resources held by distinct clients are pairwise disjoint (no resource is simultaneously held by two clients).

Also require that the allocation operation preserves the mutual-exclusion invariant (i.e., allocations are drawn only from currently available resources so they cannot create overlaps). Do not require liveness properties.
