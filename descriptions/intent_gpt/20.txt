Specify a concurrent message-passing system in which components produce and consume two kinds of messages: integer messages carrying a numeric value from a fixed small domain, and string messages carrying a value from a fixed small string domain. The model should allow any number of messages of either kind to exist in an unbounded multiset-like mailbox (a set of message values is acceptable, but the model must reflect that messages are individually present and removable). Producers nondeterministically emit integer messages with any allowed integer value and string messages with any allowed string value. Consumers nondeterministically pick a message of the appropriate kind from the mailbox and remove it.

The model must record whether a consumer has ever observed a specific sentinel integer value (e.g., a particular integer) and whether a consumer has ever observed a specific sentinel string value (e.g., a particular string). Observations are recorded only when a consumer removes a message and sees that message’s payload equals the sentinel; producing messages must not directly change these observation flags.

Specify an initial state with an empty mailbox and both observation flags false. Allow behaviors where producers and consumers interleave arbitrarily. Require an invariant that every mailbox element is well-formed (either an integer message with an allowed integer payload or a string message with an allowed string payload). Require safety properties stating that once an observation flag becomes true it remains true, and liveness properties ensuring that if producers keep adding messages of a kind, consumers are eventually able to remove and inspect such messages (i.e., no permanent starvation).
