Specify a formal model of a library of finite sequences and related combinatorial operations over discrete elements. The model should treat sequences as indexed finite ordered collections (including the empty sequence) and sets and bags (multisets) of elements. It must provide operations to: convert between sequences, sets, and bags (removing duplicates, counting multiplicities, producing some ordering or all orderings); construct subsequences, prefixes, suffixes, and all subsequences; index and locate first/last occurrences and first occurrences of subsequences; insert, remove, replace, and replace-all occurrences of single elements or subsequences (with a clearly defined deterministic disambiguation rule for overlapping replacements, e.g., prefer leftmost nonoverlapping matches); reverse, concatenate, flatten, zip, interleave, and compute k-permutations, tuples, and all bounded-length sequences; compute fold reductions (left, right, and unordered fold when the operator is commutative/associative); and basic utilities (length, front/last, cons/snoc, select index by predicate, prefixes set, longest common prefix). The model must ensure total, well-defined behavior for all inputs (including empty sequences, empty patterns, and elements not present), preserve correctness relationships between representations (e.g., converting a sequence to a set then back yields a sequence containing exactly the set’s elements once), and specify clear bounds on ranges and domains (1-based indexing). Key correctness properties: operations preserve sequence/multiset/set semantics (no unintended element loss or duplication), replace/insert/remove maintain lengths and positions as specified, fold semantics match intended associativity/commutativity assumptions, and deterministic choice when multiple valid results exist (e.g., CHOOSE-based definitions must be constrained so result uniqueness is guaranteed).
