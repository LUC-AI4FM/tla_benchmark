Specify a concurrent state machine that models a single shared integer-valued location which can be manipulated by two distinct kinds of transitions, and reason about fairness and liveness between those transitions.

Model a system whose state is an integer drawn from a small finite domain. It should start in a particular initial value. Two transition classes are available at every step: one that increments (modulo the domain size) and one that performs an arbitrary or nondeterministic move within the domain (or, in a variant, a deterministic decrement with wrap-around). The scheduler may choose either class when both are enabled.

Require the specification to support stating and checking different fairness assumptions: (1) weak fairness for one class, (2) weak fairness for the other class, or (3) no fairness, so that combinations of fairness can be compared. Also allow strengthening fairness to a scheduling condition that ensures eventual occurrence of a chosen class infinitely often.

The model must express and allow proof obligations for these properties:
- Safety: all states remain within the finite domain and all transitions respect the domain constraints.
- Invariance: certain states (or congruence classes) are reachable only under specified transition patterns.
- Liveness: under given fairness assumptions, one transition class must occur infinitely often (eventual recurrence), and the system must visit a designated base state infinitely often (recurrence to zero).
- Counterexamples: show which liveness properties fail without appropriate fairness, and which hold when a specific weak-fairness assumption is imposed.

Provide the ability to state and check combinations of temporal formulas: always, eventually, leads-to, and weak-fairness conditions for individual transition classes, and to demonstrate both validity and negation of target liveness claims.
