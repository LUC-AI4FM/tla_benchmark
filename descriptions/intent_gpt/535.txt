Specify a concurrent system that manages a fixed collection of multi-field records (tuples) and supports concurrent reads and updates while preserving atomicity and consistency invariants. The model should capture a bounded set of records with immutable key fields and mutable value fields; keys uniquely identify records. Processes may perform three high-level operations: read a full record by key, update one or more value fields of an existing record, and insert or delete records within capacity limits. Operations must appear atomic to external observers (linearizability) and must not violate uniqueness of keys or allow any record to acquire an invalid sentinel value outside an agreed domain.

Model concurrency between multiple clients executing arbitrary sequences of these operations, possibly overlapping in time. Include nondeterministic scheduling and message delays to exercise interleavings. Specify safety properties: uniqueness of keys, domain constraints on field values, absence of lost updates (every completed update must reflect in subsequent reads unless overwritten by a later completed update), and preservation of integrity during concurrent operations (no partial or torn reads). Specify liveness goals: no operation invoked by a correct client should be permanently blocked (progress under fair scheduling), and completed updates should eventually become visible to readers. Also specify invariants that prevent creating or observing records with a designated sentinel minimum value that represents invalid state.
