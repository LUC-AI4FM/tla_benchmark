Specify a formal model of a sequence-capacity and feature-guarding service used by a model-checking toolchain. The system must provide (1) a way to associate with any sequence value a nonnegative integer that represents a static upper bound on its length (the "capacity"); (2) a mechanism for declaring or signaling that a particular language feature or operator is unsupported by the model checker, such that the model checker will halt or otherwise report an explicit error when that feature would be exercised during checking.

Model the domain of sequences over arbitrary element types and ensure that every sequence produced by the system has a well-defined capacity that is never negative and that is always an upper bound on the sequence's actual length. The capacity may be larger than the current length and can be used by tools to reason about memory or resource bounds; the model must allow capacities to be queried but not violated by sequence operations.

Model the unsupported-feature signal as an operation that carries a human-readable message and whose invocation causes a distinguished failure state in the model (representing the model checker stopping with an error). The model must guarantee that when the failure operation is reachable, the system enters the failure state and that no further normal progress occurs.

Key properties to verify:
- For every valid execution, every sequence's length is ≤ its capacity.
- Capacities are nonnegative integers and remain associated with their sequences consistently across operations that copy or transform sequences.
- If an unsupported-feature operation is invoked, the system reaches the failure state and no other normal actions occur after that point (safety of the failure signal).
