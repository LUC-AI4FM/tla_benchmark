Specify a model of a single pedestrian-activated traffic light for a simple intersection. The system has two observable light states (green and red) and a button that pedestrians press to request the light turn green. Model the environment and controller as a state machine that repeatedly accepts one of three actions: a pedestrian pressing the request button, the controller switching a currently green light to red, and the controller switching a currently red light to green in response to a request.

Requirements:
- Initially the light must be red and no request is pending.
- Pressing the button while the light is red and no outstanding request exists sets a “request pending” condition; pressing the button while the light is green or while a request is already pending has no effect.
- When the controller switches the light to green, any pending request must be cleared. The controller may switch to green only when there is a pending request and the light is red. The controller may switch to red only when the light is green.
- The model must allow nondeterministic scheduling of actions but preserve that only legal transitions occur.

Correctness properties to guarantee:
- Safety: the system never violates the guards above (i.e., no unauthorized state changes).
- Liveness: every time a request becomes pending, the light will eventually turn green (no request is permanently ignored).
- Progress: the light can change state according to guards (no deadlocked reachable state except intended stable states).

Also specify state variables, initial predicate, transition relation, and LTL invariants to assert safety and liveness, without prescribing internal implementation details or timing.
