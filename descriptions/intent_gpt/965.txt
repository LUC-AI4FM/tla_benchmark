Specify a formal grammar and validator for a configuration-file language used to control a specification-checking tool. The model should capture the syntax of valid configuration files and enable automated checking of whether a given token sequence is a well-formed configuration. The configuration language must support: top-level statements that map a keyword to one or more identifiers; two classes of keywords—those that require exactly one identifier and those that allow zero or more identifiers; declaration sections for constants that can contain either assignments (name = value) or replacements (name <- identifier); identifiers composed of letters, underscores, and digits but not identical to reserved keywords; numeric values including optional leading minus; quoted string literals permitting a broad set of printable characters; and set-like value expressions using braces with comma-separated elements (including nested literal forms). The model should treat whitespace and token boundaries appropriately and allow repeated statements. Key correctness properties: (1) every accepted token sequence must unambiguously parse as a sequence of valid statements according to the grammar; (2) identifiers must be distinguished from reserved keywords; (3) numeric, string, and set literal forms must meet their lexical constraints; (4) replacements and assignments are only allowed inside constant-declaration statements; (5) the grammar is the least (smallest) grammar satisfying these rules (no extra productions). Provide enough structure to generate or validate example token sequences and to check these invariants.
