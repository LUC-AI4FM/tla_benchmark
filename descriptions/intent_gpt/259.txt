Specify a simple data-access utility that extracts a particular field from records in a collection. Model an abstract system that receives records whose structure includes a named component that can hold values from a specified domain. The system must support an operation that, given a record, returns the value of that named component. The model should not assume any particular representation beyond the record having the required component and the component values belonging to a known set.

The specification should state the allowed forms of records, the domain of component values, and the operation's input and output types. It must guarantee that for every valid record the operation deterministically returns the component value and never fails or produces a value outside the declared domain. If a record lacking the component is presented, the model should describe how the system handles that case (for example, disallowing such inputs, returning an explicit error, or using an option/Maybe result), and the chosen behavior should be made explicit.

Key correctness properties: totality on valid inputs, determinism (same input always yields the same output), and preservation of value type (output belongs to the declared domain). Optionally include a property that the operation is observationally transparent (no hidden state changes) and that composing the operation with identity-like transformations yields the same result.
