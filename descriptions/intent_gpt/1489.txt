Specify a formal TLA+ model of an abstract two-step state transition pattern and a surrounding system that uses instantiation (renaming) of variables. The model should represent a small shared state with one distinguished variable that can be renamed when embedding a sub-specification. The core of the model is a pair of actions that execute in sequence (an action composition): the first action computes a value for one component based on the current state, and the second action checks a relation between the components and updates one component to the value computed by the first. Provide two system-level scenarios for comparison: one that composes the two actions first and then applies a renaming/instantiation of the distinguished variable, and another that first applies the renaming/instantiation to each action and then composes them. The goal is to show whether instantiation distributes over action composition and to demonstrate the semantic issues that arise from primed and unprimed occurrences of variables when renaming. Require that the model:
- Treats primed and unprimed occurrences consistently with TLA+ semantics (including the need to avoid accidental capture during substitution).
- Allows the distinguished variable to take a small finite set of values for exhaustive checking.
- Exposes cases that lead to contradictions or trivial identities after renaming (e.g., yielding FALSE or an identity relation on the renamed variable).
- Includes variants such as reversing the action order, nesting compositions and ENABLED, and priming composed expressions, so model checking can validate which transformations preserve behavior and which do not.
