Model Dijkstra’s original mutual-exclusion algorithm for N concurrently executing processes (an arbitrary finite set). The model should describe the behavior of each process as it repeatedly attempts to enter a critical section, executes it, then performs noncritical work before trying again. The model must capture the shared state used by the algorithm (simple Boolean flags per process and a single shared pointer used for arbitration) and allow nondeterministic scheduling of processes and nondeterministic examination order of other processes when checking flags. Do not prescribe a particular implementation style; instead specify the abstract operations each process performs: announce intent, inspect and update the shared pointer under the algorithm’s rules, scan other processes’ announcements in some arbitrary order, enter and leave the critical section, and reset its announcement. Require fairness assumptions sufficient to rule out unjustified perpetual starvation of enabled steps but allow a process to remain forever in the noncritical section unless specified otherwise.

Specify the following correctness properties to be checked:
- Safety (mutual exclusion): at most one process may be in the critical section at any time.
- Liveness (deadlock freedom): if some process is trying to enter the critical section (is beyond the initial noncritical step), then eventually some process will enter the critical section (under appropriate fairness).
- Optional liveness (starvation freedom): if desired, state the stronger property that each process that tries indefinitely eventually enters its critical section, and note that the model should allow demonstrating whether this stronger property holds or can be violated.
