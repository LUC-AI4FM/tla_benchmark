Specify a concurrent system in which a single mutable state component represents a shared resource. The model should allow arbitrary state transitions that may read and update that shared resource, including actions that expose whether certain operations are enabled, and actions that can transform the resource into new values. The system must support defining parameterized operations that capture combining passed-in values with the current resource value into records or tuples for later inspection, and must allow operations whose effect depends on the enabledness of suboperations. Ensure the model can express both ordinary state updates and higher-level observations that include the post-state of the resource. Required correctness properties:

- Safety: Every reachable state must maintain invariants about the shared resource (e.g., it must remain within a specified value set or satisfy a predicate after every transition).
- Noninterference of read-only observers: Observational operations that only construct tuples combining parameters with the current resource must not modify the resource.
- Liveness/Progress: If an operation is enabled repeatedly, then it must eventually execute (weak fairness for enabled operations), and enabledness checks used by other operations must reflect actual potential to make progress.
- Determinacy of enabledness: The enabledness of an action should be determined solely by the current state and parameters, and the model must be able to assert properties about when enabledness implies eventual state change.

Model should be abstract (no low-level scheduling), parameterizable by the domain of values for the shared resource and by the set of operations.
