Specify a TLA+ model of a light-client protocol that verifies and tracks block headers from a set of validators that may include Byzantine (faulty) nodes. The model should represent a network of named validators, a client that periodically requests and fetches light blocks for increasing block heights, and an external notion of time with possible clock drift. The client must maintain a verified chain head and a trusted checkpoint height, and it must be able to advance verification to a higher target height by obtaining and validating a quorum of validator votes or signatures according to a specified fault threshold (e.g., fewer than one-third faulty). The model must allow some validators to behave arbitrarily (Byzantine), including providing conflicting headers, refusing to respond, or supplying stale data, while honest validators follow the protocol.

The specification should express safety properties: the client never accepts a header that conflicts with previously verified headers, and it only accepts a header when signatures satisfy the fault-tolerance threshold and time-based trust constraints. It should express liveness properties under realistic assumptions: if a sufficient fraction of honest validators respond with consistent headers and timeouts are respected, the client eventually verifies the target height. Model clock drift and a trusting period for checkpoints so the client rejects headers outside allowable time windows. State the invariants and acceptance predicates that capture correctness without prescribing a particular implementation or step-by-step procedure.
