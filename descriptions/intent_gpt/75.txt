Specify a formal model of a small statically-typed operator language feature validation system. The system should accept declarations of operators with explicit type signatures and bodies, where signatures may declare multiple input types and a result type. It must parse and check the compatibility between the declared signature and the operator body, detect annotation or syntax mistakes that arise when the signature uses an incorrect arrow/connective symbol, and produce appropriate diagnostics rather than crashing.

Model the representation of operator declarations, the interpretation of type annotations that separate multiple argument types from the result type, and the rules for matching a body expression to the declared arity and result type. Include malformed-signature scenarios such as using a different arrow token in place of the proper signature separator, missing or extra argument types, and type/arity mismatches in the body. Specify how the system reports errors and how well-formed declarations progress to a validated environment.

Key correctness properties: well-formed declarations are accepted and yield a consistent typing judgment; malformed or mismatched signatures are rejected with a clear error classification and do not cause runtime crashes or internal pattern-match failures; error reporting is deterministic and preserves system invariants (no partial or inconsistent typing state after an error). Include liveness: the checker always terminates on finite declarations.
