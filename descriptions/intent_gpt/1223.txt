Specify a formal model of a language’s value-equality and function/construction semantics sufficient to express and check whether different syntactic ways of constructing values yield the same semantic values. The model should include finite tuples, records/maps, total functions defined by generator expressions, nested functions (functions whose values are functions), functions viewed as sets of ordered pairs, Cartesian-product indexing, and functional update operations that modify nested components. It must allow expressions that build collections by comprehension, expressions that build tuples and records literally, and a facility for functional/record/tuple update that can change nested fields or elements.

The model must capture when two expressions denote the same value despite different syntactic forms (for example, a function defined by a generator over a Cartesian product versus an equivalent nested-function definition; or a record written with keys in different orders). It must also distinguish genuinely different values (e.g., different nesting structures or differing element values). Include support for empty-domain functions/empty tuples and for comparing sets of functions built by comprehensions. Specify correctness properties asserting equality for intended-equivalent expressions and inequality for intended-distinct expressions. Also specify invariants that remain true under no-op system evolution (i.e., a trivial Next), enabling these equality properties to be checked as safety assertions.
