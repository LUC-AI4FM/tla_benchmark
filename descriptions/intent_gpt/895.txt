Model a shared-memory request/response service that mediates read and write requests from a fixed set of clients to a simple memory array. The model must include a finite set of client processes, a memory mapping from addresses to values, and per-client request state that can represent either no request, a pending memory request (address, operation, and write value if any), or a completed read result. The system must allow each client to: (1) issue a request that transitions its state to pending with a well-formed memory request; (2) have the mediator execute a single-step memory operation for a pending request, which either updates the memory for a write or returns the current memory value for a read and moves the client to a completed state; (3) receive an acknowledgement that resets the client to idle/ready without changing memory. Specify constraints ensuring that pending requests carry a valid address in the memory address domain and that values are from the allowed value domain. The correctness properties to prove are: (a) type safety/invariant preservation — every reachable state respects the domains/types of memory, addresses, client states, and per-client request contents; (b) that executing a write updates exactly the memory location named by the request and that executing a read returns a value currently stored at the requested address; and (c) that client state transitions preserve the consistency between a client’s control state and the permitted shape of its per-client request data (e.g., pending requests must contain full request tuples, idle/done states must not contain pending-request structure). Do not commit to an implementation style; express allowed atomic transitions and invariants abstractly.
