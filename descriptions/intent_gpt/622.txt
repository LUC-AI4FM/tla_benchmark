Model a Byzantine-fault-tolerant replicated state-machine consensus algorithm in an asynchronous network that aims to agree on a sequence of proposals (blocks) across a set of validators. The model should include a proposer selection mechanism that rotates or selects proposers over rounds, a round-based voting protocol where validators exchange proposals and two-phase votes (prepare/commit or equivalent), and a mechanism for locking and unlocking on values to ensure safety across rounds. The system must tolerate up to f Byzantine validators out of n total (with n > 3f), allow honest validators to progress in rounds despite asynchrony, and ensure liveness under reasonable synchrony assumptions (e.g., eventual stability of message delivery and leader timeliness).

Specify the possible messages, local validator state (including round, locked value and lock-round, and decision state), and the network as an arbitrary message buffer that may delay, reorder, duplicate, or drop messages from Byzantine nodes but eventually delivers messages between honest nodes when the network is stable.

State the correctness properties the model must guarantee:
- Safety: No two honest validators ever decide on different values.
- Agreement on decided prefix: If a block is decided by an honest validator at a given sequence position, all later decisions by honest validators must extend that block at that position.
- Validity: Any decided value must have been proposed by some validator.
- Termination/Liveness (under eventual synchrony and a correct leader): All honest validators eventually decide on a value for each sequence position.
- Fault tolerance bound: The protocol maintains safety and liveness properties as long as the number of Byzantine nodes does not exceed f.

Also require the ability to trace and replay specific sequences of high-level actions (propose, prevote/prepare, precommit/commit, decide) for debugging: the model should permit constraining executions to a given action sequence to inspect and reproduce counterexamples.
