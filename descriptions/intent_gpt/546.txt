Specify a concurrent system that implements a fixed-order, round-robin mutual exclusion protocol for N processes. The model should describe a set of N identical processes that repeatedly alternate between noncritical work and trying to enter a critical section. Only one process may be in the critical section at any time. Progress through the protocol must be governed by a shared token that designates which process is permitted to enter next; the token is passed deterministically to the next process in a cyclic order after a process leaves the critical section.

The specification should include:
- A representation of processes that repeatedly perform: noncritical section, request/await permission, critical section, and token handoff.
- A shared control value that designates the current token holder; the token value must always be one of the valid process identifiers.
- A rule that a process may enter the critical section only when the shared token equals that process’s identifier.
- A deterministic token-update rule that, when a process exits its critical section, transfers the token to the next process in numeric/cyclic order (wrap-around from the last to the first).
- Initial conditions allowing any valid process to hold the token and all processes to start outside the critical section.

State the correctness properties to be verified:
- Safety: mutual exclusion — at most one process is in the critical section at any time.
- Invariance: the token value is always within the domain of process identifiers.
- Liveness/progress: every process that repeatedly attempts to enter the critical section will eventually enter it (no starvation) under a fair scheduler assumption.
