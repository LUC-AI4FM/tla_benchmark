Model a distributed replicated state machine that implements a variant of leader-based consensus for a dynamic group of servers supporting safe membership changes and node retirement. The model should describe servers that maintain per-server logs of entries (normal entries, signed entries, reconfiguration entries, and retirement markers), terms and leader election (including optional pre-vote), and an unreliable network delivering point-to-point messages. It must capture leader election, log replication via AppendEntries, vote requests/responses (including pre-vote semantics), and leader transitions, while allowing servers to join and be retired through reconfiguration transactions recorded in the log.

The specification must ensure safety and liveness-oriented correctness properties:
- Safety: committed entries are totally ordered and do not conflict across different servers; once an entry is committed, no other conflicting entry can be committed at the same log index; committed entries are present in any leader’s committed prefix and in any server that reports the entry committed.
- Election safety: at most one leader per term; a leader must have received quorums of votes in each active configuration before assuming leadership.
- Log consistency: followers accept leader AppendEntries only when they match at the advertised previous log index/term; leaders preserve only committable prefixes on assumption of signature-based committability.
- Reconfiguration safety: membership changes (adds/removes/retirements) are applied only via committed reconfiguration entries, quorums are computed per relevant configuration, and a node that reaches final retired-committed state stops participating in future elections and leadership.
- Message-type and data-type invariants: all messages and log entries satisfy declared well-formedness constraints.
Also include invariants relating committable (signed) entries, commit indices, and the computed membership state so that retirement transitions and the removal of nodes from active configurations are safe and detectable. The network model should allow message loss, reordering, and duplication according to a chosen delivery guarantee, and the spec should expose the assumptions required for verification.
