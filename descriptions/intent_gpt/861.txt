Specify a formal model of a fair readers–writers access-control system for a single shared resource. The model should describe an unbounded execution in which a fixed finite set of actors may request either read or write access, may be granted access, and may later release it. Requests must be queued so that all requests are served in a fair, FIFO manner: arrivals are enqueued and the front of the queue is considered for service. Multiple readers may hold the resource concurrently, but writers must have exclusive access. A writer may be granted the resource only when no readers are active. When the queue front is a read request, the system may grant it and may also grant subsequent queued read requests at the front(s) so long as no writer is started; when the queue front is a write request, only that writer may be started. Actors that already have a pending request must not enqueue duplicate identical requests. The model should include liveness constraints ensuring that every actor that repeatedly requests access will eventually be granted and will also eventually release the resource, and that the system does not starve any actor: every request eventually reaches the front and is served. Specify safety properties: readers and writers never hold the resource simultaneously, and at most one writer holds it at a time. Also specify type and queue-wellformedness invariants. Do not prescribe a particular implementation; leave queue and scheduling behavior abstract but constrained to satisfy the fairness and FIFO-serving requirements.
