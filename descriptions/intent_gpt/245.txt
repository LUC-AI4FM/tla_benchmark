Specify a formal model of a simple typed-expression system that supports user-defined type aliases and basic operations on values of those types. The model should represent an extensible notion of types that can include base types, uninterpreted (opaque) types introduced as aliases, and set types constructed from other types. It must allow declaration of a new alias for an uninterpreted type and then express membership and construction operations that treat the aliased type uniformly with other types. The system must enforce that values are associated with exactly one type, that set construction and membership respect the declared element type (no mixing of values from different element types), and that aliasing preserves type identity for the purposes of type-checking and set formation. Specify operations that add a type alias and form a singleton set containing a value of the aliased type, and specify checks that ensure such a singleton is well-typed. The key correctness properties are (1) type-safety: no operation produces a value whose type disagrees with its construction, (2) alias transparency: an alias behaves as the corresponding uninterpreted type in typing and membership, and (3) consistency: adding aliases does not introduce contradictions or permit construction of ill-typed sets.
