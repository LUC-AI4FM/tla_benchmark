Specify a formal model of a parametrized constant value and a dependent module instance that uses it, emphasizing assumptions and theorem obligations about the constant's value. The system should allow a top-level specification to declare a numeric parameter whose value is constrained by an assumption that equates it to a specific numeric literal. The model must instantiate or include a subordinate component, supplying that numeric parameter as an actual for a corresponding formal parameter, and propagate any fixed numeric argument values required by the subordinate component. The specification must explicitly record the assumption as a named hypothesis and also state a theorem (or proof obligation) that asserts the same numeric equality as a correctness property to be checked; both the assumption and the theorem are part of the contract the module must satisfy. The design should permit making the subordinate component a concrete instance with the given mappings, and it must support naming the instance for later reference. Key properties to guarantee: the numeric parameter equals the required literal, the subordinate instance receives the exact numeric and other required argument mappings, and the top-level theorem asserting the numeric equality follows from the declared assumptions. The model should be abstract about implementation details and focus on these structural and logical relationships.
