Specify a model of an asynchronous message-passing network between servers in which messages are represented abstractly and the network is unreliable. The model should capture a multiset (bag) of in-transit messages and allow these high-level operations: a server may send a message (adding one copy to the multiset), a server may consume or discard a message when it finishes processing (removing one copy), and a server may reply by atomically removing a request and adding a response. The network may nondeterministically drop one or more copies of a message, and may nondeterministically duplicate a message, but must never invent new message types out of thin air. The model must allow arbitrary interleaving of sends, consumes, drops, dupes, and replies.

Specify correctness properties to check about protocols running over this network:
- Safety: the multiset count for any message never becomes negative; messages are only those that were sent (possibly duplicated) or created by replies.
- Liveness assumptions: if a server repeatedly attempts to send a message, the model should allow that message to eventually appear in the multiset (nontrivial fairness option).
- No-loss guarantees for modeled reliable channels: allow optional stronger semantics in which messages, once sent, are eventually delivered unless dropped by the network; allow specification of channels with and without duplication.
- Invariants for protocol-level correctness: e.g., request–response matching (every processed request yields at most one corresponding response), and absence of unbounded message growth unless servers keep sending.

Do not prescribe concrete message encodings or process internals; the focus is on the network abstraction and the properties protocols must satisfy when run over it.
