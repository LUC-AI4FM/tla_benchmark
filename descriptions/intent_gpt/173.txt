Specify a model of a simple two-variable discrete-state system that evolves in synchronous steps. The system has two integer-valued state components and starts from a fixed initial state. At every step, both components are deterministically updated by swapping values between them. The specification should capture all reachable states and infinite behaviors produced by repeatedly applying that deterministic swap transition.

State the following correctness requirements as temporal properties to be checked against the model:
- Safety: certain bad-state conditions must never be reachable (for example, a constraint relating the two variables that must always hold).
- Liveness (recurrence): one designated value should occur in the first component infinitely often (i.e., the value recurs repeatedly along every fair infinite execution).
- Conditional eventuality: for the second component, express that either a strict inequality condition holds always, or else some designated equality value will eventually occur and possibly recur; formulate this as a temporal implication/combination mixing invariance and eventuality.
- Non-persistence / persistence distinctions: specify two contrasting temporal scenarios — one asserting that it is impossible for the first component to remain above a threshold forever after some point, and another that asserts the opposite (that it eventually stabilizes above that threshold). These are mutually exclusive and should be expressible to demonstrate detection of liveness conflicts.

Do not prescribe implementation details of the model checking run, fairness constraints beyond those inherent in the deterministic step semantics, or any particular encoding. The goal is to formally state the system, its initial condition, deterministic swap transition, and the above temporal properties so a model checker can verify which liveness combinations hold or fail.
