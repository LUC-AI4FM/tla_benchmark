Specify a TLA+ model of a simple data-inspection facility that evaluates and reports values of expressions during model checking. The model should allow a verifier to declare a collection of expressions and associated textual identifiers, request that the model checker evaluate each expression, and produce the identifier paired with the computed value for inspection. The model must support expressions that compute numbers, strings, and structured values such as records and nested records, and must allow expressions containing arithmetic, field selection, and non-destructive updates to records. Evaluation order should be controlled so that printed outputs appear in a deterministic, user-specified sequence. The model should not change the system state when printing: printing is purely observational and has no effect on other behavior. Key correctness properties:
- For every declared pair (identifier, expression) the model checker must evaluate the expression and output the identifier together with the precise value of the expression.
- The printed values must reflect the semantics of arithmetic, record selection, and record update expressions.
- The sequence of printed outputs must match the declared order.
- Printing must not introduce or mask errors in expression evaluation; evaluation failure should be reported rather than silently ignored.
Do not specify any particular implementation mechanism for how printing is invoked; describe only the observable behavior and properties above.
