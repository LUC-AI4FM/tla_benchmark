Specify a concurrent message-passing system with two independent bounded channels: one carrying integer-valued messages from a fixed small domain and the other carrying string-valued messages from a fixed small alphabet. The system supports four kinds of atomic events that can occur in any order and repeatedly: (1) nondeterministically send an integer message (choose one value from the integer domain and append it to the integer channel), (2) nondeterministically receive and remove an integer message from the integer channel and, upon receiving, record whether the value received equals a particular distinguished integer, (3) nondeterministically send a string message (choose one symbol from the string alphabet and append it to the string channel), and (4) nondeterministically receive and remove a string message from the string channel and, upon receiving, record whether the symbol received equals a particular distinguished symbol.

Model the channels as unordered sets of messages (i.e., membership matters but not ordering or multiplicity beyond set semantics). The send events add a chosen message to the corresponding set; the receive events remove some existing message from the corresponding set and update a single Boolean flag for that channel indicating whether the last-received message was the distinguished value. The two flags are independent. The model must ensure messages originate only from the two given finite domains and that channel contents remain subsets of those domains.

Specify safety properties: channel contents always consist only of valid messages, and the Boolean flags correctly reflect only values that were actually received (i.e., a flag can become true only as a result of receiving the distinguished value). Also specify liveness requirements: each send action for each value remains continuously enabled (i.e., the system can always choose to send any allowed value), and receptions are eventually possible if corresponding messages are present. Include an invariant asserting that the two channels and flags evolve independently (actions on one channel do not directly change the other channel or its flag).
