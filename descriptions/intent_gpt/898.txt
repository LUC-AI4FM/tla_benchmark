Specify a formal model of a write-through cache controller that mediates access to a shared atomic memory for a fixed set of processors. The model should describe the externally visible behavior of the memory subsystem (what processors can send and receive) and the internal state needed to implement a write-through policy, but must not commit to a particular implementation strategy. The system must allow processors to issue read and write requests, have those requests forwarded to the underlying memory, and deliver correct responses.

Requirements:
- Processors may be in one of a small set of control states that determine when they can issue a request, when a request is outstanding, and when a response can be accepted.
- Requests are either reads (address) or writes (address, value). When a write is performed, the underlying memory must be updated immediately (write-through).
- For a read request, the response must reflect the current value in memory at the requested address at the time the request is serviced.
- Communication with the memory may be modeled abstractly by an internal interface that receives a request and later produces a matching reply; the model must allow concurrency among processors but ensure each processor’s request-response pair is matched.
- The initial state must have memory initialized to some mapping from addresses to values, processors in the idle state, and no outstanding requests.
- Safety properties: (1) Type invariants on memory, control states, and buffers; (2) Coherence: every reply to a read must equal the value present in memory at the address when the request was executed/served according to the write-through semantics; (3) No lost or spurious replies: every reply corresponds to a previously issued request and processors return to idle after the reply.
- Liveness property: every issued request is eventually serviced and replied to (fairness assumptions may be required).

Deliver a high-level TLA+ specification of these components and state the invariants and refinement obligations needed to relate the model to an abstract atomic memory interface (mapping the controller’s state and buffers to the abstract memory’s state and pending operations).
