Specify a formal model of a two-phase commit protocol for a single transaction coordinator and a fixed set of resource managers. The model should capture the possible states of each resource manager and of the transaction coordinator, the messages exchanged between them, and the coordinator’s collection of “prepared” responses. It must allow asynchronous, unreliable message delivery (messages can be delayed, duplicated, or arrive out of order) but not lost permanently unless the protocol permits it, and must permit interleaving of independent actions.

The specification should express the protocol’s intended safety properties:
- Agreement: If the coordinator decides to commit, then every resource manager must eventually be in the committed state; if the coordinator decides to abort, then every resource manager must eventually be in the aborted state.
- Non‑triviality / Valid decision: The coordinator may only decide commit if all resource managers have indicated readiness to commit; otherwise the coordinator must decide abort.
- No conflicting decisions: It is impossible for some participant (coordinator or RM) to be in commit while another is in abort for the same transaction.

Include liveness goals to enable useful counterexample search:
- If all messages are eventually delivered and no failures occur, then the protocol should eventually reach a definitive decision (commit or abort) and all RMs should reach that decision.
- If the coordinator decides (commit or abort), that decision should eventually be learned by every RM provided messages are delivered.

Do not prescribe a particular implementation mechanism; allow modeling choices for message buffers, failure/timeout detection, and recovery, but require that the model can express scenarios that demonstrate coordinator abort and coordinator commit and that support symmetry reduction-friendly views for state space exploration.
