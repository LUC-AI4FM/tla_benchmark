Specify a model of a model-checker trace exporter that, after a counterexample is discovered, produces a plain-text file containing a human-readable representation of the counterexample trace. The model should capture the following behavior and requirements:

- The system accepts a description of a counterexample trace (a finite sequence of states and optionally console output) produced by the model checker.
- If no counterexample is present, or if the counterexample indicates that console output suppression is requested, no file is produced and the exporter reports success without side effects.
- If a counterexample is present and file output is enabled, the exporter writes a single UTF-8 text file whose name is derived from a provided filename template (e.g., by ensuring a .tla extension). The file contents must start with a module header identifying the file, then include a textual dump of the entire counterexample trace in a deterministic, readable format.
- The write operation must be atomic with respect to replacement: an existing file with the same name is overwritten (truncated and replaced).
- The exporter must report whether the write succeeded or failed. A successful write returns an exit code indicating success and a log message that the counterexample was written; a failure yields a nonzero exit code and an appropriate error indication.
- Model correctness properties: if a counterexample with output enabled exists, then eventually a successful write occurs and the file contents exactly reflect the textual representation of that counterexample; no spurious file is created when output is disabled; and file-naming behavior preserves the required extension and header format. Also assert liveness for completion of the write and safety for absence of partial/truncated files in the success case.
