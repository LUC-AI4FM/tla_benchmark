Specify a concurrent procedure-call system in which three independent threads each execute a recursive computation of the factorial of a given positive integer by alternating between two mutually recursive procedures. The model should treat each thread as an independent actor with its own private call stack and local procedure arguments, while sharing a global array used to accumulate each thread’s partial product. The system must allow two threads to be instances of one role and a third thread to be a separate role; each thread should be able to start a factorial computation with the same initial argument and may interleave arbitrarily with the others.

The specification must capture procedure call and return semantics: pushing a frame on the thread’s stack when a call is made, updating local arguments and locals appropriately, and restoring the calling frame on return. It must model mutual recursion between two procedures that decrement their numeric argument and multiply the thread’s accumulator by the current argument until reaching zero.

Key correctness properties to guarantee:
- Safety: each thread’s accumulator equals the factorial of its initial argument at the point where that thread completes (an assertion that the accumulated product equals n! when the thread finishes).
- Preservation: shared state invariants such as accumulators remaining natural numbers and no corruption of other threads’ stacks or accumulators.
- Progress/termination: every started factorial computation eventually returns (no permanent livelock in the recursion), and the system can reach a global quiescent state in which all threads have completed.

Do not prescribe internal implementation details such as exact variable names, labels, or scheduling; specify observable behaviors, per-thread call-stack semantics, and the above safety and liveness properties to be verified.
